# 지라 규약 — 4축 분리

GROMO 지라(`romance.atlassian.net`, 프로젝트 키 `GROMO`)에서 티켓을 어떻게 분류하고
이름 붙이는지에 대한 정본이다. 2026-08-09 전면 재편으로 확정했다.

## 왜 4축인가

재편 전에는 **성격이 다른 두 축이 에픽 필드 하나에 섞여** 있었다.

- 영구 버킷형 에픽: `그룹 기능`(자식 45) · `[Stats] 통계` · `Production 환경`
  → 안 닫히니 계속 비대해진다
- 시한부 작업형 에픽: `TT 포커스 모드` · `기획 심의` · `콜드 메일`
  → 닫히니 후속 작업이 갈 곳을 잃는다

그 결과 비에픽 티켓의 **64%가 에픽 없이** 떠 있었고, `온보딩`이 닫히자
`[Onboarding] 온보딩 플로우`가 새로 생기는 식으로 같은 도메인의 에픽이 세대별로 쌓였다.

축을 넷으로 나누면 이 문제가 구조적으로 사라진다.

| 축 | 필드 | 닫히나 | 답하는 질문 |
| --- | --- | --- | --- |
| **도메인** | **`도메인`** (드롭다운) | ❌ 영원히 안 닫힘 | "그룹 관련 전부" |
| **플랫폼** | Label | ❌ 영원히 안 닫힘 | "iOS 할 일" |
| **이니셔티브** | **Epic** | ✅ 끝나면 닫는다 | "지금 무엇을 하는 중" |
| **출시** | fixVersion | ✅ 릴리스로 끊는다 | "다음 출시에 뭐가 나가나" |

> **왜 Component 가 아니라 커스텀 필드인가**
> 처음엔 지라 표준 Component 로 만들었는데, **team-managed FREE 프로젝트에서는
> 컴포넌트 필드가 UI 어디에도 노출되지 않는다** — 이슈 화면에도, 프로젝트 필드 설정에도
> (`구성`/`compo` 검색 0건), 보드 필터에도 없고 `/components` 페이지는 404다.
> API·JQL 로는 완벽히 동작하지만 **사람이 티켓을 만들 때 고를 수가 없다.**
> 그래서 같은 값을 갖는 드롭다운 커스텀 필드 `도메인`(`customfield_10342`)을 정본으로 두고,
> Component 는 미러로 유지한다(두 필드에 같은 값을 넣는다).
> 드롭다운이라 라벨과 달리 오타·표기 흔들림이 원천 차단된다.

### 기능을 디벨롭하면 에픽은 어떻게 되나

**새 에픽을 만든다.** `도메인`이 그대로라 도메인 조회는 안 깨지고,
에픽 목록이 그 도메인의 **연혁**이 된다.

```
도메인: 챌린지·내기           (영원히 안 닫힘 — 도메인 조회의 앵커)
 ├ Epic [챌린지·내기] 챌린지 v0 — 초기 API
 ├ Epic [챌린지·내기] 챌린지·내기 v1 — 에스크로 · 정산 엔진      ✅ 닫힘
 ├ Epic [챌린지·내기] 용어 정비 · 참여 흐름 하드닝               ✅ 닫힘
 └ Epic [챌린지·내기] 챌린지 재구축 (웨이브 1~4)                🔵 진행중
```

## 1. `도메인` — 도메인축 (작업·버그·Subtask 에 필수)

**작업·버그·Subtask 는 정확히 하나를 갖는다. 에픽에는 붙이지 않는다** — 에픽은 이름의
`[도메인]` 접두가 그 역할을 하고, 필드로 또 넣으면 두 곳이 어긋날 수 있다.
티켓 화면 상단과 백로그 필터에서 바로 고를 수 있다. Component 에도 같은 값이 미러로 들어간다.

| 제품 도메인 | 엔지니어링 | 비즈니스 |
| --- | --- | --- |
| 그룹 · 챌린지·내기 · 집중세션 | 인프라·배포 · QA | 마케팅·그로스 |
| 리그 · 통계 · 스크린타임 | 개발환경·워크플로 · 관측·분석 | 기획·리서치 |
| 인증·계정 · 온보딩 · 설정 | 데이터·스키마 · 디자인 시스템 | |
| 캐릭터·상점 · 친구 · 알림·푸시 | | |

권위 있는 목록은 `도메인` 필드의 드롭다운 옵션이다. 위 표는 스냅샷이라 낡을 수 있다.

**경계가 헷갈릴 때**
- 그룹 ↔ 챌린지·내기 — 챌린지·회차·내기·참가비·정산·판정은 **챌린지·내기**.
  그룹 생성·검색·공지·멤버·초대 링크는 **그룹**.
- 도메인을 새로 만들기 전에 자문한다: **앞으로도 티켓이 계속 생기는 도메인인가?**
  아니라면 그건 도메인이 아니라 에픽이다.
- 옵션을 추가하면 **Component 에도 같은 이름으로 만들어 미러를 맞춘다.**

## 2. Label — 플랫폼과 성격 (해당될 때만)

플랫폼: `iOS` · `Android` · `BE` · `App`(프론트) · `Infra`
성격: `chore` · `refactor` · `qa` · `wave2` 같은 배치 표식

**도메인을 라벨로 넣지 않는다.** 그건 `도메인` 필드의 일이다.

### `qa` 라벨 — 검증은 도메인이 아니라 활동이다

"챌린지 결과 모달 검증"은 **챌린지·내기 도메인의 QA 활동**이지 QA 도메인이 아니다.
QA 를 도메인으로 잡으면 `"도메인" = "챌린지·내기"` 조회에서 그 티켓이 빠진다.

- 특정 제품 기능을 검증·수정하는 티켓 → **그 제품 도메인** + `qa` 라벨
- 부하테스트 하네스 · E2E 자동화 · 테스트 코드 · 실기기 패스처럼 **검증 대상이 제품 기능이
  아닌 것** → `QA` 도메인

같은 논리가 `chore`·`refactor` 에도 적용된다 — 무엇을 하느냐(활동)는 라벨,
무엇에 대해 하느냐(대상)는 도메인이다.

## 3. Epic — 시한부 이니셔티브

### 이름
```
[<도메인>] <이니셔티브 이름>
예) [챌린지·내기] 챌린지 재구축 (웨이브 1~4)
    [인프라·배포] prod 환경 구축 · 심사 준비
```

### 규칙
- **시작과 끝이 있는 작업 덩어리**에만 만든다. 끝나면 **닫는다**.
- 도메인 이름만으로(`[그룹] 그룹`) 에픽을 만들지 않는다 — `도메인` 필드와 역할이 겹친다.

#### 예외: `[공통]` — 여러 도메인에 걸치는 시한부 묶음

```
[공통] 1.1.0 앱 개선      ← 애니메이션 효과 · 온보딩 개선 … 각각은 에픽 낼 만큼 크지 않다
```

**`공통` 은 에픽 접두 전용이다. `도메인` 드롭다운에는 없다** — 티켓은 각자 실제 도메인
(온보딩 · 디자인 시스템 …)을 그대로 갖고, 우산만 에픽이 씌운다.

이게 재편으로 없앤 버킷형 에픽(`그룹 기능`)과 뭐가 다른가 — **닫히는가**로 갈린다.

| | 버킷형 (금지) | `[공통]` (허용) |
| --- | --- | --- |
| 이름 | 도메인 이름 (`그룹 기능`) | 시한이 박힌 묶음 (`1.1.0 앱 개선`) |
| 끝 | 없다 → 영원히 비대해진다 | 1.1.0 출시 = 닫힘 |
| 대안 | `도메인` 필드가 대신한다 | 없다 — 자투리를 낱개로 두면 안 보인다 |

그래서 `[공통]` 을 쓸 때는 **이름에 닫히는 조건이 드러나야 한다**(릴리스 번호·분기 등).
`[공통] 개선` 처럼 끝이 없는 이름은 버킷형과 같아진다.
- **모든 티켓이 에픽에 속할 필요는 없다.** 단발 버그·잡무는 `도메인` + 릴리스로 충분하다.
  억지로 묶으면 다시 버킷형 에픽이 생긴다.
- 에픽 하나가 30~40건을 넘어가면 쪼갤 때가 된 것이다.

### 계층
지라 FREE·팀관리형이라 계층은 **3단**이고 에픽 위로는 없다.

```
에픽 (1)          ← 시한부 이니셔티브
 └ 작업·버그 (0)   ← 도메인 · Label · fixVersion 이 붙는 층
    └ Subtask (-1) ← parent 가 이미 작업이라 에픽에 직접 못 붙는다
```

Subtask는 **에픽에 붙이지 않는다**(붙이면 부모-자식 관계가 깨진다).
`도메인`·fixVersion 은 부모 작업과 같은 값을 준다.
2026-07 이후 신규 사용이 없으니, 새로 만들 일이 있으면 그냥 작업으로 만드는 편이 낫다.

## 4. fixVersion — 출시

- **출시된 완료 티켓은 반드시 버전을 갖는다.** 어느 릴리스로 나갔는지가 이력이다.
- **출시 대상이 아닌 완료 건은 예외다** — 취소·중복으로 닫은 것, 기획·리서치·문서처럼
  코드로 나가지 않는 작업. 억지로 버전을 붙이면 그 릴리스의 범위가 오염된다.
- **미완료 티켓은 비워도 된다.** 어느 릴리스에 실을지는 아직 결정이 아니다.
- 릴리스가 끝나면 `released` 로 끊는다.
- ⚠️ **버전을 archive 하지 않는다.** archived 버전에는 이슈를 할당할 수 없고
  (`400 — 보관되었으므로 해당 버전에 이슈를 할당할 수 없습니다`),
  릴리스 페이지에서도 숨겨져 `released` 마킹이 무의미해진다.

## 5. Summary — 대괄호는 에픽만

```
에픽    [챌린지·내기] 챌린지 재구축
작업    챌린지 삭제 시 OPEN 회차 무효화 + 전원 환불
        도메인=챌린지·내기 · Label=BE · Epic=[챌린지·내기] 챌린지 재구축
```

작업·버그 summary에는 `[Group]` · `[BE]` · `[BUG]` 같은 접두를 **붙이지 않는다.**
그 정보는 전부 다른 필드에 있다. `[BUG]`는 이슈타입이 이미 말해준다.

## 신규 티켓 체크리스트

**작업 · 버그**
- [ ] `도메인` 하나 (필수)
- [ ] Label — 플랫폼이 명확하면
- [ ] Epic — **지금 굴러가는 덩어리 작업의 일부라면.** 아니면 비워둔다
- [ ] summary에 대괄호 접두 **없음**
- [ ] 출시 대상이면 완료 처리할 때 fixVersion 확인

**Subtask**
- [ ] `도메인` · fixVersion 은 **부모 작업과 같은 값**
- [ ] Epic 은 **비운다** — 부모 작업을 통해 이니셔티브에 속한다
- [ ] summary에 대괄호 접두 **없음**

**에픽**
- [ ] 이름은 `[도메인] 이니셔티브` — 에픽은 **대괄호 접두가 필수**다 (위 금지 규칙의 예외)
- [ ] `도메인` 필드는 **비운다** — 이름의 접두가 그 역할을 한다

## 자주 쓰는 JQL

```sql
project = GROMO AND "도메인" = "챌린지·내기" AND statusCategory != Done
project = GROMO AND "도메인" = "그룹"
project = GROMO AND "도메인" = "리그" AND labels = BE
project = GROMO AND parent = "GROMO-####"
project = GROMO AND fixVersion = "1.1.0"
project = GROMO AND "도메인" IS EMPTY AND issuetype != Epic
project = GROMO AND ("도메인" = "그룹" OR (issuetype = Epic AND summary ~ "\\[그룹\\]"))
```

| 쿼리 | 무엇을 보나 |
| --- | --- |
| 1 | 이 도메인에서 **지금 굴리는 것** |
| 2 | 그룹 도메인의 **작업·버그·Subtask** — 에픽은 `도메인` 이 비어 있어 안 잡힌다 |
| 3 | 리그 백엔드 |
| 4 | 특정 이니셔티브에 속한 것 |
| 5 | 다음 출시분 |
| 6 | **규약 위반** — 주워담아야 할 것 |
| 7 | 그룹 관련 **전부** (작업 + 에픽까지) — 도메인 연혁을 같이 보려면 이걸 쓴다 |

⚠️ JQL 에는 주석 문법이 없다(`--` 를 넣으면 파싱 오류). 위 표처럼 설명은 쿼리 밖에 둔다.
⚠️ 같은 사이트에 다른 프로젝트(`RVUD`)가 있으므로 **`project = GROMO` 를 반드시 붙인다.**
안 붙이면 남의 프로젝트 티켓이 섞이고, 그 상태로 일괄 변경하면 사고가 난다.

백로그·보드에서는 **필터 → 필드 추가 → 도메인**으로 같은 걸 클릭만으로 할 수 있다
(보드는 이미 프로젝트 범위라 `project` 조건이 필요 없다).

마지막 쿼리는 **정기적으로 확인한다.** 결과가 0이 아니면 누군가 도메인 없이 티켓을 만든 것이다.
복구는 저장소만으로 가능하다 — 별도 도구가 필요 없다:

1. 위 쿼리로 누락 티켓을 찾는다.
2. 각 티켓의 **`도메인` 드롭다운**에서 값을 고른다. 여러 건이면 검색 결과에서
   티켓을 다중 선택해 **일괄 변경**으로 한 번에 넣는다.

**Component 미러는 손대지 않는다.** 이 프로젝트에서 Component 는 UI 어디에도 없어
사람이 넣을 방법이 없다(위 박스 참조). 미러는 오너가 API 스윕으로 주기적으로 맞춘다 —
`도메인` 만 채워두면 된다.
