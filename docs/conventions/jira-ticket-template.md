# 지라 티켓 양식 — 받는 사람이 되묻지 않고 착수하는 지시서

티켓 본문의 **양식**, 만들 때의 **규칙**, 그리고 **게이트가 막는 조건**의 정본이다.
분류(도메인·Label·Epic·fixVersion)는 `jira-conventions.md` 가 정본이고, 이 문서는 **본문**을 다룬다.

왜 필요한가 — 팀원이 어떻게 착수해야 할지 몰라 티켓 생성이 한 사람에게 몰렸고, 그 비용이 너무 컸다.
그래서 양식을 고정하고, 양식에 못 미치는 티켓은 **만들어지지 않게** 막는다. 애매한 티켓 하나가
되묻기·재작업으로 잡아먹는 시간이 양식을 채우는 시간보다 크다.

## 1. 본문 골격 (복붙용)

Jira 에서 직접 만들 때 설명란에 그대로 붙여 넣고 채운다. 섹션 제목의 이모지·문구는 바꾸지 않는다 (게이트가 이 문자열로 섹션을 찾는다).

```
### 🎯 목표
왜 하는가 / 무엇을 만드는가 — 배경과 만들 것을 2~4줄.

### ✅ 완료 조건
- [ ] 받는 사람이 자기 손으로 체크할 수 있는 관찰 가능한 사실 1
- [ ] 관찰 가능한 사실 2

### 📎 참고 자료
- docs/prd/<기능>/policy.md — 관련 결정
- server/data-api/.../XxxService.java — 따라야 할 기존 패턴

### 📦 산출물
- 유형: PR
- 남길 위치: server/data-api — OneOrThree/phone PR

### ⏱ 예상 작업 시간
4h
```

| 요소 | 어디에 | 규칙 |
| --- | --- | --- |
| 목표 | 본문 `🎯 목표` | 필수. 10자 이상 |
| 완료 조건 | 본문 `✅ 완료 조건` | 필수. **2개 이상**, 각 항목이 관찰 가능한 사실 (§2). 3~6개가 적당, 10개를 넘으면 티켓을 쪼갠다 |
| 참고 자료 | 본문 `📎 참고 자료` | 선택. 실제로 존재하는 경로·링크만. 「알아서 찾아보세요」는 참고 자료가 아니다 |
| 산출물 | 본문 `📦 산출물` | 필수. `유형:` 은 아래 목록 중 하나, `남길 위치:` 는 구체적인 곳 (§3) |
| 예상 작업 시간 | 본문 `⏱ 예상 작업 시간` | `30m` · `4h` · `1d` · `2.5d`. **팀원에게 시키는 티켓은 필수**, 본인 백로그는 선택. 스토리 포인트로 자동 환산 (`≤2h`=1 · `≤5h`=2 · `≤8h`=3 · `≤3d`=5 · 그 이상=8) |
| 도메인 | `도메인` 필드 | 필수 (에픽 제외). 드롭다운에서 하나 |
| 담당자 | `담당자` 필드 | 기본 = 만드는 사람 본인 |
| 기한 | `기한` 필드 | 스프린트에 넣을 때만 기본 = 활성 스프린트 종료일. 백로그는 비움 |
| 스프린트 | `스프린트` 필드 | 기본 = 현재 활성 스프린트. 백로그로만 두려면 비운다 |
| Label · Epic · fixVersion | 필드 | `jira-conventions.md` 대로 — 플랫폼이 명확할 때, 시한부 덩어리의 일부일 때, 미완료는 비움 |

summary 는 **동사형 한 줄**, 80자 이내, 대괄호 접두 없음 (`[BE]` · `[BUG]` 금지 — 에픽만의 특권).

## 2. 완료 조건 쓰는 법

받는 사람이 **자기 손으로 체크할 수 있는 관찰 가능한 항목**으로 쓴다. 경로·엔드포인트·상태코드·파일·숫자가 들어가면 대개 관찰 가능하다.

| ❌ 이렇게 쓰지 않는다 | ✅ 이렇게 쓴다 |
| --- | --- |
| 잘 동작하게 한다 | `POST /api/groups/{id}/invite` 가 201 + 링크를 반환한다 |
| 테스트 추가 | 만료 링크 재사용 시 409 를 검증하는 테스트가 있다 |
| 문서화 | `docs/prd/invite/policy.md` 에 만료 정책 D 항목이 추가돼 있다 |
| 디자인 정리 | Figma 「온보딩 v2」 페이지에 시안 3종이 올라가 있고 링크가 티켓 코멘트에 있다 |
| 조사한다 | 후보 3개의 지연·비용 비교표가 `docs/engineering/<주제>/research.md` 에 있다 |

## 3. 산출물

| `유형:` | `남길 위치:` 예 |
| --- | --- |
| `PR` | `server/data-api — OneOrThree/phone PR` |
| `문서` | `docs/prd/invite/policy.md` |
| `조사 리포트` | `docs/engineering/<주제>/research.md` 또는 Confluence 링크 |
| `디자인 시안` | Figma 파일·페이지 링크 |
| `설정 변경` | `server/scripts/docker-compose.dev.yml` · AWS Secrets `gromo/dev/env` |
| `데이터 작업` | `V<N>__desc.sql` 마이그레이션 · 스크립트 경로 |
| `기타(무엇인지)` | 괄호 안에 무엇인지 적는다 — `기타(슬랙 공지)` |

위치는 **레포 경로 / PR 대상 레포 / URL / 지라 코멘트** 중 하나로 구체적이어야 한다. 「알아서」「적당한 곳」은 위치가 아니다.

## 4. 게이트 — 이 조건에 걸리면 티켓이 만들어지지 않는다

Claude Code 에서는 `.claude/jira_gate.py` 가 두 경로를 같은 규칙으로 막는다:
`/jira-assign`·`/jira-sync` 의 `jira_assign.py` 와, Atlassian MCP `createJiraIssue` 직접 호출(PreToolUse 훅).
사람이 Jira UI 에서 만들 때는 같은 표로 셀프체크한다.

| 검사 | 막는 경우 |
| --- | --- |
| summary | 비어 있음 · 2줄 이상 · 80자 초과 · 대괄호 접두 (에픽 제외) |
| `🎯 목표` | 섹션 없음 · 10자 미만 |
| `✅ 완료 조건` | 섹션 없음 · 항목 2개 미만 · **애매한 항목** — ① 「잘 동작」「테스트 추가」「문서화」「정리」「개선」「확인」처럼 단독으로 쓰인 것 ② 8자 미만인 것(구체 토큰이 있어도) ③ **강한 토큰**이 없고, **약한 토큰**도 없거나 애매한 서술어(잘·제대로·확실하게·마무리·알아서·…되도록 처리)와 같이 있는 것. 강한 토큰 = 경로·엔드포인트(`docs/prd`, `/api/x/{id}`) · 백틱 코드 · URL · HTTP 메서드·상태코드(201·409) · `GROMO-####`·`V<N>__` · 파일명 · camelCase · 버전(1.1.0) · 외부 위치(Figma·Notion·Confluence·Slack·GitHub·스토어·TestFlight·지라 코멘트, 한글 표기 포함). 약한 토큰 = 대문자 약어(3자 이상 또는 PR·CI·DB·UI·QA) · 수량+단위(3건·2개·3곳·5페이지·30%). 길이를 채우거나 숫자·약어를 덧붙이는 것으로는 통과하지 않는다. 판정은 휴리스틱이라 오탐이 있을 수 있다 — 막히면 관찰 대상(무엇이 어디에 어떤 상태로)을 한 단어 더 적는다 |
| `📦 산출물` | 섹션 없음 · `유형:` 이 §3 목록 밖 (`기타` 는 괄호 설명 필수) · `남길 위치:` 없음 또는 구체 토큰 없음 |
| `도메인` | 필드 없음 (작업·버그·Subtask) |
| `⏱ 예상 작업 시간` | 있으면 형식 검사. 담당자가 본인이 아니면 필수 |
| 에픽 | 검사하지 않는다 — 에픽은 이니셔티브 이름과 기간만 있으면 된다 |

**막혔을 때 (에이전트)**: 거부 사유는 사용자 확인창 없이 Claude 에게 돌아온다. Claude 는 빈 항목을 **사용자에게 한 번에 묶어 묻는다**(AskUserQuestion). 임의로 채워서 다시 시도하지 않는다 — 지어낸 완료 조건은 받는 사람에게 다시 되묻기로 돌아온다.

## 5. 만들 때 규칙

- 이슈 타입은 기본 `작업` (`버그` 타입은 라벨 필수 설정이라 쓰지 않는다). 에픽은 시한부 이니셔티브에만.
- **만들기 전에 중복을 찾는다** — `project = GROMO AND statusCategory != Done AND summary ~ "<키워드>"` 와 열린 PR(`gh pr list --state open --search`). 있으면 새로 만들지 않고 그 티켓에 코멘트.
- **남의 티켓을 내게 재할당하지 않는다.** 내가 구현하려면 새 티켓을 만들고 원 티켓에 코멘트로 연결한다.
- 스토리 포인트는 미부여 티켓만 채운다. 기존 추정은 보존한다. 설명이 빈 티켓은 추정하지 않고 범위부터 묻는다.
- 스프린트 id 는 매주 바뀐다 — 하드코딩하지 않고 `sprint in openSprints()` 로 찾는다.
- fixVersion 은 미완료 티켓에 비워 둔다. 출시된 완료 티켓에만 붙인다.
- 한 티켓 = 한 사람이 끝까지 끌고 갈 수 있는 한 덩어리. 여러 건이면 티켓도 여러 건.

## 6. 팀원이 쓰는 법

| 경로 | 방법 |
| --- | --- |
| Claude Code | `/jira-assign <시킬 일>` — 8요소를 묻고 채워 만든다. 게이트가 자동으로 검사한다. 크리덴셜은 각자 `.claude/settings.local.json` 의 `env` (`JIRA_EMAIL` · `JIRA_API_TOKEN` · `JIRA_BASE_URL` · `JIRA_PROJECT_KEY`, gitignored) |
| PRD 한 장을 통째로 | `/jira-sync <prd.md>` — 후보마다 8요소 payload 를 만들어 같은 스크립트로 생성 |
| Jira UI | §1 골격을 설명란에 붙여 넣고 채운 뒤 §4 표로 셀프체크 |
