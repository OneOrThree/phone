2. 하단 탭에서 그룹으로 이동한다.

4. 그룹 카드, 그룹 찾기, 그룹 만들기 진입점이 겹치거나 잘리지 않는지 확인한다.

1. 첫 카드의 그룹명, 공개 여부, 역할, 인원수를 확인한다.

3. 페이지 인디케이터와 현재 카드가 함께 바뀌는지 확인한다.

### QA-GC-03 그룹 카드 앞·뒷면 전환

### QA-WEB-002 — 부분 목킹에서 챌린지 내역 요청이 실백엔드로 빠짐

- 유형: 개발 목 구성 누락
- 심각도: 중간 — 내역 조회 불가
- 재현:
  1. `새벽 6시 기상 집중단` 그룹방에 들어간다.
  2. `챌린지 내역`을 누른다.
  3. 정상 내역/빈 상태 대신 아래 오류가 표시된다.

  ```text
  챌린지 내역
  사라진 그룹이에요.
  잠시 후 다시 시도해주세요.
  다시 시도
  ```

- 재검증 요청: `GET http://localhost:8080/api/v1/groups/10000000-0000-0000-0000-000000000001/challenge-history?size=20`
- 목 fixture groupId: `10000000-0000-0000-0000-000000000001`
- 로컬 DB의 시드 groupId 대역: `20000000-0000-7000-8000-...`
- 원인: `handlers.ts`에 그룹 상세·공지·챌린지 handler는 있지만 `GET /groups/{id}/challenge-history`가 없다. 등록되지 않은 요청은 실 Axios adapter로 통과하고, 실백엔드는 존재하지 않는 목 groupId에 `404 / NOT_FOUND`를 반환한다.
- 판정: 웹 브라우저 호환성 문제가 아니다. 같은 부분 목 설정을 쓰면 네이티브 개발 앱에서도 재현될 수 있다.

### QA-WEB-003 — 웹 카드 탐색에서 `findNodeHandle` 오류 발생

- 유형: 웹 호환성 오류
- 심각도: 낮음 — 현재 카드 동작은 지속되지만 콘솔 오류 발생
- 재현: 그룹 카드 탐색과 앞·뒷면 전환 과정
- 콘솔: `Error: findNodeHandle is not supported on web. Use the ref property on the component instead.`
- 발생 횟수: 4회

### 해결된 환경 이슈

- 초기 브라우저 미연결은 Chrome을 명시적으로 선택해 해결했다.
- 게스트 로그인 실패는 Docker·PostgreSQL·Spring 백엔드·시드를 준비해 해결했다.

### QA-GC-06 재검증 메모

- Chrome 확장 연결이 재검증 도중 끊겨 같은 클릭을 새 세션에서 반복하지는 못했다.
- 직전 실제 UI 재현 결과, 프런트 요청 경로, 목 handler 목록, 로컬 DB, 백엔드 `NOT_FOUND` 분기를 교차 확인했다.
- 무인증 동일 요청은 `401 UNAUTHORIZED`였으므로 엔드포인트 자체가 없는 404가 아니다. 인증된 UI 요청이 서비스 계층까지 도달한 뒤 목 groupId를 찾지 못해 발생한 404다.
- 결론: `QA-GC-06`의 실패 원인은 `challenge-history` 목 handler 누락 또는 목 fixture와 로컬 시드 간 ID 불일치다.
