이 문서는 **사용자가 무엇을 보고, 어떤 상태에서 무엇을 조작하는가**를 규정한다. 실제 픽셀 치수·스냅 파라미터·인터폴레이션 계수는 [LLD.md](./low-level-design.md)에 고정한다.

> **근거 수준:** 현재 실제 행동 표본은 0명이고 `is_deleted=false AND is_guest=false` 리그 조회 대상은 100명 미만이다. 이 문서는 이 규모에서 기존 전역 리그 top100을 재사용하는 단일 UX와 출시 전 품질 기준을 정하지만, 사용성이나 사업 효과가 입증되었다고 보지 않는다. “소속감·재방문·집중 전환이 좋아진다”처럼 사용자 효능을 단정하지 않으며, 출시 전 형성평가에서는 명백한 막힘과 오류를 찾는 데 집중한다.

## 0. 단일 UX 정본

1. 한 화면에는 한 그룹 카드를 크게 보여 주고, 좌우 이동으로 다른 그룹을 탐색하는 페이지형 캐러셀을 사용한다.
2. **그룹 카드 앞면을 탭하면 같은 카드가 뒤집혀 방 요약을 보여 준다.** 앞면 탭으로 `GroupRoom`에 바로 들어가지 않는다.
3. 뒷면의 **`방 전체 보기`만** full-screen `GroupRoom` 라우트를 push한다.
4. 모든 그룹 카드의 상단 visual plane은 **고정 인디고 `#5E6AD2`** 를 쓴다. 그룹별 그라데이션·색조·선화 마크는 쓰지 않는다.
5. 카드 중앙의 **`내 카드 아이콘`** 은 이 계정·이 기기에서만 보이는 개인 설정이다. OWNER와 MEMBER 모두 같은 12개 중 고를 수 있고, 로컬 값이 없거나 손상되면 `🎯`을 쓴다.
6. 카드 뒷면의 집중 정보는 **`1명 집중 중`과 같은 한 줄 상태**만 표시한다. 팀 누적·오늘 합계·`HH:MM`은 표시하지 않는다.
7. 챌린지는 임의의 대표 항목이나 연속일수를 만들지 않고, 현재 main의 `GroupChallengeResponse[]` 목록을 재사용한다.
8. 카드 재정렬은 **앞면의 공용 `ReorderHandle`을 직접 끌어 놓는 동작**으로만 시작한다. 카드 본문 롱프레스나 grip 탭으로 재정렬 모드를 열지 않는다.
9. 확정된 카드 순서는 **계정별로 이 기기에 저장**하고, 같은 계정으로 앱을 다시 실행해도 복원한다. 성공 토스트나 `저장됨` 상태는 표시하지 않는다.
10. `GroupRoom`에서 뒤로 돌아오면 진입 전 카드의 index와 **뒷면 상태를 그대로 복원**한다.

**flip은 카드 앞면과 뒷면 사이에서만** 일어난다. `GroupRoom`은 카드와 별개의 full-screen 목적지이며 기존 화면 토큰을 사용한다.

## 1. 화면 흐름과 상태 전이

```text
그룹 카드 앞면
  ├─ 짧은 탭 ───────────────→ 같은 카드 뒷면(방 요약)
  ├─ 가로 스와이프 ─────────→ 이웃 그룹 앞면
  └─ grip 직접 drag/drop ──→ 카드 순서 변경 + 계정별 로컬 저장

같은 카드 뒷면
  ├─ 앞면 보기 ─────────────→ 같은 카드 앞면
  ├─ 이 그룹으로 집중 ──────→ 기존 FocusCategory(initialGroupId)
  ├─ 방 전체 보기 ──────────→ full-screen GroupRoom
  │                              └─ Back → 같은 index의 카드 뒷면
  └─ ⋯ ─────────────────────→ 현행 full-screen GroupSettings
```

- 동시에 뒤집혀 있는 그룹 카드는 최대 1장이다.
- 이웃 카드의 앞면을 탭하면 그 카드를 먼저 중앙에 스냅한 뒤, 같은 한 번의 조작 안에서 뒤집는다. 두 번째 탭을 요구하지 않는다.
- 다른 페이지로 스와이프하면 떠나는 카드는 앞면으로 초기화한다. 다시 돌아왔을 때는 앞면부터 시작한다.
- 예외는 `방 전체 보기 → GroupRoom → Back`이다. 이 왕복에서는 사용자가 보고 있던 뒷면을 보존한다.
- 끝의 `그룹 찾기` 카드는 그룹 카드가 아니므로 뒤집히지 않는다.

## 2. 캐러셀과 카드 골격

### 2.1 페이지형 캐러셀

- 정지 상태에서는 중앙의 그룹 카드 한 장이 정보 위계를 독점한다. 좌우 이웃은 다음 페이지가 있음을 알리는 범위에서만 일부 보일 수 있다.
- 한 번의 스와이프는 한 장씩 스냅한다. 관성으로 여러 장이 지나가지 않게 감속을 빠르게 한다.
- 카드 레이아웃 폭은 `화면폭 − 48`, 간격은 `T.space.md`(12)를 기준으로 한다.
- 카드 높이는 하단 탭바와 safe area를 제외한 가용 세로의 약 90%를 후보값으로 둔다.
- 바깥 카드 shell이 peek scale/opacity를, 안쪽 flipper가 앞·뒷면 전환을 담당한다. 두 transform을 같은 레이어에 적용하지 않는다.
- 표시 배열은 **그룹 n장 + 맨 끝 `그룹 찾기` 카드 1장**이다.
- 상단 `내 그룹` 헤더에는 검색과 그룹 만들기 `＋`를 유지한다. 캐러셀 페이지를 바꿔도 두 행동의 위치는 변하지 않는다.
- 하단 전역 탭바는 기존 구조를 유지하고 `그룹`을 활성 상태로 표시한다. 가운데 집중 시작 행동과 캐러셀의 `이 그룹으로 집중`은 서로 다른 진입점임을 라벨과 위치로 구분한다.

### 2.2 인디케이터

- 페이지 수는 그룹 수 + 끝 카드 1이다.
- dots와 compact `현재 / 전체` 사이에 **고정 페이지 수 경계는 두지 않는다.** 매 layout에서 인디케이터가 실제로 쓸 수 있는 폭을 측정해 mode를 정한다.
- 인디케이터 영역은 좌우에 각각 20pt gutter를 둔다. 각 dot은 최소 44×44pt의 독립된 hit slot을 가지며 slot 사이는 4pt를 띄운다. 작은 시각 dot과 활성 pill은 이 44pt slot 안에 배치하고 인접 slot을 침범하지 않는다.
- 페이지 수를 `N`, 측정된 인디케이터 전체 폭을 `W`라 할 때 dots에 쓸 수 있는 폭은 `W − 40pt`, 필요한 폭은 `N × 44pt + (N − 1) × 4pt`다. 필요한 폭이 가용 폭 이하이면 dots, 넘으면 compact `현재 / 전체`를 쓴다.
- dots mode의 각 hit slot은 해당 페이지로 이동하는 버튼이다. 활성 dot은 색뿐 아니라 시각 pill의 폭도 늘려 현재 위치를 형태로 구분하되 44pt hit slot 크기는 바꾸지 않는다.
- 390pt 폭에서 7페이지는 dots, 8페이지는 compact가 되는 계산은 **예시일 뿐**이다. 구현에서 `7`이나 특정 화면폭을 분기값으로 고정하지 않는다.
- 회전, 분할 화면, safe-area 변화, 텍스트 확대처럼 실제 가용 폭이 바뀌면 layout이 안정된 뒤 같은 식으로 다시 계산한다. mode가 바뀌어도 활성 `groupId`, 카드 위치와 사용자의 현재 포커스를 유지한다.
- dots↔compact 전환 자체는 별도 toast나 live announcement로 알리지 않는다. 활성 카드가 전달하는 `현재 위치/전체 페이지 수` 낭독은 끊거나 중복하지 않는다.

### 2.3 앞면

| 요소 | 규칙 |
| --- | --- |
| 상단 visual plane | 모든 그룹 공통 `#5E6AD2`. 그룹별 색·그라데이션 금지 |
| 공개 상태 | visual plane 왼쪽 위의 `공개방` 또는 `비밀방` pill |
| 내 카드 아이콘 | 현재 계정·이 기기에 저장된 값 1개를 중앙 원형 frame 안에 크게 배치. 없으면 `🎯` |
| 재정렬 | visual plane 오른쪽 위의 공용 `ReorderHandle`. handle만 재정렬 drag 시작점 |
| 하단 정보 plane | 흰 표면 위에 그룹 이름 최대 2줄, 방장이면 `방장` chip, 소개 최대 2줄 |
| 하단 행동 단서 | 왼쪽 `현재/정원`, 오른쪽 `뒤집어 방 보기` |

- 카드의 일반 영역을 짧게 탭하면 뒤집힌다. `ReorderHandle`에서 시작한 포인터는 flip을 발생시키지 않는다.
- 공개 상태와 handle은 내 카드 아이콘을 가리지 않고, 각각 최소 44×44pt 상호작용 영역을 확보한다.
- visual plane의 상태 텍스트는 인디고 위에서 읽을 수 있는 고대비 전경색을 사용하고 실제 대비를 구현 단계에서 검증한다.
- 소개가 없으면 빈 줄을 예약하지 않는다.
- 내 카드 아이콘은 개인적인 카드 구분 단서다. 다른 멤버는 각자 선택한 로컬 아이콘을 보므로 그룹 이름을 항상 함께 노출한다.

### 2.4 뒷면 헤더

- 중립 표면(`T.paper`)과 공통 accent를 사용한다. 앞면의 인디고를 그룹별 tone으로 변주하지 않는다.
- 왼쪽은 `앞면 보기`, 가운데는 그룹 이름과 `공개/비밀 · 현재/정원`, 오른쪽은 `⋯` 그룹 옵션이다.
- **헤더에 별도의 원형 그룹 마크·선화 아이콘·색상 아바타를 두지 않는다.**
- 액션 사이의 폭이 좁으므로 그룹 이름은 한 줄만 쓰고 끝을 `…`로 말줄임한다. 헤더 액션의 최소 탭 영역을 침범하지 않는다.

### 2.5 긴 그룹 이름

| 노출 위치 | 시각 규칙 |
| --- | --- |
| 카드 앞면 | 최대 2줄. 두 줄을 넘으면 두 번째 줄 끝을 `…`로 말줄임 |
| 그룹 검색 결과·그룹 목록행 | 한 줄. 가용 폭을 넘으면 줄 끝을 `…`로 말줄임 |
| 카드의 좁은 뒷면 헤더 | 한 줄. 좌우 액션 영역을 보존하고 줄 끝을 `…`로 말줄임 |

- 앞면의 `방장` chip, 검색·목록행의 보조 정보, 뒷면 헤더의 양쪽 버튼은 고정 영역을 먼저 확보하고 남은 이름 영역에서만 줄 수와 말줄임을 계산한다.
- 화면에 보이는 문자열만 줄인다. 카드 disclosure, 검색·목록행, 뒷면 헤더와 관련 action의 접근성 이름은 `…`가 없는 서버 원문 전체를 사용한다.
- 글자 수로 원문을 직접 잘라 새 문자열을 만들지 않는다. 플랫폼의 line clamp와 end ellipsis를 사용해 한글 음절, 영문, 이모지 grapheme cluster가 중간에서 깨지지 않게 한다.
- 공백 없는 긴 영문도 이름 영역 밖으로 밀려나거나 액션을 덮지 않도록 wrap/ellipsis 가능한 텍스트 컨테이너를 사용한다.

## 3. 카드 뒷면 — 방 요약 정보 위계

뒷면은 방 전체를 축소 복제하지 않는다. 사용자가 다음 행동을 고르는 데 필요한 최신 요약만 한 카드 안에 담는다.

| 순서 | 블록 | 표시 규칙 |
| --- | --- | --- |
| 1 | 현재 집중 인원 | `1명 집중 중`과 같은 한 줄. 0명도 `0명 집중 중`으로 표시 |
| 2 | 챌린지 목록 | main의 `GroupChallengeResponse[]`를 서버 순서 그대로 compact row로 표시 |
| 3 | 최신 공지 1개 | 최신 게시 시각 기준 1개. 본문은 최대 2줄 |
| 4 | 멤버 요약 | `현재/정원`, 최대 5명의 아바타/이니셜과 초과 인원 `+n` |
| 5 | 다음 행동 | primary `이 그룹으로 집중`, secondary `방 전체 보기` |

카드를 처음 뒤집을 때 기존 `GET /groups/{id}?date`, `GET /groups/{id}/announcements`, `GET /groups/{id}/challenges?date`를 함께 시작한다. 해당 `localDate`의 공유 리그 cache가 없으면 카테고리를 보내지 않은 `GET /api/v1/league/me/ranking?date=YYYY-MM-DD`도 원본 응답으로 한 번 요청해 모든 카드가 공유한다. 각 요청은 독립 상태로 관리하고 성공한 섹션부터 표시하므로 한 요청 실패가 다른 정보나 CTA를 숨기지 않는다. 카드 전용 요약 API는 만들지 않는다.

### 3.1 챌린지 목록 재사용 규칙

1. 카드가 처음 뒤집힐 때 현행 `GET /api/v1/groups/{groupId}/challenges?date=YYYY-MM-DD`를 호출한다.
2. 서버가 `createdAt DESC`로 내려준 `ACTIVE | INACTIVE` 배열을 상태 필터나 재정렬 없이 표시한다.
3. 앱에 없는 `UPCOMING`, 임의 `title`, 전체 퍼센트, 연속일수를 플립 카드용으로 합성하지 않는다.
4. compact row는 현행 `missionLabel`과 같은 문장을 쓴다. 예: `하루 60분 집중`, `매일 06:00~08:00 30분 집중`.
5. 각 행의 우측 값은 내 `memberProgress`를 우선해 `달성 ✓`, `42/60분`, `—` 중 하나로 표시한다.
6. 목록이 비면 `아직 챌린지가 없어요`를 표시한다.

카드 뒷면은 읽기 전용 요약이다. 챌린지 생성·삭제·내기와 멤버별 전체 진행 목록은 `방 전체 보기` 안의 현행 `ChallengeCard`에 남긴다. 챌린지가 많으면 뒷면 본문만 세로 스크롤하며 CTA는 하단에 고정한다.

### 3.2 집중 인원 데이터 경계

- 앱은 `leagueApi.getMyRanking()`을 category 인자 없이 호출하거나 동일한 전용 query hook으로 **전역 top100 원본 배열**을 받는다. 포커스 세션의 `useSessionLeagueMembers` 결과는 자기 제외가 가능하고 `MAX_MEMBERS=12`로 slice되므로 사용하지 않는다.
- 앱은 원본 배열을 `userId -> isFocusing` map으로 만든 뒤 그룹 상세 `members[].userId`와 join/filter한다. 매칭된 행의 `isFocusing === true`만 세고, 완전성이 확인된 성공 응답(`<100`행)에 없는 ID만 `false`로 본다. `focusTimeMinutes`나 오늘 합계로 현재 집중 여부를 추정하지 않는다.
- 현재 정확성은 `LeagueRankingQueryRepository`가 `users LEFT JOIN daily_focus_stats`로 집중 기록이 0인 eligible 사용자도 포함하고, `is_deleted=false AND is_guest=false` 전체가 100명 미만이어서 top100에 모두 들어간다는 전제에서 성립한다.
- 리그 요청이 loading·error이면 `0명`으로 보이지 않고 집중 현황 블록만 skeleton 또는 `정보를 불러오지 못했어요`·재시도를 노출한다. 정상 응답에 그룹원 ID가 없을 때만 `false`로 처리한다.
- 이 버전의 서버 변경은 **0건**이다. 운영 지표 `eligible_user_count = COUNT(users WHERE is_deleted=false AND is_guest=false)`를 관찰해 90명에서 경고·대체 안을 착수하고, 100명 도달 전을 전환 release gate로 둔다. 응답 `length === 100`이면 coverage 불명 신호로 telemetry를 남기고, 그룹 상세 live 필드·그룹 멤버 batch live endpoint·live pagination 중 하나로 전환하는 TODO를 운영한다.

### 3.3 공지와 멤버 폴백

- 공지가 없으면 `아직 공지가 없어요`를 표시한다. 샘플 공지를 만들어 채우지 않는다.
- 멤버 이미지가 없으면 이름의 첫 글자나 제품 기본 아바타를 쓴다.
- 뒷면 요약 일부가 실패해도 성공한 블록과 두 CTA는 유지한다. 실패한 블록만 `정보를 불러오지 못했어요`와 재시도 행동을 제공한다.
- 요약 전체 로딩 중에는 최종 레이아웃과 같은 높이의 skeleton을 쓰며, 앞면으로 되돌아가는 행동은 막지 않는다.

### 3.4 CTA

- `이 그룹으로 집중`은 기존 집중 카테고리 선택 흐름에 `initialGroupId`를 전달한다. 버튼 문구만으로 즉시 세션이 시작된다고 오해시키는 로딩·완료 문구를 쓰지 않는다.
- `방 전체 보기`는 공지·챌린지·멤버 전체를 탐색하는 full-screen `GroupRoom`을 push한다.
- 두 버튼 모두 로딩 중 중복 실행을 막고, 실패 시 버튼 가까이에 원인과 재시도를 제공한다.

## 4. 제스처 충돌 해결 규칙

### 4.1 우선순위

| 시작 지점/의도 | 우선 동작 | 차단되는 동작 |
| --- | --- | --- |
| 앞면 grip에서 시작 | 카드 재정렬 drag/drop | 페이지 스와이프, flip |
| 앞면 일반 영역의 짧은 탭 | 같은 카드 flip | 페이지 이동 |
| 앞면 일반 영역의 수평 이동 | 캐러셀 스와이프 | flip |
| 뒷면 버튼에서 시작 | 해당 버튼 실행 | 캐러셀 스와이프 |
| 뒷면 빈 영역의 수평 이동 | 앞면으로 정리한 뒤 캐러셀 스와이프 | 버튼 실행 |
| 뒷면 본문의 수직 이동 | 뒷면 내부 스크롤 | 캐러셀 스와이프 |

- 포인터가 내려간 뒤 이동량이 탭 허용치를 넘으면 pending tap을 취소한다. 목업의 `6px`은 후보값일 뿐 제품 확정값이 아니며, 실기 오조작 확인 후 LLD에 고정한다.
- 방향 잠금이 결정되기 전에는 flip·페이지 이동을 실행하지 않는다. `|dx| > |dy|`인 수평 의도가 확인되면 캐러셀이, 수직 의도가 확인되면 뒷면 스크롤이 제스처를 소유한다.
- flip 애니메이션 중에는 같은 카드의 swipe·drag·CTA를 잠시 막는다. 완료 또는 취소 뒤 최종 face와 접근성 상태를 한 번만 확정한다.
- 페이지 스와이프가 시작되면 현재 뒷면을 앞면으로 되돌린 후 이동한다. 회전 중인 뒷면을 옆 페이지로 끌고 가지 않는다.

### 4.2 재정렬 grip

- grip은 **앞면에서만** 보인다.
- 시각·접근성 진입점은 통계 카드의 기존 계약을 추출한 공용 `src/components/reorder/ReorderHandle`을 사용한다. 화면이 점을 직접 그리거나 별도 아이콘을 만들지 않는다.
- 공용 handle은 `MaterialCommunityIcons`의 `drag-vertical`, 20pt, `T.inkSub`, 투명 36×36 hit box를 기본값으로 소유한다. 그룹 카드는 이미지처럼 공통 handle 바깥에 44×44 이상의 시각 shell을 둘 수 있다.
- 공용 handle은 축·카드 순서·좌표 계산을 소유하지 않는다. 기존 `CardOrderEditor`의 세로 `pageY` controller와 그룹 덱의 가로 `pageX` controller가 같은 handle에 각자의 gesture binding을 주입한다.
- 터치·마우스 포인터에서는 grip을 누른 채 직접 끌고, 목표 위치에서 놓아 순서를 확정한다.
- grip의 짧은 탭은 아무 모드도 열지 않는다. 카드 전체 롱프레스, 뒷면 drag, `⋯` 메뉴의 “순서 변경”은 제공하지 않는다.
- drag 중 카드를 살짝 들어 올리고 목표 위치를 시각적으로 표시한다. 가장자리에서는 한 페이지씩 자동 스크롤하되 끝 `그룹 찾기` 카드 뒤로는 옮길 수 없다.
- drop하면 화면 순서를 즉시 확정하고 §4.3의 계정별 로컬 순서로 저장한다. 성공 시 토스트·배너·`저장됨` 접근성 알림을 만들지 않는다.
- 키보드·스크린리더 사용자는 동일한 grip에서 `앞으로 이동`·`뒤로 이동` 접근성 action을 쓸 수 있다. 포인터용 탭-투-리오더 모드나 별도 순서 변경 sheet는 제공하지 않는다.
- 이 결정은 포인터 사용자를 위한 **single-pointer 비드래그 대안**까지 충족하지는 않는다. 따라서 웹 접근성 범위에서 WCAG 2.5.7 준수를 요구한다면 출시 전에 별도 대안을 합의해야 하며, 현재 목업은 해당 기준 충족을 주장하지 않는다.
- 현행 공용 handle 후보의 36×36 hit box도 44pt 권장값보다 작다. 그룹 카드의 shell 확장으로 보완하고 통계 화면 공통 모듈에도 같은 개선을 역반영할지 별도로 결정한다.

### 4.3 순서의 계정별 로컬 영속 계약

#### 저장과 복원

- 순서는 그룹 객체가 아니라 `groupId` 배열로 저장하며 **현재 로그인 계정과 이 기기**의 조합에만 속한다.
- drop 직후 바뀐 순서를 먼저 화면에 반영하고 로컬 저장을 이어서 수행한다. 같은 계정으로 화면을 다시 열거나 앱을 완전히 종료한 뒤 재실행해도 마지막으로 성공한 순서를 복원한다.
- 계정 A에서 만든 순서를 계정 B에 적용하지 않는다. 로그아웃하면 화면의 순서 상태를 비우고, 다시 로그인한 계정의 저장값만 읽는다.
- 복원 중 서버 순서를 먼저 그렸다가 카드가 재배치되는 모습을 노출하지 않는다. 그룹 목록과 로컬 순서를 함께 확인하는 동안 기존 초기 로딩 상태를 유지한 뒤 한 번에 확정된 순서를 보여 준다.
- 성공 저장은 조용히 끝낸다. `저장됨`, `동기화됨`, 체크 아이콘, 성공 토스트와 같은 완료 피드백을 표시하거나 낭독하지 않는다.

#### 서버 목록과의 병합

서버에서 최신 그룹 목록을 받을 때마다 저장된 `groupId` 배열을 다음 순서로 정리한다.

1. 저장된 ID 중 현재 계정이 아직 속한 그룹만 기존 상대 순서대로 유지한다.
2. 새로 생성했거나 가입해 저장값에 없는 그룹은 서버 응답 순서대로 기존 그룹 뒤에 붙인다.
3. 탈퇴·삭제·강퇴 등으로 서버 목록에서 사라진 그룹은 저장 순서에서도 제거한다.
4. 중복 ID는 첫 항목만 유지한다. 끝의 `그룹 찾기` 카드는 저장값에 넣지 않고 항상 마지막 footer로 둔다.
5. 정리된 결과를 해당 계정의 새 로컬 순서로 저장한다.

이 병합은 서버가 소유하는 그룹 데이터와 멤버십을 바꾸지 않는다. 로컬 저장값은 현재 계정의 **표시 순서**만 결정한다.

#### 손상과 저장 실패

- 저장값이 없거나 파싱할 수 없거나 지원하지 않는 버전·형식이면 해당 계정의 값만 폐기하고 최신 서버 응답 순서로 연다. 손상된 값 때문에 빈 화면이나 앱 중단을 만들지 않는다.
- 로컬 쓰기에 실패해도 방금 정렬한 현재 화면은 유지한다. 마지막으로 성공한 저장값은 덮어쓰지 않으며, 다음 실행에서는 마지막 정상 순서가 있으면 그것을, 없으면 서버 순서를 사용한다.
- 쓰기 실패는 성공처럼 숨기지 않는다. 화면 흐름을 막지 않는 inline 상태로 `순서를 저장하지 못했어요. 앱을 다시 열면 이전 순서로 돌아갈 수 있어요.`를 한 번 표시하고 같은 문장을 polite live region으로 알린다. 성공 저장에는 대응 토스트를 두지 않는다.
- 다시 순서를 바꾸거나 화면이 활성화되면 최신 화면 순서의 저장을 재시도한다. 성공하면 오류 상태만 조용히 제거하고 성공 메시지는 표시하지 않는다.

#### 범위 제한

- 앱 삭제나 앱 데이터 초기화로 로컬 저장소가 지워지면 순서도 함께 사라진다. 다음 실행은 최신 서버 응답 순서에서 시작한다.
- 순서는 서버로 보내지 않으므로 여러 기기 사이에 동기화되지 않는다. 같은 계정이어도 각 기기는 그 기기에서 마지막으로 저장한 순서를 독립적으로 사용한다.
- 사용자가 별도의 백업·동기화·영구 보관을 기대하게 하는 문구를 UI에 추가하지 않는다.

## 5. Flip과 모션

### 5.1 기본 모션

- 같은 카드 shell 안의 flipper를 Y축으로 180° 회전해 앞·뒷면의 공간적 연속성을 보여 준다.
- 카드의 바깥 rect·peek scale·페이지 위치는 flip 중 바꾸지 않는다.
- 뒷면은 역면 글자가 비치지 않도록 backface를 숨기고, face 전환 시 포인터·접근성 상태도 함께 바꾼다.
- 권장 시간 범위는 260~320ms다. 이는 목업 후보값이며 프레임 안정성과 형성평가 결과를 확인한 뒤 확정한다.
- 앞면으로 돌아갈 때 같은 모션을 역재생한다.

### 5.2 Reduce Motion

`prefers-reduced-motion` 또는 플랫폼 Reduce Motion이 켜져 있으면:

- 3D 회전·perspective·과도한 scale을 사용하지 않는다.
- 같은 rect 안에서 앞면을 짧게 fade-out하고 뒷면을 fade-in하는 **교차 전환**을 쓴다.
- 권장 시간 범위는 120~180ms이며, 의미 상태와 포커스는 시각 전환보다 늦지 않게 갱신한다.
- `GroupRoom` 진입은 일반 full-screen push로 처리하고 카드 확대 전환을 만들지 않는다.

## 6. `방 전체 보기`와 복귀

- `방 전체 보기`는 modal sheet가 아니라 full-screen `GroupRoom(groupId)` 목적지다.
- 진입 직전에 `groupId`, 캐러셀 index, `face: back`을 복귀 상태로 보존한다.
- 시스템 Back·헤더 Back·접근성 escape로 돌아오면:
  1. 같은 그룹 카드를 중앙에 둔다.
  2. 뒷면을 유지한다.
  3. flip 애니메이션을 다시 재생하지 않는다.
  4. 포커스를 `방 전체 보기` 버튼으로 되돌린다.
- 목록 화면이 라우트 이동 중 unmount되더라도 위 상태를 route state 또는 화면 상태 저장소로 복원한다.
- 방에서 나가거나 강퇴되어 해당 그룹이 더 이상 목록에 없으면 뒷면을 억지로 복원하지 않는다. 서버 순서상 가장 가까운 남은 그룹의 앞면으로 이동하고, 그룹이 0개면 기존 빈 상태로 전환한다.
- 개인 로컬 `내 카드 아이콘`은 내 캐러셀 카드에서만 표시하고 `GroupRoom` 헤더에는 이어 붙이지 않는다. 두 화면의 연결은 route와 Back 동작으로 전달한다.
- 전체 방의 챌린지 섹션은 main 구현을 그대로 따른다: 서버 목록 전체를 `ChallengeCard`로 렌더하고, 방장만 섹션의 `＋`와 카드별 `×`를 본다.
- `ChallengeCard`는 미션 라벨과 멤버별 진행 목록을 표시한다. 하나의 큰 퍼센트·임의 보상·연속일수 카드로 축약하지 않는다.

## 7. `⋯` 그룹 설정

뒷면과 전체 방 헤더의 `⋯`는 현행 full-screen `GroupSettings(groupId)`를 연다. 별도 설정 bottom sheet나 새로운 설정 정보 구조를 만들지 않는다.

### 7.1 역할별 노출

| 역할 | 노출 항목 |
| --- | --- |
| 방장 | `그룹 프로필 설정하기`, `방장 넘기기`, `멤버 관리`, `공지 권한`, `내 카드 아이콘`, `그룹 나가기` |
| 멤버 | `내 카드 아이콘`, `그룹 나가기` |

- 권한이 없는 항목을 disabled로 늘어놓지 않고 아예 노출하지 않는다.
- OWNER와 MEMBER 모두 기존 그룹 설정의 `내 카드 아이콘` 행에서 자신의 로컬 아이콘을 바꾼다.
- `그룹 프로필 설정하기`는 계속 OWNER에게만 보이며 이름·소개·정원·공개 설정만 편집한다.
- `그룹 나가기`는 destructive style로 표시하고 확인 alert를 거친다.
- 방장이 나가기를 시도해 `HOST_WITHDRAW`를 받으면 `방장 넘기고 나가기`로 이어진다.
- 현행 설정 허브에 없는 `그룹 삭제`, 그룹 알림, 초대 링크, 내 활동 설정 행은 만들지 않는다.

### 7.2 설정 화면 접근성

- `⋯`의 접근성 이름은 `“{그룹 이름} 그룹 옵션”`으로 한다.
- 설정 화면을 push하면 제목 `그룹 설정`을 먼저 알리고 시스템 Back·헤더 Back을 모두 제공한다.
- 각 관리 행은 이동할 목적지를 이름으로 전달하며, 현재 role에서 허용된 행만 포커스 순서에 포함한다.
- `내 카드 아이콘` 행은 OWNER와 MEMBER 모두의 포커스 순서에 포함하고 현재 선택 이름을 보조값으로 전달한다. 편집 화면을 push하면 title `내 카드 아이콘`과 helper `이 기기에서 나에게만 보여요`를 먼저 읽을 수 있게 한다.
- 나가기 확인 alert의 최초 포커스는 취소에 두고, 취소하면 호출한 `그룹 나가기` 행으로 복귀한다.

## 8. `내 카드 아이콘` — 개인 로컬 설정

### 8.1 공용 Picker와 문구

- 그룹 생성 폼과 그룹 설정의 아이콘 편집 화면은 같은 12개 option source와 같은 순서의 단일 선택 picker를 사용한다.

```text
🌅  📚  💻  ⚡  🧘  🎨  🏃  ✍️  🧠  🎯  🌿  🔥
```

- 화면 제목과 필드 label은 모두 **`내 카드 아이콘`** 으로 쓴다.
- label 바로 아래에 helper **`이 기기에서 나에게만 보여요`** 를 항상 표시한다. 그룹 공용 이미지나 다른 멤버에게 공유되는 값처럼 설명하지 않는다.
- 로컬 저장값이 없거나 지원하지 않는 값이면 `🎯`을 현재 선택으로 사용한다.
- 이모지 타일은 최소 44×44pt 탭 영역을 확보하고 선택 상태를 테두리·체크·접근성 상태로 함께 나타낸다. 색만으로 선택을 알리지 않는다.

### 8.2 기존 그룹 설정에서 변경

#### 진입과 현재 값

- OWNER와 MEMBER 모두 기존 `그룹 설정 → 내 카드 아이콘`으로 같은 full-screen 편집 화면을 연다. role에 따라 picker나 저장 기능을 다르게 만들지 않는다.
- 진입하면 현재 계정·현재 기기·현재 `groupId`에 저장된 아이콘을 미리 선택한다. 값이 없거나 손상되었으면 `🎯`을 선택한다.

#### 선택과 저장

- 다른 아이콘을 고르면 이 화면의 미리보기와 radio selected 상태만 즉시 바뀐다. 저장 전에는 캐러셀 카드의 현재 아이콘을 바꾸지 않는다.
- 초안이 마지막 정상 로컬 값과 같으면 `저장`을 disabled로 둔다. 값이 다르고 저장 중이 아닐 때만 활성화한다.
- `저장`은 단일 AsyncStorage key `gromo:groups:cardEmoji:v1` 아래 현재 `userId` bucket의 해당 `groupId` 값만 쓴다. 서버 API, 그룹 DTO, 다른 멤버의 화면을 갱신하지 않는다.
- `저장`을 실행하면 선택값을 현재 실행의 캐러셀 카드에 먼저 낙관적으로 반영한 뒤 로컬 쓰기를 시도한다.
- 저장 중에는 `저장 중…`으로 표시하고 picker와 버튼을 잠가 중복 로컬 쓰기를 막는다.
- 저장 성공 시 초안을 새 기준값으로 확정하고 현재 계정의 캐러셀 카드 아이콘을 갱신한다. 화면은 변경 없음 상태가 되고 `저장`은 다시 disabled가 된다.
- 성공 toast, alert, `저장됨` 배너와 성공 live announcement는 표시하지 않는다. 선택 상태와 카드 갱신만으로 완료를 반영한다.
- 저장 실패 시 화면의 현재 선택·미리보기와 현재 실행의 캐러셀 카드 모두 선택값을 낙관적으로 유지한다. 마지막 정상 로컬 저장값은 덮어쓰거나 지우지 않는다.
- 실패는 picker 아래 inline 상태 **`내 카드 아이콘을 저장하지 못했어요. 앱을 다시 열면 이전 아이콘으로 돌아갈 수 있어요.`** 로 표시하고 같은 문장을 polite live region으로 한 번 알린다. modal alert나 toast로 흐름을 끊지 않는다.
- 실패한 선택은 현재 실행의 pending 값으로 유지한다. 다음 아이콘 변경 또는 그룹 화면 활성화 때 최신 pending 값의 로컬 저장을 재시도하고, 성공하면 inline 상태만 조용히 제거한다.
- 재시도 전에 앱 프로세스가 종료되면 다음 실행은 마지막 정상 로컬 값이 있으면 그 아이콘으로, 없으면 `🎯`으로 시작한다.

### 8.3 그룹 생성에서 선택

- 생성 화면의 picker도 field label `내 카드 아이콘`과 helper `이 기기에서 나에게만 보여요`를 사용한다. 그룹 생성 화면의 기존 title은 바꾸지 않으며 최초 선택은 `🎯`이다.
- 선택하면 생성 폼 안의 카드 미리보기만 바뀐다. 선택값은 그룹 생성 요청에 넣지 않으며 다른 멤버에게 공유되지 않는다.
- 그룹 생성 API가 성공해 새 `groupId`를 받으면 현재 실행의 새 카드에 선택값을 먼저 적용한 뒤 같은 저장소의 `store[userId][groupId]`에 저장한다. 그룹 생성 자체와 아이콘 로컬 저장을 하나의 서버 작업처럼 취급하지 않는다.
- 로컬 저장까지 성공하면 새 카드는 선택한 아이콘을 사용한다. 아이콘 저장 성공만을 위한 toast, alert, live announcement는 표시하지 않는다.
- 그룹은 생성됐지만 로컬 저장이 실패하면 생성 요청을 다시 보내지 않는다. 현재 실행의 새 카드에는 선택값을 유지하고 마지막 정상 로컬 값은 훼손하지 않는다.
- 생성 뒤 실패도 inline 상태 `내 카드 아이콘을 저장하지 못했어요. 앱을 다시 열면 이전 아이콘으로 돌아갈 수 있어요.`를 polite로 한 번 알린다. 다음 아이콘 변경 또는 그룹 화면 활성화 때 pending 값의 로컬 저장만 재시도하고, 성공하면 상태를 조용히 제거한다.

### 8.4 로컬 범위와 fallback

- 카드 아이콘은 기기의 개인 화면 설정이다. create/update 요청, 그룹 응답 DTO, 데이터베이스 필드로 보내거나 받지 않는다.
- 논리적 식별 범위는 `{userId, groupId}`이고 AsyncStorage 자체가 현재 기기라는 물리 범위를 만든다. 같은 기기의 다른 계정은 별도 userId bucket을 사용하고, 로그아웃 시 현재 화면의 아이콘 상태를 비운 뒤 로그인한 계정의 값만 읽는다.
- 같은 계정·같은 기기에서는 화면을 다시 열거나 앱을 재실행해도 마지막 정상 로컬 아이콘을 복원한다.
- 같은 계정이어도 다른 기기에는 동기화되지 않는다. 앱 삭제·앱 데이터 초기화·재설치로 로컬 값이 사라지면 `🎯`으로 돌아간다.
- 로컬 값이 없거나 파싱할 수 없거나 허용 목록 밖이면 해당 항목만 폐기하고 `🎯`을 사용한다. 손상 때문에 카드 렌더나 그룹 진입을 막지 않는다.
- 탈퇴·삭제·강퇴로 그룹이 목록에서 사라지면 해당 계정·그룹의 로컬 아이콘 값도 제거한다.
- 선택한 이모지 glyph와 로컬 값은 analytics payload에 넣지 않는다. 기존 서버 그룹 설정 성공 이벤트의 변경 필드로도 기록하지 않는다.

### 8.5 Picker 접근성·포커스·모션

- picker 전체를 `내 카드 아이콘`이라는 단일 선택 radio group으로 노출하고 helper `이 기기에서 나에게만 보여요`를 설명으로 연결한다.
- 각 선택지에는 화면 낭독용 이름을 붙인다: `일출`, `책`, `노트북`, `번개`, `명상`, `팔레트`, `달리기`, `쓰기`, `두뇌`, `목표`, `잎`, `불꽃`.
- 카드의 glyph 자체는 별도 포커스 대상에서 빼고 카드 disclosure 이름에 `내 카드 아이콘 {선택지 이름}`을 한 번 포함한다. OS가 emoji를 제각기 낭독하거나 같은 아이콘을 중복 낭독하지 않게 한다.
- 진입 시 현재 로컬 값 또는 fallback `🎯`에 checked 상태를 전달한다. 선택 뒤에는 초안 하나만 checked가 된다.
- 미리보기는 별도 조작 대상이 아니므로 포커스 순서에서 제외한다. 선택 결과는 현재 radio의 이름과 checked 상태로 한 번만 낭독한다.
- 키보드에서는 방향키로 후보를 이동하고 Space/Enter로 선택한다. 선택 뒤 포커스는 선택한 radio에 남긴다.
- 저장 중에는 화면의 busy와 control의 disabled 상태를 전달하고 진행 indicator로 포커스를 옮기지 않는다.
- 성공과 자동 재시도 성공은 별도 낭독 없이 처리한다. 실패 inline 상태는 재실행 시 이전 아이콘으로 돌아갈 수 있다는 문장 전체를 polite로 한 번 알리고 포커스를 빼앗지 않는다.
- 같은 pending 값의 자동 재시도가 다시 실패하면 기존 status를 유지하되 같은 문장을 반복 낭독하지 않는다. 현재 checked 상태와 카드의 아이콘도 되돌리지 않는다.
- 이모지 glyph 모양이 OS마다 달라도 선택 의미가 바뀌지 않도록 이름을 option 데이터와 함께 관리한다.
- Reduce Motion이 켜지면 선택·미리보기·카드 갱신에 회전, 튕김, 확대 morph를 쓰지 않는다. checked 표시와 glyph를 즉시 교체하거나 짧게 교차 전환한다.

## 10. 접근성 정본

### 10.1 Carousel과 face

- 각 페이지는 `슬라이드` 의미와 `현재 위치/전체 페이지 수`를 전달한다.
- 중앙 활성 페이지만 탐색 가능하게 하고 비활성 peek 페이지는 포커스 순서에서 뺀다. 시각적으로 보인다는 이유로 스크린리더가 이웃 카드의 내부 버튼을 읽지 않게 한다.
- 앞면의 전체 탭 영역은 하나의 disclosure button이다. 접근성 이름 예:
  - `“새벽 6시 기상 집중단, 내 카드 아이콘 일출, 공개방, 방장, 7/10명, 방 요약 보기”`
- 앞면 button은 뒷면 summary를 `aria-controls`로 연결하고 `aria-expanded=false/true`를 갱신한다.
- 앞면이 활성일 때: 앞면 `aria-hidden=false`, `inert=false`; 뒷면 `aria-hidden=true`, `inert=true`.
- 뒷면이 활성일 때는 위 상태를 정확히 반대로 바꾼다. CSS로만 숨겨 양쪽 내용이 동시에 읽히게 하지 않는다.
- flip 완료 시 라이브 영역에 `“{그룹 이름} 방 요약이 열렸어요”`를 알리고 뒷면 제목 또는 `앞면 보기`에 포커스를 둔다.
- 앞면으로 돌아가면 포커스를 앞면 disclosure button으로 복귀시킨다.
- 키보드 `Escape`는 열린 설정/확인 modal이 없을 때 현재 카드 뒷면을 앞면으로 돌린다.

### 10.2 내용

- 집중 현황은 `현재 2명 집중 중`처럼 한 문장으로 읽는다. 팀 합계나 타이머로 오해할 보조 설명을 붙이지 않는다.
- 챌린지 compact row는 미션 라벨과 내 진행을 한 덩어리로 읽는다. `—`는 `아직 집계되지 않음`으로 읽는다.
- avatar stack은 장식 이미지의 중복 낭독을 막고, 컨테이너가 `멤버 7명, 3명 더 있음`처럼 요약한다.
- flip, 순서 이동, 순서 저장 실패, 페이지 변경, destructive 완료 결과는 과도하게 겹치지 않는 polite live region으로 알린다.
- Reduce Motion, 텍스트 확대, 고대비, 스크린리더, 키보드 전용 조작을 출시 전 형성평가의 필수 케이스로 포함한다.

### 10.3 재정렬과 로컬 복원

- drop 또는 접근성 action이 끝나면 `“{그룹 이름}, {n}번째로 이동”`처럼 **이동 결과만** 알린다. `저장됨`·`동기화됨`을 덧붙이지 않는다.
- 앱 실행 시 복원된 순서를 처음부터 `aria-posinset`과 `aria-setsize`에 반영한다. 서버 순서를 먼저 알린 뒤 위치가 바뀌는 이중 낭독을 만들지 않는다.
- 정상적인 로컬 복원과 저장 성공은 별도 live announcement 없이 조용히 처리한다.
- 저장 실패 inline 상태는 `role=status`에 해당하는 polite live region으로 한 번만 알리고 포커스를 빼앗지 않는다. 반복 재시도마다 같은 문장을 중복 낭독하지 않는다.
- 손상값을 버리고 서버 순서로 정상 복구한 경우에는 오류를 낭독하지 않는다. 사용자가 행동해야 하는 문제가 없기 때문이다.
- 계정 전환 시 이전 계정의 카드와 위치 정보는 접근성 tree에서도 즉시 제거하고, 새 계정의 확정된 첫 카드에 탐색 맥락을 다시 설정한다.

### 10.4 반응형 인디케이터

- dots mode의 각 44×44pt hit slot은 `“{그룹 이름}, {현재} / {전체} 페이지로 이동”`이라는 버튼 이름을 갖는다. 활성 항목에는 현재 상태를 함께 전달한다.
- compact mode는 화면에 `현재 / 전체`를 한 줄로 보여 주고 접근성 이름은 `“현재 {현재}, 전체 {전체} 페이지”`로 한다. 활성 카드도 동일한 위치 정보를 전달하므로 페이지 변경 때 중복 낭독하지 않는다.
- layout 재계산 전 활성 항목을 index가 아닌 `groupId`로 보존한다. dots와 compact 사이에서 mode가 바뀌어도 같은 카드가 중앙에 남고 `aria-posinset`·`aria-setsize`는 새 layout에 맞춰 한 번만 갱신한다.
- 포커스가 카드나 다른 control에 있으면 mode 재계산 때문에 옮기지 않는다. 사라지는 dot에 포커스가 있었다면 같은 현재 페이지를 나타내는 compact indicator로, compact에서 dots로 바뀌면 해당 페이지 dot으로 포커스를 이어 준다.
- mode 전환 때문에 `dots로 변경`, `compact로 변경` 같은 별도 메시지를 알리지 않는다. 포커스가 이동해야 할 때도 현재/전체 페이지 정보만 전달한다.
- 텍스트 확대 뒤 compact label을 잘라내거나 말줄임하지 않는다. 실제 layout metrics로 mode를 다시 계산하고 좌우 20pt gutter 안에 현재/전체 숫자를 온전히 표시하며, 접근성 이름도 축약하지 않는다.

### 10.5 긴 그룹 이름

- 시각적으로 한 줄 또는 두 줄 뒤 `…`가 붙어도 접근성 이름에는 서버가 제공한 그룹 이름 원문 전체를 넣는다. 축약된 표시 문자열을 접근성 이름으로 재사용하지 않는다.
- 카드 앞면 disclosure, 검색·목록행, 뒷면 헤더 제목, 그룹 옵션, `ReorderHandle`, indicator page button처럼 그룹 이름을 포함하는 모든 이름에 같은 원문을 사용한다.
- 스크린리더가 시각 `…`를 이름의 일부로 읽거나 긴 이름을 두 번 낭독하지 않게, 보이는 텍스트와 명시적 접근성 이름의 중복 노출을 제거한다.
- 한글, 공백 없는 영문, 이모지·ZWJ 조합도 원문 순서와 grapheme을 보존해 낭독한다. 시각 말줄임 위치가 바뀌어도 포커스와 접근성 이름은 바뀌지 않는다.

## 11. 출시 전 형성평가와 오류 게이트

현재 실제 사용자가 0명이므로 통계적 개선이나 사업 KPI를 검증할 단계가 아니다. 출시 전 평가는 단일 플립 UX가 주요 과업을 막지 않는지, 제스처가 오작동하지 않는지, 역할과 데이터가 정확히 보이는지를 확인하는 **형성평가**로 한정한다.

### 11.1 참여자와 방식

- 목표 사용자 조건에 가까운 내부 프록시 또는 테스트 참여자 최소 5명을 모집한다.
- 참여자는 설명 없이 정본 HTML을 처음 보고 과업을 수행한다. 진행자는 행동을 유도하지 않고 막힘, 오조작, 발화만 기록한다.
- 모바일 실기 또는 실제 터치 크기에 맞춘 환경을 우선 사용한다. 마우스만으로 통과한 결과를 터치 검증으로 대체하지 않는다.
- 선호도는 보조 의견으로만 남기고, 성공률이나 수행 시간을 실제 사용자 효능·리텐션·집중 성과로 해석하지 않는다.

### 11.2 필수 과업

모든 참여자가 다음 과업을 수행한다.

  1. 지정 그룹의 공개 여부와 멤버 수 확인
  2. 카드를 뒤집고 `1명 집중 중`과 같은 현재 집중 인원 확인
  3. main에서 내려온 챌린지 전체 목록을 훑고 내 진행 확인
  4. `이 그룹으로 집중`과 `방 전체 보기`를 구분해 전체 방 진입 후 복귀
  5. 공용 `ReorderHandle`로 카드 한 장을 재정렬하고 앱을 재실행해 같은 순서인지 확인
  6. 방장과 일반 멤버 각각의 full-screen `GroupSettings`에서 가능한 행동 찾기
  7. 새 그룹을 만들며 `내 카드 아이콘`을 고르고 생성 뒤 내 카드에서 확인
  8. OWNER와 MEMBER 각각 기존 그룹 설정에서 `내 카드 아이콘`을 변경
  9. 계정을 전환해 다른 계정의 카드 아이콘과 섞이지 않는지 확인
  10. 앞면·뒷면·캐러셀·재정렬 사이를 오조작 없이 왕복
  11. 활성 카드와 인디케이터에 포커스를 둔 채 화면 회전·분할·텍스트 확대
  12. 긴 이름 그룹을 검색하고 카드 앞면·뒷면에서 같은 그룹인지 확인

### 11.6 반응형 인디케이터 QA

아래 경계값은 인디케이터 컨테이너의 측정 폭 `W`가 각 테스트 폭과 같을 때의 계산 예시다. 실제 제품은 viewport 숫자나 결과 페이지 수를 하드코딩하지 않고 §2.2의 측정식으로 판정한다.

| 테스트 폭 | dots가 들어가는 마지막 페이지 수 | compact로 바뀌는 첫 페이지 수 |
| --- | ---: | ---: |
| 320pt | 5 | 6 |
| 390pt | 7 | 8 |
| 430pt | 8 | 9 |
| 768pt | 15 | 16 |

- 네 폭 모두 좌우 gutter 20pt, hit slot 최소 44×44pt, slot 사이 4pt를 실제 layout 측정값으로 확인한다.
- 각 경계의 앞뒤 페이지 수에서 dots/compact가 정확히 전환되고 시각 dot·활성 pill·hit slot이 겹치지 않는지 확인한다.
- 390→768 회전, 768→320 분할 화면 전환, 320→430 창 확장 때 같은 `groupId`가 활성 카드로 남는지 확인한다.
- 카드와 dot 각각에 포커스를 둔 상태로 mode를 전환한다. 카드 포커스는 그대로, 사라진 indicator 포커스는 같은 페이지의 대체 표현으로 이어져야 한다.
- 플랫폼 텍스트를 기본·150%·200%로 바꿔 다시 측정하고 compact 숫자 잘림, 카드 이동, 포커스 유실이 없는지 확인한다.
- layout만 바뀌고 활성 페이지가 그대로일 때 mode 변화 알림이나 현재 페이지 중복 낭독이 발생하지 않는지 확인한다.

### 11.7 긴 그룹 이름 QA

다음 세 종류의 이름을 최대 허용 길이 안에서 준비해 기본·150%·200% 텍스트 크기와 320/390/430pt 폭에서 확인한다.

| 데이터 | 예시 | 확인점 |
| --- | --- | --- |
| 긴 한글 | `새벽 여섯 시 기상과 독서 습관을 함께 만드는 집중단` | 자연스러운 줄바꿈, 마지막 허용 줄 끝 `…` |
| 무공백 영문 | `MorningDeepWorkAccountabilityCollective` | 컨테이너 밖 overflow·액션 침범 없이 end ellipsis |
| 이모지·ZWJ 포함 | `👩🏽‍💻📚 아침 집중 👨‍👩‍👧‍👦 함께하기` | 피부색 modifier·ZWJ family 등 grapheme이 반쪽으로 깨지지 않음 |

- 각 데이터로 카드 앞면은 최대 2줄, 검색 결과·그룹 목록행·좁은 뒷면 헤더는 한 줄인지 확인한다.
- 앞면 두 번째 줄과 한 줄 surface의 끝에만 `…`가 나타나고, 방장 chip·보조 정보·뒤집기·옵션 버튼을 덮지 않는지 확인한다.
- 동일한 원문이 카드 disclosure, 검색·목록행, 뒷면 헤더, 그룹 옵션, `ReorderHandle`, indicator page button에서 축약 없이 한 번만 낭독되는지 확인한다.
- 시각 줄임 위치가 폭·텍스트 크기에 따라 달라져도 접근성 이름 원문, 활성 카드와 포커스가 유지되는지 확인한다.
- 서버 이름이 이미 `…`를 포함한 경우에도 원문 접근성 이름을 임의로 복원·변형하지 않고 그대로 전달한다.

### 11.8 기록 항목

- 과업 성공 여부와 실패 지점
- 첫 행동까지의 멈춤과 잘못된 첫 행동
- 의도치 않은 flip, 페이지 스와이프, 재정렬 시작 또는 CTA 실행 횟수
- `뒤집어 방 보기`와 `방 전체 보기`의 의미 혼동 여부
- 챌린지 목록 누락·중복·순서 변경 여부
- `GroupRoom` Back 후 같은 카드 뒷면이 복원되었는지와 참여자의 상태 이해
- 앱 재실행 후 순서 복원 성공 여부와 서버 순서 flash 여부
- 계정 전환·새 그룹·탈퇴·삭제 뒤 카드 누락·중복·계정 간 순서 혼입 여부
- 로컬 손상·저장 실패 fallback과 실패 상태의 시각·스크린리더 전달 여부
- 정상 저장 뒤 불필요한 성공 토스트·배너·낭독이 나타났는지
- OWNER/MEMBER의 `내 카드 아이콘` 진입점, title/label/helper, 현재 로컬 값 checked 여부
- 저장 전 카드 불변, 저장 실행 뒤 현재 실행 카드의 낙관적 갱신, 실패 뒤 선택·카드 유지와 마지막 정상 저장값 보존 여부
- 변경 없음·저장 중 버튼 상태, 중복 로컬 쓰기와 불필요한 서버 요청·성공 toast·낭독 발생 횟수
- 다음 아이콘 변경·화면 활성화 재시도 횟수와 최신 pending 값 우선, 성공 시 status 자동 제거 여부
- 생성 성공 뒤 현재 실행 카드 적용·로컬 저장 순서, 로컬 실패 재시도 시 그룹 중복 생성 여부
- 계정·기기·재설치·탈퇴 경계에서 값 격리·fallback·정리 여부
- picker의 이모지 이름·radio semantics·checked 상태·helper 연결·실패 status·Reduce Motion 동작
- 320/390/430/768pt에서 계산된 indicator mode, gutter·gap·hit slot 실측값
- 회전·분할·텍스트 확대 전후 활성 `groupId`, 포커스 대상, 현재/전체 낭독 횟수
- 긴 한글·무공백 영문·이모지 이름별 surface의 실제 줄 수, `…` 위치, 액션 침범 여부
- 시각 축약 전 원문과 스크린리더 낭독 문자열의 일치 여부, 중복 낭독·grapheme 손상 여부
- 터치 목표 누락, 텍스트 잘림·겹침, 내부 스크롤 막힘, 모션 불편
- 스크린리더 이름·상태·포커스 순서와 Reduce Motion 동작

| P0 | 키보드·스크린리더로 핵심 CTA나 설정에서 빠져나올 수 없음, 현재 face와 접근성 tree 불일치 |

| P1 | Back 후 다른 그룹 또는 앞면으로 잘못 복귀, 역할별 설정 항목 오노출 |
| P1 | 같은 계정·같은 기기에서 마지막 정상 순서 미복원, 계정 간 순서 혼입, 새 그룹·사라진 그룹 병합 오류 |
| P1 | 손상된 저장값으로 앱 중단·빈 캐러셀·중복 카드 발생, 저장 실패를 성공으로 오인하게 하는 피드백 |
| P1 | 재정렬 성공 때마다 토스트·배너·저장 완료 낭독이 나타나 흐름을 방해함 |
| P1 | OWNER 또는 MEMBER에게 `내 카드 아이콘` 진입점 누락, title/label/helper 불일치 |
| P1 | 저장 전 카드 아이콘 변경, 변경 없음인데 저장 활성, 중복 로컬 쓰기·아이콘 값의 네트워크 전송 발생 |
| P1 | 성공 뒤 불필요한 icon-specific toast/alert/live, 실패 뒤 현재 선택·카드 rollback, 마지막 정상 저장값 훼손 |
| P1 | 저장 실패 inline·polite 위험 안내 누락, 다음 아이콘 변경·화면 활성화 재시도 누락, 오래된 pending 값이 최신 선택을 덮음 |
| P1 | 생성 뒤 아이콘 저장 실패가 그룹 생성 재호출·중복 그룹으로 이어지거나 현재 실행의 새 카드가 선택값을 잃음 |
| P1 | 계정 간 값 혼입, 다른 기기 동기화, 재설치 후 값 잔존, 탈퇴·삭제 뒤 orphan 로컬 값 유지 |
| P1 | picker의 radio/checked/이름/helper 누락, 실패 inline·polite 전달 또는 포커스 유실, Reduce Motion 무시 |
| P1 | 고정 7/8 분기 사용, 가용 폭 계산 오류, 44×44pt hit slot·4pt gap·20pt gutter 미충족 |
| P1 | 회전·분할·텍스트 확대 뒤 활성 카드 변경, 포커스 유실, mode 변화 별도 알림·중복 낭독 |
| P1 | 앞면 이름 2줄 초과·끝 `…` 누락, 검색·목록행·좁은 뒷면 헤더의 2줄 wrap 또는 액션 침범 |
| P1 | 접근성 이름 축약·중복 낭독, 무공백 영문 overflow, 이모지 grapheme 중간 절단 |
| P1 | 200% 텍스트 확대·작은 화면에서 주요 정보나 CTA가 겹치거나 잘려 사용할 수 없음 |

- 동일 과업에서 참여자 2명 이상이 설명 없이 진행하지 못하면 문구·정보 위계·행동 단서를 수정하고 재평가한다.
- 의도치 않은 flip·swipe·reorder가 참여자 2명 이상에게 반복되면 제스처 잠금과 hit area를 수정하고 재평가한다.
- 실제 사용자 표본과 기준선이 생기기 전에는 리텐션·집중 시작률·방 방문률의 개선을 주장하거나 목표 퍼센트를 두지 않는다.
