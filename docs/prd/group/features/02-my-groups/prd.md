## 0. 결정 요약

### 제품 결정

- 소속 그룹이 1개 이상이면 세로 목록 대신 **가로 페이지형 카드 덱**을 제공한다.
- 카드 본문을 탭하면 route 이동 없이 같은 카드가 뒤집히고, 뒷면에서 방 요약을 확인한다.
- 뒷면의 주요 행동은 **이 그룹으로 집중**, 보조 행동은 **방 전체 보기**다.
- 전 그룹 앞면 배경은 **#5E6AD2**로 고정한다.
- 사용자가 고르는 **내 카드 아이콘**과 카드 순서는 현재 계정·기기 로컬 설정으로만 저장한다.
- 카드 뒷면은 새 요약 API 없이 기존 detail·공지·챌린지·리그 API를 첫 back 시점에 조합하고, 현재 집중 상태만 foreground에서 60초마다 갱신한다.

### 현재 전제

- 행동 기준선, 그룹 수 분포, flip 발견률, CTA 전환율, 재방문율, D30 잔존율이 없다.
- 운영상 출시 전제는 리그 조회 적격 사용자(`is_deleted=false AND is_guest=false`)가 100명 미만이라는 것이다. 값이 unknown이거나 100명 이상이면 카드 덱 출시는 차단하고 대체 계약을 먼저 배포한다.
- 런타임 앱에는 적격 사용자 수가 내려오지 않는다. 따라서 성공한 전역 리그 원본 응답 길이가 100 미만일 때만 top100 완전성을 적용한다. `length === 100`·loading·error는 미산출이며 0명으로 표시하지 않는다.
- 운영 수가 90명에 도달하면 대체 계약을 준비한다.

### 이 문서가 주장하지 않는 것

- 카드 덱이 리텐션, 재방문, 체류시간, 그룹 생성·참여율을 높인다는 주장
- 로컬 아이콘이 소속감이나 애착을 높인다는 주장
- 그룹 가입자의 높은 잔존이 그룹 기능의 인과효과라는 주장

### 1.1 사용자 문제

### 1.2 현재 흐름과 한계

```
내 그룹 진입
  → 세로 목록에서 이름·인원 확인
  → 그룹 탭
  → 전체 화면 GroupRoom 이동
  → 상세·공지·챌린지 확인
  → 뒤로 가기
  → 다른 그룹을 다시 탐색
```

현재 흐름은 전체 방을 깊게 보는 데는 적합하다. 그러나 여러 그룹의 현재 상태를 빠르게 훑고 다음 행동을 고르는 중간 정보 계층은 없다.

### 1.3 제품 가설

> 이미 1개 이상의 그룹에 속한 사용자에게 같은 자리의 카드 플립 요약을 제공하면, 방을 하나씩 열지 않고도 원하는 그룹과 다음 행동을 구분할 수 있다.

```
확인된 제품 공백
  → 같은 자리의 방 요약
  → 목록 맥락을 유지한 정보 확인
  → 집중 또는 전체 방을 의도에 맞게 선택
  → 그룹 관련 핵심 행동까지의 마찰 감소
```

- **확인된 연결:** 현행 목록에는 방 요약이 없고, 그룹 탭은 전체 화면 route로 이동한다.

## 3. 사용자·역할·핵심 시나리오

### 3.1 역할과 권한

| 역할·상태            | 조회                   | 생성·가입      | 카드 상호작용                        | 관리·삭제                                | 예외                       |
| -------------------- | ---------------------- | -------------- | ------------------------------------ | ---------------------------------------- | -------------------------- |
| 소속 그룹 0개        | 현행 빈 상태           | 만들기·찾기    | 카드 덱 없음                         | 해당 없음                                | GroupScreen이 상태 소유    |
| MEMBER               | 소속 카드·요약·전체 방 | 현행 가입 흐름 | flip·page·집중·재정렬·내 카드 아이콘 | 그룹 나가기                              | 그룹 프로필·멤버 관리 불가 |
| OWNER                | MEMBER와 동일          | 현행 생성·가입 | MEMBER와 동일                        | 프로필·방장 넘기기·멤버 관리·공지·나가기 | 그룹 삭제는 없음           |
| 게스트·userId 미확정 | 현행 게스트·전이 화면  | 현행 정책      | 로컬 순서·아이콘 읽기·쓰기 금지      | 없음                                     | 계정 bucket 생성 금지      |

### 3.2 유저 스토리

- **US-1** 그룹원으로서 목록 맥락을 잃지 않고 각 방의 오늘 상태를 확인하고 싶다. 그래서 들어갈 방을 빠르게 고를 수 있다.
- **US-2** 그룹원으로서 지금 집중할지 전체 방을 볼지 구분하고 싶다. 그래서 의도와 다른 route로 이동하지 않는다.
- **US-3** 여러 그룹에 속한 사용자로서 자주 쓰는 순서와 이 기기에서 알아보기 쉬운 아이콘으로 카드를 정리하고 싶다.
- **US-4** OWNER·MEMBER로서 내 카드 아이콘이 그룹 공용 프로필이 아니라 나에게만 보이는 로컬 설정임을 알고 바꾸고 싶다.
- **US-5** 보조기술 사용자로서 flip·page·reorder와 두 CTA를 동일한 정보와 결과로 사용할 수 있어야 한다.

### 3.3 대표 여정

```
내 그룹 진입
  → 서버 소속 그룹 확인
  → 로컬 순서·아이콘 합성
  → 카드 탐색
  → 카드 본문 탭
  → 같은 자리에서 요약 확인
  ├─ 이 그룹으로 집중
  └─ 방 전체 보기 → 뒤로 가기 → 같은 groupId·index·뒷면·focus 복원
```

### 4.2 상태 전이

```
GroupScreen
  ├─ loading
  ├─ error
  ├─ guest 또는 userId 미확정
  ├─ groups=0 → 현행 empty
  └─ groups>=1 → GroupListScreen 카드 덱
                   ├─ front
                   │   ├─ horizontal drag → 다른 카드
                   │   ├─ grip drag 또는 grip tap/click → 순서 변경
                   │   └─ body tap → back
                   └─ back
                       ├─ 다시 탭 → front
                       ├─ 이 그룹으로 집중 → 집중 흐름
                       └─ 방 전체 보기 → GroupRoom → 같은 상태 복원
```

요약 데이터는 카드의 첫 back 전환에서 각 dependency가 **idle → loading → ready 또는 error**로 독립 전이한다. 현재 집중 상태는 추가로 **coverage-unknown**을 가진다.

### 4.5 알림·재방문 장치

## 6. 성공 지표와 실험 계약

### 6.1 지표 해석 원칙

- 출시 전에는 **이해 실패·상태 오류를 거르는 release gate**를 사용한다.
- 출시 후 첫 4주는 효과 판정이 아니라 행동 기준선과 데이터 품질을 수집한다.
- 사용자 행동 지표는 기준선과 충분한 표본 없이 임의의 목표값을 두지 않는다.
- 0건·100% 같은 절대 목표는 계측 중복, 권한 누수, 잘못된 서버 변경 같은 시스템 불변식에만 사용한다.
- 카드 덱 노출, flip, CTA, GroupRoom 방문, 그룹 가입, D30 잔존을 서로 다른 단계로 해석한다.
- 그룹 가입자와 비가입자의 단순 잔존 비교는 자기선택 편향이 있으므로 인과 판정으로 쓰지 않는다.

### 6.2 Primary metric

이번 기능의 출시 전 Primary는 성장 지표가 아니라 **핵심 과업 무도움 완료율**이다.

```
대상 코호트 = 그룹 1개 이상 상태를 이해할 수 있는 대표 평가 참여자 최소 5명
분자 = 설명·힌트 없이 해당 핵심 과업을 완료한 참여자 수
분모 = 해당 과업을 시도한 참여자 수
시간 창 = 출시 전 형성평가 1회와 수정 후 재평가
핵심 과업 = flip 발견, 요약 정보 찾기, 올바른 CTA 선택, reorder, 로컬 아이콘 범위 설명
비교 방식 = 과업별 독립 판정
판정 규칙 = 모든 핵심 과업이 5명 중 4명 이상. 5명 미만이면 통과가 아니라 미검증
```

상위 그룹 로드맵에는 `F02-P0 → G-P0`, `F02-P1~P2 → G-P2`, `F02-P3 → G-P3`, `F02-P4 → G-P4`로 대응한다. 기능 단계와 상위 단계를 같은 이름으로 간주하지 않는다.

### 기존 데이터·구버전 호환

- 서버 migration은 없다.
- 새 로컬 order·emoji key는 구버전이 읽지 않으며 서버 상태를 바꾸지 않는다.
- 롤백 시 로컬 key가 남아 있어도 현행 세로 목록과 서버 DTO에는 영향이 없다.
- 손상·누락 로컬 값은 서버 목록 순서와 🎯로 방어 렌더하고, 성공한 전체 목록에서만 repair한다.
- 카드 덱을 되돌려도 그룹 생성·가입·탈퇴·챌린지 등 기존 서버 상태는 유지된다.

### 되돌릴 수 없는 지점

| 지점                             | 영향                         | 예방                          | 사고 후 대응                   |
| -------------------------------- | ---------------------------- | ----------------------------- | ------------------------------ |
| 카드 flip·재정렬·로컬 아이콘     | 서버 비가역 변경 없음        | 로컬 범위와 실패 처리 명시    | 키 무시·repair·기능 롤백       |
| 카드에서 시작한 그룹 나가기      | 기존 서버 멤버십 종료        | 확인 dialog·OWNER 이전 흐름   | 기존 그룹 도메인 정책 적용     |
| 카드에서 진입한 챌린지·내기 행동 | 각 도메인의 기존 비가역 정책 | 이 PRD에서 직접 변경하지 않음 | 해당 PRD의 보상·복구 계약 적용 |

### 규모 전환 gate

- 운영 eligible 사용자 수가 90~99이면 대체 서버 계약의 오너·티켓·목표 배포일을 확정한다.
- 운영 eligible 사용자 수가 unknown 또는 100 이상이면 출시를 차단하고 대체 서버 계약을 먼저 배포한다.
- 런타임 원본 리그 응답이 100행·loading·error이면 0명으로 계산하지 않고 coverage unknown으로 처리한다.
- 100명 도달 전에 그룹 live 필드, 멤버 batch endpoint, 또는 isFocusing 포함 pagination 중 하나를 배포하고 top100 absent=false 전제를 제거한다.

추가 수용 조건:

- 재정렬은 카드 탐색·flip과 충돌하지 않고, 보조기술 및 drag 없는 단일 포인터에서도 수행 가능해야 한다.
- 현재 집중 인원은 전체 멤버를 누락시키지 않는 완전한 데이터에서만 계산하며 불완전·실패 상태를 0명으로 표시하지 않는다.
- 상태·경합·복구는 LLD를 따르고, 구체 hook·컴포넌트 이름은 구현 코드와 테스트에서 확정한다.
- 정상 로컬 저장에는 성공 toast를 띄우지 않고, 실패에만 inline 복구 경로를 제공한다.
- 첫 4주 대시보드에서 노출·flip·CTA·D7 재방문·오류·eligible 사용자 수를 성공 효과와 구분해 볼 수 있다.

## 12. 작업 패키지와 후속 결정
