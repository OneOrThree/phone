## 1. 상세 재조회와 역할 변경

```mermaid
stateDiagram-v2
    [*] --> 조회중
    조회중 --> 표시가능: 최신 요청의 상세 성공
    조회중 --> 오류: 최신 요청 실패
    오류 --> 조회중: 다시 시도 또는 화면 재진입
    표시가능 --> 조회중: 포커스 복귀·운영 작업 뒤 재조회

    표시가능: members에서 현재 userId의 role 계산
    표시가능: OWNER 행만 표시
    표시가능: MEMBER는 나가기와 허용된 운영 행만 표시
```

- 화면마다 요청 세대를 올린다. 이전 `GET /groups/{groupId}` 응답은 최신 role·멤버 목록을 덮지 않는다.
- 상세가 실패하면 운영 버튼을 추정해 활성화하지 않고 오류와 다시 시도를 보인다.

## 2. 되돌릴 수 없는 멤버십 작업

```mermaid
flowchart TD
    Confirm["확인 후 요청 수락"] --> Lock["대상별 또는 화면 전체 중복 요청 잠금"]
    Lock --> Request{"서버 결과"}
    Request -->|"204 성공"| Refresh["해당 화면 목록 반영 또는 상위 화면 재조회"]
    Request -->|"NOT_FOUND · MEMBER_ONLY"| Post{"작업별 사후조건 확인"}
    Request -->|"NOT_OWNER · CANNOT_KICK_SELF · 검증 실패"| Reject["현재 화면·서버 값 유지\n오류 표시"]
    Request -->|"일시 실패"| Retry["현재 화면 유지\n오류 표시 후 명시적 재시도"]

    Post -->|"나가기 MEMBER_ONLY: 본인 미소속 확인"| Refresh
    Post -->|"나가기 NOT_FOUND: 인증·그룹 scope 재확인"| Scope{"응답 의미"}
    Scope -->|"그룹 부재 확인"| Refresh
    Scope -->|"비활성 요청자 확인"| Session["세션 안전 복구\n성공 처리·계측 없음"]
    Scope -->|"확인 실패 · 의미 불명"| Retry
    Post -->|"강퇴 NOT_FOUND · MEMBER_ONLY"| KickCheck["최신 detail 재조회"]
    KickCheck -->|"대상 부재 확인"| Refresh
    KickCheck -->|"그룹 부재 또는 요청자 미소속 확인"| Exit["그룹 화면 안전 종료"]
    KickCheck -->|"재조회 실패 · 대상 유지 · 의미 불명"| Retry

    Transfer["위임 성공"] -.-> Demote["기존 OWNER는 MEMBER"]
    Demote -.-> Withdraw{"위임 후 나가기 경로?"}
    Withdraw -->|예| Leave["탈퇴 요청 1회"]
    Withdraw -->|아니오| Refresh
    Leave --> Refresh
```

- 위임 대상은 본인을 제외한 현재 멤버다. 위임 중에는 대상 변경·재탭·뒤로가기를 잠근다.
- `source=withdraw`에서 위임은 성공했지만 탈퇴가 실패할 수 있다. 이때 위임을 되돌리지 않으며, 사용자는 MEMBER 상태에서 나가기를 다시 시도한다.
- 강퇴는 자기 자신에게 보이지 않아야 하며, 서버의 `CANNOT_KICK_SELF`·권한·대상 없음은 성공으로 가장하지 않는다.
- 나가기의 `MEMBER_ONLY`는 최신 서버 응답이 요청자 미소속을 확인하므로 그 응답 자체가 사후조건이다. `NOT_FOUND`는 비활성 요청자와 그룹 부재가 모두 가능하므로 인증 상태·그룹 scope를 재확인한다. 그룹 부재면 목록으로 복귀하고, 비활성 요청자면 성공 처리 없이 세션을 안전 복구하며, 의미 불명·확인 실패면 현재 상태를 보존한다. 강퇴의 두 코드는 그룹·요청자·대상 중 무엇이 없는지 모호하므로 최신 detail을 다시 확인하기 전에는 대상 행을 지우지 않는다.
- 강퇴 재확인에서 target만 없으면 목록을 수렴하고, group 404나 requester 미소속이면 그룹 화면을 종료한다. 재조회 실패·target 유지면 현재 목록을 보존하고 오류를 표시하며 성공 toast·성공 이벤트를 발행하지 않는다.

## 3. 나가기와 마지막 1인

```mermaid
stateDiagram-v2
    [*] --> 확인
    확인 --> 탈퇴요청: 사용자가 나가기 확정
    탈퇴요청 --> 위임필요: HOST_WITHDRAW
    위임필요 --> 위임화면: 대상 선택
    위임화면 --> 탈퇴요청: 위임 성공 후 나가기 경로
    탈퇴요청 --> 목록복귀: 204 성공
    탈퇴요청 --> 목록복귀: MEMBER_ONLY · 본인 미소속 확인
    탈퇴요청 --> 범위확인: NOT_FOUND
    범위확인 --> 목록복귀: 그룹 부재 확인
    범위확인 --> 세션복구: 비활성 요청자 확인 · 성공 처리 없음
    범위확인 --> 오류: 응답 의미 불명 · 확인 실패
    탈퇴요청 --> 오류: 그 밖의 실패
    오류 --> 확인: 다시 시도

    목록복귀: 마지막 1인이면 서버 그룹 상태 ENDED
```

- 나가기의 `MEMBER_ONLY`만 응답 자체로 요청자 미소속을 확인한다. `NOT_FOUND`는 scope 재확인 뒤 그룹 부재일 때만 멱등 복귀하고, 비활성 요청자면 성공 처리 없이 세션을 복구하며, 확인하지 못하면 오류로 남긴다. 같은 코드라도 강퇴에서는 대상 부재를 뜻한다고 가정하지 않는다.
- 마지막 1인의 `ENDED`는 서버 결과다. 앱이 멤버 수를 보고 미리 종료를 만들지 않는다.
- 탈퇴·강퇴·계정 탈퇴는 [01 획득 링크 수명 계약](../01-acquisition/low-level-design.md#21-초대-링크-수명과-이탈-경합)에 따라 발급자의 active 링크를 같은 transaction에서 폐기한다. OWNER 위임만으로는 폐기하지 않는다.

## 4. 공지 권한과 02 `F02-P1` 로컬 편집 의존성

```mermaid
flowchart LR
    Grant["멤버 공지 권한 토글"] --> Optimistic["해당 행만 즉시 변경"]
    Optimistic --> Patch{"PATCH 결과"}
    Patch -->|성공| Done["변경 유지"]
    Patch -->|실패| Rollback["해당 행만 이전 값으로 복원\n오류 표시"]

    Emoji["내 카드 아이콘 F02-P1 계획"] -.-> Editor["02 F02-P1 로컬 편집기·route/store"]
    Editor -.-> Return["설정 허브·서버 운영 상태 불변"]
```

- OWNER의 공지 권한은 토글하지 않는다. PATCH는 대상 멤버의 `announcementGrants`만 보낸다.
- 아이콘 저장·복구는 [02 내 그룹 탐색 LLD §2](../02-my-groups/low-level-design.md#2-카드-순서아이콘-저장과-계정-경계)를 따른다. 현재 운영 화면에는 편집 진입이 없으며, 02 `F02-P1`에서 로컬 편집기와 앱 route/store가 추가된 뒤 04는 그 진입과 서버 운영 상태의 독립성만 검증한다.

## 5. 필수 검증

| 수준 | 확인                                                                                                                                                                                                                                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 단위 | OWNER/MEMBER 행 분기, 자기 위임·자기 강퇴 제외, 마지막 1인·`HOST_WITHDRAW` 분기, grant rollback, 02 `F02-P1` 아이콘 실패 독립성                                                                                                                                                                                            |
| 통합 | 위임 후 hub 재조회, 위임 뒤 탈퇴 실패, 나가기 `MEMBER_ONLY` 직접 수렴과 `NOT_FOUND`의 그룹 부재·비활성 요청자·확인 실패 분기, 강퇴/권한 변경 중 늦은 상세 응답, 강퇴 `NOT_FOUND` 또는 `MEMBER_ONLY` 뒤 detail의 target 부재·group 404·requester 미소속·재조회 실패 분기, 이탈 transaction의 발급 링크 폐기·old claim no-op |
| E2E  | MEMBER 나가기의 사후조건 확인 뒤 멱등 복귀 또는 세션 안전 복구, 다인 OWNER 위임 후 나가기, 마지막 1인 `ENDED`, 강퇴 오류 뒤 최신 detail에서 target 부재일 때만 행 제거, group 부재는 안전 종료, 재조회 실패·target 유지면 false success·로컬 제거 0건, old slug·미claim click·목록·방 접근 불가, 2xx 뒤 최신 화면 수렴     |

분석 이벤트의 정확한 속성·발행 주체는 상위 [HLD](./high-level-design.md)와 공통 분석 정본을 따른다. 기존 결과 이벤트에는 유효 시도·화면 수렴 분모가 없으므로 v1 운영 성공률 KPI에 사용하지 않는다. 이 문서는 새 제품 이벤트를 정의하지 않는다.
