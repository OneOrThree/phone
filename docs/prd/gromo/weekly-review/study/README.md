# weekly-review 구현 스터디

주간 몰입 리포트(weekly-review)를 실제로 구현하려면 뭘 알아야 하는지,
**AI·LLM API·RAG 지식이 없다는 전제**로 처음부터 끝까지 읽어가는 문서다.
`ui.html`이 "화면이 어떻게 생겼나"라면, 이 폴더는 "그 화면에 들어갈 데이터가
어디서 어떻게 만들어지나"를 다룬다.

> **문서의 지위**: 이 시리즈는 학습·설계 이해용이다. 수치(비용 단가, 모델명,
> 게이트 임계값 등)는 이해를 위한 대표값이고, **확정 스펙의 정본은 상위 폴더의
> `../prd.md`(작성 예정)** 다. 둘이 어긋나면 prd.md가 이긴다.

## drawio 파일 여는 법

`.drawio`는 XML이라 에디터로 열면 안 보이고, **GitHub 웹에서도 미리보기가 안 된다**
(XML 원문만 보인다). 셋 중 하나로 열 것:

- **웹**: <https://app.diagrams.net> 에 파일을 드래그
- **VS Code**: 확장 `hediet.vscode-drawio` 설치 후 파일 클릭
- **Obsidian**: Diagrams 플러그인 (볼트에서 볼 일이 있으면)

파일 하나에 탭(페이지)이 여러 장인 경우가 있다 — 하단 탭 확인.

## 이 시리즈의 대전제 (ui.html·ai-nudge와 공유하는 원칙)

- **LLM은 계산하지 않는다.** 모든 숫자는 서버가 SQL로 집계하고 템플릿으로 문장을
  만든다. LLM에는 계산이 끝난 결과만 주고 **해석과 제안**만 받는다. (왜 그런지는 3편)
- **침묵이 기본값.** 이번 주 유효일 3일 미만이면 리포트를 만들지 않는다.
  억지로 만든 리포트는 신뢰를 깎는다.
- **결측 ≠ 0분.** 데이터 없는 날은 "0분 몰입한 날"이 아니라 "모르는 날"이다.
  비교는 양쪽 주 모두 데이터가 있는 날끼리만(짝맞춤).
  솔직한 단서 하나: 이 원칙은 **측정 데이터**(스크린타임)에서 온 것이다. 몰입
  세션은 이벤트 데이터라 "행 없음 = 세션을 안 돌린 날"일 수도 있고, 안 돌린
  날을 비교에서 빼면 성과가 부풀 수 있다. 축별로 결측을 어떻게 읽을지는
  prd.md 확정 대상 (5편 끝 목록 참고).
