# 출석 보상 PRD

상태: 설계. 구현 전. 작성일: 2026-11-12. 에픽 GROMO-2855, 이 문서는 GROMO-2856.

규칙의 정본은 [정책](policy.md)이다. 이 문서의 숫자나 예외가 정책과 다르면 정책이 맞다.

## 문제 정의

- 2.0 출시 뒤 재방문이 적다. 2026-11-11 PostHog 측정값은 아래와 같다.

  | 지표 | 값 | 모수 |
  | --- | --- | --- |
  | D1 | 15.3% | 208 / 1,357 |
  | D3 | 5.4% | 55 / 1,028 |
  | D7 | 3.2% | 15 / 474 |
  | 최근 7일(11-04~11-10) DAU 평균 | 196명 | — |

  측정 기준: 이벤트 `app_active`, 계정(person) 기준, KST 날짜, 2026-10-21~11-10 첫 사용 1,463명. D_n 은 첫 사용일로부터 정확히 n일 뒤에 다시 앱을 연 사람의 비율이고, 관측이 끝난 코호트만 묶었다.
- 앱을 다시 열 이유가 집중 하나뿐이다. 집중하지 않고 둘러보러 온 날에는 받을 것이 없다.
- 서버는 「앱을 열기만 하고 나간 날」을 모른다. 운영 DB 에는 쓰기만 남아서 재방문 수는 하한값으로만 나온다. 그래서 운영자가 재방문 유도 기능의 참여를 볼 수단이 없다.
- 2.0 에는 출석이나 연속 기록이 없다. 1.x 의 집중 10분 스트릭과 `user_streaks` 테이블은 V0 전환 때 은퇴했다.

## 목표와 성공 지표

- 하루 한 번 앱을 열 이유를 만든다. 한 번 빠져도 손해가 작아서 다시 오기 쉬운 구조로 만든다.
- 운영자가 배포 없이 이번 주·다음 주 보상을 바꾸고, 참여 현황을 백오피스에서 본다.

| 지표 | 기준선 | 목표 | 상태 |
| --- | --- | --- | --- |
| D1 | 15.3% | 18% | 제안 — 재영님 확정 전(정책 ATQ02) |
| D7 | 3.2% | 5% | 제안 — 재영님 확정 전(정책 ATQ02) |
| 출석판 노출 대비 출석 전환율 | 없음 | 관찰 | 출시 뒤 첫 4주 값을 기준선으로 삼는다 |
| 주 7칸 완주율 | 없음 | 관찰 | 같은 주 출석자 중 7칸을 모두 받은 비율 |
| 출석한 날 집중 시작 비율 | 없음 | 관찰 | 출석만 하고 나가는 방문이 얼마나 되는지 본다 |

목표 수치는 출시 4주 뒤 성숙 코호트로 잰다. 측정 방식은 기준선과 같다(PostHog `app_active`, 계정 기준). A/B 실험 기반이 없어서 출시 전후 코호트를 비교한다. 같은 기간의 광고 유입 변화가 섞일 수 있다는 점을 보고에 함께 적는다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 출석 | 사용자가 출석판에서 「출석하기」를 눌러 그날의 칸 보상을 받은 것. 하루(UTC 날짜)에 한 번이다 |
| 출석판 | 그 주 7칸과 각 칸의 보상을 보여 주는 팝업 |
| 칸 | 한 주의 1~7번째 보상 자리. 그 주 k번째 출석이 k번째 칸을 받는다 |
| 주간 표 | 특정 주(UTC 일요일 시작)의 7칸 보상 구성 |
| 기본 표 | 자기 주간 표가 없는 주에 쓰는 7칸 보상 구성 |
| 보관 물고기 | 현재 섬이 없을 때 받은 물고기. 섬이 생긴 뒤 다음 출석 때 그 섬 통장에 들어간다 |
| 대체 물고기 | 꾸미기 칸에서 그 꾸미기를 줄 수 없을 때(이미 가짐 등) 대신 주는 물고기 |

## 사용자 장면

1. **아침 첫 접속.** 지민은 수요일 아침 9시 30분(한국)에 앱을 연다. 섬 홈이 뜨고 출석판이 자동으로 열린다. 이번 주 1·2칸에는 도장이 있고 3칸이 「오늘」로 빛난다. 「출석하기」를 누르면 「물고기 15마리가 우리 섬 통장에 들어갔어요」가 뜨고 3칸에 도장이 찍힌다.
2. **오전 9시 전 접속.** 지민은 화요일 밤 11시(한국)에 출석했다. 수요일 아침 8시(한국)에 다시 열면 아직 같은 UTC 날짜라서 출석판은 자동으로 열리지 않는다. 아이콘으로 열면 「다음 출석은 오전 9시부터」가 보인다. 하루는 한국 시각 오전 9시에 바뀐다(정책 AT02).
3. **띄엄띄엄 오는 사용자.** 민수는 이번 주 월·목·토에만 왔다. 세 번 모두 출석해서 1·2·3칸을 받았다. 빠진 날 때문에 잃은 칸은 없다. 다음 주 일요일 오전 9시(한국)에 새 주가 시작되면 다시 1칸부터다. 한국 시각 일요일 0시~9시는 아직 지난 주(UTC 토요일)라서 그 사이의 출석은 지난 주로 센다. 같은 UTC 토요일에 이미 출석했다면 그 시간에는 출석할 수 없다.
4. **팝업을 그냥 닫은 날.** 서연은 출석판을 닫고 집중을 시작했다. 그날은 아직 출석이 아니다. 홈의 출석판 아이콘에 점이 남아 있고, 그날 안에 열어 누르면 출석이 된다.
5. **섬이 없는 사용자.** 하늘은 먼바다에 있어 현재 섬이 없다. 오늘 칸이 물고기 20마리다. 출석하면 「섬에 들어가면 받을 수 있게 보관했어요」가 뜬다. 이틀 뒤 섬에 들어가 다시 출석하면 그날 칸 보상과 보관한 20마리가 함께 그 섬 통장에 들어간다.
6. **이미 가진 꾸미기.** 오늘 칸이 「빨간 목도리」인데 도윤은 이미 가지고 있다. 출석하면 운영자가 그 칸에 정해 둔 대체 물고기 30마리를 받는다. 그날 도윤이 먼바다에 있어 현재 섬이 없다면 이 30마리도 보관되고, 결과 문구는 장면 5와 같다.
7. **운영자가 주 중간에 표를 고친 경우.** 운영자 A가 수요일에 이번 주 5칸을 물고기 20마리에서 「겨울 모자」로 바꿔 올렸다. 운영자 B가 승인했고, 운영자 A가 발행했다(승인한 사람과 발행한 사람이 다르다). 이미 5칸을 받은 사람은 그대로 20마리다. 발행 뒤에 5칸에 도달한 사람은 겨울 모자를 받는다.
8. **운영자가 참여 현황을 보는 경우.** 운영자는 백오피스 「출석 현황」에서 11월 11일(UTC 날짜, 한국 11일 오전 9시~12일 오전 9시) 출석판을 본 사람 180명, 그중 출석한 사람 150명(83%), 이번 주 출석 횟수 분포, 칸별 수령 수, 지급한 물고기 합계를 본다.

## 기능 요구사항

| ID | 요구사항 | 수용 조건 |
| --- | --- | --- |
| AT-F01 | 출석판 자동 열림 | 로그인한 사용자가 팝업 게이트(편지·튜토리얼·방문·모달이 없음)를 통과했고, 서버 응답이 그날(UTC) 출석 전(`attendedToday=false`)·노출 전(`viewedToday=false`)이면 출석판이 열린다. 노출 기록이 서버에 있으므로 같은 계정은 기기 두 대·재설치에도 하루 한 번만 자동으로 열린다(정책 AT15) |
| AT-F02 | 출석판 아이콘 | 섬 홈과 먼바다 화면에서 출석판을 열 수 있다. 그날 출석 전이면 아이콘에 점이 있다 |
| AT-F03 | 7칸 표시 | 받은 칸·오늘 받을 칸·잠긴 칸, 칸마다 보상(물고기 수량 또는 꾸미기 그림·이름), 보관 물고기 합계, 두 시각(다음 출석 가능 시각 = 다음 UTC 자정, 새 주 시작 시각 = 다음 UTC 일요일 자정)을 보여 준다 |
| AT-F04 | 출석하기 | 누르면 서버가 판정하고 결과(물고기 지급·보관·대체·꾸미기 지급)를 돌려준다. 앱은 결과 문구를 보여 주고 섬 통장 잔액과 보유품을 갱신한다. 409(다른 기기에서 먼저 출석 등)를 받으면 출석판을 다시 읽어 「오늘은 이미 출석했어요」를 보여 준다 |
| AT-F05 | 노출 기록 | 출석판이 화면에 보이면 앱이 그날 한 번 서버에 노출을 기록한다. 같은 날 여러 번 보내도 한 번으로 센다 |
| AT-F06 | 서버 미지원 대응 | 서버가 출석 API를 내지 않으면(404) 앱은 출석판과 아이콘을 숨긴다 |
| AT-F07 | 하루 1회·주 7회 | 같은 UTC 날짜의 두 번째 청구는 409 로 거절한다. 주 7회 상한은 하루 1회에서 따라 나오지만 서버는 방어로도 검사한다(정책 AT04). 같은 요청 키의 재시도는 처음 결과를 다시 돌려준다 |
| AT-F08 | 칸과 보상 결정 | 칸 = 그 주 출석 수 + 1. 보상은 그 주의 최신 발행 주간 표에서 읽고, 없으면 최신 발행 기본 표에서 읽는다 |
| AT-F09 | 물고기 지급 | 현재 섬이 있으면 그 섬 통장에 넣는다. 없으면 보관한다. 다음 출석 때 현재 섬이 있으면 보관분을 함께 넣는다 |
| AT-F10 | 꾸미기 지급 | 개인 보유품으로 넣는다. 이미 가졌거나, 청구 순간에 그 상품이 은퇴했거나(`retired_at`), 표시할 수 없으면(`displayable=false`) 대체 물고기를 준다. 대체 물고기는 AT-F09 규칙을 따른다 |
| AT-F11 | 받은 보상 기록 | 출석마다 그때 받은 보상(표 개정 번호·종류·수량·상품·결과)을 저장한다. 표를 나중에 고쳐도 기록은 바뀌지 않는다 |
| AT-F12 | 표 조회 | 백오피스에서 이번 주·다음 주·기본 표의 7칸과 각 표의 발행 상태·개정 번호를 본다. 지난 주 표는 읽기만 한다 |
| AT-F13 | 표 편집 | 칸마다 종류(물고기·꾸미기), 물고기 수량, 꾸미기(기존 카탈로그에서 고르기), 대체 물고기 수량을 고친다. 이미지 업로드는 없다. 승인 요청 때 Data 가 400 으로 거절하는 경우: 칸이 7개가 아님, 수량이 1~100 밖, 꾸미기 칸에 상품이나 대체 물고기가 없음, 은퇴했거나 표시할 수 없는 상품 |
| AT-F14 | 2인 승인 발행 | 승인한 운영자와 발행하는 운영자가 다르다. 승인 뒤 표가 바뀌었으면 발행을 409 로 거절한다 |
| AT-F15 | 참여 현황 | 기간을 골라 조회한다. 일별: 노출자(그날 노출 기록이 있는 계정)·출석자(그날 출석한 계정)·전환율(출석자 ÷ 노출자). 주별: 출석 횟수 1~7회 분포, 완주자(7칸을 모두 받은 계정), 칸별 수령 수. 지급 합계: 물고기 지급·보관 중·대체, 꾸미기 상품별. 날짜는 UTC 이고 화면에 그렇게 적는다(정책 AT18) |
| AT-F16 | 발행 이력 | 표마다 누가 승인하고 누가 언제 발행했는지, 바뀌기 전후의 7칸을 본다 |

## 구현 결정

1. 출석 데이터와 표는 Data API 가 소유한다. 앱은 Business API `/me/attendance` 계열만 부른다. 백오피스는 기존처럼 Data API `/internal/admin/*` 를 운영자 토큰으로 부른다.
2. 출석 판정은 서버가 한다. 앱이 보내는 날짜를 믿지 않고 서버 시각의 UTC 날짜를 쓴다.
3. 청구는 한 트랜잭션에서 출석 기록·물고기 지급 또는 보관·꾸미기 지급·이벤트를 함께 확정한다. 기존 1회 보상(튜토리얼 물고기)과 같은 잠금 순서를 쓴다.
4. 주와 하루 경계는 랭킹 주와 같은 계산을 재사용한다(UTC 일요일 00:00Z).
5. 백오피스 발행은 꾸미기 추첨 풀의 2인 승인 흐름을 그대로 쓴다.
6. 출석판 팝업은 운영진의 편지와 같은 팝업 게이트를 쓰고, 두 팝업이 동시에 뜨지 않는다.

테이블·API·잠금 순서는 LLD(GROMO-2858)가 정한다.

## 측정 계획

| 출처 | 항목 | 쓰는 곳 |
| --- | --- | --- |
| 서버 `attendance_views` | 하루 출석판 노출자 | 백오피스 참여 현황의 분모 |
| 서버 `attendance_claims` | 출석·칸·결과·지급량 | 백오피스 참여 현황 |
| PostHog `attendance_board_viewed` | 노출(자동 열림·아이콘 열림 구분) | 퍼널, 열림 경로 비교 |
| PostHog `attendance_claimed` | 칸 번호·결과 종류 | 퍼널, 집중 시작과의 연결 |
| PostHog `app_active` | 재방문 | D1·D7 목표 측정 |

PostHog 이벤트 속성에는 사용자 식별 정보 외의 개인정보를 넣지 않는다.

측정 축이 다르다는 점을 결과와 함께 적는다. 기준선 D1·D7 은 KST 날짜로 재고, 출석의 하루는 UTC(한국 오전 9시)에 바뀐다. 오전 9시 전에 출석한 사람은 다음 날 오전 9시까지 다시 출석할 수 없어서, 「다음 날 아침에 연다」는 행동에는 출석이 덜 작동할 수 있다. D1 이 기대만큼 오르지 않으면 이 축 차이를 원인 후보로 본다.

## 범위 밖

- 백오피스 이미지 업로드. 새 꾸미기 그림은 지금처럼 저장소 PR 로 카탈로그에 넣은 뒤 표에서 고른다.
- 출석 알림 푸시. 후속 후보로 정책 ATQ04 에 둔다.
- 받은 보상의 회수와 표 소급 적용.
- 연속 출석(하루 빠지면 처음부터) 보너스와 월간 출석판.
- 출석 전용 장식 그림(출석판 배너·칸 아이콘 교체).
- A/B 실험.
