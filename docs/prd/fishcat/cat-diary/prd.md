# 고양이 일기 요구사항

> 상태: P0 초안(GROMO-2860). 결정은 [decision-log](../decision-log.md) 2026-11-12 「CD-*」 행이 정본이다.

## 1. 한 줄 정의

매주 월요일 아침, 내 고양이가 지난주(KST 월~일)를 돌아보는 일기 한 편을 도서관 내 일기장에 남기고 푸시로 알린다. 글은 LLM 이 쓰고, 글에 들어가는 숫자와 사실은 전부 서버가 계산한다.

## 2. 왜 만드는가

- 2.0 의 D7 리텐션이 3.2% 다(PostHog `app_active` 계정 기준, 첫 사용 10-21~11-10 코호트). 한 주에 한 번 돌아올 이유가 필요하다.
- 도서관 내 일기장은 숫자(그래프·달력)만 보여 준다. 고양이가 그 숫자를 「우리 이야기」로 바꿔 주면, 기록을 보는 일이 섬 생활의 일부가 된다.
- 유료 기능의 첫 후보다. 구독 1명에게 드는 API 비용은 월 ₩3~₩103 이다([cost.md](cost.md)).

## 3. 사용자 장면

1. **좋은 주.** 월요일 08:00 「고양이가 이번 주 일기를 썼어」 푸시를 누른다. 고양이가 「목요일에 너는 2시간 10분을 버텼어」로 시작하는 일기를 보여 준다. 마지막 줄은 「다음 주에도 목요일 같은 하루가 한 번쯤 더 오면 좋겠다」다.
2. **바빠서 거의 못 한 주.** 일기는 탓하지 않는다. 「지난주보다 4시간 10분 줄었지만, 섬 통장에는 물고기 60마리가 들어왔어. 쉬어 가는 주도 있는 거야」.
3. **한 번도 안 들어온 주.** LLM 을 부르지 않고 고정 문구 「이번 주에는 네 발소리를 듣지 못했어…」가 온다. 돌아오라는 압박 없이 자리를 비워 두었다고만 말한다.
4. **섬이 없는 사용자.** 바다에서 항해만 한 주에는 「이번 주에도 우리는 섬 없이 바다 위에 있었어」로 쓰고, 섬 통장·주민·순위를 말하지 않는다.

## 4. 범위

| v1 에 들어감 | v1 에 들어가지 않음 |
| --- | --- |
| 주 1편, 한국어 LLM 일기 | 사용자가 다시 쓰게 하기(재생성) |
| 활동 없는 주의 고정 문구 일기 | 영어 LLM 일기(영어 사용자는 고정 문구, [prompt.md](prompt.md) §6) |
| 도서관 내 일기장의 일기 목록, 푸시로 여는 덮개 화면 | 일기 공유·이미지 카드 |
| 반응(마음에 들어 / 별로야)과 신고 | 사용자와의 대화(답장) |
| 신청형 무료 체험권 2편, 팀 허용 목록 | 구독 결제(별도 에픽) |
| 출석 칸(출석 기록이 생기면) | 다른 주민과의 비교, 섬 안 순위 |

## 5. 흐름

### 5.1 한 주와 시각

- 한 주는 **KST 월요일 00:00 ~ 다음 월요일 00:00** 이다. 도서관 내 일기장 주간 보기도 월~일이라(GROMO-2488, `library/Diary.tsx` 의 `diaryRange`), 일기 속 숫자가 같은 건물의 화면 숫자와 같다. 서버 쪽 계산은 날짜 축 규약대로 KST 고정이다([date-axis.md](../../../conventions/date-axis.md)).
- 전망대 주간 순위는 UTC 일요일 주(`RankingWeek`)라 범위가 다르다. 그래서 일기는 순위 「등수」를 인용하지 않고, 같은 KST 주로 따로 계산한 「상위 n%」 구간만 쓴다.
- 월 00:30 KST 에 생성한다. Batch 로 제출하고 10분마다 결과를 거둔다. 월 08:00 KST 에 푸시한다. 08:00 에 준비되지 않은 일기는 준비되는 대로 보내고, 월 20:00 까지 안 되면 고정 문구로 보낸다.

### 5.2 누가 받는가

| 조건 | 결과 |
| --- | --- |
| 게스트 계정 | 받지 않는다 |
| 구독도 체험권도 없고 허용 목록에도 없음 | 받지 않는다(도서관에 「고양이 일기」 안내만 보인다) |
| 구독 중 · 체험권 남음 · 허용 목록 | 그 주 활동이 있으면 LLM 일기, 없으면 고정 문구 일기 |
| LLM 일기가 가드에 두 번 걸림 · 거절 · 예산 초과 · 20:00 까지 미완료 | 고정 문구 일기 |

- 활동은 「그 주에 끝난 집중이 있다」 또는 「출석한 날이 있다」이다.
- 체험권은 사용자가 직접 켜는 **신청형**이고 2편이다. **LLM 일기가 실제로 나간 주에만** 1편을 쓴다. 고정 문구 일기는 체험권을 쓰지 않는다.

### 5.3 어디서 보는가

- 도서관 방(`Library.tsx`)의 세 번째 물건과 내 일기장 주간 보기의 카드에서 목록을 본다. 읽지 않은 일기에는 표시가 붙는다.
- 푸시를 누르면 덮개 화면(`DeveloperLetter.tsx` 방식)으로 그 주 일기가 열린다. 도서관을 아직 짓지 않았거나 섬이 없어도 푸시로는 열린다.
- 일기 아래에 「마음에 들어 / 별로야」와 신고가 있다. 신고한 일기는 목록에서 숨긴다.

## 6. 데이터

- LLM 에 보내는 것은 수치 계약 `cat-diary-facts/1` 하나다. 필드와 만드는 법은 [prompt.md](prompt.md) §2 가 정본이다. 사용자 id·닉네임·섬 이름·방명록 같은 사용자 글은 보내지 않는다.
- 일기는 `cat_diaries` 에 사용자·주마다 한 행으로 저장한다(UNIQUE `user_id, week_start`). facts 원본, 쓴 회사·모델·프롬프트 버전, 토큰·비용, 가드 실패 코드를 함께 적는다. 표 정의는 GROMO-2863 이 정한다.
- 탈퇴하면 일기와 체험권 행을 지운다.

## 8. 성공 지표

출시 전 품질 관문, 운영 감시, 제품 지표는 [eval.md](eval.md) 가 정본이다. 제품 쪽 핵심은 셋이다.

1. 푸시 → 일기 열람 비율
2. 「별로야」 비율(15% 를 넘으면 그 주 일기를 검토한다)
3. 체험권 → 구독 전환율, 일기를 받은 사람의 다음 주 재방문율
