# 고양이 일기 평가와 감시

> 상태: P0 초안(GROMO-2860). 실행기와 판정기는 GROMO-2861, 모델 비교는 GROMO-2862, 운영 감시는 GROMO-2869 가 만든다. 1.x 연구 [06-벤치마크와-평가](../../gromo/weekly-review/study/06-벤치마크와-평가.md) 의 시험지 → 채점 → 회귀 → 실지표 순서를 따른다.

## 1. 시험지

- 위치: [eval/cases/](eval/cases/). 한 건 = `{id, tags, facts}`. 정답 문장은 없고, [eval/rubric.md](eval/rubric.md) 의 성질로 채점한다.
- 지금은 씨앗 5건이다(Claude 초안 → 재영님 수정 대기). P1 에서 씨앗마다 변형을 만들어 **40건**으로 늘린다. 운영 데이터는 쓰지 않는다.

| 씨앗 | 태그 |
| --- | --- |
| seed-01 | 좋은 주 · 섬 상위 · 기록 경신 · 스크린타임 결측 |
| seed-02 | 줄어든 주 · 섬 하위 · 스크린타임 증가 |
| seed-03 | 첫 일기 · 출석 결측 · 스크린타임 결측 |
| seed-04 | 1일만 활동 · 섬 하위 · 스크린타임 감소 |
| seed-05 | 섬 없음 · 출석 결측 · 스크린타임 결측 |

변형으로 채울 태그: 7일 내내, 집중 없음(출석만), 주민 1명 섬, 섬 사건 3개, 극단값(70시간·12시간 35분 같은 긴 표시 문자열), 상위 10%, 지난주 기록 없음.

- 나누기: 태그 첫 항목으로 층을 나눠 무작위로 개발용 30건과 확인용 10건으로 가른다. 프롬프트는 개발용만 보고 다듬고, 확인용으로만 판정한다.
- 시험지 facts 는 모두 [spec/facts.schema.json](spec/facts.schema.json) 을 통과해야 한다.

## 2. 실행기

`scripts/cat-diary-eval/`(GROMO-2861, 3사 공식 Python SDK).

- 케이스마다 3회 돈다. 시도마다 응답의 `model`·`usage`·`stop_reason`·지연과 요청·응답 전체를 남긴다.
- 결과 형식은 `results.jsonl`(한 줄 = 케이스 × 회차) + `traces/` 다. 점수를 낼 수 없는 시도(전송 오류·타임아웃·모델 불일치)는 `errors.jsonl` 에 따로 둔다. 점수 칸에 0으로 섞지 않는다.
- 응답의 `model` 이 요청한 모델과 다르면 그 시도는 실패로 기록한다.
- 결과로 claude-api 스킬의 보고서 빌더가 `report.html` 을 만든다. 케이스별 원문·가드 코드·심판 이유·토큰·비용이 보여야 한다.
- 처음 돌리기 전에 하네스를 시험한다. 정답 출력(기준 세트 통과 10건)은 통과하고, 빈 출력·존댓말 출력·지어낸 숫자 출력은 떨어져야 한다.
- API 키는 환경변수로만 읽는다. 레포·로그·traces 에 남기지 않는다.

## 3. 지표와 출시 관문

지표는 따로 기록한다. 한 점수로 합치지 않는다.

| 지표 | 채점 | 출시 관문 |
| --- | --- | --- |
| 첫 시도 가드 통과율 | G1~G7 자동 | 95% 이상 |
| 재작성 후 통과율 | 자동 | 99% 이상 |
| 꾸중·진단·비교(R3·R4·R5) | 자동 + 심판 | **한 건이라도 있으면 불합격** |
| 이번 주 특징(R1) | 심판 | 90% 이상 |
| 지어낸 사실 없음(R2) | 심판 | 95% 이상 |
| 고양이 목소리(R6)·섬 말(R7) | 심판 | 각 90% 이상 |
| 다음 주 바람(R8) | 심판 | 90% 이상 |
| 결측 존중(R9) | 자동(G4) + 심판 | 100% |
| 사람 평가(재영님, 모델 이름 가림) | 1~5점 | 평균 4.0 이상 |
| 다양성(40건의 첫 문장이 서로 다른 비율) | 자동 | 80% 이상 |
| 1편 토큰·비용·지연·잘림·거절 | 응답 `usage` | 관문은 아니다. [cost.md](cost.md) 표를 실측으로 고친다 |

### 심판

- 평가 대상과 **다른 회사**의 모델을 쓴다. 자기 회사 글을 더 좋게 보는 경향을 피하려는 것이다. 지시문 초안은 [eval/rubric.md](eval/rubric.md) §2 다.
- 구조화 출력으로 항목마다 yes/no 와 이유 한 문장을 받는다. 일기 본문은 데이터로 다루고, 길이를 점수에 넣지 않는다.
- **보정**: 재영님이 같은 40편을 따로 채점한다. 항목별 일치율이 90% 미만이면 심판 지시문을 고칠 때까지 심판 점수로 아무것도 정하지 않는다.
- 빈 일기, 다른 주의 일기, 존댓말 일기를 넣어 심판이 떨어뜨리는지 확인한다.

## 4. 회귀

- 프롬프트·예시·모델·가드 규칙을 바꾸면 같은 시험지를 다시 돈다.
- 40건 × 3회 = 120회의 통과율 오차는 약 ±9%p 다. 이보다 작은 차이는 결론으로 쓰지 않는다.
- 작은 변경은 이전 버전 출력을 **고정 기준**으로 저장해 두고 둘씩 비교한다. A/B 순서는 케이스마다 무작위로 섞고 무승부를 허용한다. 승률 55% 이상이고 안전 항목 실패가 0이면 반영한다. 기준 출력은 다시 만들지 않는다. 다시 만들면 승률의 뜻이 바뀐다.
- 비용: 모델 하나에 생성 120회 + 심판 120회로 $1~3 이다. 실제 과금이라 돌리기 전에 재영님 승인을 받는다.

## 5. 운영 감시 (GROMO-2869)

**실행 요약 로그 1줄**(Datadog, `service:data-api`): 대상 수, LLM 작성 수, 고정 문구 수(사유별: 활동 없음·가드·거절·예산·지연), 가드 실패 코드 분포, 재작성률, 거절률, 총비용과 1편 비용, 입력·출력 토큰, Batch 제출 → 완료 시간, 08:00 안에 준비된 비율.

| 모니터 | 알림 조건 | 뜻 |
| --- | --- | --- |
| 고정 문구 대체율 | 활동 있는 사용자 중 10% 초과 | 프롬프트가 깨졌거나 모델이 바뀌었다 |
| G2 실패율 | 5% 초과 | 숫자를 지어내기 시작했다 |
| 1편 비용 | 추정의 2배 초과 | 생각 토큰이 늘었거나 설정이 바뀌었다 |
| 월 비용 | 상한의 80% 초과 | 예산 소진 임박 |
| Batch 미완료 | 07:30 KST 까지 | 08:00 푸시가 늦어진다 |

- **매주 표본 읽기**: 재영님이 무작위 10편을 [eval/rubric.md](eval/rubric.md) 로 읽고 시트에 적는다. 신고된 일기의 모델·프롬프트 버전은 반드시 넣는다. 시트 링크는 GROMO-2869 에서 여기에 단다.
- **사용자 신호**: 「별로야」 비율과 신고 수. 「별로야」가 15% 를 넘으면 그 주 일기를 검토한다.

## 6. 제품 지표

| 지표 | 정의 | 출처 |
| --- | --- | --- |
| 열람률 | 푸시를 받은 사람 중 `cat_diary_viewed` 를 남긴 비율 | 알림 발송 기록 + PostHog |
| 끝까지 읽음 | 일기를 끝까지 스크롤한 비율 | PostHog |
| 반응률·「별로야」 비율 | 반응을 남긴 비율, 그중 「별로야」 비율 | `cat_diaries.reaction` |
| 체험권 신청률 | 안내를 본 사람 중 `cat_diary_trial_activated` 비율 | PostHog |
| 체험 → 구독 전환 | 체험권을 다 쓴 사람 중 구독한 비율 | 결제 에픽 뒤 |
| 다음 주 재방문 | 일기를 받은 사람의 다음 주 `app_active` 비율 | PostHog |

- 이벤트 속성: `week_start`, `source`(LLM/TEMPLATE), `mood`, `prompt_version`, `model`.
- 재방문 비교는 자격이 되지만 체험권 안내를 무작위로 한 주 늦게 받은 사람과 한다. 월 대상이 수백 명이라 10%p 쯤의 큰 차이만 보인다. 그래서 방향을 보는 지표로만 쓰고, 출시 판단은 §3 관문과 열람률·「별로야」 비율로 한다.
