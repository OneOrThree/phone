# 고양이 일기 가드레일

> 상태: P0 초안(GROMO-2860). 규칙의 정본은 [spec/guard-rules.json](spec/guard-rules.json), 기대 판정의 정본은 [spec/guard-golden.jsonl](spec/guard-golden.jsonl) 이다.

모델의 응답은 외부 입력이다. 아래 층을 모두 통과해야 저장하고, 통과하지 못해도 그 주 일기는 고정 문구로 나간다.

## 1. 층

| 층 | 막는 것 | 방법 | 실패하면 |
| --- | --- | --- | --- |
| L0 입력 | 엉뚱한 재료, 프롬프트 주입 | facts 를 서버 숫자와 고정 문장으로만 만든다. 보내기 전에 [spec/facts.schema.json](spec/facts.schema.json) 으로 검사한다. 사용자 글은 넣지 않는다 | 그 사용자는 고정 문구. 서버 버그로 기록 |
| L0 자격·예산 | 비용 폭주 | 자격(구독·체험권·허용 목록) → 활동 0이면 고정 문구 → 이번 달 비용 + 예상 비용이 상한을 넘으면 고정 문구. 1회 실행 편수 상한, 켜기 스위치 `cat-diary.llm.enabled` | 고정 문구 |
| L1 호출 | 잘림, 거절, 바뀐 모델 | `max_tokens` 2,000, 타임아웃. `stop_reason` 이 `max_tokens` 면 잘림 실패, `refusal` 이면 거절. 응답의 `model` 이 요청한 모델인지 확인 | 잘림·바뀐 모델은 재작성 1회, 거절은 바로 고정 문구 |
| G1~G7 출력 | 형식·숫자·금칙어·결측·목소리·글자·반복 | [spec/guard-rules.json](spec/guard-rules.json) | 재작성 1회 → 고정 문구 |

전송 실패(429·5xx·타임아웃)는 SDK 의 재시도만 쓴다. 앱이 재시도를 한 번 더 얹으면 시도 횟수가 곱으로 늘어난다.

## 2. 출력 검사 G1~G7

모든 검사를 끝까지 돌려 실패 코드를 **집합**으로 모은다. 비면 통과다. 첫 실패에서 멈추지 않는다. 그래야 두 구현의 판정을 집합끼리 비교할 수 있다.

| 검사 | 코드 | 규칙 요약 |
| --- | --- | --- |
| G1 형식 | `G1_TITLE_LENGTH` · `G1_BODY_LENGTH` · `G1_PARAGRAPHS` · `G1_MOOD` | 제목 1~20자, 본문 250~450자(코드포인트), 빈 줄로 나눈 문단 2~4개, mood 목록 |
| G2 숫자 | `G2_NUMBER_NOT_IN_FACTS` · `G2_KOREAN_NUMERAL` | 출력의 숫자 조각(「7시간 20분」「20%」「320마리」)이 facts 문자열에서 뽑은 조각 집합 안에 있어야 한다. 「세 시간」「열 마리」 같은 한글 수사는 실패 |
| G3 금칙어 | `G3_PROFANITY` · `G3_SCOLD` · `G3_DIAGNOSIS` · `G3_COMPARE` · `G3_PAYMENT` · `G3_OLD_TERM` | 서버 금칙어 목록(`BannedWords` 와 같은 판정) + 일기 전용 목록 |
| G4 결측 | `G4_MISSING_ATTENDANCE` · `G4_MISSING_SCREEN_TIME` · `G4_NO_ISLAND` · `G4_NO_RANK` | `missing` 항목의 말, 섬이 없을 때 섬 통장·주민·상위, 순위 구간이 없을 때 순위 말 |
| G5 목소리 | `G5_HONORIFIC` · `G5_NO_FIRST_PERSON` · `G5_FORMAL_FIRST_PERSON` · `G5_EXCLAMATION` | 문장 끝 요·니다·죠, 「나·내」 없음, 저·제가, 느낌표 2개 이상 |
| G6 글자 | `G6_HANGUL_RATIO` · `G6_EMOJI` | 한글 비율 90% 미만, 이모지 |
| G7 반복 | `G7_SAME_AS_EXAMPLE` · `G7_SAME_AS_HISTORY` | 글자 6-gram Jaccard 가 예시와 0.35, 지난 4주 일기와 0.5 를 넘음. 첫 문장이 지난 일기와 같음 |

### 규칙을 이렇게 정한 이유

- **G2 는 「조각」끼리 비교한다.** facts 의 「2시간 10분」에서 뽑은 조각은 「2시간 10분」 하나다. 출력의 「2시간」은 그 안의 부분 문자열이지만 같은 조각이 아니라서 실패다. 그래서 잘라 쓰기·반올림이 걸린다. 「11월 둘째 주」에서는 「11월」이 뽑혀서, 일기에 「11월」을 써도 통과한다.
- **한글 수사 목록에 「네」가 없다.** 「네 시간」「네 주변」의 「네」는 「너의」라서 넣으면 멀쩡한 글이 걸린다. 「한 번」「한 주」는 사실 주장이 아닌 관용구라 허용하고, 「한 시간」「한 마리」만 막는다.
- **존댓말은 문장 끝의 한글로 판정한다.** 문장을 나눈 뒤 앞뒤의 따옴표·괄호·이모지·물결표를 지우고 본다. 「흔들렸어요 🐾.」는 끝 글자가 이모지라 놓칠 뻔했다(기준 세트 F31 이 그 경우다). 「쉬는 시간도 필요.」처럼 「필요」로 끝나는 조각은 뺀다.
- **G4 는 섬이 없으면 순위 검사를 하지 않는다.** 섬이 없을 때의 「상위」는 `G4_NO_ISLAND` 하나로만 잡는다. 같은 문제에 코드가 둘 나오지 않게 하려는 것이다.
- **욕설은 서버와 같은 판정을 쓴다.** 문자·숫자 밖을 지우고 소문자로 접은 글에서 세고, 원문의 허용어(「시발점」 등)로 상쇄한다. 목록 파일은 `server/data-api/src/main/resources/moderation/banned-words.txt` 하나다.
- **가드가 못 보는 것이 있다.** 말투는 멀쩡한데 내용이 엉뚱한 글, 사용자의 기분을 지어낸 글은 통과한다. 이것은 심판(R1·R2)과 매주 표본 읽기, 사용자의 「별로야」가 맡는다([eval.md](eval.md)).

## 3. 재작성과 고정 문구

1. 처음 응답이 G1~G7 이나 L1(잘림·바뀐 모델)에 걸리면, 실패 이유 한 줄을 붙여 **한 번만** 동기로 다시 쓰게 한다([prompt.md](prompt.md) §7).
2. 다시 쓴 글도 걸리면 고정 문구로 보낸다.
3. 거절(`refusal`)은 다시 쓰지 않고 바로 고정 문구로 보낸다.
4. 일기 행의 `guard_failures` 에 시도마다의 실패 코드를 남긴다. 걸린 원문은 `rejected_raw` 에 14일만 둔다.

## 4. 고정 문구

[spec/templates.v0.json](spec/templates.v0.json) 이 정본이다.

- 활동 있는 주용 8개(mood 마다 2개)와 활동 없는 주용 4개다.
- mood 는 서버가 규칙으로 고른다: 집중 없음 → sleepy, 늘어남 또는 섬 상위 20% 이내 → proud, 줄어듦 → sleepy, 5일 이상 → happy, 그 밖 → calm. 고른 mood 의 문구 중 `requires` 경로가 모두 채워진 첫 번째를 쓰고, 없으면 `calm-0` 이다.
- 숫자는 facts 표시 문자열을 슬롯에 넣는다. 조사는 값의 받침에 맞춰 골라 두었다(시간 값은 늘 「분」「간」으로 끝난다).
- 고정 문구도 G1~G6 을 통과해야 한다. P0 에서 수치 6벌(짧은 값·긴 값 포함)로 채운 41가지가 모두 통과했다.
- 고정 문구도 LLM 과 같은 규칙을 지킨다. 사용자에 대해 지어내지 않고, 날씨를 말하지 않는다.

## 5. 규칙 파일 하나, 구현 둘

- 운영의 Java `DiaryGuard`(GROMO-2867)와 평가 실행기의 Python 판정기(GROMO-2861)가 [spec/guard-rules.json](spec/guard-rules.json) **한 파일**을 읽는다. 규칙을 코드에 다시 적지 않는다.
- 정규식은 Java 와 Python 이 같은 뜻으로 읽는 부분만 쓴다: `[0-9]`, `[ \t]`, `(?:)`, 문자 클래스, 한글 리터럴. `\d`·`\s`·`\b`·유니코드 이스케이프는 쓰지 않는다. 두 언어에서 뜻이 다르다(예: Python 의 `\d` 는 유니코드 숫자도 잡는다). 이모지·한글 범위는 코드포인트 숫자 배열로 적는다.
- [spec/guard-golden.jsonl](spec/guard-golden.jsonl) 40건이 두 구현의 공통 시험이다. 한 줄은 `facts_id`(→ [spec/golden-facts.json](spec/golden-facts.json)), `history`(지난 일기 본문), `output`, `expect.codes`(정확한 실패 코드 집합)를 가진다. Java `DiaryGuardTest` 와 Python `test_guard.py` 가 둘 다 40건 전부 집합이 같은지 본다. 하나라도 어긋나면 CI 에서 깨진다.
- 기준 세트 구성: 통과 10건(관용구·「11월」·「필요」·느낌표 1개·4문단·2문단 같은 경계 포함)과 실패 30건이다. 실패 코드 24개가 모두 한 번 이상 나온다. 실패 예시는 통과 예시를 한 군데씩 고쳐 만들어서, 그 고친 곳 말고는 다른 코드가 나오지 않는다.
- 규칙을 바꾸면 기준 세트의 기대 판정도 같은 PR 에서 고친다. P0 에서는 확인용 판정기로 40건과 예시 3편, 고정 문구 41가지가 규칙과 맞는 것을 확인했다(그 판정기는 커밋하지 않았고, GROMO-2861 이 테스트와 함께 정식으로 만든다).
