# 고양이 일기 정책

> 상태: P0 초안(GROMO-2860). 결정의 정본은 [decision-log](../decision-log.md) 2026-11-12 「CD-*」 행이다. 이 문서는 그 결정을 기능 규칙으로 풀어 쓴다. 기계로 검사하는 부분은 [guardrails.md](guardrails.md), 사람·심판이 보는 부분은 [eval/rubric.md](eval/rubric.md) 가 맡는다.

## 1. 누가 말하는가

- 화자는 **사용자의 고양이**다. 1인칭 「나」로 쓰고 사용자를 「너」라고 부른다(CD-화자).
- 말투는 반말이다. 앱의 다른 고양이·NPC 대사와 같다(`DESIGN.md` 「고양이는 반말로…」, `ko.json` 의 `onboardingStory`·`guide`). 일기 화면의 버튼·안내 같은 UI 문구는 앱 규칙대로 해요체다.
- 다정하고 담백하게 쓴다. 이모지를 쓰지 않고, 느낌표는 일기 전체에서 1개까지다.
- 섬의 말을 쓴다. `CONTEXT.md` 의 `_Avoid_` 말(코인·재화·통계·그룹·멤버·캐릭터·지갑 등)은 쓰지 않는다.

## 2. 쓰는 것과 쓰지 않는 것

| 쓴다 | 쓰지 않는다 |
| --- | --- |
| facts 의 숫자(표시 문자열 그대로) | 계산·반올림·단위 변환한 숫자, 한글로 풀어 쓴 숫자 |
| `highlights` 첫 항목을 중심으로 한 그 주의 특징 | 어느 주에나 붙는 덕담만으로 채운 글 |
| 고양이 자신의 상상(졸기, 꼬리, 부두, 찌, 바구니) | 사용자에 대해 facts 에 없는 일: 시간대·과목·횟수·기분·사정 |
| 섬 비교는 `rank_band` 문자열(「상위 20%」) | 다른 주민·다른 사람과의 비교, 섬 안 순위 |
| 줄어든 주에는 곁에 있는 말 | 꾸중, 실망, 죄책감, 「해야 해」 압박 |
| 마지막에 다음 주의 작은 바람 하나 | 건강·마음 진단과 조언, 앱 기능·보상·결제·구독 약속 |

- 섬 안 주민 순위를 보여 주지 않는다는 2.0 결정(B23, `CONTEXT.md` 「리그 · 주민 순위」)을 일기도 따른다.
- AI 집중 측정 결과는 앱 메모리 밖으로 내보내지 않는다는 규칙(`DESIGN.md` 집중 인증)에 따라 일기의 재료로 쓰지 않는다.

## 3. 결측은 0 이 아니다

- 측정이 없는 항목은 facts 에서 `null` 이고 `missing` 에 이름이 들어간다(지금은 `attendance`·`screen_time`). 일기는 그 항목을 말하지 않는다. 「기록이 없다」·「0일」이라고도 쓰지 않는다.
- 집중이 한 번도 없는 주는 `focus: null` 이다. 이것은 측정 실패가 아니라 실제로 쉬어 간 주라서 `missing` 에 넣지 않는다. 일기는 「쉬어 간 주」로 담담하게 쓰고 집중 시간을 말하지 않는다.
- 섬이 없으면 `island: null` 이다. 일기는 바다·뗏목으로 쓰고 섬 통장·주민·순위를 말하지 않는다.
- 섬 순위가 상위 절반 밖이면 `rank_band: null` 이다. 순위를 말하지 않는다(낮은 순위를 알려 주지 않는다).

## 4. 활동 없는 주와 고정 문구

- 그 주에 끝난 집중도, 출석한 날도 없으면 LLM 을 부르지 않는다. 고정 문구 4개 중 하나를 보낸다(CD-빈주). 비용은 0이다.
- LLM 일기가 가드를 두 번 통과하지 못하거나, 거절되거나, 이번 달 예산을 넘거나, 월 20:00 까지 준비되지 않으면 활동 있는 주용 고정 문구 8개 중 하나를 보낸다. 고르는 규칙은 [spec/templates.v0.json](spec/templates.v0.json) 의 `mood_rule`·`pick_rule` 이다.
- 고정 문구도 같은 가드(G1~G6)를 통과해야 한다. 어떤 경우에도 그 주 일기는 나간다.

## 5. LLM 에 보내는 데이터

| 보낸다 | 보내지 않는다 |
| --- | --- |
| 그 주의 집계 수치(표시 문자열), 서버가 고른 고정 문장(`highlights`·`events`) | 사용자 id·이메일·기기 정보, 닉네임·섬 이름·소개·방명록·편지 같은 사용자 글 |
| 첫 일기 여부, 지난주와의 증감 방향 | 원본 세션 로그, 과목, 측정 앱 목록, AI 집중 측정 결과 |

- 요청의 식별자(Batch `custom_id`)는 일기 행 id 다. 회사 쪽에서 사용자를 알아볼 수 없다.
- 식별자를 빼도 한 사람의 주간 행동 패턴은 개인정보로 볼 수 있다. 그래서 운영에서 LLM 호출을 켜기 전에 개인정보 처리방침의 위탁·국외 이전 항목에 고른 회사와 국가, 넘기는 항목, 보관 기간을 적는다(GROMO-2870).
- 고른 회사의 API 데이터 정책(보존 기간, 학습 미사용)을 공식 문서로 확인하고 이 절에 URL 을 적는다(GROMO-2870). Gemini 무료 등급은 입력을 제품 개선에 쓰므로 쓰지 않는다([cost.md](cost.md)).
- 서버 로그에 facts 와 일기 본문을 남기지 않는다. API 키도 남기지 않는다.

## 6. 보관과 삭제

| 데이터 | 보관 |
| --- | --- |
| 나간 일기(제목·본문·mood·facts·모델·토큰·비용) | 계정이 있는 동안. 탈퇴하면 지운다 |
| 가드에 걸린 원문(`rejected_raw`) | 14일. 디버깅에만 쓴다. 탈퇴하면 바로 지운다 |
| 체험권 | 계정이 있는 동안. 탈퇴하면 지운다 |

## 7. 반응과 신고

- 일기 아래에 「마음에 들어 / 별로야」 버튼과 신고가 있다(CD-반응).
- 반응은 일기 행에 하나만 남고, 다시 누르면 바뀐다. 품질 감시의 사용자 신호로 쓴다([eval.md](eval.md) §5).
- 신고하면 그 일기를 사용자의 목록에서 숨기고 운영 검토 대상으로 표시한다. 신고된 일기의 모델·프롬프트 버전은 다음 주 표본 읽기에 꼭 넣는다.

## 8. 비용 상한

- API 비용은 월 ₩10,000 안이다(CD-예산). 서버 설정 `cat-diary.monthly-budget-usd` 는 7 로 시작하고, 회사 콘솔의 지출 한도도 같은 값으로 건다.
- 이번 달 비용과 이번 실행의 예상 비용의 합이 상한을 넘으면, 넘는 몫은 고정 문구로 보낸다. 사용자는 일기를 그대로 받는다.
- 구독자가 늘면 상한 규칙을 「구독 순매출의 10%」로 바꾼다. 상한은 설정값이라 배포 없이 바꾼다.
