## 측정과 UTC 보고

- 네이티브는 기존 KST 날짜 경계를 유지한다. Monitor는 날짜별 `{bucket, firedAt}`와
  측정 구간 시작을 저장하며 브리지 `getUsageTimeline`이 조회한다. 이벤트·시작 표식은 4일 보존한다.
- 최초 수집 이전·소유자 변경·재부팅·권한 공백·선택 변경 날짜는 완전한 측정으로 추정하지 않는다.
  소유자가 바뀌면 네이티브 측정 데이터를 먼저 초기화한다. 조회·승격은 직렬화하고 인증 세대를 검사한다.
- `screenTimeWindow.ts`는 UTC 하루를 KST 날짜별로 나눠 누적값 차분을 합산한다.
  UTC 10/8은 KST 10/8 09:00부터 10/9 09:00까지다. 일합계를 ISO로 라벨만 바꾸지 않는다.
- 선택한 앱·카테고리·웹의 **15분 눈금 근사치**다. 전체 기기 정확값이 아니다.
  900분 포화, 누락된 날짜, 역행 이벤트, 부분 측정은 `unavailable/null`이다.

### 당일 중간 관측의 서버 계약 제한

현재 서버는 `authorized` 중간 관측에도 UTC 날짜가 끝나면 달성을 판정할 수 있다.
이 때문에 현 앱 구현은 **진행 중 날짜를 `pending/null`로 보고하고, 닫힌 UTC 하루만 숫자로 보고한다.**
서버의 당일 통계는 대기 상태이며, 앱 미실행으로 최종 보고가 없으면 결측으로 남는다.
통계와 퀘스트 모두 실제 숫자 보고를 사용한다. 두 소비자를 동시에 실시간으로 지원하려면
서버가 중간 관측과 최종 관측을 구분하는 계약 및 판정 변경이 선행돼야 한다.

이 제한은 보상 적용 범위를 축소하는 제품 정책이 아니라 불완전 관측의 허위 달성을 막기 위한
현재 계약의 구현 한계다. 15분 눈금 경계 오차가 퀘스트 상한에 미치는 영향은 실기기 검증 전
해결됐다고 간주하지 않는다. 권한이 앱 미실행 중 철회됐다가 재승인된 모든 공백을 확정할 수 있다는
보장도 없다.

## 업로드와 소비자 갱신

- `api/screenTime.ts`: `PUT /me/screen-time/{date}`, `timezone=UTC`, `deviceId=AT.sid`,
  실제 관측 시각 `measuredAt`, UUID 멱등키. 서버 필드를 임의로 추가하지 않는다.
- `screenTimeReporting.ts`: 사용자·sid별 영속 큐. 동일 관측 재시도는 본문·시각·키를 유지한다.
  동의 철회 후에는 숫자 보고를 폐기하고 `denied` 상태를 보낸다. 계정/동의 세대가 바뀐 작업은 중단한다.
- 다음 날 12:00Z 이후 보고는 폐기한다. 네트워크·429·5xx는 재시도하고 영구 오류는 별도 거절 이력에
  남긴다. 실패를 전송 성공으로 기록하지 않는다. 앱 전경의 1분 주기·복귀·날짜 변경·동의 변경에 동작한다.
- PUT 성공 뒤 `screenTimeEvents.ts`로 현재 도서관 통계와 게시판·퀘스트 상세를 재조회한다.
  PUT 응답을 계정 합계로 사용하지 않으며 수령과 섬 원장 반영은 기존 서버 경로를 유지한다.

- 차단 적용·해제는 `focusShield.ts`에서 직렬화한다. 종료 요청보다 앞서 대기한 적용을 폐기하고,

  중복 Activity를 정리하고 종료/해제된 Activity를 재사용하지 않는다.
- 서버 ActivityKit push/APNs 등록·종료 API는 이번 조사에서 확인되지 않았다. `pushType:nil`을 유지한다.

원문 2장의 `구현됨`은 앱·서버·키·dev/prod 연결, 구현자 기능 테스트 및 전체 QA 통과를 뜻한다.
본문에는 `구현 완료`도 혼용되지만 별도 정의는 없다. 같은 완료 의미로 판단하면
**이번 작업에서 완료 라벨로 확정할 항목은 아직 없다.** 코드 완료와 QA 완료를 합치지 않는다.

### 원래 로드맵에 있던 미완료 작업

- **3-11·12:** 실기기의 권한·날짜 경계·누락·실서버 보고·철회·재전송 검증.
- **3-13:** Family Controls 운영 권한, dev/prod 설치본, 휴식·종료·재부팅 차단 해제.
- **3-14:** Android 차단 전체. 이번 티켓에서 제외한 기존 항목이다.
- **3-15:** 백그라운드 페이즈 전환과 종료 후 잔존 표시. APNs 토큰 등록·원격 갱신/종료는
  이 요구를 충족할 구체 작업으로 드러난 것이며 별도의 신규 제품 기능은 아니다.
- **3-16·6-07:** 설치본 위젯 QA 및 방문자 경로 재현 확인.
- **5-03/B12:** 측정 불가를 측정 전과 구분하는 표시. 이번에 만든 오류가 아니라 원문에 있던 미수정 항목이다.
- **5-05/B21·5-06·4-01:** 퀘스트 운영 플래그 및 달성·수령·원장 검증. 통계/퀘스트 연결만으로 전체 항목을 닫지 않는다.
- **4장 공통 완료 기준:** 구현자가 아닌 팀원의 QA, 배포 설정·설치본 확인.

### 이번에 구체적으로 발견한 제약과 후속 작업

새로운 제품 기능 요청은 없다. 아래는 원문에 구체적으로 적히지 않았던 기존 기능의 기술 제약이다.

| 발견 사항 | 현재 처리 | 필요한 후속과 연결 항목 |
| --- | --- | --- |
| 서버가 중간 관측과 최종 관측을 구분하지 않아 이전 중간값으로 달성할 수 있음 | 진행 중 UTC 날짜는 pending/null, 닫힌 날짜만 수치 전송 | 당일 실시간 통계와 안전한 보상 판정을 함께 제공하려면 최종성 계약·판정 변경 필요. 3-12·5-03·5-06의 하위 작업 |
| 기존 15분 버킷·900분 상한으로 정확한 사용량과 차이가 생김 | 포화·부분 관측·누락은 unavailable, 결측을 0으로 보내지 않음 | 퀘스트 상한 부근 오차 및 불완전 관측의 보상 판정 검증·보완. 3-11·5-06의 하위 작업 |
| 앱 미실행 중 권한 철회 후 재승인된 모든 공백을 확정할 수 없음 | 발견한 권한 공백·선택 변경·재부팅 날짜는 미확인 처리 | 실제 OS 동작과 측정 완전성 기준 확인·보완. 3-11·12의 하위 작업 |

추가로 재부팅 시 ShieldConfiguration 호출 시점, WidgetKit 갱신 시점은 OS가 결정한다.
각각 기존 3-13·3-16의 검증 조건이며 앱 코드 작성만으로 즉시 실행을 보장했다고 표시하지 않는다.

## Android 후속

3-14는 기존 PR #686의 활성 2.0 적합성과 앱 차단 서비스·권한·오버레이·강제 종료/재부팅 복구를
별도로 검토한다. 이번 작업에서 Android 차단을 구현하거나 완료로 표시하지 않는다.
