# 콘텐츠 백오피스 구현 결과

2026-10-29 사용자 요청: FCM, 앱 내 개발자 공지, 잡지를 한곳에서 검토·승인·발송·게시한다.

## 구현

- 독립 React 웹과 Node 서버. 운영자별 로그인, 서버 전용 서비스 자격, CSRF, 영구 초안·수정본·승인·감사 이력.
- dev·prod 별도 인스턴스와 SQLite 볼륨을 쓰고, 시작 및 내부 조회·발행 전 Data·Notification이 실제 연결한 DB의 환경 표식과 Notification의 FCM 프로젝트를 확인해 교차 연결을 거부한다. 로컬 `test` 계정은 연결 모드에서 거부한다.
- 수정하면 승인 취소. 게시 중·완료·결과 불확실 상태에서는 편집을 막는다. 응답 유실 후 같은 발행 UUID로만 재시도하며, 나중의 인증 거부가 최초 발송 결과를 바꾸지 않는다.
- FCM은 서비스 공지(`ADMIN_ANNOUNCEMENT`) 전용이며 승인한 문구를 알림 원장에 고정한다. 명시적 UUID 1~100명에게 서비스 공지를 요청하며 수신 설정·탈퇴·조용한 시간·발송 게이트를 준수한다. PENDING은 요청 접수다.
- 개발자 공지는 평문 제목·본문·게시 기간을 보관한다. 앱 설정의 목록·상세 화면은 현재 노출 기간에 해당하는 최신 100개 공지를 읽으며 빈 화면·재시도·만료·계정 변경을 처리한다.
- 잡지는 공개 호 생성 전 비공개 스냅샷을 만든다. 검토한 홍보·편집부 내용을 게시하며 홍보 변경·섬 종료·새로 생긴 섬의 비공개 전환은 재검토한다. 당일 KST 07시 이후 평균 집계를 완료한 후 최종 미리보기·게시가 가능하다. 미래 날짜의 초안은 당일 최종 미리보기를 다시 불러 검토·승인한다. 자동 호 생성 대신 관리자가 매일 승인·게시한다. 늦은 밤 게시와 일시 실패에 대비해 24시간 주기로 유효한 미알림 호를 재시도한다.

웹의 잡지 화면은 게시 데이터 검토용이며 앱의 픽셀 단위 지면과 같다고 보장하지 않는다. 게시 후 수정·철회, 전체 사용자 일괄 발송, 예약 FCM, 복수 백오피스 인스턴스는 이번 구현에 포함하지 않는다. 공지는 종료 시각을 지정할 수 있다.

## 배포 순서

1. Data V4, Notification V14와 서버 API를 적용한다. 기존 V0 baseline은 수정하지 않았다.
2. 백오피스 운영자별 Data/Notification 자격, HTTPS, 단일 인스턴스 영구 볼륨을 설정한다. 잡지 자동 발행 전환 전에 매일 게시 담당자를 준비한다.
   dev·prod는 서로 다른 URL·볼륨·서비스 자격을 사용하고 각 인스턴스의 `BACKOFFICE_ENV`·`BACKOFFICE_FCM_PROJECT_ID`를 맞춘다. Data·Notification의 각 DB에 환경 표식을, Notification DB에는 그 환경의 FCM 프로젝트 ID를 DB 소유자가 설정한 뒤 연결한다.
3. 앱 공지 읽기 화면을 배포한다. 서버와 앱 변경은 별도 브랜치다.

운영 설정·실행은 [백오피스 README](../../../../backoffice/README.md), 잡지는 [운영 런북](../magazine/ops-runbook.md)을 따른다.

## 검증

- 백오피스 Node 테스트 13개: 인증·출처·CSRF·승인 상태·환경/FCM 대상 대조·스냅샷·중복 방지·응답 유실·재시작 복구·정적 경로 검증 통과. 큰 잡지는 스냅샷 ID·digest만 전송하고 서버의 원본으로 복원해 저장한다.
- TypeScript와 Vite 배포 빌드 통과.
- Chrome 로컬 브라우저: 세 채널 작성→검토→승인→모의 게시, 승인 후 수정, UUID 입력 검증, 잡지 스냅샷 무효화, 게이트 대기 표시, 로그아웃 통과. 320/375/414/768/1440px 가로 넘침 없음, 브라우저 오류·외부 요청 0건.
- Notification 전체 206개 테스트와 Checkstyle·SpotBugs 통과.
- Data 콘텐츠·잡지·권한·알림·아키텍처 회귀 및 Business 공개 API 계약 검사 통과. 로컬 PostgreSQL migration 적용과 DBML 82개 테이블 대조에서 드리프트 없음.
- 앱 관련 28개 테스트, 전체 타입 검사, 변경 파일 ESLint 통과. 공용 디자인 토큰과 IslandSheet/SheetRow/Txt/Btn을 재사용했다. 로컬 UI Kit 문서가 없어 DESIGN.md와 코드 정본을 사용했다.
- 별도 코드 리뷰에서 불확실 발송의 편집 잠금 해제와 큰 잡지 원본 재전송 문제를 수정했다. 재시작 후 재시도 인증 실패 및 3,000칸 로컬 스냅샷의 작은 참조 저장을 확인했다.

AWS 부하·부하용 데이터 생성·운영 발송·운영 게시·배포는 실행하지 않았다. 로컬 검증은 모의 상류 또는 Mockito 전송을 사용했다.
