# 신고센터 후속 구현 범위와 검증 기준

[정책](policy.md) · [이메일 접수 계약](email-intake-contract.md) · [법적 근거·긴급 대응](legal-response.md) · [결정 로그](../decision-log.md)

이 문서는 기존·신규 후속 티켓에 배정할 작업 범위다. 이 문서에서 Jira 티켓을 생성하거나 수정한 것은 아니다. 차단 API·일부 표시 필터는 GROMO-1975, 여섯 텍스트 입력의 금칙어 검증은 GROMO-1986으로 구현됐지만 신고센터 전체 구현은 완료되지 않았다. 확정 RP 정책을 기준으로 구현하고, 정책의 D 초안 항목은 설계 검토에서 확정한다. 2026-09-24 RP-메일정본에 따라 자체 신고 사건·원문 DB는 범위에서 제외한다.

## 현재 코드 대조 — 2026-09-24, main e221cc58

- `UserBlockRepository`와 `UserBlock`에 더해 GROMO-1975의 차단 생성·해제·목록 API가 있다. 친구 목록·검색과 받은 편지함 목록에는 차단자 관점 표시 필터가 붙었다. `FriendService.createRequest`와 `InternalLetterService.send`에는 차단 판정이 없고, 앱에는 차단 조작 UI가 확인되지 않았다. RP-차단의 양방향 직접 연락 제한과 채팅·댓글·공지 숨김은 남은 범위다.
- `InternalLetterService.close`는 수신자 권한 확인 후 `softDeleteIfActive`로 편지를 닫는다. 조회와 닫기 경합은 처리하지만 신고 증거 확보와의 경합 처리는 새로 연결해야 한다.
- GROMO-1986의 `BannedWords`는 공지·댓글·편지·닉네임·섬 이름·소개 입력을 서버에서 검증한다. 기존 `CharacterModerationService`는 누끼 이미지 검사다. 섬 채팅과 링크 정책, 작성 전 동의까지 완료됐다는 근거는 아니다.
- 채팅 정본은 realtime의 `gromo_chat`이며 기존 [우체통 정책](../island-mailbox/policy.md)을 따른다. 신고 때문에 전체 채팅 이력을 Data로 복제하지 않는다.

GROMO-1670은 정책·범위 정의 티켓이다. 위 기존 티켓들은 별도로 이미 발행됐지만 현재 Jira에서 1670과의 연결이나 설명 갱신은 확인되지 않았다. 앱 UI는 GROMO-1673과 GROMO-1976에서 분리해 진행할 수 있다. F1 서버 메일 접수, F2 서버 차단, F3 운영, F5 잔여 필터·규범은 UI만으로 닫히지 않는다.

원문 조회·메일 발송·제재 소유권은 기존 Data/Business/realtime 경계에 맞춰 상세 설계한다. 다른 서비스의 DB를 직접 조회해 신고 원문을 가져오는 방식은 채택하지 않는다. 채팅 증거 확보를 포함해 성공 기준을 먼저 정하고, 부분 실패에서 메일 증거 없는 ‘접수 완료’를 반환하지 않는다. 메일함의 접근 권한·상태·결과 통지·파기·백업과 개인정보 고지를 검증한다.

## 필수 검증 시나리오

1. 공지·댓글·채팅·친구 편지·닉네임·섬 이름/소개 각각 신고 가능. 읽을 수 없는 비공개 콘텐츠 ID를 직접 보내면 접수·원문 열람 불가.
2. 편지 신고가 먼저 확정되면 이후 닫아도 증거 유지. 닫기가 먼저 확정되면 신규 신고 거절. 중복 요청과 응답 유실 재시도도 한 건으로 귀결.
3. 신고 시점의 작성자·원문 버전을 고정. 이후 수정·삭제·탈퇴로 증거를 다른 내용으로 바꾸지 않음. 미확보한 과거 원문을 추정하지 않음.
4. 신고한 콘텐츠만 개인 숨김. ‘함께 차단’ 미선택이면 상대의 모든 글을 숨기거나 친구 관계를 변경하지 않음.
5. 차단 시 양방향 편지/친구 요청 차단. 차단자가 보는 채팅·댓글·사용자 공지, 알림·목록 미리보기·재접속 캐시에서 상대 콘텐츠가 새어 나오지 않음.
6. 커뮤니티 제한은 집중·기록을 보존하면서 모든 UGC 쓰기 우회를 막음. 전체 정지는 기존 세션·실시간 연결까지 반영하되 이의제기·탈퇴 접근은 보존.
7. 운영자가 확인한 재위반만 경고→7일→30일→영구 단계로 상승. 동일 사건의 여러 신고나 과거 사건 지연 접수로 중복 상승하지 않음.
8. 7일/30일 만료 경계·6개월 무위반 초기화·영구 정지 제외·경고의 기산점·검토 중 신고 경계를 검증.
9. 확인된 답장 주소가 있는 사건은 최초 결과 답장 발송, 답장 주소가 없는 사건은 종결부터 원문 30일 파기. 답장 재시도로 기한 연장 안 됨. 제재 최소 이력, 법적 보존 예외가 분리되고 백업 복원 시 파기 대상이 다시 노출되지 않음.
10. 긴급 선택만으로 자동 계정 정지하지 않음. 담당 알림 실패/부재 시 대체 경로, 임시 정지 재검토, 오판 복구, 신고자 신원 비노출 확인.
11. 정지된 방장 때문에 섬 운영이나 주민 탈퇴가 막히지 않음. 방문자가 신고/차단해도 원래 게시판 접근 권한을 넘어선 정보가 노출되지 않음.
12. CSAM 대응 훈련은 합성된 무해한 텍스트·사건 메타데이터로 수행. 실제 불법 이미지·영상을 테스트 자료로 사용하지 않음.

## 티켓 완료와 출시의 구분

1670은 정책과 후속 범위를 확정하는 티켓이다. [완료조건 판정](gap-review-2026-09-24.md#2026-09-24-완료-판정)에 따라 네 문서 완료조건은 충족했다. D 상세안의 조정, 메일 제공자 검증과 회사별 사실 확인은 후속 구현·출시 작업으로 추적한다. 실제 2.0 출시 전 신고·차단·필터·운영·선택적 결과 이메일이 동작해야 하며, 이 문서나 API 단위 테스트만으로 출시 조건 충족을 주장하지 않는다.
