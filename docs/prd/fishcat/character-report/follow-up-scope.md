# 신고센터 후속 구현 범위와 검증 기준

[정책](policy.md) · [법적 근거·긴급 대응](legal-response.md) · [결정 로그](../decision-log.md)

이 문서는 후속 티켓을 나눌 수 있는 작업 범위다. 아직 Jira 티켓을 생성하거나 앱·서버를 구현한 것은 아니다. 확정 RP 정책을 기준으로 구현하고, 정책의 D 초안 항목은 설계 검토에서 확정한다.

## 현재 코드 대조 — 2026-09-22, main 50887946

- `UserBlockRepository`와 `UserBlock`은 존재한다. 리포지토리는 탈퇴 정리에도 쓰인다. 티켓 본문의 ‘테스트에서만 사용’은 현시점 설명으로 사용하지 않는다. 스키마 존재가 사용자 차단 API·노출 제어 완료를 의미하지 않는다.
- `InternalLetterService.close`는 수신자 권한 확인 후 `softDeleteIfActive`로 편지를 닫는다. 조회와 닫기 경합은 처리하지만 신고 증거 확보와의 경합 처리는 새로 연결해야 한다.
- 기존 `CharacterModerationService`는 누끼 이미지 검사다. 2.0 텍스트 전 표면의 필터링이 이미 있다는 근거가 아니다.
- 채팅 정본은 realtime의 `gromo_chat`이며 기존 [우체통 정책](../island-mailbox/policy.md)을 따른다. 신고 때문에 전체 채팅 이력을 Data로 복제하지 않는다.

## 구현 작업 분할

| --- | --- | --- | --- |
| F1 접수·증거 | 대상 종류/ID·사유·인가, 원문 스냅샷, 멱등 접수·중복 병합, 접근 감사·만료/보존 예외 | D1·D2·D6 초안 정리 | 삭제·편집·닫기 경합에서도 잘못된 원문이나 권한 밖 데이터가 저장되지 않음 |
| F2 차단·숨김 | 기존 `user_blocks` 활용, 양방향 직접 연락 제한, 차단자 콘텐츠 비노출, 목록·상세·실시간·알림에 적용 | F1과 독립 진행 가능, D3 범위 확인 | 모든 입구에서 동일한 차단 효과, 재로그인·복수 기기에서도 유지 |
| F3 운영·제재 | 긴급/일반 큐, 사건 배정·검토·조치, 7일/30일 만료, 영구 정지, 6개월 초기화, 이의제기·오판 취소 | F1, D4·D6·D7 | 같은 사건 중복 제재 없음, 각 기간 경계와 재심 취소 동작 확인 |
| F4 앱 | 대상별 신고, 선택적 함께 차단, 차단 목록/해제, 접수·결과 안내, 제재 상태·이의제기 경로 | F1/F2/F3 계약 | 신고 직후 숨김, 실패 시 재시도, 열린 편지에서 신고 중 닫기 방지 |
| F5 필터·규범 | UGC 작성 전 정책 동의 확인, 금지 텍스트 필터·외부 링크 처리, 공개 규범·연락처·아동 안전 고지 | 기존 약관/계정 계약 및 공개 채널 확인 | 서버 직접 요청에서도 우회 불가, 정상 텍스트 오탐·실패 동작 검증 |
| F6 운영·출시 | 담당/대체·검토일 지정, 긴급 알림 전달/미확인 시험, 기관 접수 절차, 개인정보 고지, 기기별 QA | F1~F5, 법적 적용 사실 확인 | 실제 신고 접수부터 운영 검토·결과 통지·파기까지 시연 |

공통 저장·제재 소유권은 기존 Data/Business/realtime 경계에 맞춰 상세 설계한다. 다른 서비스의 DB를 직접 조회해 신고 원문을 가져오는 방식은 채택하지 않는다. 채팅 증거 확보를 포함해 성공 기준을 먼저 정하고, 부분 실패에서 증거 없는 ‘접수 완료’를 반환하지 않는다.

## 필수 검증 시나리오

1. 공지·댓글·채팅·친구 편지·닉네임·섬 이름/소개 각각 신고 가능. 읽을 수 없는 비공개 콘텐츠 ID를 직접 보내면 접수·원문 열람 불가.
2. 편지 신고가 먼저 확정되면 이후 닫아도 증거 유지. 닫기가 먼저 확정되면 신규 신고 거절. 중복 요청과 응답 유실 재시도도 한 건으로 귀결.
3. 신고 시점의 작성자·원문 버전을 고정. 이후 수정·삭제·탈퇴로 증거를 다른 내용으로 바꾸지 않음. 미확보한 과거 원문을 추정하지 않음.
4. 신고한 콘텐츠만 개인 숨김. ‘함께 차단’ 미선택이면 상대의 모든 글을 숨기거나 친구 관계를 변경하지 않음.
5. 차단 시 양방향 편지/친구 요청 차단. 차단자가 보는 채팅·댓글·사용자 공지, 알림·목록 미리보기·재접속 캐시에서 상대 콘텐츠가 새어 나오지 않음.
6. 커뮤니티 제한은 집중·기록을 보존하면서 모든 UGC 쓰기 우회를 막음. 전체 정지는 기존 세션·실시간 연결까지 반영하되 이의제기·탈퇴 접근은 보존.
7. 운영자가 확인한 재위반만 경고→7일→30일→영구 단계로 상승. 동일 사건의 여러 신고나 과거 사건 지연 접수로 중복 상승하지 않음.
8. 7일/30일 만료 경계·6개월 무위반 초기화·영구 정지 제외·경고의 기산점·검토 중 신고 경계를 검증.
9. 결과 통지 재시도로 보존 기한 연장 안 됨. 원문 30일 파기, 제재 최소 이력, 법적 보존 예외가 분리되고 백업 복원 시 파기 대상이 다시 노출되지 않음.
10. 긴급 선택만으로 자동 계정 정지하지 않음. 담당 알림 실패/부재 시 대체 경로, 임시 정지 재검토, 오판 복구, 신고자 신원 비노출 확인.
11. 정지된 방장 때문에 섬 운영이나 주민 탈퇴가 막히지 않음. 방문자가 신고/차단해도 원래 게시판 접근 권한을 넘어선 정보가 노출되지 않음.
12. CSAM 대응 훈련은 합성된 무해한 텍스트·사건 메타데이터로 수행. 실제 불법 이미지·영상을 테스트 자료로 사용하지 않음.

## 티켓 완료와 출시의 구분

1670은 정책과 후속 범위를 확정하는 티켓이다. 이 초안은 여섯 정책 주제, 증거·운영 흐름, 긴급 대응과 작업 분할을 채웠다. D 초안의 승인과 회사별 사실 확인은 상태를 표시해 추적한다. 실제 2.0 출시 전 신고·차단·필터·운영·통지가 동작해야 하며, 이 문서나 API 단위 테스트만으로 출시 조건 충족을 주장하지 않는다.
