# 이메일 정본 신고 접수 계약 — 2026-09-24

[정책](policy.md) RP-메일정본 · [후속 구현 범위](follow-up-scope.md) · [긴급 대응](legal-response.md)

## 확정 경계

- 앱 안에서 신고 대상과 사유·설명을 제출한다. 앱 UI는 GROMO-1670과 분리된 기존 GROMO-1673에서 현재 계약에 맞춰 구현한다.
- 자체 신고 사건·원문 DB를 만들지 않는다. 서버가 신고 권한과 대상의 현재 원문을 확인해 **전용 운영 메일함에 남긴 메시지**가 신고·증거 정본이다. 사용자 설명은 원문과 구분한다.
- 텍스트만 이 흐름으로 보낸다. 실제 CSAM 의심 이미지·영상은 메일에 첨부하거나 URL에서 자동 다운로드하지 않는다.
- 신고 원문은 확인된 주소로 결과 답장을 발송한 사건은 최초 발송 후 30일, 주소가 없거나 발송 실패가 확정된 사건은 운영자 무연락 종결 후 30일에 파기한다. 진행 중 조사·분쟁·적법한 보존 요청은 사유·담당·재검토일을 남겨 별도로 관리한다.

## 후속 구현 계약

1. **입력·권한:** 앱은 대상 종류·ID, 화면이 본 **신고 텍스트의 리비전**/시각, 사유·설명, 재시도 때 유지할 요청 ID·조회 시 서버가 발급한 불변 스냅샷 토큰과 선택적 답장 이메일만 보낸다. 로그인 사용자 ID는 서버 인증에서 얻는다. 서버는 토큰이 증명하는 조회 당시 열람 권한·원문·작성자·텍스트 리비전을 검증하고 현재 원 서비스 상태와 대조한다. 내용이 달라져도 유효한 토큰이나 검증 가능한 과거 리비전이 있으면 조회 당시 원문으로 접수하며, 둘 다 없으면 새 내용을 신고한 것으로 바꾸지 않는다. 공지의 공용 `notice.version`은 댓글 추가에도 바뀌므로 제목·본문 전용 리비전을 별도로 검증한다. 닉네임·섬 이름을 포함한 수정 가능 대상은 조회 시점의 불변 스냅샷 토큰을 제출·검증한다. 이를 제공하지 못하면 해당 필드 신고 UI를 열지 않는다.

   공지·댓글·채팅·편지·프로필·섬 정보 등 신고 가능한 **모든 텍스트 조회 응답**에는 원 서비스가 **대상 종류·ID·필드 식별자**, 조회 당시 원문·작성/수정 주체·텍스트 리비전·열람자 ID·열람 권한 근거·발급/만료 시각을 인증 암호화한 불변 스냅샷 토큰을 붙인다. 앱은 원문 대신 이 토큰을 신고 입력에 포함한다. 서버는 토큰의 무결성·열람자 일치·7일 유효기간·권한 근거와 제출한 대상 종류·ID·필드의 정확한 일치를 검증해 조회 당시 원문을 복원하며, 원문 수정·하드 삭제 뒤에도 이 검증된 사본으로 접수한다. 하나라도 다르면 접수·숨김·제재 판단을 하지 않는다. 토큰이 없거나 만료됐고 원 서비스에 해당 리비전의 검증 가능한 이력이 없으면 접수를 거절하고 재조회 가능 여부를 안내한다. 토큰 원문을 로그에 쓰지 않고, 암호화 키 교체 시 유효 토큰의 복호화 능력을 만료까지 유지한다. 기존 편지 닫기 선행 경계는 4항을 따른다.
2. **메시지 형식:** 서버 생성 사건 ID, 요청 ID, 신고자 ID, 대상 종류·ID·필드·버전, 원문 작성/수정 시각, **확인 가능한 실제 작성·수정 주체**, 서버가 토큰 또는 검증된 리비전 이력에서 확인한 원문, 신고 사유·별도 사용자 설명, 접수 시각을 구조화한다. 수정 주체를 확인할 수 없으면 원 작성자에게 제재를 귀속하지 않고 콘텐츠 조치만 검토한다. 동일 대상·필드·버전의 위반 판단 ID를 별도로 부여해 신고자별 사건이 여럿이어도 제재는 한 번만 적용한다. 답장 주소·소유 확인 상태와 근거는 사건 ID에 결박된 보호 필드로 보존한다. 피해자 실명 등 불필요한 프로필은 포함하지 않는다. 원문·자유 설명은 HTML 메일에 삽입하지 않고 안전한 일반 텍스트로 직렬화한다. 외부 링크는 아래의 클릭 불가능한 표시본과 정확한 인코딩 원문으로 분리하고 자동 미리보기·방문·원격 리소스 로드를 끈다. 메일 제목·푸시·알림에는 원문을 넣지 않는다.
3. **접수 성공:** 메일 API의 단순 발송 요청 수락만으로 앱에 ‘접수 완료’를 보여주지 않는다. 운영 메일함에서 사건 ID로 해당 메시지가 조회 가능해지고, 사건 ID·요청 ID에 결박된 계정 숨김 표지까지 확정된 뒤 성공을 반환한다. 서버는 목록·상세·실시간·푸시 발송 직전에 `(신고자, 대상, 필드, 리비전)` 숨김 표지를 권위 있게 검사한다. 신고 접수와 경합해 이미 큐에 들어간 같은 리비전의 전송은 폐기하고, 실시간 fanout·알림 대기열의 해당 전송 배출까지 확인한 뒤 접수 성공을 반환한다. 두 저장소를 원자적으로 갱신할 수 없으면 부분 성공을 조정한다. 메일만 성공한 재시도는 기존 사건을 찾아 누락 표지를 멱등 생성한 뒤 성공을 반환하고, 표지만 남은 실패는 메일 접수를 완료하거나 표지를 실패 상태로 되돌린다. 조정 전에는 영구 숨김·접수 성공을 표시하지 않는다. 이 조건을 제공할 메일/헬프데스크 서비스가 없다면 이 방식은 출시 계약을 충족하지 못한다. 조회 실패·시간 초과는 성공으로 접지 않고 재시도 가능한 상태로 안내한다.
4. **편지 경합:** 편지는 활성 여부·수신자 권한·원문 조회와 메일함 접수 확인이 닫기 명령과 직렬화돼야 한다. 닫기가 먼저 확정되면 신규 신고를 거절한다. 신고가 먼저 확정되면 이후 닫혀도 메일 증거가 남는다. 외부 메일 요청이 시간 초과된 뒤 늦게 성공할 수 있으므로 일시적 DB 잠금만으로 완료 순서를 보장하지 않는다. 구현은 편지에 내구적인 신고 예약·닫기 fence를 두고 메일함 확인·실패·늦은 성공을 대조해 상태를 확정해야 한다. 확정 전 닫기는 대기하거나 재시도되며, 예약 실패를 확인하기 전에는 닫기 확정도 접수 실패도 표시하지 않는다.
5. **재시도·중복:** 앱은 같은 요청 ID로 재시도한다. 서버는 **인증된 신고자 ID + 요청 ID**로 메일함 사건을 조회해 응답 유실 뒤에도 같은 사건을 돌려준다. 이 키는 대상 종류·ID·필드·버전, 사유·설명 및 답장 주소의 정규화된 입력에 대한 keyed digest에 결박한다. 같은 키에 다른 입력이 오면 `IDEMPOTENCY_KEY_REUSED`로 거절한다. 제공자의 원자적 멱등 생성 또는 동등한 예약/대조 기능을 확인해야 하며, 불확실한 발송 결과는 조회·조정 전 신규 사건으로 재발송하지 않는다. 원문 파기 뒤에도 같은 요청을 새 사건으로 만들지 않도록 인증된 신고자 ID·요청 ID의 keyed digest와 입력 digest·파기 상태만 남기는 최소 멱등 표지를 둔다. 파기된 키의 재시도는 `REQUEST_EXPIRED`로 거절하며 원문을 복원하지 않는다. 이 표지는 사건·원문 DB가 아니며 계정 삭제와 키 보존·파기 근거는 개인정보 처리 설계에서 정한다. 중복 메시지가 생겨도 같은 사건·위반 판단 ID로 묶어 한 번만 검토·제재한다. ‘정확히 한 통’을 보장한다고 쓰지 않는다.
6. **운영 상태·결과:** 운영 메일함에서 새 신고·긴급·검토 중·종결·보존 예외를 사건 ID로 찾을 수 있어야 한다. 상태 변경자·시각과 조치·종결 시각을 메일함/헬프데스크의 감사 가능한 기록에 남긴다. 일반 사건이 접수 후 30일 동안 미종결이면 담당자·대체 담당에게 상향 알리고, 운영자는 종결 또는 사유·담당·재검토일이 있는 보존 예외로 전환한다. 이후 7일 안에 두 조치가 모두 없으면 자동으로 `검토 미완료`로 종결하고 운영 누락을 감사 기록에 남긴다. 확인된 주소에는 이 상태를 사실대로 답장하며, 주소가 없거나 발송 실패가 확정되면 무연락 종결로 전환한다. 단순 `검토 중` 상태만으로 무기한 원문을 보관하지 않는다. 긴급 사건은 별도 담당 확인·보존 예외 절차를 따른다. 답장받을 이메일은 선택 입력이며 소유 확인 전에는 결과를 보내지 않는다. **사건 종결 후 7일**까지 주소 소유가 확인되지 않으면 미확인 주소를 폐기하고 그 시각에 무연락 종결로 전환해 30일 원문 파기 시계를 시작한다. 종결 시 주소가 아예 없으면 즉시 무연락 종결한다. 확인된 주소가 있으면 종결 후 사건 ID가 연결된 정형 결과 답장만 보낸다. 확인된 주소의 최초 결과 발송은 사건 종결 후 24시간 안에 시도하고, 작업 유실·미시도로 이 기한을 넘기면 발송 실패로 확정해 무연락 종결 및 30일 파기 시계를 시작한다. 최초 시도 뒤 일시적 발송 실패는 최초 시도 후 7일 또는 총 3회 재시도 중 먼저 도달한 한도에서 실패 확정·무연락 종결로 전환한다. 반송 주소로 계속 보내지 않으며 기한 초과 뒤 재발송으로 보존 시계를 늦추지 않는다. 주소가 없거나 실패가 확정되면 사후 결과 통지는 하지 않는다. 앱은 접수 확인과 사건 ID만 제공한다. 운영자 임의 삭제·외부 전달·로컬 내려받기·자동 전달을 금지하고 접근 권한·감사 기록을 적용한다. 승인된 복사본이 필요하면 같은 사건 ID·파기 기한을 적용한다.
7. **파기:** 확인된 주소로 결과 답장한 사건은 최초 답장 발송 시각, 답장 주소가 없거나 발송 실패가 확정된 사건은 운영자 무연락 종결 시각부터 일반 원문을 30일 보존한다. 실패한 발송은 결과 통지 완료로 기록하지 않는다. 피신고자 제재 통지 후 30일의 이의제기 기한이 이보다 늦게 끝나면 그 기한까지 사건별 보존 예외를 설정하고 종료 시 파기한다. 만료 건은 메일함·보낸 편지·승인된 사본·첨부·검색 사본·백업의 실제 삭제 가능 범위를 확인해 파기한다. 보존 예외는 자동 파기에서 제외하되 근거 종료를 재검토한다. 제공자가 이 계약을 지원하지 않으면 다른 제공자나 저장 구조를 선택해야 한다.
8. **긴급 알림:** 같은 사건 ID의 긴급 알림을 지정된 운영 시간·전달 체계에 따라 주 담당과 대체 담당에게 전달하되 알림에는 원문·피해자 정보·외부 링크를 넣지 않는다. 단순 발송 성공을 담당 확인으로 보지 않고 미확인 시 대체 경로로 넘긴다. 긴급 분류는 일반 일일 한도에서 제외하되 분당·일일 남용 한도, 동일 대상 반복 알림 병합, 한도 초과 건의 안전한 검토 대기열을 둔다. 실제 사람·연락처·운영 시간·확인 기준은 출시 점검에서 지정한다. 운영 시간을 정하기 전에는 야간·휴일 상시 대응을 약속하지 않는다. 즉각적인 신체 위험에는 출시 국가별 긴급 번호를 안내하며, 국내 출시 화면은 112를 쓴다.

   메일 생성 앞단에서 계정별·전역 수용량이 정해진 대기열을 적용하고 사건 생성 대기열은 인증된 신고자·대상 종류/ID·필드·리비전별로만 병합한다. 서로 다른 신고자의 사건은 분리하고 대상 단위 병합은 위반 판단 ID와 긴급 알림에만 적용한다. 일반 경로가 가득 차면 새 사건을 메일로 보내거나 접수 완료로 표시하지 않고 재시도 가능 시각을 포함한 과부하 응답을 준다. 긴급 경로에는 별도 예약 용량과 독립 한도를 두며, 이마저 가득 차면 담당자에게 용량 경보를 보내고 앱에는 접수 실패와 긴급 서비스 연락 안내를 표시한다. 초과 건을 무제한 축적하거나 접수되지 않은 건을 검토 대기 중이라고 표시하지 않는다.

### 외부 URL의 안전한 메일 표현
