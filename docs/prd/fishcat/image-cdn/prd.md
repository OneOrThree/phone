# 이미지 CDN 및 기기 캐시 PRD

상태: 구현 명세. 운영 적용 전. 작성일: 2026-10-29.

## 문제 정의

앱의 정적 그림을 모두 번들로 제공하면 사용하지 않는 화면의 이미지도 배포에 포함될 수 있다. 반대로 CDN URL로만 바꾸면 첫 진입 지연, 반복 다운로드, 오프라인 공백이 생긴다. 이용자가 한 번 본 그림을 기기에 보관하고 필요한 변경분만 받아야 한다.

기준 main `4f3a3d96c`의 이미지 원본은 690개/205.12MiB다. 이는 압축 설치 크기가 아니다. 이후 main `af74aa5cc`의 변경은 운영 Redis ACL 문서이며 이 기능 기준 코드에 영향이 없다. 별도로 서버 꾸미기 카탈로그의 PNG·rig JSON은 이미 정적 경로로 제공된다. 두 경로를 합쳐 같은 문제가 있다고 가정하지 않는다.

## 목표와 성공 조건

- 동일 버전의 보존 캐시를 재방문할 때 이미지 본문 다운로드 0 bytes.
- 열려 있는 화면의 이미지·좌표 메타데이터는 같은 버전 유지. 부분 다운로드 노출 0건.
- 이미지 전달 경로의 API/Redis 요청 추가 0건. 카탈로그 조회 등 업무 API는 유지.
- 최초 오프라인·CDN 장애·디스크 부족에도 필수 UI와 탐색 가능. 원본 상세 이미지의 최초 오프라인 표시까지 보장하지 않는다.
- Android/iOS 릴리스 산출물과 Expo export에서 시범 원본의 번들 참조 제거를 증명. 실제 감소 bytes를 기록하고 임의 절감률을 약속하지 않는다.
- 첫 진입 시간/메모리 p95는 시범 전후 같은 기기로 측정하고, 확대 전 수용 기준을 확정한다.

## 해결 방법

공개 이미지 전용 CDN과 콘텐츠 해시 기반 기기 저장소를 둔다. 화면은 캐시 또는 최소 번들 대체 이미지를 즉시 표시한다. 필요한 팩을 검증해 받은 뒤 안전한 화면 경계에서 전환한다. 시간 경과만으로 정상 파일을 다시 다운로드하지 않는다.

## 사용자 이야기

1. 이용자로서 이미 본 이미지는 다시 방문할 때 기다리지 않고 보고 싶다.
2. 이용자로서 네트워크가 불안정해도 화면의 기능을 계속 쓰고 싶다.
3. 신규 이용자로서 모든 그림을 미리 받지 않고 필요한 화면부터 쓰고 싶다.
4. 이용자로서 저장 공간 부족 때문에 앱이 멈추지 않기를 원한다.
5. 이용자로서 오랫동안 보지 않은 그림은 자동 정리되기를 원한다.
6. 이용자로서 화면을 보는 중 그림과 아틀라스 좌표가 서로 바뀌지 않기를 원한다.
7. 이용자로서 앱을 다시 켜도 다운로드를 반복하지 않기를 원한다.
8. 이용자로서 로그아웃해도 공개 그림을 다시 받지 않기를 원한다.
9. 구버전 앱 이용자로서 새 콘텐츠 배포 뒤에도 내 앱과 호환되는 그림을 보고 싶다.
10. 운영자로서 검증한 이미지 묶음만 공개하고 실패하면 이전 릴리스로 돌아가고 싶다.
11. 운영자로서 CDN·캐시 변경이 원래 카탈로그 권한과 장착 데이터에 영향을 주지 않기를 원한다.
12. 개발자로서 재다운로드량·메모리·번들 용량을 수치로 확인해 확대 여부를 판단하고 싶다.
13. 이용자로서 다운로드 도중 앱을 종료해도 다음 실행에 깨진 그림이 표시되지 않기를 원한다.
14. 운영자로서 지원 중인 구 앱과 롤백 릴리스가 쓰는 파일을 실수로 삭제하지 않기를 원한다.

## 기능 요구사항

| ID | 요구사항 | 수용 조건 |
| --- | --- | --- |
| CDN-F01 | 공개 전용 원본과 CDN | S3 직접 접근 거부, CDN HTTPS GET 성공, API 사용자 토큰 미전송 |
| CDN-F02 | 파일 후 포인터 공개 | 파일 검증 실패 시 활성 채널 변화 없음. 동시 배포 충돌은 실패 처리 |
| CDN-F03 | 호환 팩 조회 | 스키마/호환 세대 불일치 시 기존 캐시 유지 |
| CDN-F04 | 재사용·증분 수신 | 동일 SHA 파일은 팩을 넘어 재사용. 새 SHA만 다운로드 |
| CDN-F05 | 수명/용량 관리 | 6시간 확인·30일 미사용·7일 직전 버전·256/192MiB 예산 정책 통과 |
| CDN-F06 | 표시 일관성 | 화면 lease가 참조하는 객체는 GC/업데이트로 제거되지 않음 |
| CDN-F07 | 실패 복구 | 부분 파일/손상/타임아웃/디스크 부족에서 정상 캐시 또는 대체 UI 사용 |
| CDN-F08 | 롤백·구 앱 | 증가한 generation이 이전 릴리스를 가리키는 롤백 허용 |
| CDN-F09 | 기존 꾸미기 경로 보존 | PNG·rig·공용 band 경로 모두 CDN에서 조회 가능. 업무 카탈로그 캐시/권한 불변 |
| CDN-F10 | 점진 이전·계측 | 시범 팩의 번들 참조 제거와 릴리스 산출물 검증 후 후속 확대 |

## 구현 결정

1. S3 + CloudFront OAC. 별도 이미지 프록시·DB 테이블·Redis 키를 만들지 않는다.
2. 이미지 바이트의 SHA-256을 식별자로 사용하고, 앱 호환 세대별 채널과 불변 릴리스 manifest를 둔다.
3. 기존 맵 캐시의 계약/테스트 방식은 재사용하지만 맵의 6파일 전용 파이프라인은 1차에 변경하지 않는다.
4. 첫 시범은 회관 내부 정적 이미지 한 팩. 화면의 소형 대체 이미지를 번들에 남기며 사용자 문구/기능을 새로 설계하지 않는다.
5. 메타데이터·정리·활성화는 하나의 저장소 조정자가 소유하고 실제 다운로드만 제한 병렬 실행한다.
6. 초기 숫자 정책은 policy의 구현 기본값이며 실기기 성능 검증을 통과한 설정이라는 뜻이 아니다.
7. 네이티브에서 수신 bytes·deadline·SHA-256을 제한하고 검증 가능한 불변 metadata snapshot으로 강제 종료에 대응한다. 따라서 Android/iOS 새 바이너리가 필요하다.
8. 기존 꾸미기 서버 경로는 경로 보존형 CDN 이전 후 별도 티켓에서 기기 팩 캐시로 연결한다. 종전 nginx 경로는 구 앱을 위해 유지한다.

## 테스트 결정

가장 높은 경계인 저장소 공개 API와 실제 화면 소비 경로를 검증한다. 파일시스템·다운로더·시간·디코드 검사 어댑터를 주입해 결과(요청 수, 선택된 URI, 보존된 버전, 예산, 복구)를 단언한다. 기존 맵 캐시 회귀 20개는 유지하고 새 캐시 수명/경합 시나리오를 별도 검사한다. 실제 CDN GET 및 Android/iOS 디코드는 단위 테스트로 대체하지 않는다.

## 범위 밖

사용자 업로드·비공개 사진, 원격 실행 코드, 동적 이미지 변환 서버, 전 이미지 WebP 전환, 지도 통행/배치 계약 변경, 개인정보가 포함된 캐시, 즉시 원격 삭제 보장, 모든 원본 이미지의 오프라인 선탑재.
