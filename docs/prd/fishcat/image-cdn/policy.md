## 삭제 우선순위

소유 작업 없는 임시 파일 → 미사용 손상/비호환 팩 → 보존 7일이 지난 직전 버전 → 30일 미사용 팩 → 나머지 미사용 팩 LRU(7일 이내 직전 버전 포함). lease가 있는 팩은 건너뛴다. 어떤 보존 팩도 참조하지 않는 객체만 실제 삭제한다. 다 쓰는 화면을 지워 억지로 용량을 맞추지 않는다.

30일 정리는 앱 시작/복귀 후, 24시간에 한 번으로 제한한다. 용량 정리는 새 다운로드의 예산 예약 직전에 필요할 때 수행한다. 설치 중 백그라운드 서비스를 실행하지 않는다. wall clock의 비정상 이동은 한 번의 확인/정리를 허용하되 열린 화면을 절대 삭제하지 않는다.

## 한도와 장애 기본값

네트워크 다운로드 동시성 2. 채널 최대 16KiB, 릴리스 manifest 최대 1MiB, 파일 최대 16MiB, 팩 최대 32MiB, 팩당 파일 최대 128개, 릴리스 최대 512개 팩/4096개 파일. 이미지는 한 변 최대 4096, 면적 최대 16,777,216 pixels. 이 기본값을 넘는 원본은 조용히 축소하지 않고 빌드 실패 후 분할/예산 검토한다.

채널/manifest 요청 제한 10초, 이미지 파일 전체 제한 60초(진행 여부와 독립). 네트워크 단절/5xx/해시 불일치는 1회 추가 시도, 403/404/스키마 오류는 해당 시도 즉시 종료 후 백오프. 잘못된 팩을 성공으로 표시하지 않는다. 디코드 불량 SHA는 로컬 불량 집합에 기록하고 다른 해시의 정상 릴리스 또는 명시적 캐시 초기화 전에는 반복 활성화하지 않는다. 임시 통신 실패는 영구 불량 해시로 기록하지 않는다.

## 롤아웃과 호환

호환 식별자 `assetApiVersion`은 숫자 `1`부터 시작한다. 채널은 환경/호환 세대별 분리한다. 앱/OTA 코드가 새로운 호환 세대를 요구하면 콘텐츠 선배포 후 앱을 공개한다. URL/파일명/해시 불변성 때문에 CDN 캐시와 기기 캐시를 구분할 수 있어야 한다.

기존 꾸미기 카탈로그는 1시간 메모리 캐시와 별도 실패 백오프를 유지한다. 본 문서의 6시간은 CDN 채널 확인에만 적용하며 구매/장착/권한/외양의 최신성 정책을 바꾸지 않는다.

비용/속도/메모리 측정으로 숫자를 바꾸는 경우 결정 근거와 기기·코드 SHA·측정값을 남긴다. 원본 공개 취소를 즉시 보장해야 하는 요구가 생기면 별도 폐기 정책을 만든다.

## 네이티브 제한과 metadata 복구

파일 쓰기 상한·취소 deadline·증분 SHA-256은 네이티브 모듈에서 적용한다. JS progress callback이나 timer는 하드 상한의 근거가 아니다. snapshot 생성 중 bytes도 256MiB 예산에 예약한다. 논리 용량은 파일 내용 bytes이며 파일시스템 블록 오버헤드·다른 프로세스의 저장 공간 사용은 포함하지 않으므로 OS 쓰기 실패를 별도 처리한다.

metadata는 기존 파일 덮어쓰기 대신 digest가 붙은 증가 seq의 불변 snapshot으로 저장한다. 최신/직전 검증 snapshot과 그 참조 객체를 보존해 중간 종료를 복구한다. 채널·manifest 성공 상태와 팩 수신 실패는 별도 관리하며, 팩 실패 후 백오프 만료 기회에는 채널 6시간 제한을 우회해 롤백을 다시 확인한다. 채널 성공만으로 같은 팩 수신 실패 횟수를 초기화하지 않는다.

새 모듈을 포함한 Android/iOS 바이너리 선배포가 필요하다. 구 바이너리로 새 native 호출을 보내는 OTA는 금지한다.

최신 active 팩의 객체 일부가 사라졌다면 온전한 직전 호환 팩의 lease를 먼저 사용하고, 그것도 없을 때 번들로 대체한다. 부팅 시 손상된 파일까지 포함해 식별 가능한 최대 seq보다 큰 번호로 다음 snapshot을 쓴다. GC는 후보 사이에 잠금을 풀어 화면 lease 획득을 장시간 막지 않는다. 열린 lease는 7일을 지나도 삭제하지 않는다.
