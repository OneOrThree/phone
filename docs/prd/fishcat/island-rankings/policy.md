## 결정된 것 (2026-09-21)

| ID | 결정 | 근거 |
| --- | --- | --- |
| RK-D01 | **분모 = 그 섬 «전체 주민 수»**(활성 멤버십 + 미탈퇴 계정 — `countByGroupIdIn` 과 같은 모수). **산정 시점은 「주가 끝난 시점」으로 동결**한다. 진행 중인 주는 아직 동결할 것이 없어 지금 인원으로 나눈다 | 기획 정본 「평균 = 해당 섬에서 집중한 시간 합계 ÷ 해당 섬 전체 주민 수」 + 2026-09-21 재영님 확정. 동결하지 않으면 **주민을 내보내는 것만으로 지난 주 평균이 오른다**(강퇴 조작). `group_members` 는 (user, group) 한 행이고 `left_at` 이 없어 사후 복원이 불가능하므로 표로 동결한다 — **migration V85 `island_weekly_member_counts`** |
| RK-D01-기준시각 | **동결의 기준은 크론이 «실행된» 순간이 아니라 그 주의 «종료 경계»(다음 주 시작 00:00Z)다.** 가입은 `created_at < 경계` 로 걸러 경계 이후 가입자가 지난 주 분모에 섞이지 않게 한다. **이탈 방향은 쿼리로 닫을 수 없다** — `group_members` 에 이탈 시각이 없고(`left_at` 부재), `updated_at` 은 알림 토글에도 갱신돼 증거가 아니며, `created_at` 은 `rejoin()` 이 갱신하지 않아 «최초» 가입 시각이다. 대신 **실행 유예**(`ranking.freeze.grace`, 기본 1시간)를 넘긴 실행은 **아무것도 쓰지 않는다** — `ON CONFLICT DO NOTHING` 이 첫 값을 영구 고착시키므로, 늦게 돈 배치가 「하루치 이탈이 반영된 인원」을 그 주의 정답으로 굳히는 쪽이 더 나쁘다 | 2026-09-21 PR #861 codex P1. 잔여 창은 RK-D12 |
| RK-D01-결손 | **끝난 주에 동결 행이 없는 섬은 랭킹에서 «빠진다».** 「없으면 지금 인원으로」 라는 대체 경로를 두지 않는다 | 대체 경로가 있으면 동결이 막으려던 조작이 그대로 살아난다. 조용히 틀린 순위보다 비어 있는 순위가 낫다 |
| RK-D02 | **동점은 공동 순위** — 1,1,3(SQL `RANK()`). 다음 순위는 건너뛴다. UUID 오름차순은 같은 점수 안의 «표시 순서»만 고정하는 보조 키이며 순위를 가르지 않는다 | 2026-09-21 재영님 확정 |
| RK-D03 | **끝난 집중만 반영한다** — 진행 중(ACTIVE·PAUSED) 세션은 정렬·표시·`myRank` 어디에도 넣지 않는다 | 2026-09-21 재영님 확정. `lifecycle = COMPLETED` |
| RK-D05 | **섬 귀속 = 세션이 시작할 때 고정한 `focus_session_details.island_id`.** 다른 섬에서 집중한 시간은 이 섬 분자가 아니다 | 2026-09-19 결정 RC-D01 과 같은 축. 기획 정본 「다른 섬에서 집중한 시간은 제외한다」 |
| RK-D06 | 평균 = **정확한 초 합 ÷ 분모를 정수로 내린 값**이고, **그 정수가 곧 정렬 키**다 — 표시값과 순위 기준이 같아야 「화면에는 같은 숫자인데 순위가 다른」 줄이 생기지 않는다. 분모가 없거나 0 이면 그 섬은 참가가 아니다(0점으로 만들지 않는다) | 2026-09-21 구현 결정 |
| RK-D07 | **페이지를 만들지 않는다** — 상위 `limit` 개(기본 30, 최대 100)만 싣고 `nextCursor` 는 언제나 `null` 이다. 목록에서 잘린 사용자는 `myRank` 로 자기 섬 순위를 **전체 모집단** 기준으로 받는다 | 움직이는 집계에 keyset 을 붙이면 페이지 사이에 행이 빠지거나 겹치는데(LLD §4), 페이지가 없으면 그 문제 자체가 없다. 선례 RC-P12-적용(회관 기록 scope=island) |
| RK-D08 | **불변 snapshot 저장소·사용자 역색인·공통 lifecycle 잠금을 만들지 않는다** | 응답이 섬 이름과 평균 초뿐이라 지킬 타인 PII 가 없다. 2026-09-19 RC-P12-적용이 회관 기록에서 내린 같은 판단 |
| RK-D09 | **참가 모집단 = 그 주에 그 섬 귀속 완료 집중이 있었던 섬.** 집중이 0인 섬은 줄 세우지 않고, 그런 섬의 `myRank` 는 `null` 이다 | 0점 참가를 지어내지 않는다(RK-D06 과 같은 결). 모수가 집계 결과라 이어지는 분모·이름 조회도 유한하다 |

## 남은 미결

| ID | 미결 | 비고 |

| RK-D04 | 지난 주의 **늦은 finish 수용 창**. 지금은 분자를 집중 정본에서 «항상 다시» 계산하므로, 주 경계를 걸친 세션이 늦게 끝나면 지난 주 합이 그만큼 늘어난다(분모는 동결이라 움직이지 않는다). cutoff 를 둘지, 둔다면 언제인지는 미결 | 분모 동결과 달리 분자는 복제하지 않았기 때문에 생기는 창이다. 복제하면 정본과 어긋나므로 지금 구조가 더 안전하다 |
| RK-D10 | **`myRank` 를 공개 계약에 올린 것**은 원본 `/rankings/islands` JSON 에 없던 필드다(`asOf` 와 같은 승인된 추가로 취급). 목록을 상위 N 으로 자르는 대신 자기 순위를 알려 주기 위해 넣었다 — 기획 확인 필요 | RK-D07 과 한 쌍이다. `myRank` 를 뺀다면 페이지가 다시 필요해진다 |
| RK-D11 | **과거 주의 공개 범위**. 지금은 「아직 오지 않은 주」만 422 로 막고 과거는 제한하지 않는다(동결 행이 없는 주는 자연히 빈 결과다). 보존 기간을 둘지는 미결 | |
| RK-D12 | **동결의 잔여 창 — 「경계 ~ 배치 실제 실행」 사이의 «이탈»은 지난 주 분모에 반영된다.** 이탈 시각이 DB 에 없어서 생기는 구멍이고, 지금은 유예(기본 1시간)로 «시간»을 좁혔을 뿐 닫지는 못했다. 크론이 제때 돌면 창은 초 단위다. 완전히 닫으려면 `group_members` 에 **이탈 시각 컬럼**(+ `rejoin()` 이 갱신하는 가입 시각)이 필요하며, 그것은 소속 도메인의 별도 변경이다 — 이 티켓에서 코어 테이블을 바꾸지 않았다 | 후속 티켓 필요. 없는 근거를 지어내지 않는다 |

비적격 `eligibility` enum·섬 썸네일 DTO 는 **주민 랭킹과 함께 사라졌다** — 섬 간 랭킹 응답에 `eligibility` 필드가 없다.
