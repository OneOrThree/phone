# PRD — 섬 이동 서버

상태: 구현 전 제안. 정책 구분은 [policy.md](policy.md), 설계는 [HLD](high-level-design.md)를 따른다.

## 1. 배경과 목표

현재 앱의 섬은 원화 위에 시설·식물·캐릭터를 올리고 로컬 A*로 이동을 연출한다. 앱마다 위치를 계산하므로 실제 주민이 같은 장소에서 함께 움직이는 정본은 없다. 서버가 통행 맵과 실제 위치를 소유하고, 앱은 입력 즉시 반응하면서 서버 상태에 수렴해야 한다.

첫 사용자는 섬의 활성 주민이다. 주민은 빈 땅이나 길을 눌러 이동하고, 다른 주민의 이동을 볼 수 있다. 운영자는 방·맵 버전·연결 상태로 문제를 추적한다. 후속 게임은 동일한 이동 엔진에 별도 맵과 이동 규칙을 등록한다.

## 2. 범위

**1차 구현:** 공통 좌표, 맵 배포, 주민 입장 인증, 목적지 이동, 양쪽 A*, 20Hz 서버 시뮬레이션·전송, 경로 보정, 실제 주민 표시, 네트워크 복구, 관측과 단계적 활성화.

**후속 범위:** 전투·물리 충돌, 주민끼리 밀기·길 막기, 전역 오픈월드, 이동 자체의 보상, 영속적인 마지막 위치 저장, 방문자의 실시간 관전, 웹 브라우저용 WebTransport. 다중 게임은 인터페이스를 분리하고 합성 맵으로 독립성을 검증하는 수준까지다.

기존 건물 화면 진입·재화·집중 세션의 권한은 기존 API를 따른다. 이동 완료 이벤트만으로 시설 권한이나 보상을 발급하지 않는다. 건물 접근 후 화면을 여는 연출은 확정 도착 이후 연결할 수 있지만, 기존 API 권한을 대체하지 않는다.

## 3. 기능 요구사항

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| MV-01 | 공통 100×100 좌표 | 화면 크기·카메라 확대와 관계없이 같은 지점을 탭하면 같은 월드 좌표가 된다. 왕복 양자화 오차는 축당 0.005 이하 |
| MV-02 | 서버 맵 정본 | 서버와 앱이 같은 mapVersion/layoutRevision/navRevision을 사용한다. 불일치 시 명령을 거부하고 동기화한다 |
| MV-03 | 입장·권한 검사 | 유효한 해당 섬 활성 주민만 입장한다. 만료·다른 방·재사용 티켓은 거부한다 |
| MV-04 | 서버 A* | 출발점은 서버 위치다. 벽·바다·대각선 모서리를 통과하지 않으며 도달 불가능한 목적지는 같은 연결 영역의 가장 가까운 유효점으로 조정한다 |
| MV-05 | 클라이언트 A* | 유효 맵이 있으면 탭 직후 예측한다. 서버 응답의 경로가 다르면 서버 경로에 수렴한다 |
| MV-06 | 서버 주도 이동 | 서버 속도로 50ms마다 경로 위 위치를 전진시킨다. 클라이언트의 위치·시간·속도 조작으로 빨라지지 않는다 |
| MV-07 | 부드러운 표시 | 내 캐릭터는 예측·보정, 다른 주민은 지연 버퍼로 경로를 보간한다. 장애물 모서리를 가로질러 보간하지 않는다 |
| MV-08 | UDP·20Hz·바이너리 | 혼잡 없는 활성 방에서 초당 20개 시뮬레이션 틱과 좌표 전송 기회를 제공한다. 작은 정수 패킷으로 전송한다 |
| MV-09 | 양방향 전송 보호 | 인증서 검증, 암호화·무결성, 앱 계층 중복 거부를 검증한다. 상태 변경 0-RTT는 받지 않는다 |
| MV-10 | 빠른 목적지 변경 | 최신 commandSeq가 우선한다. 이전 A* 결과·응답·패킷이 새 경로를 덮어쓰지 않는다 |
| MV-11 | 복구·상실 처리 | 재접속은 새 세션으로 전체 상태를 받는다. 강퇴·로그아웃은 권한 갱신 실패 또는 취소 통지로 이동·구독이 종료된다 |
| MV-12 | 맵 변경·서버 분리 | 배치 변경 시 새 통행 맵으로 원자 전환하고 경로를 재검증한다. 별도 서비스가 여러 방을 처리하며 한 방의 확정 작성자는 하나다 |
| MV-13 | 진단 가능성 | 요청→경로→틱→보정을 gameId/roomId/roomEpoch/commandSeq/pathId/navRevision으로 추적한다. 인증 비밀은 로그에 남기지 않는다 |

## 4. 사용 시나리오

1. **길 선택:** 주민이 길을 누르면 즉시 걷기 시작한다. 서버가 도착점을 확정하고 다른 주민에게도 같은 이동을 보낸다.
2. **바다·건물 선택:** 서버는 도달 가능한 가장 가까운 통행점 또는 건물의 유효 진입점을 고른다. 물 위로 순간 이동하지 않는다.
3. **다른 곳 재선택:** 새 목적지로 경로를 교체한다. 늦게 온 옛 명령은 캐릭터를 되돌리지 않는다.
4. **네트워크 지연:** 잠깐의 손실은 보간한다. 오래 좌표가 오지 않으면 이동을 멈추고 연결 상태를 표시한다. 복구 시 서버 위치를 따른다.
5. **시설 완공:** 충돌체가 달라지면 경로를 재계산한다. 새 건물 내부에 갇힌 캐릭터는 지정된 안전 지점으로 재배치하고 이를 명시적으로 전달한다.
6. **강퇴·접속 종료:** 해당 방의 위치를 더 받을 수 없다. 다른 주민에게 퇴장이 전달된다.

## 5. 비기능 목표 — 측정 후 조정할 초기 제안

| 항목 | 초기 수용 목표 / 측정 조건 |
| --- | --- |
| 로컬 반응 | 지원 기준 기기에서 탭→첫 표시 갱신 p95 ≤ 50ms. 네트워크 시간을 제외한 클라이언트 지표 |
| 서버 경로 | 현행 96×64 통행 맵에서 A* 실행 p95 ≤ 5ms, 명령 대기 포함 확정 처리 p95 ≤ 20ms |
| 틱 | 50ms 고정 스텝, 처리 시간 p99 ≤ 25ms. 50ms 초과율 < 0.1% |
| 초기 부하 | 합성 100개 방 × 15명 = 1,500연결, 이동 명령 평균 1회/초/명, 30분. 실제 섬 정원 변경을 뜻하지 않음 |
| 기준 자원 | 전용 Linux 4 vCPU / 8GiB worker 1개에서 위 부하 측정. CPU 지속 70% 이하·메모리 6GiB 이하를 증설 여유 목표로 설정; 실측 전 수용량 보장 아님 |
| 네트워크 | RTT 100ms, 지터 ±30ms, 손실 2%, 중복·역순 주입에서 벽 관통·권한 우회 0건 |
| 표시 지연 | 다른 주민 보간 버퍼 시작값 100ms. RTT 포함 지연 분포·보정 거리·배터리를 실기기 측정해 튜닝 |
| 회복 | 연결 가능 네트워크로 돌아온 후 정상 재입장 p95 ≤ 3초, worker 장애 후 p95 ≤ 10초를 실험 목표로 설정 |
| 데이터 보호 | 잘못된 패킷·권한·세대 입력은 상태 변화 0건. 정상 사용자와 다른 방의 위치 유출 0건 |

20Hz는 네트워크 수신 보장이나 화면 프레임률이 아니다. 혼잡 시 오래된 스냅샷은 버리고 최신 상태를 보낸다. 무제한 큐로 전송 횟수를 맞추지 않는다.

## 6. 출시 게이트

- [검증 표](validation.md)의 좌표·A*·프로토콜·장애·보안 시나리오를 통과한다.
- iOS와 Android 실제 기기에서 네이티브 전송, 앱 복귀, Wi-Fi/셀룰러 전환을 검증한다.
- 정책의 미정 항목과 아키텍처 직접 연결 예외를 확정한다.
- 사내 섬 → 제한된 사용자 → 점진 확대 순으로 켠다. 네트워크 기능은 앱 버전별 기능 플래그로 제어한다.
- 롤백 시 실제 주민 동기화·이동 연결을 끄고 기존 로컬 연출로 복귀한다. 로컬 장식 고양이를 실제 접속자로 표시하지 않는다.
