# 정책·설계 결정

작성: 2026-09-23. 사용자 요구의 범위는 [제품 결정 로그의 MV-방향](../decision-log.md)에 기록한다. 아래 추천값은 제품 확정이나 아키텍처 승인으로 간주하지 않는다.

## 1. 요구와 제안의 구분

| 구분 | 내용 | 상태 |
| --- | --- | --- |
| 사용자 요구 | 100×100 절대 기준, 클라이언트·서버 A*, 서버 맵·경로·좌표, 전용 서버, UDP 약 20Hz, 양방향 보호·작은 바이너리 검토 | 설계 입력 |
| 좌표 해석 | 좌표 범위 `[0,100]²`, 통행 격자 해상도 별도 | 확인 중. 정확히 10,000셀 요구라면 맵 재생성·좁은 길 회귀 검증 필요 |
| 전송 | QUIC + DATAGRAM, 명령은 reliable stream | 추천. 모바일·부하 POC 통과 전 기술 확정 아님 |
| 구현 스택 | Go + quic-go 서버, 모바일 quiche 기반 네이티브 어댑터 후보 | POC 출발안. 기존 Java 서비스에 무조건 추가하지 않음 |
| 서비스 경계 | Business 인증·입장 티켓, Movement 직접 UDP, Data에 코어 데이터 유지 | 기존 직접 연결 규칙에 대한 예외 검토 필요 |
| 제품 영향 | 방문자 실시간 위치 미제공, 주민 충돌 없음, 장애 시 입구 복귀 | 1차 범위 추천. 기능 활성화 전에 제품 확인 |

## 2. 권한·생활주기 추천

- 입장은 기존 섬 활성 소속과 현재 섬 컨텍스트를 Business가 검사한다. 선택하지 않은 다른 섬의 위치 구독을 열지 않는다. 섬 전환은 기존 전환 규칙을 먼저 통과한다.
- 방문자는 기존 공개 요약만 본다. 실시간 주민 위치·경로는 공개 요약에 추가하지 않는다.
- 동일 사용자·방에서 움직이는 actor는 하나다. 재접속 또는 다른 기기의 새 세션은 기존 이동 세션을 대체한다. 계정 전체의 복수 기기 정책은 변경하지 않는다.
- 배경 전환 시 앱은 일시 정지를 알리고 연결을 닫는다. 통지가 유실되어도 liveness 만료로 서버가 멈춘다. 재개는 새 티켓·전체 동기화로 시작한다.
- 영속 위치는 1차 범위 밖이다. 방 재생성·소유자 장애·세션 만료 후에는 서버가 검증한 입구에서 재입장한다. 이 정책이 불가하면 체크포인트 소유·저장소·복구 계약을 추가한 후 출시한다.
- 도착은 서버가 판정한다. 시설의 기존 REST 권한·집중 세션·재화 처리는 위치 서버가 수행하지 않는다.
- 주민 간 충돌은 없고 정적 지형·시설과 캐릭터 반경만 통행에 반영한다.

## 3. 초기 파라미터 제안

| 파라미터 | 값 | 목적 |
| --- | --- | --- |
| 시뮬레이션 / 방송 | 20Hz / 최대 20Hz | 고정 50ms 이동 스텝, 혼잡 시 방송 생략 가능 |
| 좌표 정밀도 | 0.01 world unit | uint16의 0..10000 사용 |
| 보간 / 외삽 한도 | 100ms / 100ms | 원격 주민의 흔들림과 무한 이동 방지 |
| 명령 제한 | 사용자당 초당 10개, 순간 20개 | 탭 폭주 방지. 적용 대기 명령은 actor당 최신 1개 |
| 입장 티켓 | 발급 후 30초 이내 1회 사용 | audience·방·사용자·jti·권한 버전 결합 |
| 권한 lease | 10초, 3초마다 Business가 갱신 push | 제어 경로 단절 시 무기한 권한 유지 방지 |
| liveness | 양방향 heartbeat 1초, 인증된 수신 부재 3초 | 멈춘 앱의 이동 정지·퇴장 |
| 방 소유 lease | 3초, 1초마다 갱신 | 소유권을 잃으면 틱·송신 중단 |
| 패킷 상한 | 앱 payload ≤ 1000B 및 협상된 DATAGRAM 한도 이하 | 단편화 회피. 더 작은 실제 한도가 우선 |

권한 lease와 소유 lease는 목적이 다르다. 강퇴 이벤트를 받으면 즉시 종료하고, 누락되어도 권한 lease가 마지막 정상 갱신 후 최대 10초 이내 만료되도록 한다. 강퇴 커밋 직후 모든 망에서 즉시 단절된다는 보장은 아니다. 이 지연 허용 여부는 출시 게이트다. 전송 중이던 이전 권한 갱신은 원래 만료 시각을 보존하며 수신 시점 기준으로 연장하지 않는다.

## 4. 열려 있는 결정

| ID | 결정 주체 | 닫는 시점·방법 |
| --- | --- | --- |
| MV-D01 | 제품 | 100×100 좌표/셀 의미를 맵 변환 착수 전에 확정 |
| MV-D02 | 아키텍처 담당 | 직접 UDP 공개 면, 제어 경로, 데이터 소유를 정식 A 결정으로 기록한 후 네트워크 배포 |
| MV-D03 | 클라이언트·서버 | quic-go ↔ quiche 상호 운용·기기 테스트·처리량 결과로 라이브러리·버전 고정 |
| MV-D04 | 제품·운영 | 동접·지역·비용, 권한 취소 최대 지연, 입구 복귀·다중 기기 대체를 출시 전 확정 |
| MV-D05 | 클라이언트·디자인 | 월드 속도·반경과 비정방형 원화의 체감을 실기기에서 조정. 탐색 metric은 서버와 동일하게 유지 |

결정이 바뀌면 제품 항목은 제품 결정 로그, 서비스 경계·인증·저장소 항목은 아키텍처 결정 장부를 먼저 갱신하고 이 문서에 전파한다.
