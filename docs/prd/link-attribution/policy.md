| L12 | 앱은 **첫 실행에 Install Referrer 를 로컬에서 읽어** 출처가 LINK · META · GOOGLE 이면 fingerprint 매치를 건너뛴다(LINK 는 `/l/resolve` 로 초대 시트·목적지를 연다). ORGANIC · UNKNOWN · 읽기 실패면 기존 매치를 시도한다. **로컬 판별은 서버 판별(LLD §4.1)과 같은 규칙·같은 순서**다(META 는 `utm_content` JSON 에 `source.data`·`source.nonce` 가 둘 다 있을 때만). 그래도 세션 뒤 `/l/referrer` 응답이 UNKNOWN·ORGANIC 인데 그 설치에서 매치를 아직 안 했으면 그때 `/l/match` 를 1회 부른다. ORGANIC·UNKNOWN 응답의 `attributionId` 는 보관하지 않는다. **이 기능이 들어간 버전으로 업데이트한 설치**(Android `firstInstallTime < lastUpdateTime`)는 Play 가 돌려주는 과거 referrer 로 `/l/resolve` 화면 이동과 `attributionId` claim 을 하지 않고 저장만 한다 — `/l/resolve` 1회 이동은 새로 설치한 경우만이다. 서버 저장(`/l/referrer`)은 세션 확보 뒤 — 로그인·게스트 시작 직후와 **콜드스타트 세션 복원 성공 직후** 두 지점 — 에 한다(L23) | 결정적 신호가 확률 매치보다 우선이다. 랜딩을 거쳤는데 referrer 가 안 남은 경우(스토어 직접 검색 등)는 fingerprint 가 받는다. 판별을 저장 응답에 기대지 않으므로 로그인 전에 토큰이 없어도 초대 시트가 늦지 않는다. 앱이 서버보다 느슨하게 META 로 판정하면(예: `source.nonce` 만 있음) 매치를 건너뛴 뒤 서버는 UNKNOWN 으로 저장해 fallback 귀속을 영구히 잃으므로 규칙을 맞추고, 어긋남이 생겨도 저장 응답으로 한 번 더 받친다 |
| L13 | 캠페인 링크의 목적지는 **`gromo://` 스킴의 허용 경로 목록 안에서만** 고른다. 자유 입력을 받지 않는다 | 콘솔 입력이 그대로 앱 네비게이션이 되기 때문이다. 목록은 앱 라우트를 추가하는 앱 PR 과 같은 시점에 서버 상수로 갱신한다 |
| L14 | 폐기된 링크의 랜딩은 스토어 버튼만 보여주고 **클릭을 기록하지 않는다.** referrer 귀속 대상이 아니다 — referrer 저장도 링크 쪽 행을 잠근 뒤 활성을 재검증해, 그 사이 폐기·보관되면 UNKNOWN 으로 남긴다. 매치에서는 최신 후보로 잡혀도 소진만 하고 `matched:false` 로 끝내며, **더 오래된 다른 후보로 내려가지 않는다** | 기본값 채택. 이미 뿌린 게시물의 방문자가 막다른 길을 만나지 않게 한다. 후보 조회를 활성 조건으로 먼저 거르면 폐기된 최근 클릭 뒤의 과거 클릭이 엉뚱한 기기에 붙는다 — 현행 `InviteLinkMatchService` 도 같은 이유로 최신 후보를 고정한다 |

| L16 | **콘솔 = business-api 안 Thymeleaf 서버 렌더링.** 팀원별 비밀번호 슬롯 + 서명 쿠키, 실패 잠금·폼 토큰은 Redis. DB 테이블 없음. 2차 비밀번호 없음 | 사용자 2~4명 · 화면 3장 · 폼과 표뿐이다. React 빌드는 Gradle CI 에 Node 툴체인을 끌어들인다. 알림 콘솔은 같은 `/console/**` 인증에 나중에 붙는다(이번 범위 밖) |
| L17 | 개인정보: 원본 IP 는 저장하지 않는다(현행) — **레이트리밋·로그인 잠금의 Redis 키도 원본 IP 대신 business-api 전용 비밀로 HMAC 한 값**을 쓴다. `link_clicks`·`install_referrers` 의 `claimed_user_id` 와 `install_referrers.reporter_user_id` 는 **탈퇴 트랜잭션에서 NULL** 로 만들고, claim·referrer 저장 모두 유저 행 배타 락으로 탈퇴(배타 락)와 직렬화한다(유저 활성 조건은 `users.is_deleted = false`). claim 은 요청자 행을 따로 먼저 잠그지 않고 **관련 user(요청자·INVITE 발급자)를 UUID 오름차순으로 한꺼번에** 잠근 뒤 group·membership 또는 campaign → link 순으로 잠근다(교착 방지, LLD §2.5). 익명화는 `claimed_user_id` 만 지우고 `claimed_at` 은 남기며, **미claim 판정은 `claimed_at IS NULL`** 이라 탈퇴 뒤 다른 계정이 같은 클릭·referrer 를 재선점하지 못한다. SKAN 포스트백에는 기기·유저 식별자가 없다 | A22 ⓐ 의 익명화 요구를 같은 트랜잭션으로 닫는다. TTL 이 있어도 Redis 키에 적힌 동안은 원본 IP 저장이다. 락이 없으면 탈퇴의 UPDATE 뒤·커밋 전에 끼어든 claim·referrer 저장이 연결이나 `reporter_user_id` 를 남긴다 |
| L18 | `/l/match`·`/l/referrer`·`/l/resolve` 는 **결과가 없으면 200 `{matched:false}`**(`/l/referrer` 는 `source` 를 함께 싣고, `/l/resolve` 는 없는 slug 면 404), **data-api 오류·타임아웃은 503 + `Retry-After`**, **레이트리밋은 429** 로 응답한다. `/l/referrer` 는 `installId` 가 없으면 400(미저장), 토큰이 없으면 401, 유저당 KST 당일 저장 상한을 넘으면 429(미저장), 저장 도중 탈퇴한 유저면 200(미저장·`attributionId` 없음)이다. SKAN 수신은 **서명을 통과한 우리 앱 포스트백만 저장**하고, 서명 실패·모르는 버전·다른 앱은 저장 없이 200(건수만 셈), 본문 16KB 초과는 413, 인스턴스당 동시 서명 검증 상한(32건) 초과는 503 + `Retry-After`(과부하 보호용), 저장 실패는 5xx 다. **SKAN 경로에는 IP·엣지 레이트리밋을 두지 않는다** | 현 앱 `deferredInvite.matchOnce` 는 2xx 일 때만 완료 플래그를 세우고 오류·타임아웃이면 다음 실행에 다시 묻는다(`deferredInvite.ts:94-108`) — 일시 장애를 200 으로 접으면 귀속이 영구 유실된다. 같은 이유로 `installId` 누락을 200 미저장으로 두면 앱이 완료로 저장해 다시 보내지 않으므로 400 으로 알린다(새 엔드포인트라 보내지 않는 구 앱이 없다). SKAN 경로는 무인증이라 서명 실패까지 저장하면 누구나 DB 를 채울 수 있다. 저장 실패는 Apple 의 재전송에 기대지 않고 로그로 잡는다. 포스트백은 개별 기기가 아니라 Apple 이 여러 설치 분을 서버 간으로 보내 발신 IP 가 사용자 식별자가 아니므로, IP 한도는 캠페인이 커질 때 유효한 포스트백을 서명 검증 전에 잘라 과소 집계한다 |
| L20 | 스키마는 **expand / contract** 로 나눈다. expand 동안 **V21 전체 unique 를 유지하고 링크 폐기·재발급을 켜지 않는다.** 기존 ACTIVE 초대 링크 **전부**의 `REVOKED` 보정(재가입 이력 증명 불가) · 부분 unique 교체 · 폐기·재발급 활성화 · 테이블 rename · V52 링크 테이블 DROP 은 공개 경로 전환이 안정된 **마지막 단계**(contract)에서 한 배포로 하고, 그 전 단계는 모두 이전 이미지로 되돌릴 수 있게 한다. **contract 자체는 roll-forward 전용**이다 | prod `ddl-auto: validate` 라 rename 직후 이전 이미지는 기동하지 못한다. 이전 이미지는 `findByGroupIdAndInviterId` 로 상태 조건 없이 단건을 읽어, 폐기 행과 새 활성 행이 공존하면 다건 예외를 내거나 폐기된 slug 를 유효하게 돌려준다. 현 prod 에도 폐기가 없어 expand 기간은 현행보다 나빠지지 않는다. contract 이미지가 재발급을 한 번만 해도 같은 쌍에 행이 둘 이상 생겨 전체 unique 를 되살릴 수 없으므로 이전 이미지 복구를 보장하지 않는다. 장애는 핫픽스로 앞으로 고치고, 최후 수단은 contract 직전 RDS 스냅샷(그 뒤 쓰기 손실)이다. 기존 초대 링크를 전부 폐기하는 이유: `GroupMember.rejoin()` 은 기존 행을 되살려 `is_left=false` 로 돌리고 재가입 시각 컬럼이 없으며, V52 의 `membership_epoch` 도 링크에 발급 당시 값이 없어 링크가 이탈·재가입보다 앞섰는지 증명할 수 없다 — 현재 상태만 보는 보정은 이탈 전에 공유된 slug 를 비공개 가입 자격으로 남긴다. 대가로 contract 시점에 공유된 초대 링크는 모두 만료된다 |
