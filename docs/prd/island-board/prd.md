# 게시판 공지·댓글 — PRD

[정책](policy.md) · [HLD](high-level-design.md) · [LLD](low-level-design.md)

새 화면은 6개 계약을 사용한다. 기존 서버의 비슷한 이름을 그대로 연결하면 권한·정산·중복 제거의 의미가 달라진다. 목표는 원본 스키마와 기존 동작을 대조해 구현 가능한 경계와 남은 제품 결정을 남기는 것이다.

## 범위와 완료 조건

- [ ] [원본 6계약](source-contracts.json)의 모든 요청/응답과 LLD의 명시 확장·오류를 구현한다. 내부 호출은 화면 API 수에 더하지 않는다.
- [ ] 신규 무접두어 Business ingress, 검증한 주체 위임, 현재 사용자/주민/시설/역할 인가를 적용한다.
- [ ] 변경의 원자성과 중복 재시도·버전·커서·수신 권한 회수·개인정보 파기를 검증한다.
- [ ] 로그에 requestId·작업 단계·안전한 결과코드를 남기고 토큰/본문/프로필을 기록하지 않는다.
- [ ] 정책 문서의 미답 출시 조건을 해결하고 실제 서비스 간 실패/경합 테스트를 통과한 뒤 활성화한다.
- [ ] 기존 공개 경로·응답·의미의 회귀를 확인한다. 현재 설계 파일 작성으로 구현 완료를 체크하지 않는다.

공통1750/이벤트1754와 연결하되 BFF13개는 각 재료 기능 뒤에 구현한다. 세부 수용 사례는 LLD 마지막 절에 있으며 새 제품 정책을 샘플 값으로 대신하지 않는다.
