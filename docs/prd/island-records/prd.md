# 회관 기록 요구사항

주민이 회관에서 주/월 기록과 나/섬 전체를 바꾸어 집중 시간과 스크린타임을 확인한다. 집중 시간에는 실제 집중한 ACTIVE 구간만 들어간다. 측정이 없다는 사실은 사용량0과 다르므로 빈 측정은 숫자로 채우지 않는다.

| API | 사용자 결과 |
| --- | --- |
| GET `/islands/{islandId}/statistics/focus` | 기간 집중 합·일별 그래프·본인 상세 또는 공개 주민 집계 |
| GET `/islands/{islandId}/statistics/screen-time` | 본인 또는 주민별 측정 상태·사용량·갱신 시각 |
| PUT `/me/screen-time/{date}` | 본인 기기·KST 날짜의 실제 측정 보고를 중복 합산 없이 저장 |

두 회관 GET은 현재 소속과 회관 시설이 필요하다. scope=island는 주민 집계이며 주민의 과목/상세 세션 기록을 공개하지 않는다. 측정 PUT은 본인 권한으로 수행하고 회관이 없다고 기기 원본 저장을 막는 계약을 만들지 않는다.

티켓의 “OS 미연동”은 현재 신규 화면의 목업 상태 설명이다. 기존 iOS에는 DeviceActivity의 실제15분 눈금 측정과 서버 전송이 있다. 다만 선택 앱/카테고리/도메인 범위·900분 상한·근사치이며 완전한 기기 전체 사용량은 아니다. 새 API를 기존 daily upload의 필드 별명으로 구현하면 deviceId·measuredAt 순서·권한 상태·KST 날짜를 잃는다.

수용 조건: 날짜 포함 범위와 KST 반열림 창, 자정 ACTIVE 분할·휴식 제외, 전체 합과 페이지 분리, 측정0/null 구분, 기기별 내구 저장·역순/동일시각 경합·탈퇴 차단, 기존 경제 중복 지급0이다. 개인/섬 귀속과 복수기기 병합은 사용자 결정 전 확정하지 않는다. 이 두 결정과 측정 마감/불완전 기간 표시까지 정해져야 정책 완료 조건과 해당 공개 경로 출시가 충족된다.
