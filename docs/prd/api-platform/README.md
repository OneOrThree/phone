# 같이숲 공통 API 계약

GROMO-1750 · 작성 2026-09-12 · **설계 문서, 구현 완료 보고가 아님**.

신규 Business API의 접두어 없는 경로, JSON 봉투, 오류, 명령 재시도, 자원 버전, 커서, 화면 집계의 공통 경계를 정한다. 이후 구현 티켓 1751~1753과 도메인 설계가 이 계약을 사용한다.

## 원본 출처와 보존

원본은 관련 티켓 [1739](https://romance.atlassian.net/browse/GROMO-1739)의 화면별 스펙에 대응하는 로컬 다운로드 `GROMO-화면별-API-스펙.html`이다. 원문 자체가 **예상 계약**이라고 명시한다. 제공된 파일을 바이트 변경 없이 복사했다.

- 크기: **154,704 bytes**
- SHA-256: `2b56a4553d75863f1c1db50fd1c1f7123dd21ecf99bac4d38959ad945e9f9c30`
- 로컬 제공본과 이 복사본의 해시 일치를 검증했다. 원격 Jira 첨부를 다시 다운로드한 해시와의 동일성은 검증하지 않았다.
- 원문 `/v1/...`와 `POST /v1/islands/{islandId}/emotes`를 그대로 남겼다. 실제 채택 경로/전송은 [변경 대조표](policy.md#원본과-채택-계약-대조)에 따른다. HTML을 조용히 편집해 결정 이력을 지우지 않는다.

## 정본과 구현 기준점

사용자 명시 결정 → 기존 [아키텍처 결정 장부](../../architecture/decisions.md)·도메인 정책 → 이번 설계 → HTML의 예상 계약 순으로 읽는다. 제품 정책이 충돌하면 공통 API 문서로 임의 결정하지 않는다. 이 문서 세트 안에서는 `policy.md`가 우선한다.

조사 기준 main은 `529a396e5f0f88cb78c172110920e1fa6b9388a9`이다. 당시 Business는 미리보기 서비스이고, 1659의 내부 호출·명령 기반은 미통합 브랜치였다. [HLD의 재사용 경계](high-level-design.md#기존-코드와-통합-선행-조건)는 **이미 main에 있다는 주장과 구현 의존**을 구분한다.

이번 PR은 DB 마이그레이션·서비스 코드·운영 설정을 바꾸지 않는다. 66개 도메인 계약과 13개 BFF가 구현된 뒤 실제 코드·테스트·로그를 연결한 전체 시스템 학습 가이드를 이 디렉터리에 추가한다. 이 설계 문서를 그 최종 학습 가이드나 서비스 구현 완료로 계산하지 않는다.
