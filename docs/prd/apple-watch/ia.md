# 애플워치 컴패니언 — IA (정보구조·화면 설계)

> 정본 체인: `prd.md`(R1~R17) · `policy.md`(D1~D15) → **이 문서(화면·상태)** → HLD/LLD.
> PRD가 확정한 상태·계약을 화면 언어로 번역한다 — 여기서 새 정책을 만들지 않으며,
> 각 화면·상태 옆에 근거(R·D 번호)를 단다. 페이즈 구분은 PRD §6과 같다.
> 검토용 화면 시안(HTML 목업)은 티켓 1612의 아티팩트로 관리하고, 확정된 결정만 이 문서에 남긴다.

## 1. 구조 원칙

- **워치 UI는 상태 머신의 뷰다** — 폰 엔진(D2)이 SoT이고, 워치는 「마지막으로 받은 권위 스냅샷 + 로컬 앵커 틱」만 그린다(R4). 화면 전환의 주어는 사용자 내비게이션이 아니라 **스냅샷이 말하는 세션 상태**다.
- **루트 스왑, 스택 없음**: watchOS 루트 화면 하나가 세션 상태에 따라 교체된다(유휴 ↔ 미러 ↔ 완료). 뒤로 갈 곳이 없다 — 워치에서 「이전 화면」은 항상 현재 상태의 뷰로 되돌아오는 것.
- **미확정을 그린다**: 이 앱의 고유 난점은 성공/실패가 아니라 **모르는 상태**(전송 후 응답 유실, 단절)다. 「확인 중」 「종료 대기」 「동기화 필요」는 오류가 아니라 1급 화면 상태다(§4.2 응답 유실은 실패 확정이 아니다).

## 3. W3 미러의 모드별 변형

폰 세로 화면과 같은 의미론(특성화 스위트로 고정된 현행)을 축약 표현한다:

| 모드 | 큰 시간 | 보조 표시 | 비고 |
|---|---|---|---|
| 카운트업 | 경과 (증가) | 과목명 | 워치 발 시작은 이 모드뿐(D5) — 미러링은 3모드 전부 |
| 카운트다운 | **남은 시간** (감소) | 과목명 · 목표 | 폰과 동일하게 display 기준 — 경과 아님 |
| 뽀모도로 | 페이즈 남은 시간 | **세트 n / N** · 집중=과목명 / **휴식=「휴식」** | 페이즈 경계에 햅틱(로컬 예약 알림, R8-①) |

공통 오버레이(모드 무관):
- **일시정지**: 시간 동결 + 재개 버튼 강조.
- **연결 끊김 배지**: 단절이어도 앵커 표시는 유지(숨기지 않는다 — §4.2). 낡음 3조건 도달 시에만 W3f로.
- **일시정지 대기**(뽀모도로 휴식 만료 후): 「다음 세트 대기 중」 + 재개 버튼 — 폰 현행 의미론 그대로.

## 4. 상태 결정 규칙 (루트 스왑의 우선순위)

위에서 아래로 첫 매치가 루트 화면이 된다:

1. 미페어링/tombstone → **W9**
2. `protocolVersion` 불일치 → **W7**
3. 킬스위치 on + 활성 세션 없음 → **W6** (활성 세션 있으면 W3에 시작류만 숨김)
4. 알림 권한 미결정(최초 1회) → **W8**
5. 미확인 `end` 아웃박스 잔존 → **W4**
6. 활성 스냅샷: 낡음 3조건 → **W3f**, 아니면 → **W3**
7. 직전 세션 완료 미확인(요약 미표시) → **W5**
8. 그 외 → **W1**
