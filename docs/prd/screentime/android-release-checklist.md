# 안드로이드 Play 출시 준비 체크리스트

2026-08-18 작성. 집중 실드(GROMO-996)까지 구현된 시점 기준으로, **Play 출시 전에 반드시
해결해야 하는 것**과 **심의(리뷰) 때 요구받는 소명 답안**을 모아 둔다.

> 이 문서는 안드로이드 전용이다. iOS 배포는 `app/ios/fastlane` + TestFlight 흐름이 따로 있다.

---

## A. 출시 차단 항목 (이게 안 되면 올릴 수 없다)

### A-1. 릴리즈 서명 키가 없다 🔴

`android/app/build.gradle` 의 release 빌드가 **디버그 키로 서명**되고 있다.

```gradle
release {
    // Caution! In production, you need to generate your own keystore file.
    signingConfig signingConfigs.debug   // ← 디버그 키
}
```

Play는 디버그 키로 서명된 AAB를 거부한다. 업로드 키를 새로 만들어
`android/credentials/prod/` 에 두고 release가 그걸 쓰도록 고쳐야 한다.

```bash
keytool -genkeypair -v -keystore app/android/credentials/prod/upload.keystore \
  -alias gromo-upload -keyalg RSA -keysize 2048 -validity 10000
```

⚠️ **이 키를 잃어버리면 같은 앱을 다시 못 올린다.** 1Password 등에 백업할 것.
(관련 티켓이 이미 있다 — PR #390 `achore/GROMO-1001-release-signing`.)

### A-2. prod Firebase 자격 🔴

`android/credentials/prod/google-services.json` 과 `keystore.properties` 가 필요하다.
dev와 섞으면 푸시가 전부 `SENDER_ID_MISMATCH` 로 죽는다(iOS에서 GROMO-1234로 겪은 것과 같은 축).

**Play 앱 서명을 켜면** Play 콘솔이 재서명하므로, 콘솔의 **앱 서명 인증서 SHA-1** 도
Firebase에 추가로 등록해야 구글 로그인이 동작한다.

### A-3. versionCode 수동 관리 🟡

`android/app/build.gradle:104` 와 `app.config.js` 두 곳에 versionCode가 있다(현재 둘 다 3).
Play는 같은 versionCode 재업로드를 거부하므로 올릴 때 **둘 다** 손대야 한다.
iOS는 fastlane이 자동 증가시키지만 안드로이드는 자동화가 없다.

### A-4. 개인정보 처리방침 갱신 🔴

스크린타임 기능이 **앱별 사용 시간**을 수집한다는 사실이 처리방침에 반영돼야 한다.
현재 앱 화면 고지는 **"기기에서만 처리 · 서버 미전송"** 이다 — 지금은 사실이다.
서버 전송을 시작하는 순간 이 문구와 처리방침·데이터 보안 폼을 **함께** 고쳐야 한다.

## B. 심의 소명 — 권한별 답안

Play 콘솔이 민감 권한에 대해 용도 설명을 요구한다. 아래를 그대로 쓰면 된다.

### B-1. `PACKAGE_USAGE_STATS` (사용 정보 접근)

> gromo는 사용자가 스스로 설정한 스크린타임 목표를 달성했는지 확인하기 위해 기기 사용
> 시간을 측정합니다. 사용자가 직접 시스템 설정에서 권한을 허용해야만 동작하며, 앱 안에서
> 목표 대비 사용 시간과 앱별 사용 시간을 보여주는 용도로만 사용합니다. 수집한 사용 기록은
> 기기 내에서만 처리하며 서버로 전송하지 않습니다.

### B-2. `SYSTEM_ALERT_WINDOW` (다른 앱 위에 표시)

> 사용자가 시작한 집중 세션 동안, 사용자가 미리 허용하지 않은 앱을 열면 "지금은 집중
> 시간이에요" 안내 화면을 덮어 원래 하던 공부로 돌아가도록 돕습니다. 세션이 끝나면 즉시
> 사라지며, 세션 밖에서는 어떤 화면도 덮지 않습니다. 사용자가 직접 설정에서 권한을 켜야
> 동작하고, 허용할 앱 목록도 사용자가 고릅니다.

### B-3. `FOREGROUND_SERVICE_SPECIAL_USE`

매니페스트에 선언한 subtype: `focus_session_app_shield`

> 집중 세션이 진행되는 동안에만 실행되며, 현재 화면에 떠 있는 앱이 사용자가 허용한 앱인지
> 확인해 안내 화면을 덮는 역할을 합니다. 미디어 재생·위치·통화 등 기존 포그라운드 서비스
> 유형 중 어디에도 해당하지 않아 specialUse 로 선언했습니다. 세션이 끝나면 서비스도 종료됩니다.

### B-4. `POST_NOTIFICATIONS`

> 집중 세션 상태 표시(포그라운드 서비스 알림)와, 사용자가 설정한 집중 리마인더·목표 달성
> 알림에 사용합니다.

### B-5. 접근성 서비스 — **쓰지 않는다**

심사에서 가장 위험한 항목이라 **의도적으로 배제**했다. 차단은 사용 정보 접근 + 오버레이
조합으로만 구현한다. 이 결정의 근거는 `android-focus-shield.md` §1.

## C. 데이터 보안 폼 (Play Console → 앱 콘텐츠 → 데이터 보안)

현재 구현 기준 답안. **허위 기재는 앱 정지 사유**이므로 코드가 바뀌면 같이 고칠 것.

| 항목 | 답 | 근거 |
| --- | --- | --- |
| 앱 사용 기록(앱별 사용 시간) 수집 | **아니요 (전송 안 함)** | 기기 내 처리만. `UsageStatsManager` 조회 결과는 서버로 안 감 |
| 앱 사용 기록 기기 내 처리 | 예 | 위와 같음 |
| 개인 정보(이메일·이름) | 예 — 계정 기능 | 소셜 로그인 |
| 사용자 콘텐츠(사진) | 예 — 선택 | 캐릭터 만들기(누끼) |
| 광고 ID | 예 | Meta/GA4 SDK 포함 |
| 전송 중 암호화 | 예 | HTTPS |
| 삭제 요청 경로 | 예 | 앱 내 회원 탈퇴 |

> ⚠️ **앱별 사용 시간을 서버로 보내기 시작하면 첫 두 줄이 바뀐다.** 그때는 이 표, 앱 화면
> 고지("기기에서만 처리 · 서버 미전송"), 개인정보 처리방침, 별도 동의 UI가 **함께** 가야 한다.

## E. 출시 전 실기기 검증 (에뮬레이터로 못 잡는 것)

에뮬레이터 검증은 끝났다(`android-focus-shield.md` §5). 아래는 **실기기에서만** 확인 가능하다.

- [ ] **삼성 기기 배터리 최적화** — 장시간 세션에서 포그라운드 서비스가 살아남는지.
      One UI가 가장 공격적이라 여기서 죽으면 차단이 조용히 풀린다
- [ ] 화면 꺼짐 → 복귀 후 차단 유지
- [ ] 분할 화면·팝업 뷰에서의 동작
- [ ] 스크린타임 측정 엣지 5종(`docs/prd/screentime/screentime.md` §4.5)
- [ ] 구글 로그인(실기기 SHA-1 등록 확인) · 카카오 로그인(키 해시)
- [ ] FCM 푸시 수신

## F. CI

안드로이드는 **CI에 빌드 잡이 아예 없다**. `lint.yml` 은 JS만 돌아서 네이티브가 깨져도
PR에서 안 잡힌다. 이번 세션에도 Kotlin 컴파일 에러를 로컬에서야 발견했다.
최소한 `assembleDebug` 를 도는 잡이 필요하다.
