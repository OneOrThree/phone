이 시안이 「코드와 같다」는 말의 뜻

기기 프레임은 393 × 852 논리 픽셀 1:1로 그린 뒤 transform: scale()로만 줄여 보여준다. 그래서 프레임 안의 CSS px 값은 곧 React Native 의 pt 값이다 — 여백 20, 카드 radius 16, 아이콘 36×36 같은 수치가 비슷하게 맞춘 값이 아니라 app/src의 StyleSheet 값 그대로다. 아래 § 코드 대조표가 항목별 출처를 건다.

다른 점 딱 하나 — 아이콘 글리프는 Ionicons 실물이 아니라 같은 이름·같은 크기의 근사 패스다. 이름(chevron-forward 등)·치수(18/17/26)·색은 코드와 같지만 곡선 모양은 다를 수 있다.

이번에 코드를 읽고 바로잡은 것 3가지

① 화면 배경은 회색이 아니라 흰색이다. T.paperLight가 #FFFFFF라 설정 화면은 흰 바탕 위에 흰 카드가 1px #F5F6F9 테두리로만 구분된다. 이전 시안은 #F4F5F8 바탕을 깔아 카드가 실제보다 또렷해 보였다.

② 앱에 알약(radius 999) 선택 칩이 없다. 실제 칩은 OccupationScreen의 r13·1.5px 또는 ChallengeComposeSheet의 r12·1px 둘뿐이다. low-level-design.md 의 「칩 radius 999」 지정은 코드에 없는 모양이라 위 표대로 정정한다.

③ 확인 모달은 가운데 정렬이 아니다. ConfirmCardModal에 textAlign이 없어 제목·본문이 왼쪽 정렬된다. 버튼 라벨만 가운데다.

문의 상태를 왜 안 그렸나

처음 고르셨던 MVP에는 「접수 · 확인중 · 답변완료」가 있었는데, 대화가 카카오톡에서 일어나는 순간 앱도 서버도 그 상태를 알 방법이 없다. 아래가 세 가지 강도와 각각의 대가다.

강도무엇을 보여주나대가판정
S1아무것도 안 보여준다 — 카톡방 자체가 상태다없음. 백엔드 0 · 화면 1개채택
S2「언제 · 누구에게 · 어떤 주제로」를 기기에 기록해 목록으로기기를 바꾸면 사라진다. 사용자가 직접 「해결됨」을 눌러야 해 거의 안 눌러 목록이 영영 쌓인다탈락
S3진짜 상태 — 담당자가 바꾼 값을 앱이 읽는다담당자가 상태를 바꿀 어드민 화면이 통째로 딸려온다. 백엔드에 권한 개념 자체가 없어(@PreAuthorize 0건) 인증·권한부터 새로 만들어야 한다탈락

표시하지 않는 편이 정직하다

S2·S3 없이 「접수됨」만 띄우는 선택지도 있었지만, 그건 서버가 모르는 사실을 앱이 단정하는 것이다. 담당자가 아직 안 읽었어도 「접수됨」이 뜬다. 카톡방을 열면 읽음 표시·마지막 메시지가 다 보이므로 상태는 이미 그쪽에 있다 — 앱이 흐린 사본을 하나 더 만들 이유가 없다 (policy.md D4).

착수 전에 채워야 하는 것

시안의 「개발자 A · B · C」와 소개 · 응답 시간은 전부 자리표시자다. 아래 항목이 정해지기 전에는 구현을 시작해도 화면을 완성할 수 없고, 개인정보 승인은 출시 자체를 막는 게이트다 (policy.md 미결).
