# 1:1 문의 — 한눈에 보기

## 1. 한 문장

**앱은 「누구에게 / 어떤 주제로 물어볼지」만 고르게 하고, 대화는 카카오톡 1:1 오픈채팅방에서 한다.**

## 2. 왜 이렇게 만드는가

앱에 문의 창구가 **하나도 없다**. 사용자는 오류를 만나면 앱을 지우는 것 말고 할 게 없고, 팀은 스토어 리뷰 말고 버그 리포트를 받을 데가 없다.

그렇다고 앱 안에 메신저를 만들면 **반대편(담당자가 답을 쓰는 화면)이 통째로 딸려온다.** 화면이 2배가 되고 권한 체계와 심사 리스크가 생긴다. 담당자 3명이 이미 쓰는 도구로 내보내는 편이 훨씬 싸다.

## 3. 그래서 이렇게 생겼다

```
「전체」 탭 › 계정 · 정보 › 1:1 문의
        │
        ▼
  ┌─────────────────────────┐
  │ 무엇을 도와드릴까요?      │
  │                         │
  │ [집중·스크린타임] [그룹·챌린지] [계정·기타]   ← 고르면 담당자가 위로
  │                         │
  │ ┌─ 담당자 카드 ────────┐ │   닉네임 · 성격 설명 · 한 줄 소개
  │ │ (아바타) 이름  [추천] │ │   응답 가능 시간
  │ │  "어떤 증상일 때 나"  │ │   [카카오톡으로 문의하기]
  │ └─────────────────────┘ │
  │  × 3                    │
  └─────────────────────────┘
        │ 버튼 탭
        ▼
  확인 모달 — 「대화는 카카오톡에 저장되고 gromo 서버에는 남지 않아요」
        │ 이동하기
        ▼
  카카오톡 오픈채팅방 (앱 밖 — 여기서 gromo의 역할은 끝난다)
```

## 4. 세 가지만 기억하면 된다

| | |
|---|---|
| **담당자는 사용자가 고른다** | 자동 배정이 없다. 배정 상태를 소유할 서버가 없기 때문이다 |
| **문의 상태를 표시하지 않는다** | 대화가 카톡에서 일어나므로 앱도 서버도 진행 상황을 모른다. **카톡방 자체가 상태다** |
| **백엔드를 건드리지 않는다** | 테이블 0 · API 0 · 마이그레이션 0. 앱 화면 1개가 전부다 |

## 5. 놓치기 쉬운 것

- **담당자 정보는 앱 상수다.** 그래도 교체할 때 앱 심사를 안 탄다 — hot-updater OTA가 이미 붙어 있어 JS 변경은 즉시 나간다.
- **링크는 https 오픈채팅 URL만 쓴다.** 카카오톡 커스텀 스킴을 쓰지 않으므로 미설치 폴백이 공짜로 따라온다 (OS가 브라우저로 연다).
- **오픈채팅방이 죽어도 앱은 모른다.** 서버가 없어 헬스체크할 방법이 없다. 이 설계의 가장 큰 구조적 약점이고, 완화책은 운영 런북뿐이다 — 방별 책임자 · 주 1회 점검 · **OTA 배포 전에도** 링크 확인 · 당일 복구 (`high-level-design.md` §5.1).
- **담당자는 닉네임으로 쓴다.** 실명이 아니다 — 노리는 건 「사람이 답한다」는 신호이지 신원 확인이 아니라서, 닉네임으로도 그 신호가 그대로 나온다 (D10).
- **GA4 이벤트 3개가 유일한 계측 수단이다.** 빼면 이 기능은 영영 측정 불가가 된다.
- **카테고리는 서버로 안 간다.** 담당자를 고르는 길잡이일 뿐이고, 분포는 GA4로만 본다.

## 6. 착수 전에 채워야 하는 것

**전부 출시 게이트다** — 하나라도 비면 화면을 내보내지 않는다 (`policy.md` 미결).

- 담당자 3명 **닉네임(활동명)** · 성격 설명 · 소개 문구 · 응답 시간 (실명을 쓰지 않으므로 노출 동의 절차 없음 — D10)
- 카카오톡 1:1 오픈채팅방 3개 개설 + 영구 URL + **운영 런북 합의** (`high-level-design.md` §5.1)
- **개인정보 처리 범위 확정 + 법무·개인정보 책임자 승인** — 사용자가 문의창에 적을 계정·기기 정보가 카카오와 담당자 개인 계정에 남는다. 앱 내 고지(D8)는 「대화가 카톡에 남는다」까지만 커버한다
- GA4 DebugView로 이벤트 3개 수신 확인 **+ 커스텀 측정기준 등록**(`category`·`contact_id`·`is_recommended`) — 등록 전 수집분은 소급 조회가 안 된다

**알고 미루는 것 (D14)**: 로그인 자체가 실패한 사용자는 이 창구에 도달할 수 없다 — `App.tsx`가 미인증 상태에서 `RootNavigator`를 마운트하지 않아 유일한 진입점인 「전체」 탭이 없다. 가장 도움이 필요한 사용자가 막히는 구조지만, 진입점을 더 두는 건 인증 전 네비게이션을 건드리는 별도 설계라 **1차는 이대로 낸다**. 이 실패는 GA4로 안 잡히니(도달 못 한 사용자는 이벤트를 안 남긴다) **스토어 리뷰를 사람이 읽는 것이 유일한 관측 수단**이다.
