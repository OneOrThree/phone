# 섬 실시간 이벤트 — PRD

> GROMO-1754 · 2026-09-12 · 설계 계약. **14종 전체의 동작 완료 보고가 아니다.**
> [구성 설계](./high-level-design.md) · [상세 계약](./low-level-design.md)

## 목적과 기준

같은 섬에서 집중·휴식·꾸미기·공동 구매를 하면 다른 주민의 화면에도 변경이 전달되어야 한다. 앱이 연결을 놓쳤다가 돌아와도 서버의 최신 상태로 회복하고, 섬을 떠난 사용자는 계속 정보를 받지 않아야 한다.

기준은 화면별 API 스펙 v0.3-proposed(참고 티켓 1739), [서비스 아키텍처](../../architecture/service-architecture.md), [결정 장부](../../architecture/decisions.md)의 A4·A9·A21 및 다음 사용자 결정이다.

- 신규 외부 REST 경로에는 `/api`·`/v1`을 붙이지 않는다. 기존 `/api/v1/chat` 등은 호환 대상으로 보존한다.
- 집중 시작·휴식·재개·종료는 REST 명령이다. 집중/휴식 구독과 응원 SEND만 STOMP를 사용한다. 원본의 emote REST 예시는 이 결정으로 대체한다.
- `server/chat`을 `server/realtime`으로 개명한다. 집중 중 채팅 차단은 유지한다.
- 13개 화면 BFF는 도메인 계약 뒤에 구현한다. 화면 진입 시 BFF로 받은 스냅샷을 같은 화면에서 다시 중복 조회하지 않는다.

원본의 금액·보상·공동 소비 권한·일부 시설 정책은 미확정이다. 이 문서는 이벤트 운반과 수신 범위를 정의하며 그 제품 정책을 대신 확정하지 않는다.

## 범위와 단계

| 단계 | 완료할 내용 | 아직 완료라고 할 수 없는 내용 |
|---|---|---|
| 이 문서 | 14종 봉투·payload·버전 비교 범위, 채널, 생산자, 내구화, 구독과 스냅샷, 권한 철회 계약 | 실제 생산자·새 섬 데이터 모델 |
| 참고 티켓 1755 | 모듈/패키지/CI 경로 개명, `/ws/realtime` 추가, 구형 경로 유지, 이벤트 타입·목적지·라우터·기본 인증 골격 | 14종 자동 발행, 시설/권한 판정 완료, 집중/휴식 데이터 생산 완료 |
| 참고 티켓 1764/1765 | 집중 상태 생산, 조회 스냅샷, 응원·주민 구독, 실제 수신 인가와 스냅샷 경쟁 처리 | 퀘스트·구매·외양 등 다른 도메인 구현 |
| 각 도메인 구현 | 자신의 영속 명령과 outbox, 해당 이벤트 payload/버전, 수신·재조회 통합 테스트 | 다른 도메인의 제품 정책 |

내부 호출·서비스 인증·명령/outbox 기반은 참고 티켓 1659 및 공통 API 작업과 합류한다. 설계에 있는 내부 호출을 이미 main에서 제공하는 API로 기술하지 않는다. 새 채널은 필요한 권한 판정기·생산자·복구가 모두 배선된 기능부터 활성화한다. 검사기가 없을 때 허용하거나 빈 성공 이벤트를 만들지 않는다.

`gromo_chat` DB, 기존 메시지/읽음 커서 테이블, `chat:fanout`, `cache:chat:member:*`, `presence:focus:*` 이름은 개명으로 이관·초기화하지 않는다. `presence:focus:*`는 Data 소유이고 Realtime은 읽기만 한다.

## 사용자 요구사항

| ID | 요구사항 | 판정 기준 |
|---|---|---|
| R01 | 집중 사용자가 실시간 서버에 연결할 수 있다 | CONNECT는 인증만 검사. 집중/휴식 구독 허용과 채팅 거절을 같은 토큰으로 검증 |
| R02 | 허용된 목적지만 사용할 수 있다 | 정확한 UUID/채널 allowlist, wildcard 구독·브로커 직접 SEND·타인 개인큐 거절 |
| R03 | 개인 재화/보유품이 새지 않는다 | 개인 wallet/inventory는 본인 모든 유효 세션, 공동 것은 해당 섬 주민에게만 전달 |
| R04 | 14종이 하나의 봉투를 쓴다 | [상세 계약 §2](./low-level-design.md#2-이벤트-14종-정본)과 타입 집합이 정확히 같음 |
| R05 | 중복·역순이 상태를 되돌리지 않는다 | eventId dedup와 **투영/aggregate별** 버전 비교. 서로 다른 자원에 섬 전체 최대 버전 적용 금지 |
| R06 | 명령 성공과 영속 이벤트가 함께 남는다 | 상태/원장/outbox 같은 DB TX. 응답 유실·프로세스 종료 뒤 relay 재전달 |
| R07 | 재연결 도중 변경이 빠지지 않는다 | 구독 등록 완료 확인→버퍼→스냅샷→병합. overflow/누락 감지 시 재조회 |
| R08 | 권한 상실 후 수신을 차단한다 | 서버 구독/세션 정리와 전달 직전 인가. 앱의 UNSUBSCRIBE 여부와 무관 |
| R09 | 응원은 짧게 보이고 저장되지 않는다 | 5종만, 서버가 만료시각 결정, 만료/재연결 replay 없음 |
| R10 | 로컬 표현은 서버가 건드리지 않는다 | 음량·음소거·미리듣기·카메라/배 연출은 이벤트 대상 아님 |

|---|---|---|

| `rest.member.updated` | 휴식 자리·시작 시각을 갱신 | 같은 섬 주민 |
| `focus.emote` | 만료 전 말풍선 표시 | 같은 섬에서 현재 집중 중인 사용자 |

| `message.created` | 편지 추가, messageId/clientMessageId 중복 병합 | 우체통 접근 권한이 있는 해당 섬 주민; 신규 시설 정책은 우체통 설계에서 확정 |
| `quest.progress.updated` | 해당 회차의 퀘스트 카드 재조회 | 같은 섬 주민 |

| `inventory.updated` | 보유 배지/내 배/음원 목록 재조회 | 개인 소유는 본인, 공동 소유는 해당 섬 주민 |
| `member.appearance.updated` | 해당 주민 배/고양이 외양 갱신 | 외양이 표시되는 같은 섬 주민 |
| `island.appearance.updated` | 섬/건물 외양 갱신, 카메라 유지 | 같은 섬 주민 |
| `island.updated` | 시설/목표/섬 정보 재조회 | 같은 섬 주민 |
| `island.members.updated` | 주민/역할/접근권한 재조회 | 해당 섬 주민; 이탈자 차단은 별도 서버 제어 |
| `join.request.updated` | 본인 신청 상태/방장 관리 목록 재조회 | 요청자 본인과 전달 시점 해당 섬 방장 |
| `notice.updated` | 공지 목록/상세 재조회 | 같은 섬 주민 |

## 미정 정책과 출시 조건

- 우체통 해금 시점, 읽음 커서의 존치/사용 범위는 참고 티켓 1774에서 결정한다. 새 `message.created`에는 상대 읽음 표시·읽음 이벤트가 없다. 기존 읽음 REST·DB를 이 문서 때문에 삭제하지 않는다.
- 공용 구매/건설/테마 실행 권한, 재화 승계·가격·보상은 해당 도메인의 결정이다. 이 문서의 수신 대상이 곧 쓰기 권한이라는 뜻은 아니다.
- 공용 곡 변경은 같은 섬 주민 누구나라는 원본 결정을 사용한다. 구매 권한과 섞지 않는다.
- 응원 유효 시간의 목업은 3초이며 빈도 제한 수치는 미정이다. 참고 티켓 1765에서 양의 TTL·사용자/세션 제한 설정과 결정 근거를 확정한 후 활성화한다.
- 과거 섬 주민에게 개인 외양 변경을 보내지 않는다. 여러 소속 중 어디에 노출되는지는 현재 섬/주민 표시 계약(참고 티켓 1758/1763)을 따른다. 후보 섬마다 현재 표시 권한을 검사한다.

## 완료 조건과 비목표

문서 완료는 세 문서 간 링크, 14종 집합, payload와 버전 키, 인가·복구·관측·후속 티켓 소유 경계가 서로 일치하는 상태다. 코드 빌드나 제품 기능 완료를 의미하지 않는다.

실제 구현 완료는 [상세 계약의 검증표](./low-level-design.md#8-구현-검증표)를 통과해야 한다. 무중단 무손실 소켓 전달, exactly-once 네트워크, 오프라인 응원 replay, 새 재화 정책, 읽음 기능 제거는 이 문서의 목표가 아니다.
