## 현재 설계의 한계와 배포 전 조건

1. **관측 유실을 0이라고 보장하지 않는다.** encoder 이전 손실, host disk 소실, buffer 포화, source rotation, sink 영구 거절은 남는다. P0에서 수집 지연 목표·중단 예산·측정 방식을 고정해야 한다.
2. **모든 로그가 trace를 갖지는 않는다.** agent 미활성·기동·인프라 로그는 request/origin/message/edge ID 또는 시간·source로 조사한다. 이미 저장되지 않은 과거 로그의 문맥을 사후 복원할 수는 없다.
3. **공유 작업은 단일 trace 조회만으로 완결되지 않는다.** 관련 operation을 추가 탐색하고, 다른 origin의 contributor가 보이더라도 원인을 덮어쓰거나 같은 요청이라고 해석하지 않는다.
4. **외부 환경은 미확인이다.** 실제 배포 tracer 버전, env, Loki 자원/한도, Nginx source, S3/IAM/lifecycle, dev→AWS 인증, Datadog 보존·샘플링과 비용은 P0의 증거로 확정한다.
5. **코드와 wire 호환은 구현 테스트가 필요하다.** provider·decorator·Outbox nullable migration·Kafka/Redis carrier와 Notification 후속 저장 모두 P1/P3의 통합 검증 전에는 완료가 아니다.
6. **진입 기준을 넘기지 못하면 그 단계 배포를 보류한다.** 검증 결과를 얻기 위해 기존 domain 처리·멱등·권한·offset 보장을 약화하지 않는다. 원격 access가 필요한 항목을 추측으로 통과시키지 않는다.

## 문서 검증

검토는 실제 코드 경계 조사와 별도 공식 자료 담당의 독립 검토로 진행했다. 아래는 이번 문서 작업에서 실행한 결과다.

- 상대 링크 75개 대상 존재, XML 예시 2개 well-formedness, 코드 블록 닫힘 및 `git diff --check`: 통과.
- Mermaid CLI `12.0.0`으로 현재 구성·목표·HTTP·Outbox·수집·조사·Redis·묶음 발송의 8개 SVG를 본문 소스에서 다시 생성: 모두 통과.
- 공유 operation·중복·origin 조회: 합성 11행을 SQLite 메모리 DB에 넣고 문서의 SQL을 실행했다. ISO timestamp 함수는 문자열을 돌려주는 대체 함수를 사용했다. 기대한 8행과 일치했고, 기존 scalar 필터는 공유 send를 놓치며 수정한 semijoin은 이를 찾는 것을 확인했다. 재전송 1건 제거·다른 원요청의 공유 contributor 보존·agent 없는 origin_request 조회·NULL log ID의 구형 레코드 보존·무관/범위 밖 로그 제외를 대조했다. **Athena 엔진·SerDe·시간 파싱·비용 검증은 아니다.**
- 미실행: Java provider/decorator 빌드, Loki/Athena 실쿼리, Docker/Redis/Kafka 통합 기동, AWS·Datadog 실측, 부하·장애 실험, 배포.
