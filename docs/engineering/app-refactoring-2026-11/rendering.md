# 렌더링 조사와 회귀 비교

구조 변경 뒤 기존 렌더 최적화가 유지되는지 같은 입력으로 확인했다. 별도 테스트 사본에서 기존 `App.clock`, `WorldMap.renderCount`, `FishingIsland.renderCount`의 카운터를 출력했으며 **13개 관측값이 전후 모두 같다**. 원값은 `render-counts.json`, 계측 파일 해시는 `measurement/render-instrumentation.json`에 있다. 제품에 프로파일링 코드를 넣지 않았다.

| 시나리오                              | 변경 전 | 변경 후 | 해석                          |
| ------------------------------------- | ------: | ------: | ----------------------------- |
| 홈에서 5초 대기 중 지도 추가 렌더     |       0 |       0 | 기존 루트 시계 분리 유지      |
| 고양이가 건물까지 걷는 동안 지도 렌더 |       1 |       1 | 기존 걷기 상태 분리 유지      |
| 홈 지도 드래그 / 손 뗀 뒤             |   0 / 1 |   0 / 1 | 기존 transform·커밋 경계 유지 |

| 집중 지도 드래그 / 손 뗀 뒤           |   0 / 1 |   0 / 1 | 기존 지도·HUD 경계 유지       |
| 집중 지도 핀치 / 손 뗀 뒤             |   0 / 1 |   0 / 1 | 기존 배율·좌표 계약 유지      |

이 횟수는 테스트의 `IslandOcean` 호출을 지도 전체 갱신의 대리 지표로 센다. React Profiler commit 시간이나 Skia/GPU 프레임 수가 아니다. `WorldMap.renderCount`는 이미지 섬의 웹 분기를 대상으로 하고, 네이티브 타일 지도의 실제 GPU 비용을 이 수치로 대신하지 않는다. 기존 티켓 2371~2373의 개선을 이번 성과로 다시 집계하지 않는다.

## 이번에 줄인 작업

- `useNow`와 App의 초 경계 예약은 inactive/background에서도 살아 있었다. 표시용 시계가 배경으로 가면 예약을 없애고 active 복귀 즉시 현재 벽시각을 반영한다. 변경 후 테스트에서 배경 60초 동안 콜백·예약 0, 10회 구독·해제 뒤 남은 타이머·리스너 0을 확인했다. 이것은 배경 예약의 제거이지 전경 지도 렌더 횟수 감소 주장이 아니다.
- App의 `boatTravel`은 어떤 뷰에도 연결되지 않았는데 이동 시 애니메이션을 만들었다. 선언·예약을 제거했다. 실제 항해 컷신은 유지했다.
- 장면 내부의 짧은 모션과 화면 전환은 이탈 시 중지한다. 토스트 타이머도 루트 해제 시 정리한다.

## 유지한 장면과 범위

게시판 상세 뒤 목록은 스크롤·선택을 보존하기 위해 마운트한다. opacity 0과 포인터·접근성 차단을 함께 사용하며, 무조건 unmount하는 변경은 하지 않았다. 게시판의 초 단위 값은 건설 완료·시계 변경·완료 재시도 소비자가 있어 유지했다. `backgroundHome`처럼 JSX를 만들었어도 실제 반환·마운트하지 않는 경우는 숨은 화면 렌더로 세지 않았다.

게시판 121개 테스트, `WorldMap.renderCount` 3개, `FishingIsland.renderCount` 15개, `App.clock` 2개와 고양이·장면 모션 테스트를 전체 회귀 실행에 포함했다. 접근성 글자 배율·태블릿 크기·지도 확대 시 HUD 배치와 동작 줄이기도 기존 테스트가 통과했다. 모든 언어·태블릿·다수 고양이·긴 목록 조합의 네이티브 프레임 프로파일은 수집하지 않았다. 이 장면들에 비용이 증명되지 않은 캐시·가상화·memo를 추가하지 않았다.

전경 CPU·메모리와 네이티브 화면 전환 관측은 `comparison.md`에 있다. 시간 측정의 자동화 오버헤드·호스트 편차를 포함하며 FPS 향상을 입증하는 자료로 쓰지 않는다.
