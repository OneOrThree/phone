# 코드·자산 변경 근거

채택 변경의 근거다. 수치와 회귀 결과는 comparison.md에서 비교한다.

## 미사용 코드

| 대상                              | 조사 근거                                                                                                                                                                             | 처리                    | 번들 영향                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- | --------------------------------------------------------- |
| focus/VerificationSetup.tsx       | 정적 import 그래프에 소비자가 없고 index.native/index.web·네이티브 등록·scripts에도 진입 없음. 유일 소비자는 전용 테스트. 현재 카메라 설정은 VerificationSpike와 집중 화면에서 연결됨 | 화면과 전용 테스트 제거 | 원래 Metro 진입 그래프 밖이므로 감소 효과로 집계하지 않음 |

| App·미리보기 진입점·sentry.ts     | src 내부 참조는 없으나 index.native.ts/index.web.ts에서 선택·초기화                                                                                                                   | 유지                    | 삭제하지 않음                                             |

expo-camera는 VerificationSpike와 Expo 플러그인이 사용하므로 제거하지 않는다. 네이티브 위젯용 글꼴·이미지 복사본도 별도 번들 소비자가 있어 유지한다.

## 중복 코드

- FishingIsland와 CurrentScreens의 `afterForegroundMs`는 100토큰 중복 탐지 뒤 본문 전체와 호출 계약을 대조했고 바이트 수준으로 동일했다. `utils/afterForegroundMs.ts`로 통합했다.
- 낚아올리기·황금 물고기 연출에 쓰는 포그라운드 누적 시간, 취소, 구독 해제를 유지한다. 배경에서 시작·일시 중지/복귀·중복 active 알림·10회 진입/이탈을 검증하는 테스트를 추가했다.
- useBoardNotices/useMailbox/useShop과 useIslandManagement/useConstruction의 일부 반복은 오류 및 명령 경합 경계다. 도메인별 쓰기·재시도 정책이 달라 계약을 비교하기 전에는 통째로 합치지 않는다.

## 이미지 압축

- PNG 307개(100KB 이상)를 pngcrush로 시험했다. 생성 타일 지도·바다 원화·CDN 계약 경로는 이번 일괄 압축에서 제외했다. 현지화 도장은 생성 검사로 픽셀 동등성을 확인한다.
- 원본 크기·RGBA 픽셀·IDAT/IHDR/PLTE/tRNS 외 메타데이터 청크가 모두 같고 바이트가 감소하는 262개만 채택했다.
- 소스 파일 합계 3,190,831바이트 감소. 해상도는 같으므로 디코딩 메모리 절감으로 집계하지 않는다.
- 메타데이터 변화가 있는 후보는 픽셀이 같아도 제외했다. 전체 후보·파일별 해시·크기는 png-compression.json에 있다.
- 제외 45개는 부가 청크 변화 33개와 바이트 감소 없음 12개다. 무감소 후보의 원본 재검사 결과도 보고서에 포함했다.
- 실제 번들에서는 같은 해시 파일이 합쳐질 수 있으므로 위 합계를 설치 용량 절감으로 사용하지 않는다.

## 타입과 테스트 입력

- 앱 루트가 제공하는 데이터·명령을 `navigation/ScreenEnvironment.ts`에 명시한다. 명령 타입은 실제 서비스의 반환 타입을 재사용한다.
- 작은 화면과 도착/항해 헬퍼는 필요한 필드만 Pick으로 요구한다. 서버 명령이 없는 목업과 실제 서버 화면을 구분하며 늦게 실행되는 콜백의 빈 값 처리를 확인한다.
- 검토실과 테스트는 `createPreviewEnvironment`로 명시적인 로컬 문맥을 만든다. 연결하지 않은 서버 명령을 호출하면 오류가 나며 실제 앱 루트는 이 팩토리를 사용하지 않는다.
- 삭제한 이전 화면의 전용 테스트만 제거하고 현재 기능의 검증과 기대값은 유지한다. 불완전한 API 모형은 실제 계약의 필수 필드를 채운다.

## 되돌리기 경계

- 구조·타입 분리는 기존 진입점과 새 하위 모듈·모든 호출부를 함께 되돌린다. 옛 `BuildingInteriors`나 `model.ts` 하나만 복구하면 export/입력 계약이 어긋날 수 있다. 이전 전용 테스트도 구현 복구와 함께 돌린다.
- PNG 압축은 `png-compression.json`의 채택 경로만 기준 SHA의 동일 파일로 복구할 수 있다. 해상도·좌표 계약은 같지만 파일 해시가 달라지므로 복구 자산을 새 업데이트로 묶어야 한다. 배포된 CDN 객체를 덮어쓰지 않는다.
- 표시용 시계 변경은 `foregroundClock`, `useNow`, App 호출부를 하나의 단위로 되돌린다. 공용 `afterForegroundMs`는 두 소비자와 함께 복구한다. 세션/집중 시간의 저장 형식을 바꾼 것은 아니다.
- 미사용 글꼴·이전 화면 제거는 원본과 필요한 import·테스트를 함께 복구한다. 필요가 확인되지 않은 채 오래된 경로만 다시 등록하지 않는다.
- 전체 변경을 되돌려야 하면 이 리팩토링 커밋의 revert PR로 처리한다. main·release를 reset하거나 force push하지 않는다. 배포가 필요한 경우 파이프라인·소유자 승인 규칙을 별도로 따른다.

채택하지 않은 패키지 제거, 손실 이미지·영상 압축, 인증 런타임 순환 재작성은 이번 변경에 없으므로 복구할 내용도 없다.
