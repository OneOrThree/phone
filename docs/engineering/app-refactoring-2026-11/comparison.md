# 앱 리팩토링 전후 비교

기준 SHA `fd2881a4f6527004ac8422ef3d3d245c78405f3e`와 동일 의존성·Release 설정으로 비교한다. 활성 앱 `app/app-dev`를 대상으로 기능 경계 분리, 미사용 코드 제거, 표시용 작업의 수명 정리, 무손실 PNG 압축을 적용했다. 임의의 종합 점수 대신 재측정 가능한 지표를 공개한다.

iOS Simulator 앱은 0.85%, Android APK는 0.023%, export 포함 자산은 0.63% 감소했다. Android/iOS export Hermes는 각각 0.27%/0.19%, 웹 JS는 0.94% 증가했다. 파일 분리와 공용 계약 도입의 비용도 비교에 포함한다.

위 `.app`은 Simulator 논리 파일 크기이고 APK는 전용 로컬 키로 만든 arm64 산출물이다. App Store의 thinning·압축 다운로드, Play split APK, 실제 사용자 기기의 코드·데이터·캐시를 합친 설치 크기는 확보하지 않았다. 배포용 서명·스토어 처리와 실제 기기 측정이 필요하다. PNG는 해상도·픽셀이 같아 디코딩 메모리 절감으로 집계하지 않는다. [자산 근거](assets.md), [원시 크기](bundle-comparison.json).

CPU는 홈 확인 5초 후의 10초 구간이며 한 코어 100% 기준이다. iOS는 footprint 출력 MB, Android는 TOTAL PSS KiB를 1,024로 나눈 MiB다. 플랫폼 간 메모리 수치를 직접 비교하지 않는다. Android CPU는 회차 편차가 커 새 설치 후 20초 안정화·60초 대기 관찰을 전후 한 번씩 추가했다. 살아 있는 스레드 CPU 합은 5.65%→6.30%, JS 스레드는 0.216%→0.233%, RenderThread는 3.27%→3.99%였다. 짧은 표본에서 보인 두 배 차이는 줄었지만 CPU 개선을 입증하지 못했고, 반복적인 전경 CPU 회귀가 없다고 단정하지도 않는다. 스레드 종료분은 이 합에서 빠질 수 있어 주 측정의 프로세스 CPU와 동일 지표가 아니다. 원값은 `measurements/android-cpu-60s.json`이다. 전체 CPU·메모리 절감이 확인됐다고 주장하지 않는다.

## 12분 동일 프로세스 관찰

iOS에서 각 버전의 같은 PID를 유지하고 홈→상점→홈→집중 자리 선택→홈을 10회 왕복했다. 두 버전 모두 720초 이상 실행했고 프로세스 종료·자동화 실패는 없었다.

| 시점의 footprint MB | 변경 전 | 변경 후 |
| ------------------- | ------: | ------: |
| 시작                |     178 |     178 |
| 첫 왕복 후          |     318 |     315 |
| 열 번째 왕복 후     |     387 |     387 |
| 12분 종료           |     388 |     388 |

전후 모두 178→388MB로 증가했다. 처음 장면을 연 뒤 ImageIO는 약 29→107MB가 되고 종료 때도 107MB였다. 이후 MALLOC_LARGE 등도 증가했으므로 전체 증가를 이미지 캐시 하나로 설명하지 않는다. 이번 변경의 메모리 개선은 입증되지 않았고, 12분 관찰만으로 누수가 없다고 결론 내리지 않는다. 장시간 heap/할당 추적이 추가로 필요하다. 원시 footprint와 회차별 값은 `measurements/`에 있다.

## 검증

- 변경 전 267개 스위트 / 4,603개 테스트, 변경 후 267개 스위트 / 4,580개 테스트 통과. 삭제한 이전 화면 전용 29개를 제거하고 수명 계약 6개를 추가했다. 현행 기능의 기대값을 완화해 테스트 수를 맞추지 않았다.
- CI가 별도로 실행하는 네이티브 자산 캐시 모듈 계약 테스트 3개도 통과했다.
- 전후 typecheck·lint·format:check 및 iOS/Android/Web export 통과. 최종 iOS·Android Release 빌드 성공. 네이티브 실행은 빌드와 별도로 검증했다.
- 렌더 카운터 13개 관측값 전후 동일. 홈 5초 추가 지도 렌더 0, 걷기 1, 드래그/핀치 중 0·손 뗀 뒤 1 유지. 새 배경 시계 테스트는 배경 60초 예약·콜백 0과 10회 해제 뒤 남은 자원 0을 확인했다. [렌더 근거](rendering.md), [수명 근거](lifecycle.md).
- 이미지 생성 검사 중 영문 도장 검사만 전후 동일하게 실패한다. 파일은 변경하지 않았으며 원본 재현성 문제를 이번 리팩토링의 새 실패로 세지 않았다. 전체 생성 검사 통과라고도 표시하지 않는다. [세부 결과](assets.md).

실행 명령·장비·캐시·판정 조건은 [baseline.md](baseline.md), 테스트별 결과는 [validation.json](validation.json), 시나리오별 실제 실행·미검증 구분은 [regression-matrix.md](regression-matrix.md)에 있다. 네이티브 원시 측정은 `measurements/`에 수록한다.

## 검증의 한계와 남은 일

- 실제 계정 로그인·원격 서버·실기기 촬영·푸시·네이티브 앱 차단은 이번 로컬 DEMO 성능 검증 범위 밖이다. 해당 계약의 기존 테스트는 통과했지만 실기기 통합 검증을 대체하지 않는다.
- iOS 27.0에서 실행·재실행을 확인한다. 설치되지 않은 27.0.1에서 검증했다고 표시하지 않는다. Xcode 26.6 규칙은 유지했다.
- 모든 언어·태블릿·긴 목록·다수 고양이 장면의 실기기 GPU 프로파일을 수집하지 않았다. 비용을 입증하지 못한 memo·가상화·해상도 축소는 채택하지 않았다.
- 생성 영문 도장 재현성, 남은 거대 모듈·인증 순환은 후속 조사 대상으로 남는다. 전체 앱에 더 이상 개선할 곳이 없다는 뜻은 아니다.
- 운영 배포·PR 머지·실기기 설치는 수행하지 않는다. main 머지는 Android Play internal 배포를 부를 수 있어 별도 판단이 필요하다.
