# 자산 압축과 호환성

PNG 307개를 시험해 262개만 채택했다. 채택 파일은 모두 형식·해상도·RGBA 픽셀과 부가 메타데이터가 같고 바이트만 줄었다. 소스 PNG 합계 절감은 **3,190,831바이트**다. 해상도와 디코딩 픽셀이 같으므로 디코딩 메모리 감소 효과는 없다.

`png-compression.json`에 파일별 전후 크기·해시·해상도·채택 여부가 있다. 이전 원본은 기준 SHA의 같은 경로에 있다. `asset-inventory.json`은 전체 추적 미디어 798개의 크기·해상도·직접 문자열 소비자·플랫폼 export 포함 여부다. 소비자 목록은 동적 조합·네이티브 등록을 모두 표현하지 않으므로 빈 목록을 삭제 근거로 쓰지 않는다. export 포함은 내용 해시로 대조했으며 네이티브 리소스 등록 여부와 별도다.

## 변환과 화질

Xcode 26.6에 포함된 pngcrush 1.6.4를 사용했다. 재실행 도구는 `app/app-dev/scripts/optimize-png.py`이며 기본값은 조사만 한다. `--pngcrush`에 바이너리 경로, `--report`에 결과 경로를 주고, 실제 적용할 때만 `--apply`를 넣는다. 생성 아틀라스·바다 원화·CDN 계약 경로는 제외했다.

알파 가장자리, 이미지 속 한글·영문, 낮/밤 그림은 변환 전후 픽셀 전체를 비교했다. 채택 자산의 좌표·앵커·스케일도 바꾸지 않아 지도 확대나 태블릿 배율에서 쓸 픽셀은 동일하다. 이는 모든 태블릿/언어 조합의 실제 화면을 수동 검수했다는 뜻은 아니다. 네이티브 대표 화면 검증 범위는 `comparison.md`에 별도로 기록한다.

바이트가 작아져도 부가 청크가 달라진 후보 33개와 크기가 줄지 않은 후보 12개는 제외했다. 누락됐던 무감소 후보도 기준 원본으로 다시 압축해 동일 크기임을 확인하고 보고서에 보충했다. 채택 원본 262개는 모두 8비트 PNG다. MP4의 손실 재인코딩, 임의 사용자 문자열을 표시하는 글꼴의 부분집합 생성은 채택하지 않았다. 사용되지 않는 `gowun-dodum-board.ttf` 49,996바이트만 삭제했다. 본문 글꼴과 네이티브 등록 복사본은 유지했다.

낮/밤 지도 `tileset@2x.png` 각각의 RGBA 단순 추정은 33,554,432바이트(32MiB)다. 실제 GPU 텍스처·mipmap·중복 디코딩을 포함한 프로세스 메모리와는 다르며, 이 아틀라스는 이번에 축소하지 않았다.

## 생성물·OTA

Pillow 12.2.0 / NumPy 2.4.4 환경에서 island-ocean, tile-atlas, focus-ocean, facility-crops 검사가 통과했다. report-palette와 nav-fixture 검사도 통과했다. `gen:localized-stamp:check`는 **전후 모두** 영문 `blueprint-ready-stamp-v3.en.png`에서 실패했다. 해당 파일은 변경하지 않았고 전후 SHA-256은 `a47898f5c8a463acbe76dd1f9d8d30c3196911bc457c453690b2c4a79a418f3a`로 같다. 전체 생성물 검사가 통과했다고 표시하지 않는다. 생성 환경 차이 규명은 남아 있다.

`assetPatternsToBeBundled: ['src/assets/ota/**/*']`, 플랫폼별 runtimeVersion, 지도 manifest·내용 해시 계약·네이티브 등록 설정은 유지했다. OTA 폴더의 PNG는 픽셀이 같아도 파일 해시가 달라지므로 새로운 업데이트의 자산이다. Metro export가 새 내용 해시를 만들며 오래된 해시의 서버 파일을 덮어쓰지 않는다. CDN 패키지 생성물은 압축 대상에서 제외했다. `services/assets` 계약·repository·nativeAdapter·channelClient와 mapAssets 테스트를 전후 전체 테스트에 포함했다. 실제 운영 OTA 배포·기존 설치본 수신은 수행하지 않았다.

플랫폼 export의 포함 자산은 109개를 유지하고 28,839,063→28,656,263바이트로 182,800바이트 줄었다. iOS Simulator 앱과 Android APK의 실제 산출물 크기는 `bundle-comparison.json`에 별도로 있다. 소스 감소분을 설치 용량 감소분으로 바꾸어 표시하지 않는다.
