# Android 집중 중 앱 차단 구현 계획

- 작성: 2026-11-07
- 상태: 구현 전 제안. 통합 안내 작업 [GROMO-2795](https://romance.atlassian.net/browse/GROMO-2795)의 후속 범위다.
- 사용자 흐름: 통합 기능 안내 → 측정할 앱 → 집중 중 허용할 앱. 낚시섬 진입 버튼은 **허용 앱 설정**이다.

## 현재 코드에서 확인한 것

`modules/screen-time/.../ScreenTimeModule.kt`의 `supportsFocusShield`는 `false`이고 `syncAndroidFocus`는 차단을 시작하지 않는다. 사용량 측정·앱 선택과 `FocusSessionState`는 남아 있지만 차단 서비스는 없다.

[PR #1295](https://github.com/OneOrThree/phone/pull/1295), 커밋 `095843d02`에서 Play 정책 대응을 이유로 specialUse 포그라운드 서비스, 오버레이, 부팅 복구 수신기 등을 제거했다. 실제 심사 반려 사유 원문은 이번 조사에서 확인하지 않았다. 상수만 바꾸거나 삭제 코드를 그대로 복원해서는 동작하지 않는다.

## 권한과 안내

| 기능                 | iOS                   | Android 계획                   |
| -------------------- | --------------------- | ------------------------------ |
| 선택 앱 사용량 측정  | Screen Time 승인      | 사용정보 접근                  |
| 집중 중 다른 앱 차단 | 같은 Screen Time 승인 | 접근성 서비스 사용 동의·활성화 |

기능 소개 화면은 하나로 유지한다. Android에는 “스크린타임 권한 한 번으로”라는 문구를 사용하지 않는다. 측정과 차단을 각각 설정하며 한쪽 권한을 거절해도 다른 기능은 사용할 수 있게 한다.

차단 단계에서는 **접근성 API 전용 고지 → 명시적 동의 → 시스템 접근성 설정 → 앱 복귀 후 실제 서비스 연결 확인 → 허용 앱 저장** 순서로 진행한다. 서비스 활성화 전 앱 안에서 어떤 정보에 접근하는지, 차단 목적과 저장·전송 여부를 설명한다. 이 고지는 일반 기능 소개나 다른 정보 수집 고지에 합치지 않는다. 고지를 닫거나 시스템 설정에서 돌아온 것만으로 완료 처리하지 않는다.

Google Play는 접근성 도구가 아닌 앱에 별도 고지·동의와 선언 양식을 요구한다. Cattus는 장애인 지원 도구라고 표시하지 않는다(`isAccessibilityTool=false`). 정해진 사용자 규칙에 따른 동작이 허용될 수 있다는 정책 문구는 개별 앱의 승인 보장을 뜻하지 않는다. [공식 정책](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)

## 권장 기술안과 먼저 검증할 점

1. `AccessibilityService`에서 앱 창 전환 이벤트의 패키지명을 받아 활성 집중 세션·허용 목록과 비교한다. 화면 내용·메시지·입력값은 읽지 않고 `canRetrieveWindowContent=false`, `canPerformGestures=false`로 시작한다. 필요한 이벤트만 구독한다. [서비스 문서](https://developer.android.com/guide/topics/ui/accessibility/service)
2. 차단 대상 앱에는 `TYPE_ACCESSIBILITY_OVERLAY`로 Cattus 차단 화면을 표시한다. 사용자가 앱을 종료하거나 다른 앱 프로세스를 강제 종료하는 구현은 아니다. 다른 앱 위에 실제로 표시되고 입력을 막는 범위는 PoC에서 확인한다. 별도 `SYSTEM_ALERT_WINDOW`나 specialUse FGS는 이 안의 기본 전제에 넣지 않는다. [WindowManager 문서](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_ACCESSIBILITY_OVERLAY)
3. 사용자 지정 **허용 목록 밖의 앱**을 차단한다. Cattus, 홈 런처, 시스템 설정·권한 화면, 시스템 UI, 전화·긴급전화, 현재 키보드는 필수 예외로 분리한다. 앱 검색은 기존 런처 앱 조회를 활용하며 `QUERY_ALL_PACKAGES` 추가를 기본 전제로 삼지 않는다.
4. 홈·최근 앱, 알림으로 이동, 화면 잠금·해제, 멀티윈도·PiP, 키보드·권한창 전환에서 예외 앱이 차단되거나 오버레이가 남지 않는지 실기기로 검증한다. 패키지 전환 이벤트만으로 구분할 수 없는 경우는 동작 한계를 명시하고 출시 범위에서 제외하거나 설계를 다시 검토한다.

specialUse FGS + UsageStats 주기 조회 + 일반 오버레이 복원안은 대안으로만 남긴다. specialUse도 용도 선언과 Play 심사를 요구하고 기존 삭제 사유가 있으므로 자동으로 더 안전한 선택이라고 볼 수 없다. [FGS 공식 문서](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)

## 세션·상태 계약

- `supportsFocusShield`는 바이너리 지원 여부로만 사용한다. 별도의 상태 조회로 `permissionRequired / disconnected / ready / blocking`을 반환하고, 화면은 실제 상태를 보여 준다.
- 설정 완료는 **권한 승인 + 서비스 연결 + 허용 목록 저장**으로 판정한다. 목록 0개를 저장한 상태와 아직 저장하지 않은 상태는 구분한다. 0개는 필수 예외 외 모두 차단한다는 의미다.
- 기존 `FocusSessionState`의 owner·sessionId·version·종료 표식을 재사용하되, 로컬 집중 상태를 장기간 그대로 복원하는 현재 28일 유효기간은 차단 복구 근거로 사용하지 않는다. 복구 시 서버 확인과 짧은 유효기간 정책을 먼저 설계한다. 검증 불가·기간 만료는 차단을 해제하고 상태를 안내한다.
- 집중 시작은 서버 성공 뒤 차단 요청, 휴식·종료·로그아웃·계정 전환은 우선 차단 해제 순서다. 늦은 요청·과거 계정·종료된 세션이 차단을 다시 켜면 안 된다.
- 서비스가 재연결되거나 프로세스가 재생성되면 최신 세션을 검증한다. 원격 종료를 수신하지 못한 상태까지 고려해 만료 해제가 독립적으로 작동하게 한다. 기존 `FocusRemoteDelivery`의 실제 수신 경로를 다시 연결하고 중복·역순 전달을 검증한다.
- 사용자가 접근성 권한을 끄거나 앱을 강제 종료하는 동작을 막지 않는다. 차단 화면에 Cattus로 돌아가기와 집중 종료 진입을 제공한다. 권한 철회 시 측정은 계속 사용할 수 있다.
- `focusShieldApplied()`와 앱 이탈 판정은 서비스 연결·현재 세션 적용 응답을 확인한다. 지원 상수나 측정 권한만 보고 차단 중이라고 처리하지 않는다.

## 작업 순서와 산출물

| 단계              | 산출물·통과 조건                                                                                                      | 추정  |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- | ----- |
| 1. 기술·정책 PoC  | 최소 서비스와 오버레이, Pixel·Galaxy 창 전환 검증, 고지 초안, 기존 심사 사유 확인. 차단 가능 범위를 결정한다.         | 1~2일 |
| 2. 네이티브 구현  | 허용 목록·필수 예외, 세션 버전·만료·복구, 종료 해제, 실제 상태 브리지와 단위 테스트.                                  | 2~3일 |
| 3. 앱 연결        | 통합 안내의 Android 분기, 접근성 전용 동의, 설정 복귀 확인, 허용 앱 설정·상태 안내, 이탈 판정 연결.                   | 1~2일 |
| 4. 검증·심사 준비 | 지원 최소 OS·목표 OS, Pixel·Galaxy Release 실행, 접근성 선언·동의/거절/재진입 동영상, 스토어 설명·개인정보 문서 검토. | 1~2일 |

총 **개발·검증 5~9일 추정**, Google Play 심사 기간 제외. 1단계 결과로 수정한다. Android 네이티브 변경이므로 OTA만으로 배포할 수 없다. 이 저장소는 앱 변경이 main에 합쳐지면 Play 내부 트랙 발행을 시작하므로, 선언·배포 준비 전에는 서비스가 포함된 PR을 합치지 않는다.

## 완료 기준

- 선택하지 않은 일반 앱은 집중 중 차단되고 허용 앱은 열리며, 측정 목록 변경이 허용 목록을 바꾸지 않는다.
- 휴식·종료·계정 전환·만료·권한 철회 후에는 차단 화면이 남지 않는다.
- 프로세스 재생성·재부팅·네트워크 단절·역순 세션 명령 후 과거 집중이 되살아나지 않는다.
- 홈·시스템 설정·권한 해제·전화·긴급전화 접근을 막지 않는다.
- 사용량 측정만 설정한 사용자는 차단을 당하지 않으며, UI는 미설정·연결 끊김·차단 중을 정확히 구분한다.
- 실기기 Release 검증 결과와 미지원 동작을 기록한다. 컴파일·업로드 성공만으로 차단 구현 완료라고 보고하지 않는다.
