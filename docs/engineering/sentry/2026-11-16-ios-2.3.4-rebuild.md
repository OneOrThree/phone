# 2026-11-16 iOS 2.3.4 재빌드·실행 조사

대상은 [CATTUS-8](https://oneorthree.sentry.io/issues/7835276494/)의 iPad13,18 / iOS 27.2 / 2.3.4(13) `EXC_BREAKPOINT`다. 원본 dSYM 확보와 별개로, 같은 소스를 다시 빌드해 오류를 재현하면 새 빌드와 일치하는 dSYM으로 조사할 수 있다. 이 경로를 실제 실행했다. 재현되지 않은 크래시를 해결 처리하지 않는다.

## 소스와 빌드

- 태그: `app-2.3.4-ios-13`
- 커밋: `2a741d6b1f8e6d9752edd86820fa075ec6247a7b`
- 격리한 소스: `/tmp/cattus-2.3.4-repro-20261116`
- 빌드: Xcode 26.6 (`17F113`), iOS Simulator SDK 26.5, arm64, **Release**
- entry: `index.native.ts`. 진단 전용 entry가 아니라 실제 앱을 실행한다.
- 산출물: `/tmp/cattus-234-ios-build/Build/Products/Release-iphonesimulator/Cattus.app`
- dSYM: 같은 폴더의 `Cattus.app.dSYM`

`npm ci`로 태그의 lockfile을 설치했다. CocoaPods 버전도 태그와 대조했다. Podfile.lock의 차이는 ExpoModulesCore 사전 빌드 파일의 절대 경로가 달라 생긴 podspec 체크섬 한 개다. 최신 카메라 수정 패치는 이 복사본에 적용하지 않았다.

앱 소스·의존성 lockfile·패치·메인 네이티브 소스의 추적 파일 1,431개를 태그의 Git blob SHA와 대조했다. 차이는 아래 버전 메타데이터를 맞춘 메인 Info.plist뿐이다. [대조 결과](evidence/ios-2.3.4-2026-11-16/cattus-234-source-verification.json)

태그에 체크인된 메인 앱 Info.plist는 2.3.0(12)였다. 당시 Fastlane은 업로드 전에 버전·빌드 번호를 바꾸고 그 변경을 커밋하지 않는다. 재현 복사본의 메인 앱 버전과 모든 확장 빌드 번호를 2.3.4(13)에 맞췄다. 저장소의 서명 설정은 변경하지 않았다.

시뮬레이터의 키체인도 사용하도록 `CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO`로 빌드했다. `CODE_SIGNING_ALLOWED=NO` 빌드는 실행은 됐지만 SecureStore가 `-34018`을 반환했다. 앱에 직접 iOS 권한을 ad-hoc 서명하면 macOS가 제한된 권한으로 거부하므로, Xcode가 `*-Simulated.xcent`를 생성·내장하는 경로를 사용했다. 이 두 실패는 시뮬레이터 구성 문제이며 운영 CATTUS-8의 재현으로 집계하지 않는다.

## 재현 환경의 차이

- 내장 2.3.4 번들을 검사하려고 **산출물의** Expo.plist에서만 `EXUpdatesEnabled=false`로 설정했다. 최신 OTA가 덮어쓰지 않는다.
- Sentry SDK는 켜 두고 DSN을 `http://repro@127.0.0.1:18734/1`로 바꿨다. 이벤트는 `/tmp/cattus-234-envelopes`에 수집한다. 초기 네 흐름에서는 PostHog 토큰을 비웠다. 아래 집중 화면 추가 검사에서는 SDK를 켜고 가상 토큰·로컬 수집 주소를 사용했다.
- 첫 실행 검사는 운영 API 설정으로 로그인 화면까지 검사한다. 운영 게스트 계정을 만들지 않는다.
- 로그인 이후 검사는 같은 네이티브 실행 파일에 `EXPO_PUBLIC_API_URL=http://127.0.0.1:18735`만 바꾼 실제 앱 번들을 넣었다. `EXPO_PUBLIC_DEMO=0`이며 앱의 인증·SecureStore·홈·회전 코드를 그대로 실행한다.
- 로컬 HTTP 서버가 가상 계정·섬을 반환한다. `/me`와 `/me/member-appearances`에 `401 UNAUTHORIZED`를 주고 `/auth/sessions/current/refresh`에서 200을 반환한다. 응답은 실제 사고의 데이터 전체를 복원한 것이 아니다. 부가 화면·WebSocket의 미구현 경로는 404다.

처음 사용한 로컬 오류 코드 `AUTH_TOKEN_EXPIRED`는 앱의 갱신 조건과 달라 `UNAUTHORIZED`로 교정했다. 교정 전 실행은 토큰 갱신 검증에 포함하지 않는다. 회전 후 iPad 창 모드에서 XCTest가 하단 버튼을 접근성 트리에 싣지 않는 경우가 있어, 회전 검사는 홈 제목의 접근성 확인과 스크린샷으로 검사한다. 최초 실패를 앱의 네이티브 크래시로 분류하지 않는다.

## 실행 기록

**2.3.4(13)을 iPad 10세대 / iOS 27.2 (`24B114`)에서 실제 실행했다. 다음 검사에서는 CATTUS-8의 크래시가 재현되지 않았다. 해결 완료 판정은 아니다.**

앱 실행 파일과 dSYM의 arm64 UUID는 모두 `8CA0554A-5451-35B4-B7B7-27DE2900D8B8`이었다. 메인 앱과 다섯 확장도 전부 2.3.4(13)이다. [빌드 정보](evidence/ios-2.3.4-2026-11-16/cattus-234-build-evidence.json)

## 11/17 추가 조사 — 사고 시간과 카메라 초기화 비교

Sentry 메일 본문의 CATTUS-8 발생 시각은 **2026-11-08 14:05:33 KST**다. 메일 도착은 14:05:59이며 발생 시각과 다르다. 실제 기기의 OS 빌드는 `24B119`, 사용한 시뮬레이터는 `24B114`다. 기기 종류와 OS 버전이 같아도 실기기 자체를 복원한 것은 아니다.

PostHog에서 같은 시각·iPad 10세대·iOS 27.2·2.3.4(13)에 해당하는 이용 기록을 찾았다. 다만 Sentry 기본 사용자 식별자와 PostHog의 식별자가 달라 동일 사용자의 사고로 직접 연결하지 못했다. 아래는 **재현 경로를 고르는 후보 근거**이며 원인 확정 자료가 아니다. 개인 식별자와 원본 메일은 저장소에 복제하지 않는다.

| 시각(KST)           | 관측                          |
| ------------------- | ----------------------------- |
| 13:47:43            | 집중 화면, AI 측정 켜짐       |
| 13:49:33            | 미리보기 열림                 |
| 13:49:54            | 집중 화면에서 백그라운드 이동 |
| **14:05:33**        | **Sentry CATTUS-8 발생**      |
| 14:05:37            | 후보 기기의 앱 열기           |
| 14:05:42 → 14:05:44 | 집중 → 휴식 화면              |

따라서 14:05:44의 휴식 전환을 크래시 원인으로 해석하면 시간 순서가 거꾸로다. 집중·AI 측정 상태에서 백그라운드로 갔다 돌아오는 경로를 추가 검사했다. 같은 후보 기록의 PostHog SDK 설정은 세션 리플레이를 끈 상태이며, 리플레이를 원인으로 단정할 근거도 없다.

추가 검사 번들은 실제 2.3.4 소스를 유지하고 PostHog를 `EXPO_PUBLIC_POSTHOG_PROJECT_TOKEN=phc_repro`, `EXPO_PUBLIC_POSTHOG_HOST=http://127.0.0.1:18734`로 켰다. 로컬 API에 활성 집중 세션·pause·resume 응답을 더해 실제 집중 화면으로 진입했다. Sentry와 API 주소도 로컬이며 외부 분석 프로젝트나 운영 DB에 가상 사용자 기록을 보내지 않았다.

### 재현된 별도 오류와 기존 수정의 효과

원본 2.3.4의 AI 측정을 켜자 다음 예외가 앱을 종료했다.

```text
OrientationManager.startOrientationUpdates(...):
Cannot listen to device orientation changes - accelerometer is not available!
RCTFatalException → EXC_CRASH / SIGABRT
```

VisionCamera의 `useOrientation` 구독 effect에서 가속도계가 없는 시뮬레이터에 방향 감지를 요청해 발생했다. 새 실행 파일과 `.ips`의 UUID는 모두 `8ca0554a-5451-35b4-b7b7-27de2900d8b8`이며 해당 dSYM도 확보했다. [크래시 요약](evidence/ios-2.3.4-2026-11-16/camera-initialization-crash.json), [원본 실패 결과](evidence/ios-2.3.4-2026-11-16/camera-before.xml). **CATTUS-8의 EXC_BREAKPOINT와 다른 크래시다.**

현재 코드에는 [PR #1622](https://github.com/OneOrThree/phone/pull/1622)의 `CameraErrorBoundary`가 이미 있다. 비교용 2.3.4 복사본에 이 예외 처리만 옮기고 같은 네이티브 실행 파일에 Release 번들을 다시 넣었다. 회전 판정이나 모델·Worklets 코드를 수정한 비교가 아니다. [적용한 최소 차이](evidence/ios-2.3.4-2026-11-16/camera-boundary-backport.patch).

예외 처리 후 같은 초기화 실패는 「카메라를 사용할 수 없어요.」와 재시도 버튼으로 처리되고 앱은 계속 실행됐다. **재시도·백그라운드 복귀·회전 3회 검사는 75초에 통과**했다. [JUnit](evidence/ios-2.3.4-2026-11-16/camera-after.xml), [Maestro 흐름](evidence/ios-2.3.4-2026-11-16/camera-after.yaml), [실제 화면](evidence/ios-2.3.4-2026-11-16/camera-unavailable-alive.png).

이어서 집중→휴식→집중을 세 번 전환하고 마지막 집중 화면까지 확인했다. [추가 JUnit](evidence/ios-2.3.4-2026-11-16/focus-rest-after.xml), [휴식 화면](evidence/ios-2.3.4-2026-11-16/rest-visible.png), [복귀한 집중 화면](evidence/ios-2.3.4-2026-11-16/focus-after-rest.png). [실행 파일 해시와 크래시 목록](evidence/ios-2.3.4-2026-11-16/camera-comparison-result.json)도 보관했다.

현재 저장소에는 effect 초기화 예외도 안내·재시도로 복구하고 실패 중 인증 시간을 적립하지 않는 회귀 검사를 추가했다. 카메라·세션 Jest **58건**, 변경 테스트 파일 ESLint·Prettier, 전체 TypeScript 검사를 통과했다. 실제 서비스의 예외 처리 구현은 이미 있으므로 중복 수정하지 않았다.

이 비교는 **카메라를 사용할 수 없을 때 앱 종료를 막는 효과**를 확인한다. 시뮬레이터에서 실제 촬영·가속도계·프레임 콜백을 검증한 것이 아니다. 따라서 실기기 카메라가 작동하던 CATTUS-8과 기존 네이티브 작업 수명 수정의 운영 효과까지 증명하지 않는다.

## 판정 기준

빌드 성공, 첫 화면 성공, 특정 재현 흐름 성공은 서로 구분한다. CATTUS-8의 해결 판정에는 해당 크래시의 재현과 수정 전후 검증, 또는 원본 사고를 해독한 원인 확인이 더 필요하다. 이번 재빌드의 dSYM을 과거 UUID `53ca47a9-42aa-3e6f-b33c-3f30568f5b52`에 대응하는 심볼로 업로드해서는 안 된다. 실기기 설치·TestFlight 업로드·운영 배포는 이번 실행에 포함하지 않는다.

이번 결과는 원본 소스를 재빌드해서 첫 실행과 사고 주변 경로를 조사할 수 있음을 보여준다. 실제 사고 당시의 응답 데이터·로컬 저장 상태·실기기 카메라 프레임을 복원한 검사는 아니다. **CATTUS-8의 원인은 아직 확정하지 못했고, 이 조사로 새 크래시 수정 코드를 추가하지 않았다.** 기존 카메라 수명 및 dSYM 업로드 수정은 [별도 기록](2026-11-16-camera-and-dsym.md)의 근거와 한계를 유지한다.
