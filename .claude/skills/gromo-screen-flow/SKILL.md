# gromo-screen-flow — 앱 화면 흐름도를 피그마에 올리기

gromo 2.0 앱(이 레포의 `app/app-dev`, React Native + Expo)의 화면 전체를 피그마 한 페이지에 "누르면 어디로 가는지"가 보이게 올린다. 2026-10-05에 화면 215개·화살표 195개로 처음 만들었고, 이 스킬은 그때 통한 방법과 막혔던 곳을 정리한 것이다. 문서에 나오는 "오스카"는 이 스킬의 오너(레포 소유자)다.

## 결과물

피그마 `new-design` 파일(fileKey `XzlUvx1LGl5OZt6wHr2WRg`)의 "화면 워크플로우" 페이지.

- **안내판 1개**(읽는 법·묶음 목록·알아둘 점)와 **묶음 13개**(온보딩, 몽돌 튜토리얼, 홈, 집중, 스크린타임 권한, 마을회관, 게시판, 도서관, 전망대, 우체통·친구, 상점, 내 뗏목, 공용 팝업).
- 화면은 폰 크기(402×874) 캡처. 팝업·확인창·바텀시트는 주황 테두리, 전환 장면은 보라 테두리.
- **빨간 굵은 화살표** = 누르면 가는 길. 누르는 버튼에 빨간 테두리를 치고 화살표가 거기서 출발한다. 옆 굵은 글씨가 "무엇을 누르는지".
- 회색 점선 = 누르는 것이 아니라 조건에 따라 보이는 모습(비었을 때, 방장이 아닐 때 등).
- 화살표로 못 그린 나머지 이동은 화면 아래 글로 적는다(파란 글씨 = 다른 묶음으로 이동).

## 먼저: 어떤 작업인지 가른다

| 요청 | 할 일 |
|---|---|
| 처음부터 전체 / 크게 바뀜 | 아래 파이프라인 1~7 전부 |
| 코드가 조금 바뀌어 갱신 | "갱신할 때" 절 |
| 화면 한두 장 교체 | `references/figma-upload.md`의 "한 장 교체" |
| 웹에서 안 뜨는 화면(공유 창, 스크린타임 창) | `references/simulator.md` → "한 장 교체" |

지난 실행 결과가 있으면 거기서 시작한다. 화면마다 그 상태에 도달하는 방법(캡처 설정)을 찾는 것이 전체 시간의 대부분이었고, 그게 이미 적혀 있다.

## 준비물

- **macOS.** `make-jpg.sh`는 `sips`, `upload-svgs.sh`·`simulator.md`는 BSD `stat -f`를 쓰고, 시뮬레이터 보완은 Xcode가 필요하다. 리눅스에서는 그 부분을 바꿔야 한다.
- 레포를 `npm ci`한 상태(`app/app-dev/node_modules/playwright`를 쓴다 — 따로 설치하지 않는다).
- Figma MCP(`upload_assets`, `use_figma`)가 연결된 Claude Code. 대상 파일 `new-design`에 편집 권한.
- 시뮬레이터 보완까지 하려면 Xcode와 Maestro(`brew install maestro`).

## 작업 폴더와 스크립트

- **스크립트** `SK` = `<레포>/.claude/skills/gromo-screen-flow/scripts`. 결과물은 전부 작업 폴더에 쓴다. 다만 묶음 정의(`sections.cjs`)와 합치기 규칙(`merge.cjs`의 `alias`·`unusedRoutes`)은 앱이 바뀌면 스크립트를 직접 고친다.
- **작업 폴더** `WF` — 이동 지도, 캡처 설정, 캡처 원본, 그림이 놓이는 곳. 스크립트가 고르는 순서: 환경변수 `WF_DIR` → `~/soma/capture-catus`(오스카의 보관 폴더, 있을 때만) → `<레포>/app/app-dev/.docs/screen-flow`(gitignore 돼 있음). 스크립트를 돌리면 첫 줄에 어느 폴더인지 찍힌다.
- **처음 쓰는 기계에서는** 작업 폴더가 비어 있다. 스킬의 `last-run/`(지난 실행의 캡처 설정, 하네스 사본, 이동 지도, 보고, 튜토리얼 단계, 시뮬레이터 조작 파일, `run.json`)을 작업 폴더에 복사해서 시작한다. 화면마다 그 상태에 도달하는 방법이 전부 거기에 있다.
  ```sh
  cp -R <레포>/.claude/skills/gromo-screen-flow/last-run/. $WF/
  ```
  캡처 원본(`shots/final/`, 모아보기 `_sheet-*.png`)은 레포에 없다. 그래서 처음 쓰는 기계에서는 "갱신"이 아니라 **전체 재캡처**가 되고, 지난번과 나란히 비교할 모아보기도 없다. 캡처 없이 `layout.cjs`만 돌리면 화면 자리가 전부 빈 틀("캡처 없음")로 나온다 — 그림의 뼈대를 확인하는 용도로만 쓴다.
- `run.json`에 지난 실행의 커밋·개수·피그마 프레임 id·캡처용 시뮬레이터 id가 있다. 시뮬레이터 id는 오스카 기계의 것이라 다른 기계에서는 새로 만든다.
- 스크립트가 레포 밖에서 돌 때(작업 폴더 안에서 하네스 사본을 돌릴 때 등) 앱 위치는 환경변수 `GROMO_APP=<레포>/app/app-dev`로 알려 준다. 없으면 `~/soma/phone/app/app-dev`로 간주한다.

| 스크립트 | 하는 일 |
|---|---|
| `merge.cjs` | 묶음별 이동 지도(`nav-*.json`) → `merged.json` |
| `sections.cjs` | 묶음 13개 정의 |
| `gen-targets.cjs` | 캡처 담당별 대상 목록 `capture/targets-*.json` |
| `capture.cjs` · `capture-example.cjs` | 웹 캡처 하네스와 설정 예시 |
| `contact-sheet.cjs` | 폴더의 캡처를 한 장에 모아 보기 |
| `promote.cjs` | 다시 찍은 캡처를 `shots/final/`로 옮기기(시뮬레이터 캡처는 보존) |
| `hot-hook.cjs` · `gen-hotspots.cjs` | 화면마다 누를 수 있는 것의 자리를 저장하고, 이동마다 버튼을 찾기 |
| `make-jpg.sh` | 캡처를 가벼운 JPEG로 |
| `layout.cjs` | 묶음별 그림(SVG) 생성. `EMBED=1`이면 캡처를 품은 업로드용 |
| `preview.cjs` | 그림을 PNG로 미리보기 |
| `upload-svgs.sh` | 업로드용 그림을 피그마로 전송 |

## 파이프라인

단계별 방법과 에이전트에게 줄 지시문은 references에 있다. 조사와 캡처는 양이 많아 서브에이전트에 나눠 병렬로 맡긴다. 한 번에 5~7개가 적당했다.

1. **화면 이동 지도 뽑기** — 코드에서 "화면, 누르는 것, 도착 화면"을 뽑는다. 화면 주소(route) 54개만 세면 안 되고 상태·팝업·시트까지 봐야 한다(실제로 208개가 나왔다). → `references/nav-extraction.md`. 끝나면 `node $SK/merge.cjs`.
2. **웹 빌드와 서버** — 캡처는 웹의 연습용 모드에서 한다. 화면 상태를 코드로 바로 만들 수 있어 200장을 자동으로 찍을 수 있기 때문이다. → `references/capture.md`
3. **캡처** — `node $SK/gen-targets.cjs`로 담당을 나누고, 담당마다 설정 파일을 써서 찍고, 모든 장을 눈으로 확인한다. 화면마다 ok / approx / uncaptured와 이유를 남긴다. → `references/capture.md`
4. **버튼 자리** — 같은 설정을 `hot-hook.cjs`를 끼워 한 번 더 돌리고 `node $SK/gen-hotspots.cjs`. 화살표가 버튼에서 출발하게 하려는 것이다. → `references/capture.md`
5. **그림 만들기** — `$SK/make-jpg.sh 76` → `node $SK/layout.cjs` → `node $SK/preview.cjs`로 두세 묶음을 눈으로 확인 → `EMBED=1 node $SK/layout.cjs`.
6. **피그마에 올리기** — 그림 파일을 통째로 올린다. 화면 데이터를 피그마 코드에 타이핑하지 않는다. → `references/figma-upload.md`
7. **네이티브 화면 보완** — 아이폰이 직접 그리는 화면은 시뮬레이터에서 찍어 그 화면만 갈아 끼운다. → `references/simulator.md`

마지막에 `WF/run.json`을 새 커밋·개수·프레임 id로 고친다. 다음 갱신의 기준점이다.

## 갱신할 때

1. **범위 가늠.** 빌드는 늘 작업 폴더 그대로를 쓰므로 커밋 안 된 수정까지 본다: `git status --short`, `git diff --stat <run.json의 head> -- app/app-dev/src`. 단, 지난 실행(2026-10-05)의 `run.json`은 `note`대로 커밋 안 된 수정이 섞인 작업 폴더에서 찍은 것이라 `head`와의 diff가 바뀐 양을 **적게** 보여 준다(이동 지도의 `source` 줄번호도 그 코드 기준). 다음 실행부터는 깨끗한 커밋에서 찍고 그 해시를 `head`에 적는다.
2. **다시 찍기.** 웹 빌드를 새로 만들고, `WF/capture/`의 기존 설정을 새 폴더로 돌린다(`CAPTURE_OUT=$WF/shots-new/<담당>`). 설정 파일 머리말에 정확한 명령이 있고, 명령이 여러 개인 담당은 전부 돌린다. 전체가 3분쯤이다. 모아보기를 지난번(`shots/<담당>/_sheet-*.png`)과 나란히 보고, `-FAILED.png`가 나오거나 달라진 장의 설정만 고친다.
3. **최종으로 옮기기.** `node $SK/promote.cjs $WF/shots-new/<담당>`. 시뮬레이터로 찍어 둔 화면은 웹 캡처로 덮이지 않게 건너뛴다.
4. **이동 지도.** 화면이 생기거나 없어진 묶음만 다시 뽑는다.
5. **그림과 피그마.** 4~6단계를 다시 한다. 피그마 쪽은 바뀐 정도에 따라 고른다.
   - 캡처만 바뀌고 화면·화살표 구성이 그대로면 → 바뀐 장만 "한 장 교체".
   - 한 묶음의 구성이 바뀌었으면 → 그 묶음 그림만 올리고(`ONLY=07-board`) 옛 프레임을 지운 뒤 정리 스크립트로 전체를 다시 줄 맞춘다.
   - 여러 묶음이 바뀌었으면 → 전부 다시 올린다.

   프레임을 지우기 전에 오스카에게 묻는다. 그 페이지에 손으로 고치거나 댓글을 단 것이 있을 수 있다.

## 오스카가 정한 것

- 팝업·바텀시트·확인창까지 전부 포함한다. 세로 화면만(가로는 같은 화면을 눕힌 것).
- 화살표는 빨간색으로 굵게, 실제 누르는 버튼 위치에서 출발.
- 오스카 기계에서는 캡처 원본과 결과를 `~/soma/capture-catus`에 보관한다(스크립트 기본값). 다른 기계에서는 레포의 `app/app-dev/.docs/screen-flow`에 쌓이고 커밋되지 않는다.
- 피그마에 적는 글은 초보도 읽을 수 있는 한국어로. "연습용 모드(서버 없이 가짜 데이터)"처럼 풀어 쓴다.
- 기존 "화면 플로우" 페이지와 v2~v4 시안 페이지는 건드리지 않는다. v4에는 삭제된 앵무새 안내가 남아 있어 그대로 복사하면 안 된다.

## 어느 단계에서든 지킬 것

- **깔려 있는 앱·빌드를 믿지 않는다.** 시뮬레이터 앱도, 레포의 `dist/`도 옛것일 수 있다. 옛 빌드로 본 것을 앱의 한계로 단정했다가 틀린 적이 있다. 언제 만든 것인지 확인하고 쓴다.
- **레포는 읽기만 한다.** 캡처·그림·임시 파일은 `WF`나 스크래치패드에 쓴다. 시작할 때 `git status`를 보고, main에 커밋 안 된 남의 수정이 있으면 "그 상태 그대로 찍었다"고 보고에 적는다.
- **내가 띄우지 않은 프로세스는 건드리지 않는다.** 8081의 개발 서버나 켜져 있는 시뮬레이터는 다른 작업이 쓰고 있을 수 있다. 다른 포트, 따로 만든 시뮬레이터를 쓴다.
- **끝났다고 말하기 전에 피그마에서 다시 캡처해 눈으로 본다.** 묶음 하나와 확대한 한 구역이면 된다.

## 있는 그대로 표시한다

웹 연습용 모드는 실제 폰과 다르다. 감추지 않고 그림 안에 적는다. `layout.cjs`가 `shots/report-*.json`을 읽어 화면 아래에 넣는다.

| report의 값 | 그림에 나오는 것 |
|---|---|
| `status: "approx"` | "※ 실제와 다를 수 있음: 이유" — 서버 전용 화면을 조건을 풀거나 가짜 응답으로 찍은 것 |
| `status: "uncaptured"` | 빈 틀에 "캡처 없음"과 이유 |
| `via: "simulator"` | "※ 아이폰 시뮬레이터에서 찍은 실제 화면 (날짜)" |

버튼을 못 찾은 화살표는 화면 가장자리에서 출발한다(글자 없는 건물 그림·아이콘, 자동 전환).

## 끝낼 때

- 내가 띄운 서버·번들러·시뮬레이터를 정리하고, 레포 `git status`가 시작 때와 같은지 본다.
- 보고에는 링크, 화면·화살표 개수, approx·uncaptured 개수와 이유, 남은 것을 적는다.
- 캡처하다 눈에 띈 앱 문제는 따로 모아 준다. 확인 수준을 구분한다: [재현] 실제로 일어남 / [화면] 캡처에서 봄 / [코드] 코드만 읽음.
