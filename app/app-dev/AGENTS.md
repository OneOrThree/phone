# AGENTS.md — GroMo 활성 2.0 앱

이 파일은 `app/app-dev/` 아래에서 작업하는 모든 에이전트에게 적용되는 앱 전용 규칙이다.
저장소 루트의 `AGENTS.md`와 `CLAUDE.md`를 대체하지 않으며, UI·디자인 작업 규칙을 추가한다.

## UI 작업의 필수 진입점

화면, 컴포넌트, 스타일, Figma 시안과 관련된 작업을 시작하기 전에 다음 문서를 먼저 읽는다.

- `DESIGN.md`

이 문서는 색·타이포·간격·컴포넌트·기능 패턴을 흡수한 에이전트용 단일 디자인 명세이다. 기본적인 UI 판단은 이 문서만으로 완료하고, 연결된 HTML·PNG·코드는 시각 검증이나 실제 구현이 필요할 때 추가로 확인한다.

로컬 `.docs`가 없는 환경에서는 아래 코드 정본을 먼저 확인하고, UI Kit 문서가 없다는 사실을 작업 결과에 명시한다.

- `src/design-system/tokens.ts`
- `src/design-system/primitives.tsx`
- `src/design-system/patterns.tsx`
- 구현하려는 기능과 가장 가까운 기존 화면

## 디자인 정본과 우선순위

1. 디자인 의도와 시각 규칙: `DESIGN.md`
2. 실제 앱 토큰과 공용 구현: `src/design-system/`
3. 화면별 사용 방식: 현재 구현된 2.0 화면
4. 새 화면의 임시 판단: 위 세 계층에 없는 경우에만 허용

문서와 코드의 값이 다르면 제3의 값을 새로 만들지 않는다. 이를 디자인 드리프트로 보고 차이를 알린 뒤, 작업 범위가 허용하면 문서와 코드를 함께 맞춘다.

## 반드시 지킬 UI 규칙

- 주간 기본 팔레트는 딸기 소다이다. Primary는 핑크, Secondary는 하늘색, Accent는 버터색이다.
- 임의의 초록색, 파란색, 보라색을 주요 CTA나 선택 상태에 사용하지 않는다.
- `forest`, `sage` 같은 과거 이름만 보고 실제 초록색을 추론하지 않는다. 주간 테마에서 이 별칭은 각각 핑크와 버터 계열에 연결된다.
- 화면과 기능 컴포넌트에 색상·간격·반경·그림자를 임의 하드코딩하지 않는다. 기존 semantic token 또는 component token을 사용한다.
- 같은 역할의 공용 컴포넌트나 패턴이 있으면 새 로컬 컴포넌트를 만들기 전에 재사용한다.
- 최소 터치 영역 44pt, 접근성 라벨, 텍스트 대비와 동적 글자 크기를 확인한다.
- 기존 구현은 동작과 정보 구조의 참고 자료이며, 우연히 들어간 로컬 스타일을 새 정본으로 승격하지 않는다.
- Figma의 연결 라이브러리가 비어 있어도 UI Kit가 없다고 판단하지 않는다. 먼저 로컬 UI Kit와 앱 코드를 확인한다.

## 화면 설계 순서

1. `DESIGN.md`에서 관련 토큰, 공용 컴포넌트, 기능 정책을 확인한다.
2. 시각적 판단이 더 필요할 때만 연결된 HTML·PNG 표본을 연다.
3. 가장 가까운 기존 화면에서 현재 정보 구조와 상태를 확인한다.
4. Primitive → Semantic → Component 순서로 토큰을 선택한다.
5. 기존 패턴으로 해결되지 않는 부분만 확장한다.
6. 새 토큰이나 컴포넌트를 추가했다면 `DESIGN.md`와 코드 정본을 같은 작업에서 갱신한다.
7. 결과물에서 재사용한 컴포넌트, 새로 만든 요소, 남은 드리프트를 구분해 보고한다.

## 금지 사항

- UI Kit 확인 없이 생성형 도구의 기본 팔레트나 기본 버튼을 사용하지 않는다.
- 디자인 토큰이 있는데 raw hex, 임의 spacing, 임의 radius를 새로 넣지 않는다.
- 단일 화면 편의를 위해 공용 컴포넌트와 거의 같은 복제 컴포넌트를 만들지 않는다.
- Figma 라이브러리 검색 결과만 근거로 “연결된 디자인 시스템이 없다”고 단정하지 않는다.
