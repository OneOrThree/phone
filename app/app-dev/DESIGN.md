## 신고센터 — 승인한 단일 메일 진입 (2026-10-20)

- 내 뗏목 → 설정 → 안전에 `신고센터` / `이메일로 신고하기`를 일반 `SheetRow`로 둔다. 기존 설정과 같은 `SheetGroup flat`이며 전용 핑크 배경·외곽 테두리·그림자를 추가하지 않는다. 차단한 사용자 관리는 같은 안전 그룹 첫 줄(신고센터 위) 「차단한 사용자」 `SheetRow`(부제 `settings.blockedUsersSub`)에서 연다 — 친구 관리 머리의 진입은 뺐다(2026-10-26 GROMO-2473).
- 누르면 기기 메일 앱에 운영팀 수신 주소·제목·작성 안내를 채운다. 내용 작성·캡처 첨부는 메일 앱에서 한다. 앱에 별도 신고 작성 화면이나 첨부 UI를 만들지 않는다.
- 메일 열기 실패 시 주소와 직접 메일 보내는 방법을 확인창으로 안내한다. 메일 창 열기를 접수·발송 완료로 표현하지 않는다. 한국어·영어 작성 안내와 접근성 이름을 제공한다.
- 신고센터 바로 아래에 `문의하기` / `오류 제보·기능 제안` 행을 같은 방식으로 둔다(GROMO-2383). 수신 주소는 신고센터와 같고 제목 말머리 `[집중할고양 문의]`로 구분하며(신고는 `[집중할고양 신고]`, 앱 이름은 i18n `onboardingStory.brand` 를 따른다), 본문 안내 끝에 앱 버전과 기기 OS를 채운다. 실패 안내·완료 표현 규칙은 신고센터와 같다.
- 잡지의 길게 누르기·접근성 신고와 홍보 칸 신고 시트, 친구/받은 요청/편지 메뉴의 신고 진입은 제거한다. 사용자 메뉴는 기존 차단·친구 삭제를 유지한다. 방명록은 섬장에게 글 지우기만 제공하고 차단 진입은 두지 않는다. 사용자 차단은 친구 관리의 사용자 메뉴에서 하고(2026-10-25), 차단한 사용자 목록·해제는 앱 설정 → 안전에서 한다(2026-10-26).

## 출항 준비 영상 — 먼바다·집중섬 공통 (2026-10-20 승인)

- 뗏목 「바다로 출항」과 「집중하러 가기」, 홈 집중 시작의 `focusTravel`은 같은 `DepartureStory`를 쓴다. 출항 준비는 `ota/cutscenes/departure.mp4`(4초, 회색 고양이, 무음 세로 영상)를 `VideoCutscene`이 자동 재생하며, 동작 줄이기에서는 건너뛴다. 영상 상자는 화면 높이에 맞춘 9:16 이라 세로 폰에서는 위아래를 꽉 채우고 좌우가 한쪽에 최대 10%쯤 화면 밖으로 나가며, 태블릿·가로처럼 납작한 화면에서는 좌우에 여백을 두고 전체를 보인다(위아래 띠를 두면 영상 가장자리의 섬·부두가 잘린 것처럼 보인다). 별도 글자·건너뛰기·첫 출항 이력은 두지 않는다. 영상 컷신 다섯 편(출항·섬 도착·항해 중단·황금 물고기·펠리컨 배달)은 2026-10-20 제작 조건대로 고정 회색 고양이이며 내 털색·꾸미기를 합성하지 않는다(§7.9의 예외). 영상이 첫 프레임을 못 그리면 뒤 장면을 Cinematic overlay로 덮은 채 최대 8초 기다렸다가 건너뛴다.
- 끝나면 바다는 `sea`, 집중섬은 기존 `fishingArrival`로 이어진다. 방문 중 떠나기 확인·가입은 출항 전에 유지하고, 방문 상태는 완료 때 정리한다. 복귀·휴식 항해는 기존 Sailing을 유지하고, 소속 섬 사이 항해는 도착 영상(§8.16)을 쓴다. 한국어·영어 접근성 설명으로 목적지와 동작을 알린다.

## 다른 고양이 정보창 — 홈·집중섬·먼바다·휴식 공통 (2026-10-26, GROMO-2474)

- 홈 섬, 집중섬(자리 고르기·집중 중·낚시 구경), 먼바다 표류, 휴식(모닥불)에서 다른 고양이를 누르면 가운데 정보창(`IslandPopup`)이 뜬다. 오른쪽 위 ×·바깥 누르기·안드로이드 뒤로 가기로 닫는다. 내 고양이를 누를 때의 반응(홈 모션·바다 내 카드)은 그대로다. 신원이 없는 고양이(목업 보충 고양이·서버 방문 섬의 연출 고양이)는 누를 수 없다.
- 코드는 `screens/island/CatInfoPopup` 하나다. 고양이 터치 영역은 44pt 이상이고 접근성 이름은 「{이름} 정보 보기」다. 정보창이 뜬 동안 뒤 장면은 스크린리더에서 숨긴다.
- 위에서부터 고양이 그림 → 닉네임(두 줄까지) → 「오늘 집중 N시간 N분」 한 줄 → 행동 하나다. 그림은 장면과 같은 그리기 부품·털색·착용을 멈춘 채로 쓴다: 홈 idle, 집중섬 낚시 자세와 낚싯대, 바다 뗏목(`SeaRaft`), 휴식은 그 자리의 자세(식빵·책 읽기, `restPose`). 크기는 `componentTokens.catInfoPopup`(고양이 112 · 뗏목 160)이다.
- 바다 표류에서만 상대의 한마디를 고양이 머리 위 말풍선으로 보인다. 바다 장면 말풍선(Paper 90% · 반경 Control 14)에 Brown 1.5 선과 아래로 향한 꼬리를 두고, 최대 폭 240 안에서 한마디 전체를 줄바꿈해 보인다. 한마디가 없으면 말풍선이 없고, 다른 장면에는 말풍선이 없다.
- 「오늘 집중」은 서버 값만 쓴다 — 친구 목록(`GET /screens/friends`)의 `focusTimeMinutes`(오늘)다. 친구가 아니면 값이 없어 줄을 비운다. 상태·과목·세션 시계는 두지 않는다(바다·집중섬 참가자의 집중 시간은 이번 세션 값이라 오늘 합계가 아니다).
- 행동: 요청 가능 [친구 요청] · 받은 요청 [친구 요청 수락] · 보낸 요청 [요청 중](비활성) · 친구는 버튼 대신 `Badge` soft 「친구」 · 처리 중 [처리 중…](비활성) · 실패는 안내 한 줄 「요청을 보내지 못했어요. 다시 눌러 시도해 주세요.」와 원래 버튼. 영어는 Add friend · Accept friend request · Requested · Friends · Processing…다. 설명 문장을 덧붙이지 않는다.
- 관계·명령은 친구 관리와 같은 정본(`useFriendsScreen`)이다. 요청은 `POST /friends/requests`, 수락은 받은 요청의 `requestId`로 `POST /friends/requests/{id}/accept`다. 서버 성공 뒤에만 버튼이 바뀌고 목록을 다시 읽으며, 중복 입력은 막는다. 이미 친구·이미 보낸 요청·먼저 처리된 요청은 안내 없이 목록을 다시 읽어 버튼을 맞추고, 게스트 거절은 회원 전환을 연다. 정보창을 닫았거나 다른 고양이로 바뀌었거나 계정이 바뀐 뒤 도착한 응답은 화면을 바꾸지 않는다.
- 글자는 고운돋움 하나다(§5.1 예외). 버튼 글자는 `Btn.font`로 넘기고, 「친구」 배지는 공용 `Badge` 글꼴 그대로다.
- 목업 모드는 로컬 친구 목록으로 같은 상태를 보이고 로컬 리듀서로 요청·수락한다(캡처용). 차단한 상대의 진입점 숨김은 GROMO-2470에서 다룬다.

## 1. 문서의 권한과 범위

UI·화면·컴포넌트·Figma 시안을 만들 때는 이 문서를 먼저 읽는다. 색, 글자, 간격, 형태, 상태, 공용 컴포넌트의 사용 원칙은 이 문서만으로 결정할 수 있어야 한다.

이 문서에서 `tokens.json`, `components/`, `foundations/`, `runtime/`처럼 적은 UI Kit 경로는 모두 `.docs/project-context/ui-kit/`를 기준으로 한다. 앱 코드 경로인 `src/design-system/`은 `app/app-dev/`를 기준으로 한다.

기존 파일의 역할은 다음처럼 제한한다.

| 원본                                     | 남겨 두는 이유        | 언제 추가로 여는가              |
| ---------------------------------------- | --------------------- | ------------------------------- |
| `tokens.json`, `tokens.css`              | 기계가 읽는 토큰 원본 | 자동 변환·동기화·값 대조 시     |
| `components.json`                        | 컴포넌트 인덱스       | 자동화 도구가 목록을 읽을 때    |
| `foundations/`, `components/`의 HTML·PNG | 렌더링된 시각 표본    | 모양과 상태를 눈으로 검증할 때  |
| `runtime/`의 JS·CSS                      | 모션 시연             | 낚시·휴식·항해 동작을 검증할 때 |
| `src/design-system/`                     | 앱 런타임 코드 정본   | React Native로 구현할 때        |

HTML에 내장된 이미지 데이터와 실행 코드는 이 문서에 복제하지 않는다. 그 외 에이전트가 UI를 판단하는 데 필요한 규칙과 제품 정책은 이 문서가 흡수한다.

### 충돌 처리

- 디자인 의도는 이 문서가 정본이다.
- 실제 출시 앱의 현재 동작은 `src/design-system/`이 정본이다.
- 둘이 다르면 임의의 제3 값을 만들지 않는다. 차이를 디자인 드리프트로 기록하고 같은 작업에서 양쪽을 맞춘다.
- 특정 화면의 로컬 스타일은 공용 디자인 시스템의 근거가 아니다.

## 2. 디자인 성격

GroMo 2.0은 장기 시험·자격 준비생이 함께 공부하는 섬이다. UI는 생산성 도구처럼 차갑거나 게임처럼 과도하게 장식적이지 않아야 한다.

- **따뜻함:** Cream 바탕과 Paper 표면 위에 Pink·Sky·Butter를 사용한다.
- **손으로 붙인 느낌:** Brown 윤곽선과 단단한 스티커형 그림자를 쓴다.
- **또렷함:** 본문은 Ink, 보조 정보는 Muted로 역할을 분리한다.
- **생활감:** 고양이, 배, 섬의 그림은 정보와 상태를 설명할 때 사용한다.
- **절제:** 한 화면의 강한 색은 행동, 선택, 상태 전달에만 쓴다.

임의의 초록색 CTA, 무채색 SaaS 카드, 보라색 그라데이션, 흐릿한 회색 블러 그림자를 기본값으로 사용하지 않는다.

## 3. 토큰 체계

모든 스타일 결정은 다음 계층을 따른다.

```text
Primitive → Semantic → Component → Screen composition
```

- **Primitive:** 원색, 고정 간격, 기본 반경, 지속 시간
- **Semantic:** `canvas`, `surface`, `text`, `primary`, `outline`처럼 역할을 가진 값
- **Component:** 버튼, 카드, 입력창, 배지처럼 특정 요소의 값
- **Screen:** 기존 토큰과 컴포넌트의 조합. 화면에서 새 원시값을 만들지 않는다.

새 코드는 `semanticTokens` 또는 `componentTokens`를 우선한다. `C.*`는 기존 화면 호환 별칭이다.

마을 건물의 새 소식 배지와 툴팁 치수는 `componentTokens.villageNotificationBadge` 및 `componentTokens.villageNotificationTooltip`에서 관리한다. 게시판·우체통·도서관이 같은 크기와 윤곽을 공유하고, 지도 배율은 배지 토큰 치수에 곱해 적용한다. 타일섬과 일반 이미지 섬에서는 완공된 건물·뗏목·모닥불에 작은 나무 팻말을 표시한다. 이름은 빈 팻말 에셋 위에 현재 언어의 텍스트로 얹고, 팻말을 눌러도 같은 장소로 진입한다. 팻말은 화면 오버레이에 배치하되 나무 이미지·글자·간격을 건물과 같은 배율로 확대·축소한다. 기본 카메라에서 정한 크기와 충돌 회피 위치를 함께 변환해 건물 대비 크기·상대 위치가 유지되며, 핀치 중 팻말을 다시 밀어내지 않는다. 기본 카메라의 가로폭은 이름 길이에 따라 64·88·112pt, 높이는 기본 64pt 팻말의 원본 비율로 정해 긴 영어 이름은 가로로 넓힌다. 시스템 글자 크기 설정은 팻말 크기에도 반영한다. 이름과 상태는 건물 터치 영역의 접근성 라벨로도 제공한다. 외곽선·누름·팻말 치수는 `componentTokens.tileFacility`를 사용한다.

- 목록 항목마다 같은 제목(지우기·신고)이 되풀이되면 `accessibilityLabel` 에 어느 글·누구인지 덧붙인다(`지우기: 글 내용`). 기본은 `title` 이다.
- 제목만으로 안 읽히는 «누르면 일어날 일»은 `accessibilityHint` 로 덧붙인다. 흐리게 보이지만 눌러서 확인창을 여는 버튼(망원경의 항해 중 [망원경에서 빼기])은 `disabled` 로 막지 않는다 — 막으면 스크린리더 사용자가 확인창에 닿지 못한다. 모양만 비활성 opacity 로 흐리고 힌트로 이유를 말한다.

**소셜 로그인 버튼** — Apple·Google 은 한 틀로 그린다(`componentTokens.loginButton`). 최소 높이 54(큰 글자에서 늘어난다), pill, 로고 20 상자를 왼쪽 20 에 고정하고 라벨은 가운데 Body semibold. 색만 브랜드별이다 — Apple 은 Black 바탕·흰 로고·글자, Google 은 White 바탕·Google Border 1px·Google Text. 로고는 `components/ProviderLogo` 의 SVG 를 쓴다(iOS 네이티브 Apple 버튼은 글꼴·로고를 시스템이 정해 다른 버튼과 맞출 수 없어 쓰지 않는다). 그 아래 보조 행동 「게스트로 시작하기」는 `Btn` Secondary이고 소셜 버튼과 같은 최대 폭 360이다.

### 7.14 Navigation and overlays

- 뒤로·닫기는 공용 `NavBtn`(`design-system/patterns`, 치수 `componentTokens.navButton`) 하나다. Paper 원 34 + Brown 1.5px 선 + `0 2px 0 Brown` 그림자 안에 Ink 선형 아이콘 18을 둔다. 누르는 자리는 원을 가운데에 둔 44×44 상자이고, 비활성은 0.45 투명도에 그림자를 뺀다.
  - **‹(기본)** — 지금 장면을 떠나거나 한 단계 위로 돌아갈 때. 건물 안(게시판 · 우체통 · 마을회관 · 축음기 · 도서관) · 망원경 · 낚시섬 구경 · 일기장은 화면 왼쪽 위, 게시판 공지·퀘스트 상세·쓰기와 우체통 종이의 한 단계 뒤로는 종이 왼쪽 위다.
  - **×(`close`)** — 장면 위에 뜬 시트·패널·말풍선·게시판 종이를 닫고 그 장면에 남을 때. 머리 오른쪽 위에 둔다.
  - 같은 곳으로 가는 ‹와 ×를 한 화면에 같이 두지 않는다(일기장은 ‹ 하나). 시트 머리처럼 ‹(한 단계 위)와 ×(시트를 닫고 섬으로)가 서로 다른 곳으로 가면 둘 다 둔다.
  - 글자 알약(「뒤로」 · 「닫기」 · 「돌아가기」), 밑줄 글자(「← 목록」), 글자 ‹·×를 뒤로·닫기로 쓰지 않는다. ‹의 읽는 이름은 목적지가 정해져 있으면 그 목적지를 말하고(「섬으로 돌아가기」 · 「공지 목록으로 돌아가기」 · 「이웃들의 일기장으로 돌아가기」), 들어온 화면에 따라 목적지가 달라지면 「뒤로」다(시트 머리 · 망원경 · 일기장 첫 화면). 「닫기」는 ×에만 쓴다(「게시판 닫기」).
  - 크림 `Page` 머리 막대(§7.1)의 chevron은 막대 안 기본 머리라 이 규칙 밖이다.
- 설정, chevron은 Brown/Ink 선형 아이콘을 사용한다.
- 탭·세그먼트·칩은 선택 상태를 `accessibilityState`에도 반영한다.
- 오버레이 뒤 콘텐츠는 스크린 리더 탐색에서 숨긴다.
- 섬 위 팝업(`IslandPopup`)은 표현만 한다. 열려 있는 동안 모달이라는 것은 iOS `accessibilityViewIsModal` 로만 알리고, Android 뒤로 가기와 Android 스크린리더용 숨김(`importantForAccessibility="no-hide-descendants"`)은 호출자가 맡는다. 뒤로 가기는 `e.backOverride` 로 팝업 닫기를 건다(App 의 뒤로 가기 핸들러는 방문 분기보다 먼저 열린 확인창·건물 전환·`backOverride` 를 본다). 숨김은 팝업 뒤 장면을 감싸는 쪽이 건다(방문 지도 `visit-scene`).
- 키보드가 열린 상태에서도 입력과 CTA가 가려지지 않아야 한다.

#### 몽돌 튜토리얼 스포트라이트

- 실제 조작 대상의 영역만 선명하게 두며, 딤은 `semanticTokens.color.overlay`를 사용한다. 인접 버튼으로 터치가 새지 않도록 대상 밖에 구멍 여백을 두지 않는다.
- 블러 뒤 장면은 접근성 트리에서 숨긴다. VoiceOver·TalkBack에서는 대화창 안에 현재 단계의 버튼·입력만 제공하고, 실제 UI와 같은 값·명령 핸들러를 사용한다.
- 대화창은 키보드 위 가용 영역 안에서 스크롤한다. 모든 스포트라이트에 안내 종료를 제공하고, 대상 측정이 2초 이상 실패하면 동일한 명령을 실행하는 대체 조작을 제공한다.
- 자리 선택은 지도 터치를 유지하되 배경 접근성 탐색은 차단한다. 스크린리더에는 현재 점유·시설·물고기 배치·보행 경로를 검사한 빈 땅을 선택하는 동작을 제공한다.

### 7.15 빈 상태 (GROMO-2412)

- 가진 게 없으면 공용 `EmptyState`(`patterns.tsx`)로 앱에 이미 있는 그림 한 장과 한 줄(17/700, 가운데)만 둔다. 설명 문장을 덧붙이지 않는다. 치수는 `componentTokens.emptyState`(그림 96 · 간격 12 · 위아래 24 · 장면 상자 최소 240 — 카드 글줄이 길면 늘어난다)다.
- 그림은 장식이라 스크린리더에서 숨기고 한 줄만 읽힌다. 불러오는 중·실패에는 빈 상태를 띄우지 않는다(§12).
- 쓰는 곳: 상점 목록 0개(내 털색 고양이 옆모습) · 옷장 보유품 0개(내 털색 고양이 식빵 자세, 서버는 보유품을 받은 뒤에만) · 친구 화면에서 받은·보낸 요청과 친구가 모두 0건(펠리컨 — 섹션 제목·「받은 요청 0」 배지 없이 이것 하나, 하나라도 있으면 기존 목록).
- `scene`은 장면 그림을 Preview 상자(radius 22, Brown 2)에 cover로 깔고 한 줄을 그 위 `Card`에 둔다. 섬 찾기의 공개 섬 0건은 망원경 바다(`seaAssets.telescopeSea`)를 쓴다.
- 소속 섬 없이 주민 화면을 열 때의 「가입한 섬이 없어요」 모달은 회색 단색 대신 먼바다 그림(`seaAssets.background`)을 `Overlay.background`로 깔고 제목과 [바다로 가기]만 둔다.
- 짧은 내용을 큰 틀에 남기지 않는다: 상품 상세는 `IslandSheet fit`(세로 폰에서 내용·버튼 줄 높이까지만 올라오고 길면 `tall`과 같다. 처음 다 재기 전에는 숨긴다. 한 번 보인 뒤 버튼 줄이 새로 붙는 등 다시 재는 동안은 숨기지 않고 마지막 자리에 둔 채 다 재면 높이만 바꾼다. 재는 주기마다 300ms 안전장치가 걸려 그 안에 못 재면 `tall` 높이로 보이고, 다 재면 타이머를 끈다), 게시판 청사진 상자는 안내 한 줄뿐(목표 없음·전체 완공·불러오는 중·실패)이면 고정 높이 없이 내용만큼, 이웃 일기장 책은 내용 높이까지만 펼친다(내 일기장은 그대로).

### 8.1 단일 재화

- 재화는 물고기 하나이며 섬 소유다. 개인 물고기 지갑이나 제2 재화는 없다.
- 집중 보상과 퀘스트 보상은 모두 섬 잔액에 귀속되고, 집중한 섬에만 쌓인다.
- 상점 상품·축음기 음원 구매와 건물 건설은 섬 잔액에서 차감한다.
- 물고기 잔액과 주민별 누적 획득 기록은 구분한다. 구매·건설로 잔액이 줄어도 누적 기록은 유지한다.

시각 검증: `components/01-currency/`

### 8.2 건설

- 상태는 부족, 건설 가능, 선행 시설 잠금, 완료를 구분한다.
- 다음 건물 목표 선택과 건설하기는 방장만 한다. 방문자에게는 건설 UI를 열지 않고, 일반 주민은 옵션을 읽기만 한다.
- 권한이 없는 주민에게 옵션은 `selectable=false`/`blockedReason=FORBIDDEN`으로 내려온다 — 선택·건설 CTA는 disabled다.
- 현재 목표, 필요한 공동 자원, 기여 결과, 다음 건물을 같은 흐름에서 이해할 수 있게 한다.
- 회관에서 목표를 정한 뒤에는 `건설하기` 버튼을 유지한다. 서버의 `buildable`이 거짓이면 공통 버튼의 비활성 투명도로 흐리게 표시하고 터치를 막으며, 부족한 조건을 안내한다. 섬 잔액만으로 활성 여부를 추측하지 않는다.
- 회관 청사진 상단에는 `BUILDING PLAN · 01` 같은 영문 일련번호를 표시하지 않는다.
- 게시판 배경 위에는 선택한 건물 이미지를 덧붙이지 않는다. 청사진을 누르면 열리는 상세 안에서만 건물 미리보기와 건설 현황을 보여 준다.
- 게시판 청사진도 회관과 같은 서버 건설 목표·가격·잔액·건설 가능 여부를 읽고 서버 착공 명령을 사용한다. 열린 청사진 상세에서 총 건설비·각자 목표량·대상 주민별 실제 기여/남은 수량을 구분해 표시한다. 새로고침 버튼은 두지 않고 청사진 재진입·앱 전면 복귀 시 다시 조회한다. 각자 몫은 목표 선택 시점 대상 주민 수로 총액을 나눈 올림이며, 총액 1마리·2명이면 각자 1마리를 채우고 착공 때 섬 잔액에서 1마리만 차감한다. 회관·게시판은 섬 잔액 합산 방식이다. 로딩·조회 실패·목표 없음은 구분하며, 이전 서버가 주민별 진행량을 제공하지 않으면 조회 불가를 알리고 숫자를 지어내지 않는다. 공사 시간도 서버에 없는 값을 시안으로 채우지 않는다.
- 완료 상태에서는 반복 CTA 대신 성취와 다음 행동을 보여준다.
- HTML의 상품·기록 수치는 시연 데이터다.

시각 검증: `components/02-construction/`

### 섬 홈과 뗏목 이동 (2026-10-20 승인)

- 홈 왼쪽 위에는 고양이 프로필·섬 이름·오늘 집중 시간을 같은 얇은 반투명 Paper 표면에 둔다. 프로필은 40pt, 터치 영역은 44pt이며 글자 없이 꾸미기로 이어진다.
- 오른쪽 친구·설정 아이콘은 44pt 원형이며 프로필 표면과 세로 중심을 맞춘다. 친구 요청 수는 서버에서 확인한 값만 배지로 표시한다. 내 정보·메인 섬 변경은 설정에 둔다.
- 기존 오른쪽 아래 88×88 원형 집중 시작 버튼은 유지한다. 방문자 HUD와 권한은 별도 흐름을 유지한다.
- 뗏목은 승인된 귀여운 그림체의 1인칭 배경을 쓴다. 상단 「어디로 떠나볼까요?」, 왼쪽 위 「소속 섬으로」(`Btn` glass 작은 크기), 지평선 「바다로 출항」, 왼쪽 집중섬 「집중하러 가기」(둘 다 `Btn` glass)를 배치한다. 마지막에 고른 목적지 버튼만 Primary(Pink)로 칠하고 `accessibilityState.selected`로도 알린다 — 한 화면에 Primary는 하나다. 밑줄 글자·화살표는 쓰지 않는다. 별도 뒤로 버튼·부제·목적지 점·노는 표시하지 않는다.
- 방문 중에는 집중섬 행동을 숨긴다. 소속 섬은 가 본 섬만 선택 창에서 표시하며 마지막 선택을 저장한다. 임시 망원경·내 뗏목·구경 끝내기 행은 제거한다.
- 구경 중(서버 방문) 지도 아래에는 「다시 바다로」(glass)와 「이 섬에 가입」(Butter)을 한 줄로 나란히 둔다(GROMO-2405). 두 버튼은 가용 폭을 나눠 쓰고(`flex: 1`, `dynamicHeight`), 글자 배율이 `semanticTokens.typography.largeTextThreshold`(1.3) 이상이면 세로로 쌓는다. 「다시 바다로」는 소속 섬 유무와 관계없이 구경을 끝내고 바다로 가며, 가입하지 않은 방문자에게는 뗏목과 같은 「가입하지 않고 떠날까요?」 확인창을 한 번 띄운다. 왼쪽 위 방문 HUD 의 섬 이름은 한 줄로 가운데를 줄여 「구경 중」을 남기고, 읽는 이름에는 전체 이름을 둔다.
- 글자 배율이 1.2를 넘으면 제목·입구·목적지를 줄바꿈 가능한 세로 스크롤 흐름으로 배치한다. 기본 배율에서도 목적지 버튼의 폭을 안전 영역 안으로 제한한다.
- `componentTokens.homeNavigation`·`raftDestinations`가 승인 시안의 치수·배치·아이콘·그림자 정본이며 ko/en 번역을 함께 유지한다. 뗏목 제목·집중섬 이름(「낚시섬」)의 텍스트 그림자 반경은 5이고 `raftDestinations.textShadowRadius`에서 관리한다. 입구·목적지는 `Btn`이라 글자 그림자가 없다.

### 8.3 집중·낚시·휴식

- 일반 집중섬 도착 즉시 섬 아래 바다에 “집중할 자리를 골라주세요!” 안내와 메인 섬 귀환 버튼을 표시한다. 자리 선택 전·자리로 걷는 중에도 버튼 또는 안드로이드 뒤로가기로 뗏목을 타고 귀환한다. 자리 선택 안내는 착석하면 숨긴다. 최초 집중 체험 중에는 기존 단계별 안내와 건너뛰기를 유지한다.

- 낚시섬에서 원하는 곳을 누르면 오늘의 할 일 모달을 연다. 목표 시간 입력 없이 할 일만 정하고 카운트업으로 집중한다.
- 앱이 정한 자리 목록이나 자리 번호는 없다.
- 핀치 확대 시 내 고양이와 낚시 자리, 축소 시 같은 섬에서 지금 낚시 중인 주민 전체를 보여준다.
- 각 자리에는 확대 시 이름·과목·집중 경과 시간을 표시하고, 축소 시 다른 주민의 과목·경과 시간을 감춰 이름만 남긴다. 표시가 겹치면 내 표시를 우선한다. 다른 주민의 물고기 획득은 공개하지 않는다.
- 유효 집중 60초마다 물고기 1마리가 섬 잔액에 바로 들어간다. 주민 한 명이 한 섬에서 집중으로 낚는 물고기는 하루 최대 480마리다. 상한에 닿아도 집중 기록은 계속 쌓이고 물고기만 더 낚지 않는다. 하루 기준 시간대는 아직 정해지지 않았다(초기화 시간대 미결).
- 물고기 더미는 이번 집중 누적을 내 고양이 옆에만 보여준다. 유효 집중 1분 전에는 표시하지 않고, 1~59분 한 마리, 60~119분 작은 바구니, 120~239분 중간 바구니, 240분 이상 큰 더미 네 단계다.
- 더미 단계는 누적량을 보여주는 시각 연출이며 보상 배율이 아니다. 이 화면에 섬 잔액이나 잡은 물고기 숫자를 따로 강조하지 않는다.
- 집중 체험은 현재 기기에서 계정당 1회다. 완료·그만 보기 이력은 일반 앱 상태와 별도로 보관하며 섬 이동·탈퇴·재가입·재로그인으로 다시 실행하지 않는다. 설정의 체험 다시보기 진입은 제공하지 않는다. 앱 재설치·다른 기기 간 동기화는 범위 밖이다.
- 첫 섬 튜토리얼은 실제 집중 세션이 아닌 화면 체험이다. 기존 버튼·입력·이동·블러 스포트라이트를 재사용하고 집중 기록·통계·퀘스트·실시간 집중 채널에는 참여하지 않는다. 5초 체험 뒤 세션 없는 보상 API로 일반 물고기 1마리의 실제 지급을 확인하고 → 기존 낚아올리기 액션 2초 → “첫 물고기를 낚았어!” 순서로 보여 준다. 별도 선물 대사는 추가하지 않는다. 체험 결과의 물고기는 0/1마리이며 오래 기다려도 일반 적립·황금 추첨은 발생하지 않는다. Reduce Motion에서는 낚아올리기 액션 없이 다음 대사를 보여 준다. 재실행은 홈의 시작 버튼부터 다시 안내하고 보상 재요청은 계정별 서버 영수증으로 중복을 막는다. 구버전에서 이미 생성된 실제 세션은 기존 수명주기로 복구한다.
- 휴식하기를 누르면 유효 집중 누적을 즉시 멈춘다. 뗏목 이동과 모닥불까지 걷는 시간도 휴식에 포함하고, 섬 지도와 분리된 모닥불 전용 화면에서 고양이가 쉰다. 자세는 멤버마다 고정이다 — 멤버 식별자 해시가 짝수면 식빵(호흡만), 홀수면 책 읽기(호흡 + 미세 회전 + 3.4초·9.4초에 책장 한 번)다. 12초 주기로 불꽃 한 겹·불티·연기·불빛이 서로 다른 속도로 움직이고, 배경에 그려진 정지 불꽃은 돌·장작 그림으로 덮어 불꽃이 둘로 보이지 않는다(`screens/focus/RestCampfireMotion`). 연출은 보상·휴식 시간을 만들지 않으며, 동작 줄이기에서는 정지 한 장면, 백그라운드에서는 멈춘다.
- 복귀하면 기존 집중 시간과 물고기 수를 이어간다.
- 낚시 장면의 물보라·물결 고리·물빛 반짝임 색과 반경은 `componentTokens.fishingScene`(splashDrop · splashRing · floatRing · glint · radius)을 쓴다.
- 휴식 화면에는 같은 모닥불에서 쉬는 주민의 이름과 이번 휴식 경과 시간을 표시한다.
- 캐릭터, 배, 낮·밤 상태는 집중과 휴식 사이에서 유지한다.

동작 검증: `components/03-focus/`, `runtime/fishing-catch.js`, `runtime/cat-motion-metrics.js`, `runtime/rest-group.js`

#### 응원 이모트 버튼

- 같은 섬에서 집중 중인 주민에게 이모트로 응원을 보내는 둥근 버튼이다. 주민의 집중 화면(하단 바 왼쪽)에만 둔다. 낚시 구경 화면(방문자)에는 두지 않는다 — 방문자는 응원을 보내지도, 주민의 이모트를 보지도 않는다(2026-10-16 계획 변경).

- 선·그림자 색은 집중 화면 외곽선 상수 `OUTLINE`(`screens/focus/FishingIsland.tsx`)이다. 값은 `componentTokens.nameplate.outline`을 참조한다(토큰 Brown 과 같은 값, §13). 치수 52·46, 간격 6, 선 2px 도 토큰 없이 `EmoteFab` 안에 둔 코드 상수다(선 2px 는 Strong stroke 와 같은 값).

| 기본                            | 버튼만 보인다                                  | 누르면 펼친다. `accessibilityState.expanded`는 false                                               |
| 펼침                            | 버튼 위에 이모트 5종                           | 하나를 고르면 보내고 접는다. `expanded`는 true, 각 이모트에 이름 라벨                              |

### 8.4 퀘스트

- 시간대 집중 퀘스트와 하루 폰 사용 퀘스트를 구분한다.
- 조건, 측정 구간, 현재 진행, 보상, 완료 여부를 한 카드에서 읽을 수 있게 한다.
- 개인 달성 보상은 완료만으로 지급되지 않고 해당 주민이 `받기`를 눌러 수령한다. 전원 달성 보너스만 수령 없이 1회 자동 적립된다. 수령 가능, 수령 완료, 자동 보너스 적립을 같은 완료 상태로 뭉개지 않는다.
- 게시판 완공 뒤 홈에는 `오늘 집중` 시간 바로 아래에 작은 쪽지 묶음을 둔다. 한 개면 실제 제목과 조건, 여러 개면 앞 퀘스트와 전체 개수, 받을 보상이 있으면 `보상 받기`와 개수를 우선 표시한다. 진행률 막대는 넣지 않으며, 누르면 게시판의 퀘스트 목록을 연다. 이때 보상 모달은 현재 섬의 미수령 개인 보상만 순서대로 연다. 일반 게시판 진입은 기존처럼 전원 달성 자동 보너스 알림도 처리한다. 게시판 미완공·방문 중·퀘스트와 받을 보상이 모두 없는 상태에서는 숨긴다.
- 쪽지의 치수·간격·그림자는 `componentTokens.homeQuestIndicator`를 정본으로 삼는다. 높이는 고정하지 않고 콘텐츠에 맞춰 늘어나며, 큰 글자 모드에서는 제목과 조건을 각각 두 줄까지 표시한다. 홈 HUD와 쪽지는 같은 세로 레이아웃에 두어 HUD 높이가 커져도 겹치지 않는다.
- 새 퀘스트가 없거나 측정할 수 없는 상태를 실패와 구분한다.
- UI 예시 수치를 실제 서비스 수치처럼 사용하지 않는다.

### 8.5 우체통 · 우리 섬 편지방

- 같은 섬 구성원이 함께 대화하는 단체 채팅이다.
- 상대 메시지는 왼쪽, 내 메시지는 오른쪽에 둔다.
- 프로필, 이름, 작성 시간을 표시한다.
- API 연결 상태: 현재 섬 편지방 응답에는 작성자 `catColor`/appearance가 없다. 계약이 추가되기 전에는 이름·시각과 중립 프로필 자리표시자를 사용하고 꼬리는 그 자리표시자를 향하게 하며, 이름/사용자 ID로 털색·외양을 추측하지 않는다. 이는 최종 고양이 프로필 요구의 폐기가 아니라 미완료 API의 명시적 대체 상태다.
- 우리 섬 단체 편지방에는 내 것과 타인의 것을 포함해 읽음·안 읽음·읽은 인원 표시를 제공하지 않는다. 이는 친구에게 받은 개인 편지함의 “열지 않은 편지 수”를 없앤다는 뜻이 아니며, 개인 편지함 배지는 별도 계약대로 유지한다.
- 수신자를 고르지 않고 섬 전체에 보낸다.
- 빈 메시지는 보내지 않는다.
- 채팅방 진입·앱 전면 복귀 시 최신 이력을 즉시 조회하고, 채팅방을 보고 있을 때만 10초 간격으로 갱신한다. 화면 이탈·백그라운드에서는 조회를 멈춘다. 새 글은 기존 이력과 ID로 병합하며 입력 중인 내용은 유지한다.
- 말풍선 꼬리는 해당 고양이 프로필을 향한다.

### 8.5.1 건물 설명과 완공 안내

- 건물 설명은 계정별·건물 종류별 1회다. 현재 섬의 서버 완공 목록으로 확인한 건물을 눌렀을 때 섬 화면 위에서 설명하며, 우체통이 없는 섬이나 홈 진입만으로는 띄우지 않는다. 회관·게시판·축음기·도서관·우체통·전망대·상점에 같은 정책을 적용한다.
- 공용 `BuildingGuide`는 몽돌·펠리컨·강아지 기본 에셋과 기존 하단 대화창을 사용한다. 모달로 배경 입력·스크린리더 접근을 차단하고, 큰 글자·가로 화면에서는 대화창을 스크롤한다.
- 처음 보는 건물은 고양이가 입구에 도착해도 섬 화면을 유지하고 공용 `BuildingGuide`를 표시한다. 설명 완료·안내 그만 보기의 이력 저장이 성공한 뒤 내부 화면을 연다. 이미 본 건물은 도착 즉시 연다. 안내 대기처럼 실제 화면 이동을 하지 않은 요청은 걷기 진입 잠금을 해제해, 안내를 닫은 뒤 건물과 집중하기를 다시 누를 수 있다. 안내 도중 섬·계정이 바뀌거나 홈을 떠나면 보류한 진입을 취소한다.
- 완료·안내 그만 보기는 계정 ID별 별도 기기 저장소에 기록한다. 섬 이동·재가입·로그아웃과 계정 전환으로 삭제하지 않는다. 기존 우체통·상점 열람 이력은 소유자를 확인해 이관한다. 읽기 실패를 미열람으로 간주하지 않고, 저장 실패 시 안내를 유지하며 재시도를 제공한다. 안내 이력 읽기 오류로 서버의 섬 동기화·생성·전환 성공을 실패 처리하지 않고, 읽지 못한 체험 완료 값은 동기화 액션에서 생략해 기존 완료 상태를 보존한다. 최초 진입의 이력 조회 대기·오류 화면은 닫기와 Android 뒤로 가기로 보류한 진입만 취소할 수 있고, 이력을 삭제하거나 읽은 것으로 기록하지 않는다. 안내 도중 종료하면 다음 건물 진입에서 이어서 안내받는다.
- 완공 안내는 서버가 착공 시점에 확인한 실제 기여 주민에게만 홈에서 표시한다. 각자 몫 건물은 소비된 목표의 양수 기여 주민, 합산 건물은 해당 섬에서 물고기를 적립한 현재 주민을 대상으로 고정한다. 완공 여부는 서버 확정만 따른다. 설명을 본 계정에는 완공 안내만 표시한다. 완공 안내 열람 키는 계정·섬·건물별이며 설명 이력과 분리한다.
- 과거 완공 건물의 기여자는 추정해서 등록하지 않는다. 새 서버 필드가 없는 동안에는 완공 축하를 생략하고 건물 설명은 정상 제공한다.
- 집중 세션이 남아 있거나 다른 섬 방문 중에는 안내하지 않는다.
- 완공된 우체통은 안 읽은 수신 편지 — 친구 편지 **또는 섬 시스템 편지(강퇴·가입 승인, 티켓 2275)** — 가 있을 때만 `characters/pelican/npc/on-mailbox.png`로 교체한다(2026-10-25 재영님 결정, GROMO-2489). 기존 우체통 레이어·건물 테마 착색은 중복해서 그리지 않는다.
- 공지·단체 편지방·발신 편지는 착석 조건이 아니다. 기존 `unreadLetters`/`LETTER_READ`가 정본이며, 마지막 안 읽은 편지(시스템 편지 포함)를 열어 읽음 처리하면 기본 우체통으로 돌아간다. 우체통 목록 진입만으로는 읽음 처리하지 않는다.
- 안 읽음 수는 어디서나 같은 기준이다 — 지도 우체통 배지(`buildingIndicators.fetchMailboxUnreadCount`, 시스템 편지 첫 페이지를 먼저 본다 — 목록도 첫 페이지만 쓰므로 같은 집합이고, 조회가 실패하면 친구 편지만으로 판정한다) · 우체통 안 「새 편지 N통」 · 받은 편지 목록 「아직 열지 않은 편지 N통」 · 우체통 안 「받은 편지」 칸 오른쪽 위 모서리의 느낌표 배지(지도와 같은 `VillageNotificationBadge`, GROMO-2489)는 모두 `letters` + `systemLetters` 의 `!isRead` 합이다. 「받은 편지」 칸의 읽는 이름은 새 편지가 있으면 「받은 편지 열기, 새 편지 N통」(`home.door.inboxNewLetters`)이다.
- 우체통이 없는 사용자(유일한 섬에서 강퇴돼 먼바다로 나온 사용자, 우체통을 아직 짓지 않은 섬의 주민)의 시스템 편지 진입점은 현상 유지 — 우체통 건물이 있는 섬에서만 본다. 강퇴 사실은 먼바다로 나온 것 자체로 알게 되고, 편지는 다음 섬 우체통에서 읽는다. 먼바다 진입점·토스트·잠금 예외는 만들지 않는다(2026-10-25 재영님 결정).
- 원본 우체통 rect `[298, 520, 46, 63]`의 바닥·폭에 합성 에셋을 맞추고, 카메라 확대·이동과 함께 변환한다. 접근성 라벨에도 새 편지가 있음을 표시한다.

### 8.6 공동 음원

- 공동 음악 장치의 이름은 축음기로 통일한다. 우리 섬에 축음기를 지은 뒤부터 낚시섬에 놓인 축음기를 눌러 음원을 바꾼다.
- 주민 누구나 보유 음원을 바꿀 수 있고, 선택한 음원은 같은 섬에서 집중 중인 주민에게 공동 적용한다.
- 기기에서는 집중 중이고 공용 재생·개인 소리가 켜져 있으며 음량이 0보다 클 때만 재생한다. 휴식·집중 종료·세션 없음·개인 음소거·음량 0에서는 플레이어를 일시정지한다. 축음기 진입·곡 선택·미리듣기도 이 조건을 우회하지 않는다.
- 기본 세 곡(잔잔한 파도·모닥불·숲속 바람)은 모든 섬에 무료 제공하며 구매 없이 바로 재생한다. 서버 공동 인벤토리에 항상 포함하고, 기본곡만 구매 이력 없이 재생을 허용한다. 판매 목록에 남은 기본곡도 이미 소유한 것으로 처리해 중복 결제를 막는다. 집중·휴식 중에는 판매곡을 숨기고 기본곡과 보유곡만 표시한다.
- 그 외 판매 음원은 세션 없이 완공된 축음기에서 섬 물고기로 직접 구매하고 공용 곡으로 선택한다. 실제 소리는 집중 중인 주민에게만 재생한다. 상점을 거치지 않는다.
- “상점을 거치지 않는다”는 화면 동선의 뜻이다. 축음기 안에서 판매 음원·가격·잔액·확인을 보여 주고 구매를 끝내며, 서버가 공통 catalog/purchase·원장 구현을 재사용해도 상점 화면으로 이동시키지 않는다.
- 기기 음량·음소거는 개인 설정이다.
- 누가 어떤 음원을 선택했는지와 현재 공동 적용 상태를 명확히 보여준다.

시각 검증: `components/06-shared-player/`

### 8.7 상점

- 상점 NPC는 강아지다. 사용자 캐릭터는 고양이다.
- 상점 최초 설명은 강아지가 사용법을 안내한다. 완공 축하와 분리하며 8.5.1의 계정별 1회 정책을 따른다.
- 첫 상점 안내는 공용 `BuildingGuide`의 `NpcGuide.GuideBox` 하단 대화창과 강아지 기본 에셋을 사용한다.
- 주민 누구나 섬 물고기로 상품을 구매한다. 진입 시 섬 물고기 잔액을 보여준다.
- 상품은 구매 가능, 부족, 보유, 적용 중 상태를 구분한다.
- 개인 의상·장신구는 구매한 주민의 보유품이고, 공동 섬·건물 꾸미기는 섬 소유다. 소유 주체를 혼동하지 않는다.
- 구매 전 확인과 구매 후 완료 피드백을 제공한다.
- API 연결 상태: 서버 구매 판정(`SharedPurchase.canSpend`)은 제품 정책과 같다 — 활성 주민은 누구나 구매하고, 게스트는 첫 구매 시도에 소셜 로그인을 요청한다. `FORBIDDEN` 거절은 권한 상실·게스트 안내로 처리한다.

### 8.8 주민·프로필 목록

- 역할은 방장, 주민, 방문자를 구분한다.
- 현재 상태는 집중, 휴식, 오프라인/기타 상태를 구분한다.

### 8.9 게시판·공지

- 방명록은 최신순 30개씩 커서로 이어 읽는다. 주민·방문자 게시판의 부모 스크롤 하단에서 다음 페이지를 요청하며, 실패 시 기존 글과 초안을 유지하고 다시 시도할 수 있다. 작성 후에도 이전 글을 30개로 자르지 않는다.

- 공지 목록, 상세 읽기, 작성·수정·삭제를 구분한다. 파일 첨부·업로드는 지원하지 않는다.
- 게시판 시설이 완공돼야 열린다 — 미완공이면 주민·방문자 모두 잠금 안내다.
- 신규 게시판의 공지 쓰기·수정·삭제는 방장만 가능하다. 삭제는 되돌릴 수 없으므로 확인창을 거친다.
- 댓글은 주민 누구나 쓰고, 본인 댓글 또는 방장이 삭제할 수 있다. 삭제는 확인창을 거치며 서버 성공 후 목록과 댓글 수를 갱신한다. 작성·전송·실패·재시도를 입력 흐름에서 구분한다.
- 방문자는 공지·댓글·퀘스트를 읽기만 하고 쓰기 진입을 노출하지 않는다.
- 빈 목록, 로딩, 실패, 재시도 상태가 필요하다.
- 작성 권한과 읽기 권한을 행동 위치와 disabled 상태로 설명한다.
- 공지 목록의 「+ 새 공지」와 퀘스트 목록의 「+ 만들기」는 `Btn` 작은 크기(Pink)다. 종이 안 상세·쓰기의 한 단계 뒤로는 종이 왼쪽 위 ‹ `NavBtn`, 종이를 닫는 것은 오른쪽 위 × `NavBtn`이다(§7.14).

### 8.11 섬 내비게이션

- 섬 장소 자체를 직접 누르는 방식이 기본이다.

- 타일섬과 일반 이미지 섬 홈의 완공된 축음기는 그림·외곽선·터치 영역·팻말을 표시하고 주민은 기존 음악 화면으로 진입한다. 방문자에게는 축음기 상호작용을 노출하지 않는다. 집중섬 음악 기능은 유지한다. 우체통은 원화 기준 24px 위로 이동하며 펠리컨·배지·터치·걷기 도착점도 함께 움직인다.
- 나무 팻말은 건물 아래에 둔다. 뗏목 팻말은 그림을 가리지 않도록 오른쪽 위에 배치하고 데모에서 확정한 위치를 사용한다. 타일섬 플래그와 관계없이 동일하게 적용한다. 별도 원화의 새 마을 미리보기와 낚시 화면은 제외한다.
- 부두 → 낚시 집중
- 모닥불 → 휴식
- 도서관 → 기록
- 마을회관 → 공동 자원·주민·섬 관리
- 전망대 → 주간 랭킹·섬 이름 검색 (§8.17)
- 기본 중앙 화면, 전체 섬 보기, 드래그, 핀치 확대·축소, 고양이 터치 이동을 지원한다.

- 낮·밤과 성장 7단계를 반영한다.
- 장소는 그림만으로 식별시키지 않고 라벨 또는 접근성 이름을 제공한다.

### 8.14 마을회관

- 건물 선택 목록은 “어떤 건물을 지을까요?” 제목만 표시한다. 완공 카드는 투명 배경 `src/assets/ui/construction-complete.png`의 Brown 잉크 “건설완료” 도장을 **카드 오른쪽 아래에 겹쳐** 찍는다 — 건물 이름은 가리지 않고 설명 위에 걸치며 살짝 비친다(흐름 밖 절대 위치, 바닥에서 `hallCompletionStamp.bottomInset` 8 띄워 `rotation` -14° 로 기울임, `hallCompletionStamp.opacity` — 2026-10-26, 종전엔 도장이 한 줄을 차지해 글이 아래로 밀렸고 바닥에 붙이니 너무 내려가 보였다). 모든 건물을 완공해도 기존 건물 그리드를 유지하며 제목은 “건설 현황”으로 바꾼다. 카드는 같은 폭의 2열이고, 2열일 때 홀수 마지막 카드(상점)는 한 줄 전체 폭이다(2026-10-26 GROMO-2486 — 2413 의 「같은 폭」 규칙을 뒤집음). 3열 가로(격자 450 이상)에서는 5장이 3+2 라 전체 폭 카드가 없다. 목록은 도서관·전망대 / 우체통·축음기 / 상점 5장이며 마을회관·게시판은 목록에 없다. 격자 폭은 패널 폭에서 실제 테두리 2.6×2 를 빼서 잰다 — 4 로 빼면 393·375pt 폰에서 둘째 카드가 다음 줄로 밀린다. 카드 설명은 `sm` 14로 두 줄까지(좁은 폰에서도 단어가 한 줄에 들게 짧게 쓴다)(GROMO-2413). 작은 화면·가로 화면에서는 그리드를 스크롤할 수 있다. 채운 캡슐 배지 대신 종이에 찍힌 형태를 쓰며, 치수와 색은 `componentTokens.hallCompletionStamp`를 따른다. 완공 카드는 상태 확인용이며 건설 계획 선택·착공 명령을 다시 실행하지 않는다.

- 공동 가계부는 잔액·월별 적립 및 사용·거래 내역을 표시한다. 상단 영문 장식 문구와 “우리 섬 물고기” 중복 제목은 표시하지 않는다.
- 공동 자원 내역, 주민 관리, 섬 관리의 허브다. 주민의 집중·스크린타임 기록은 도서관 완공 후 도서관에서 조회한다.
- 열람 정보와 관리 행동을 같은 위계로 섞지 않는다.
- 방장에게만 가능한 행동은 권한과 영향을 분명히 표시한다.
- 섬 탈퇴, 주민 내보내기, 방장 위임은 별도의 확인 단계를 사용한다.
- 섬 정보 카드에서 방장과 주민 모두 탈퇴 버튼을 볼 수 있다. 방장 혼자 남았으면 섬 공동 데이터 삭제를 확인한 뒤 탈퇴하고, 다른 주민이 있으면 방장 위임을 먼저 안내한다. 방문자에게는 탈퇴 버튼을 표시하지 않는다.

시각 검증: `components/14-hall/`

### 8.16 망원경

- 뗏목 행선지의 「망원경」으로 연다(임시 입구 — 먼바다 화면이 생기면 바다 담당이 정리한다). 망원경 바다 그림(`ota/sea/telescope-sea.jpg`, 1024×1536 · 수평선 545px — `seaAssets.telescopeSea`)을 화면에 cover 가운데 맞춤 크기로 깔고, 수평선 위에 섬을 가로 파노라마(`ScrollView`)로 늘어놓는다. 바다는 파노라마와 함께 밀린다(GROMO-2414): 같은 크기·높이의 그림을 가로로 이어 붙이되 한 장 건너 좌우 반전해 이음매를 숨기고(`telescopeSeaTiles` — 스크롤 0 의 첫 장은 예전 한 장 자리, 스크롤 끝과 양쪽 튕김까지 한 화면씩 더 덮는다), 파노라마의 가로 스크롤 오프셋을 네이티브 드라이버 `Animated.event`로 바다 층의 `translateX`(−오프셋)에 이어 섬과 같은 속도로 UI 스레드에서 움직인다. 하늘·수평선 높이는 그대로이고, 오른쪽 아래 뗏목 고양이는 고정이라 망원경을 돌려 보는 느낌이다. 움직임 줄이기에서도 바다는 스크롤을 따른다 — 장식 모션이 아니라 사용자가 미는 스크롤 그 자체다. 서버가 이 시간대에 고른 섬 최대 8개를 응답 순서대로 보여 주고 앱이 다시 정렬하지 않는다(GROMO-2317 승인 시안 T1).
- 섬 그림은 잡지 칸 섬 프로필과 같은 4장(`ISLAND_STAGE_ART` — 같은 땅에 집 0·1·3·5채, 섬만 잘라 둔 480×266)이고 `islandStage(memberCount, buildingCount)`가 고른다: 주민 0명(무인도) 집 0채 · 완공 건물 0~2 집 1채 · 3~4 집 3채 · 5 이상 집 5채. 서버가 `buildingCount` 키를 빼면(롤링 배포) 0이다.
- 섬 칸은 폭 146(`componentTokens.telescope.islandBox`)를 최소로 하고, 그림 126(`islandArtWidth`)을 칸 위에서 37(`islandArtTop`) 내려 가운데 둔다. 이름 알약은 그림 12(`pillGap`) 아래의 공용 `Badge` soft이고 `style`(`alignSelf: center` · `maxWidth` 200 `pillMaxWidth`)로 가운데에 놓는다. 칸 폭은 알약이 더 길면 알약을 따라 늘어나 옆 섬 알약과 겹치지 않는다. 칸 사이는 4(`cellGap`), 홀수 번째 섬은 40(`stagger`) 낮게 어긋나 한 줄 목록처럼 보이지 않게 한다.
- 알약 글은 소속 섬이면 이름만, 그 밖의 섬은 「이름 · 항해 시간」(`telescope.islandLabel`, 시간은 `formatDuration` — 15분 · 30분 · 1시간 · 1시간 30분)이다. 보통 한 줄이고 넘치면 가운데를 줄여(`ellipsizeMode="middle"`) 끝의 「· 항해 시간」을 남긴다. 큰 글자(글자 배율이 `semanticTokens.typography.largeTextThreshold` 이상)에서는 두 줄까지 보인다(`numberOfLines` — 안드로이드 두 줄은 끝 말줄임만 된다). 섬의 읽는 이름도 소속 섬이 아니면 같은 항해 시간을 덧붙인다(「○○, 항해 30분」 · 「○○, 잡지에서 찜한 섬, 항해 30분」).
- 띠 높이: 짝수 번째 섬 칸 위쪽이 수평선보다 80(`horizonGap`) 위에 오도록 띠의 위 여백을 화면 크기·위 막대 높이로 잰다(`onLayout`, cover 배율 = max(가로/1024, 세로/1536) — 402×874 폰은 수평선 310 · 1024×1366 태블릿은 460). 짝수 번째 섬 그림(126×70)은 수평선에 걸쳐(위 43 · 아래 27) 하늘 쪽으로 솟아 빈 하늘을 줄인다(GROMO-2414). 첫 그림은 onLayout 전에도 창 크기와 보통 글자의 위 막대 높이로 계산해 띠가 튀지 않는다. 위 막대가 길어지는 큰 글자·가로 화면에서는 기본 여백 40으로 물러나 겹치지 않는다.
- 오른쪽 아래에는 망원경을 든 내 털색 고양이 뗏목(`ota/sea/raft-telescope/{색}.png`, `seaAssets.raftTelescope`)을 폭 200으로 깐다(안전 영역 안쪽 오른쪽 26 · 아래 50, `telescope.raft`). 바다 그림 바로 위 · 파노라마 아래의 장식이라 누름을 받지 않고 스크린리더에서 숨긴다. 가로 화면(가로 > 세로)에서는 섬 띠 뒤에 깔리므로 그리지 않는다.
- 내 소속 섬(`slot=joined`)에는 기존 `Flag`(`screens/cosmetics/Cosmetics.tsx`)를 깃대 밑동이 섬 그림 위 가운데에 오게 꽂는다. 깃발은 장식이라 스크린리더에서 숨기고, 섬의 접근성 라벨(「○○, 내가 사는 섬」)이 소속을 말한다.
- 섬을 누르면 말풍선(`IslandPopup`)이 뜬다. 이름 · 소개 · 주민 {n}/{max} · 평균 집중 · 항해 {n}분(정보 줄은 `SheetGroup` 안의 `SheetRow`) 아래에 행동 버튼을 둔다. 평균 집중이 «집계 전»(null)이면 0분과 구분해 「아직 집계 전」이다.

| 소속 섬 · 가 본 적 없음(망원경 가입) | [항해하기] 하나 — 도착하면 그 섬이 현재 섬이 된다                                     |
| 그 밖의 섬                           | [항해하기] + 가입 버튼 하나. 정원이 차도 구경(항해)은 된다                            |

- 가입 버튼은 [바로 가입] · [가입 신청] · 「신청 중」(비활성) · 「정원이 찼어요」(비활성) 중 하나다. 가입 요청은 한 번에 하나만 나가고, 요청 중인 섬의 버튼만 「처리 중이에요」로 바뀐다(다른 섬을 열면 그 섬의 가입 버튼은 평소 글자 그대로 비활성이다). 망원경 가입은 즉시 가입이어도 현재 섬을 옮기지 않는다 — 처음 한 번은 항해해서 가야 한다. [항해하기]는 주민·비주민 모두 바다 항해 집중으로 간다 — 섬 도착(주민이면 현재 섬 이동, 비주민이면 구경)은 정박 뒤 [섬에 내리기]의 결과창이 맡는다.
- 승인 대기 신청이 있으면 위 막대에 [가입 신청 확인]을 둔다. 신청한 섬이 이번 시간대 목록에서 빠져도 기존 승인 대기 화면에서 상태를 확인·취소할 수 있다. 부팅 소속 동기화가 실패했다면 잡지 등 진입 경로와 관계없이 목록을 읽기 전에 동기화·저장소 복구를 재시도하며, 실패 시 망원경의 [다시 시도]를 표시한다.
- 왼쪽 위 뒤로가기는 건물 안과 같은 ‹ `NavBtn`(§7.14)이라 글자 크기와 상관없이 모양이 같다. 작은 버튼(오류의 「다시 시도」)은 보통 글자에서 38pt 모양 그대로이고, 큰 글자에서는 `dynamicHeight`가 켜져 38pt에서 최소 52pt로 커지고 글자가 더 커지면 그에 맞춰 더 늘어난다. 말풍선의 [항해하기] · [돌아가기] · 가입 버튼은 글자 크기와 상관없이 늘 `dynamicHeight`다. 오른쪽 위 구석에는 목록이 바뀌기까지 남은 분 「N분 뒤 새 섬」(영어 「Islands change in N min」) `Badge` 하나만 둔다. 항해 시간으로 읽히지 않게 «까지»를 쓰지 않는다. 서버가 준 남은 분에서 1분마다 줄고(갱신 시각 기준이라 앱이 백그라운드에 있다 돌아와도 따라잡는다) 0이 되면 목록을 다시 읽는다. 전망대에서 섬을 넣거나 망원경에서 섬을 빼는 요청이 성공했을 때도 다시 읽는다(요청이 느려 끝나기 전에 망원경을 열어, 또는 나갔다 다시 열어 옛 목록을 받아 둔 경우 — `onTelescopeChanged`). 다시 읽는 동안과 읽기에 실패했을 때도 보던 목록은 그대로 둔다.
- 배치: 위 막대(뒤로가기 · 남은 분)와 파노라마를 세로 `ScrollView` 안에 위에서 아래로 쌓는다(절대 위치를 쓰지 않는다). 큰 글자 · 좁은 폭 · 가로 화면에서도 서로 겹치지 않고, 화면보다 길어지면 세로로 밀어 끝까지 닿는다. 파노라마만 가로로 민다.
- 로딩(스피너와 안내) · 빈 목록(「지금은 보이는 섬이 없어요」 한 줄) · 오류(문구와 「다시 시도」)는 공용 `Card`를 파노라마 자리(수평선 띠)에 두어 구분한다. 소속·찜 섬만 남고 새 섬이 없을 때는 따로 안내하지 않는다. 오류 안내가 뜰 때 스크린리더에 한 번 알린다(iOS는 직접 읽어 주고, 안드로이드는 오류 문구의 live region).
- [항해하기]는 바다 집중 세션이다(GROMO-2310): 한마디 시트(`SeaVoyagePreparation`, 비워도 된다) → `POST /focus-sessions/sea` → 먼바다 항해 화면(`SeaVoyageHost`). 한마디는 출항 뒤 따로 저장하고 실패해도 출항은 유지한다. 섬에는 정박한 뒤 [섬에 내리기]로 내린다. [돌아가기]는 도착 영상(`ota/cutscenes/arrival.mp4`, 4초)을 `VideoCutscene`으로 재생한다. 서버 요청이 먼저 끝나고(실패는 영상 없이 토스트), 영상이 끝나면 화면만 옮긴다. 요청·영상 중에는 섬이 눌리지 않아(말풍선이 열리지 않는다) 뒤로가기는 계속 삼키고, 말풍선이 열려 있을 때만 뒤로가기가 말풍선을 닫는다. 이 화면에는 자체 모션이 없고, 움직임 줄이기에서는 영상을 건너뛰고 바로 옮긴다.
- 직접 넣은 섬(`slot=pinned` — 잡지·전망대 핀)은 서버가 목록의 핀 칸에 담아 준다. 앱은 `slot`·`pinnedFrom` 만 보고 그리고 «넣었다» 상태를 따로 들지 않는다 — 목록이 정본이라 06:59:59 에 넣은 핀이 1초 뒤 만료돼도, 되살아난 핀 때문에 가장 오래된 핀이 목록에서 빠져도 그대로 따라간다.
- **「찜」 리본**은 잡지에서 넣은 섬(`pinnedFrom=magazine`)에만, 섬마다 1개 붙는다. 공용 `Badge`(Butter + Brown)의 알약 반경만 4로 줄여 각진 테이프로 만들고, 섬 그림 왼쪽 위(그림 모서리에서 왼쪽 4 · 위 6, `telescope.ribbonOffset`)에 `componentTokens.telescope.ribbonTilt`(-12도)만큼 기울여 붙인다(노란 마스킹테이프 «찜!»). 전망대에서 넣은 섬 · 무작위 · 가까운 · 소속 섬에는 없고 출처를 모르는 핀(`pinnedFrom` 없음)에도 없다. 리본은 장식이라 스크린리더에서 숨기고 섬의 읽는 이름이 「○○, 잡지에서 찜한 섬」으로 대신 말한다(깃발과 같은 방식). 섬 누름을 가로채지 않는다.
- **잡지 칸 미리보기(SCOPE-09)**는 잡지에서 넣은 섬의 말풍선에서 소개 아래 · 정보 줄 위에 1장 뜬다.
  - 서버가 그 핀의 홍보 칸(`magazineCell` — 홍보 칸에서 `promotionId` 로 넣은 핀이고 그 칸이 현재 호에 보일 때만)을 주면 잡지와 같은 `AdCell`(§8.18)로 그리고 아래에 「잡지 칸 미리보기」 meta 한 줄을 둔다. 칸 폭은 말풍선 안 자리를 재서 정한다.
  - 칸의 「주민·평균」 줄은 빼고 그린다(`hideMeta`). 실린 날 숫자라 바로 아래 정보 줄(지금 숫자)과 다르게 겹쳐 보이기 때문이다. 칸은 섬 이름·글을 스스로 읽고, 신고 동작은 없다.
  - 칸이 없으면(편집부 칸·전망대에서 넣었거나 숨겨짐·현재 호 아님) 섬 그림(`island/whole`)만 종이 틀(Paper + Brown 2px, 반경 Control, 안쪽 여백 8)에 둔다. 미리보기가 아니라 장식이라 「잡지 칸 미리보기」 글이 없고 스크린리더에서도 숨긴다 — 섬 이름은 말풍선 제목이 읽는다.
  - 서버 없이 볼 때는 목업 모드에 `EXPO_PUBLIC_MAGAZINE_MOCK=telescope` 를 준다(칸 있는 잡지 찜 · 칸 없는 잡지 찜 · 전망대 찜 · 무작위 섬). 서버 세션이 없어 말풍선의 행동 버튼은 모두 막힌다(보기만).
- **[망원경에서 빼기]**는 `slot=pinned` 인 섬(출처 무관)의 말풍선 맨 아래에만 둔다. 낮은 위계라 `Btn` ghost(`dynamicHeight`)다. 소속 · 가까운 · 무작위 섬에는 없다. 누르면 `DELETE /me/telescope/pins/{id}` 뒤 말풍선을 닫는다. 목록은 화면이 따로 읽지 않고 빼기 성공 알림(`onTelescopeChanged`)으로 다시 읽는다(요청 중 나갔다 다시 연 화면도 같이 갱신된다) — 빈 자리는 서버가 그 시간대의 무작위 섬으로 채우므로 앱에 복귀 로직이 없다. 요청 중에는 말풍선의 모든 버튼이 막히고(한 번에 하나), 실패하면 섬 오류 문구로 알리고 말풍선을 그대로 둔다.
- **항해 중인 섬**은 지금 구경(방문) 중인 섬이다(`serverVisit`). 그 섬의 [망원경에서 빼기]는 흐리게 보이되 `disabled` 로 막지 않는다 — 접근성 힌트 「항해 중이라 빼려면 항해를 그만둬야 해요」가 이유를 말하고, 누르면 확인창 「항해를 그만둘까요?」(확인 = 「그만두고 빼기」)를 1번 띄운다. 취소하면 아무 일도 없다. 확인하면 빼고 뗏목 행선지의 「구경 끝내기」와 같은 종료(`endServerVisit`: `END_VISIT` 뒤 홈, 소속 섬이 없으면 섬 선택)로 구경도 끝낸다. 빼기가 실패하면 구경을 끝내지 않는다. 서버에는 항해 상태가 없어 «항해 중 빼기» 거절이 없다 — 앱이 이 확인창으로 거친다. [항해하기] 요청 · 연출 중에는 섬 칸이 막히고 연출이 화면을 덮어 말풍선이 열리지 않으므로 따로 보지 않는다. 지금은 구경 중에 뗏목 행선지의 「망원경」이 숨고 라우트도 막혀 이 화면에 닿지 못한다. 바다 항해(집중) 중에는 망원경이 없다(SAIL-06) — 먼바다 화면에서 망원경은 표류 중에만 열린다.
- 코드: 화면은 `screens/island/Telescope.tsx`, 목록·카운트다운은 `useTelescope`, 요청 → 항해 연출 → 도착 처리와 구경 끝내기(`endServerVisit`)는 `useIslandSailing`이다(뗏목 행선지와 공유). 핀 빼기 요청은 `services/api/telescope.ts` 의 `unpinFromTelescope`이고, `pinToTelescope` 처럼 성공하면 `onTelescopeChanged` 구독자에게 알린다.

### 8.17 전망대

- 전망대(건설 필요)가 여는 것은 섬 간 주간 랭킹(`tower`)과 섬 이름 검색(`explore`) 둘뿐이다. 공개 섬을 둘러보는 탐색(`discover`)은 없다. 전망대를 짓지 않은 섬과 남의 섬을 방문 중일 때는 두 입구가 모두 잠긴다(`CurrentScreens` 시설 잠금).
- 랭킹 시트 헤더의 「섬 찾기」가 검색으로 간다. 서버 검색은 섬 이름만 본다(입력 안내도 「섬 이름」) — 초대 코드는 초대 링크 흐름이 맡는다. 서버 없는 목업 모드의 `explore`는 예전 로컬 필터 그대로다.
- 섬 행(랭킹 · 검색 결과 공통)은 공용 `SheetRow`를 `SheetGroup` 안에 둔다. 검색 행은 이름 · 소개 · 「주민 n/max」, 랭킹 행은 순위 · 이름 · 평균 집중이고 끝에 섬 썸네일이 있다. 내 소속 섬은 「소속됨」 `Badge` soft가 붙고 꺾쇠 없이 누를 수 없다 — 소속 섬은 뗏목으로 바로 간다. 가입 신청 중인 섬(검색)은 「신청 중」 배지가 붙지만 망원경에는 넣을 수 있다. 상태는 배지와 읽는 이름(「…, 소속됨」) 둘로 전한다. 배지는 행 안 세로 가운데에 둔다(`style`). 큰 글자(글자 배율이 `semanticTokens.typography.largeTextThreshold` 이상 — 망원경과 같은 판정)에서는 고정 폭 순위·썸네일 옆에 배지를 두면 이름 칸이 0으로 줄어서, 배지를 본문 칸 안 이름·평균(소개) 아래 별도 줄로 내린다(`SheetRow`의 `below`).
- 소속이 아닌 섬 행을 누르면 확인창(제목 = 섬 이름, 확인 = 「망원경에 넣기」)을 먼저 띄운다 — 훑다가 잘못 눌러 넣으면 다른 섬이 빠지기 때문이다. 확인하면 요청을 한 번만 보내고(요청 중에는 행이 막힌다) 토스트로 「망원경에 넣었어요 — 뗏목의 망원경에서 볼 수 있어요」를 알린다. 직접 넣은 섬이 가득 차 밀려난 섬이 있으면 같은 토스트에 「○○섬이 망원경에서 빠졌어요」 한 줄을 더한다. 방문 화면으로 보내지 않는다.
- 넣기 실패는 섬 오류 문구로 알린다. 강퇴 섬(403)은 일반 권한 오류와 코드로 구분되지 않아 「이 섬에는 넣을 수 없어요」, 내 소속 섬(409)은 「이미 내가 속한 섬이에요」로 따로 말한다.
- 검색: 입력이 300ms 멈추면 서버를 부른다. 빈 검색어는 부르지 않는다(입력칸 아래 안내 문구는 두지 않는다). 늦게 온 옛 검색어 응답은 버리고, 입력을 바꾼 직후에는 이전 검색어의 결과를 남겨 두지 않는다. 첫 페이지(20개)만 읽고 더 있으면 검색어를 좁히라고 안내한다.
- 검색의 로딩(스피너와 「섬을 찾고 있어요」) · 빈 결과(「찾는 섬이 없어요」) · 오류(문구와 「다시 시도」 — 디바운스 없이 바로 다시 부른다)는 따로 그린다. 오류·빈 결과 안내가 뜰 때 스크린리더에 한 번 알린다(iOS는 직접 읽어 주고, 안드로이드는 문구의 live region). 「다시 시도」는 `dynamicHeight` 보조 버튼이라 큰 글자에서도 잘리지 않는다.
- 코드: 검색 화면은 `screens/island/ObservatorySearch.tsx`, 검색 상태는 `useIslandSearch`, 확인창 → 요청 → 토스트는 `useTelescopePin`(랭킹 행과 검색 행이 공유)이다. 요청은 `services/api/telescope.ts`의 `pinToTelescope`이고, 성공하면 `onTelescopeChanged` 구독자에게 알려 열려 있는 망원경 목록이 다시 읽게 한다(화면을 떠난 뒤 끝난 요청도 알림은 나간다).

### 8.18 고양이 잡지 칸

- 섬장이 꾸민 홍보 칸 한 장을 그리는 공용 렌더러는 `screens/magazine/AdCell` 하나다. 쓰기 화면 · 잡지 지면 · 크게 보기 · 망원경 말풍선 미리보기가 모두 이것을 써서 섬장이 본 모양 그대로 실린다. 화면마다 칸을 다시 그리지 않는다.
- 칸은 비율이 고정이다(`componentTokens.magazineCell.aspect` = 199/338, Figma A안 C1 편집 칸 338×199). 스티커·테이프 좌표는 칸에 대한 비율(0~1, 가운데 점)이라 어떤 너비로 그려도 같은 모양이다. 치수(섬 프로필 지름 40 · 이름 17 · 글 13 · 주민 줄 11 · 행간 1.4)는 기준 너비 338 에 대한 값이고 실제 너비에 비례해 줄고 는다.
- 틀 그림은 칸을 꽉 채워 늘려 붙인다(틀 원본 비율 1.67~2.32 → 1.70). 틀마다 글 상자(`MAGAZINE_FRAMES[id].inset` — 왼·위·오른·아래 비율)를 재 두었고, 섬 프로필·이름 · 한 줄 글 · 「주민 N/정원 · 평균 X시간 Y분」은 이 상자 밖으로 나가지 않는다. 고양이 귀·편지 봉투 덮개와 모서리 접힘·나무 간판 끈과 못·구명 튜브 고리·티켓 점선·폴라로이드 안쪽 칸 선, 그리고 틀에 인쇄된 하트·별 장식 위에는 글을 놓지 않는다. 고양이 귀 틀은 아래쪽 하트를 피하려고 한 줄 글을 2줄까지만 쓰고(`maxBodyLines`) 주민 줄을 왼쪽 하트 너머에서 시작한다(`metaLeft`).
- 60자 글이 상자에 들어가도록 틀마다 글자 배율과 글 줄 수를 계산한다(`layout.cellTextFit` — 고운돋움 한글 한 글자 ≈ 0.92em 실측). 예상보다 넓은 글자(이모지·영문 대문자)는 `adjustsFontSizeToFit` 로 마지막에 줄이고, 이름은 한 줄(최대 50자라 줄이다가 말줄임)이다.
- 칸 안 글자는 기기 글자 크기 설정을 따르지 않는다(`allowFontScaling={false}`, P12). 스티커가 글 위에 겹쳐 붙어 줄바꿈이 바뀌면 섬장이 본 모양과 달라지기 때문이다. 대신 칸 전체가 접근성 요소 하나로 「○○섬, 주민 N/정원, 평균 …, ‘글’」을 읽고, 누르면 크게 보기를 연다.
- 섬 프로필은 Sky 원 + Brown 선 안에 섬 그림을 원보다 크게(폭 = 지름 × 1.3) 가운데 맞춰 넣는다. 섬만 잘라 둔 그림(1.8:1)이라 양옆 물가가 조금 잘리고, 그림 높이가 지름의 약 0.72라 위아래로 하늘(Sky 원 바탕)이 보인다. 그림은 망원경과 같은 4장(GROMO-2317 v5 — 같은 땅에 집 0·1·3·5채)이고 `islandStage` 가 고른다(주민 0명 집 0채 · 완공 건물 0~2 집 1채 · 3~4 집 3채 · 5 이상 집 5채). 섬 이름은 `islandTitle`(`src/i18n/format.ts`)을 거친다 — ko 「바다」→「바다섬」, en 「Sea」→「Sea Island」, 이미 섬/Island 로 끝나면 그대로. 번역 키의 `{{name}}` 뒤에 섬/Island 를 직접 붙이지 않는다(뗏목 행선지·전망대 토스트·잡지 공통). 유일한 예외는 `magazine.islandTitle`(ko `{{name}}섬`·en `{{name}} Island`) — `islandTitle` 이 접미를 붙일 때 쓰는 키라 다른 문구에서 직접 쓰지 않는다.
- 칸 숫자(실린 날)와 지금 숫자가 같이 보이는 곳 — 망원경 말풍선 — 은 `hideMeta` 로 「주민·평균」 줄을 빼고, 읽는 이름도 「○○섬, ‘글’」로 줄인다. 잡지 지면·크게 보기는 그대로 칸 숫자를 보인다.
- 신고 접수는 위 단일 메일 진입 정책을 따른다. `AdCell`은 누르기·망원경·우리 섬 배지만 제공한다.
- 오른쪽 아래 자리: 바다에서 본 오늘 호의 남의 섬 칸에만 망원경 동그라미(Paper 원 + Brown 선 + 망원경 그림, 터치 영역 44 이상), 내 소속 섬 칸은 「우리 섬이에요」 Butter 배지(칸 안 글 상자 오른쪽 아래, 주민 줄 높이 — 칸 밖으로 나가 아래 칸과 겹치지 않는다. 장식이라 읽는 이름에 포함), 그 밖(섬에서 본 잡지 · 지난 호)은 아무것도 없다. 강퇴된 섬은 남의 섬과 같다(티켓 2315 — 서버가 관계를 `NONE` 으로 보낸다. 옛 서버가 보내는 `KICKED` 칸에만 아무것도 없다). 망원경 동그라미만 칸 모서리에 걸친다. 이 자리는 스티커보다 늘 위에 그린다.
- 꾸미기 재료(틀 11 · 스티커 45 · 테이프 8, 전부 무료)와 섬 그림은 `src/assets/ota/magazine/` 에 두고 `constants/magazineAssets` 표로 부른다. 이 앱 버전에 없는 재료 id(새 시즌)는 건너뛰고, 모르는 틀은 기본 틀(분홍 물결)로 그린다.
- 글이 넘치는지 볼 때는 개발 전용 미리보기를 연다 — 웹 `?magazine`, 네이티브 개발 빌드는 `EXPO_PUBLIC_MAGAZINE_PREVIEW=1` 로 Metro 를 띄운다(틀 11 × 짧은 글 · 60자 · 띄어쓰기 없는 60자 · 이모지 섞인 60자).

### 8.19 우리 섬 홍보 쓰기

- 공개 여부와 무관하게 섬장이 신청할 수 있다. 스티커는 기존 붙이기·저장 상한 5개를 사용하고, 테이프 1개는 별도다. 스티커를 줄여 저장하라는 별도 안내·흐름은 두지 않는다.

- 섬장만 연다(라우트 `promotionEditor`, 코드 `screens/magazine/PromotionEditor`). 입구는 마을회관 「섬 관리」 카드에서 「섬에 친구 초대하기」 바로 위 줄 「냐옹잡지에 섬 홍보하기 ›」 한 곳이다(10/15 문구·자리)(내 섬 섬장만, 구경 중에는 없다 — 홍보는 마을회관에서, 10/5 · 10/14 확정). 우체통과 잡지 끝 장에는 쓰기 입구가 없다. 섬장 여부는 그 카드의 다른 섬장 전용 동작과 같은 지금 역할(실서버는 관리 API — 위임하거나 위임받으면 바로 바뀐다)로 보고, 쓰기 화면도 회관이 확정한 그 역할을 먼저 본다(없으면 홈 스냅샷). 그래서 입구와 쓰기 화면이 엇갈리지 않는다. 뒤로가기는 App 기록으로 그 카드에 돌아간다. 섬장이 아니면 안내만 보이고 서버를 부르지 않는다. 게스트 섬장은 들어가는 순간 회원 전환 시트가 열린다(서버 403 `SOCIAL_LOGIN_REQUIRED` → `e.conversion.offer`).
- 세 단계로 쓴다(10/15): 종이 → 글 → 스티커. 세 단계 모두 잡지 속지(`MAGAZINE_UI.page`, 잡지와 같은 비율로 남은 자리 가운데에 가장 크게) 위에서 하고, 칸·종이는 속지 안 가운데에 둔다. 작은 화면·키보드로 보이는 속지가 종이·[다음]보다 낮아지면 글 단계는 속지 안을, 스티커 단계는 화면 전체를 세로로 민다(칸 위에 손가락이 있는 동안은 잠금). 단계 줄은 두지 않고 뒤로가기로 한 단계씩 돌아간다. ① 종이: 속지 띠에 「종이를 골라주세요.」, 속지 안에 빈 종이(틀 그림만 — 글·스티커·섬 이름 없음)를 가운데 한 장씩 크게 두고 세로로 밀어 고른다. 새로 쓰면 아무 종이도 골라 두지 않는다. 고르면 바로 글 단계로. 종이·스티커·테이프는 서버가 보유를 확인한 재료만 표시한다. 재료 조회 중에는 편집을 열지 않고, 실패하면 다시 읽기를 제공한다. 보유 재료가 없으면 빈 상태를 표시한다. ② 글: 속지 띠에 「냐옹」, 가운데에 고른 종이. 칸 안 한 줄 글 자리가 곧 입력 칸이다 — 들어오면 커서가 서 키보드가 뜨고, 칸 어디를 눌러도 그 자리로 간다(`AdCell bodyInput` — 글은 늘 실릴 칸의 표시용 글자(줄 수 맞춤·0.7배까지 축소·단어 단위 줄바꿈)로 그리고, 입력 칸은 그 위에 글자가 투명한 채 겹쳐 커서·선택만 보인다(표시용 글자가 축소되면 첫 줄 높이로 잰 배율로 입력 칸도 줄여 커서가 보이는 글자에 맞는다). 쓰는 중에도 실릴 모양 그대로다). 60자(코드포인트), 줄바꿈은 띄어쓰기로, 빈 글이면 「한 줄 글을 적어 주세요」, 칸 아래에 빨간 안내와 글자 수. 종이 아래 속지 안에 [다음](빈 글이면 꺼짐, 바닥 줄 없음)이 있고 키보드 [완료]도 같은 일을 한다. ③ 스티커: 속지는 종이와 그 바로 아래 [완료]가 들어갈 만큼만 보이고, 그 아래 남은 높이를 다 쓰는 스티커 서랍(Paper 시트, 탭 고양이 · 바다 · 친구들 · 꾸미기, 꾸미기 탭 첫 줄이 마스킹테이프)이다. 바닥 줄·[새로 꾸미기]·꾸미기 버튼 줄은 없다. 스티커를 누르면 그 스티커가 맨 앞으로 오고, 고른 꾸미기는 점선 상자 왼쪽 위 ✕(지름 26, 누르는 자리 44)로 지운다(상자와 같이 돈다). [완료]는 처음 싣기면 확인창 「잡지에 이대로 실으시겠습니까?」 + 섬 물고기 그림(`art.fish`)과 숫자 「60」 + [취소] [싣기]를 띄우고, 이미 낸 홍보면 확인창 없이 바로 저장한다. 신청 창이 닫힌 00~07시면 [완료] 자리에 「아침 7시에 다시 열려요」(꺼짐). 버튼이 꺼진 이유(잔액 부족 · 자정 지나 잠김)만 [완료] 아래에 한 줄로 알리고, 신청 거절 같은 안내는 토스트로. 읽기 전용이면 [완료] 없이 안내만. 문구는 최소 — 설명 문장을 덧붙이지 않는다. 쓰기 화면의 칸은 「주민·평균」 줄을 그리지 않는다(`hideMeta` — 평균은 발행 때 정해져 쓰는 중에는 「집계 전」이라 잡지와 달라 보인다). 새로 쓰면 빈 종이에서 시작한다 — 지난번에 실은 글·스티커를 채워 두지 않는다. 이미 낸 홍보로 들어오면 먼저 「올린 홍보글을 수정하시겠습니까?」 [취소](회관으로) [수정]을 묻고, [수정]이면 그 칸으로 스티커 단계(칸 전체)에서 연다. 읽기 전용이면 묻지 않고 칸만 보인다. [완료]로 싣거나 고쳐 저장하면 토스트 한 줄(「잡지에 신청했어요」 · 「고친 내용을 저장했어요」 — 실리는 건 다음 07시라 「실렸어요」라고 하지 않는다)과 함께 회관으로 돌아간다(접수 확인창·발도장 없음). 뒤로가기(안드로이드 하드웨어 포함)는 스티커 → 글 → 종이 → 회관 순이다. 신청이 글 문제(금칙어 등)로 거절되면 글 단계로 돌아가 안내한다.
- 칸 위 조작은 판 하나(칸보다 둘레 8% 넓다 — 스티커가 걸칠 수 있는 범위)의 손가락으로 한다: 한 손가락으로 눌러 고르고 끌어 옮긴다, 두 손가락으로 크기·회전·위치를 함께 바꾼다, 고른 꾸미기 오른쪽 아래 손잡이를 한 손가락으로 끌어 크기·회전한다(손잡이·✕는 꾸미기가 가장자리에 있어도 판 안으로 끌어들여 늘 누를 수 있다), 빈 곳을 톡 누르면 고르기가 풀린다. 고른 것은 점선 테두리(Brown)와 손잡이(Paper 원)로 보인다. 테이프는 크기가 없고, 놓는 순간 가장 가까운 테두리 띠에 붙는다. 스티커는 5개까지(10/15 — 서랍은 그대로 두고 6번째를 붙이려 할 때만 「스티커는 5개까지 붙일 수 있어요」 토스트. 서버 저장 검증도 5개 상한이다), 같은 스티커 여러 장은 된다.
- 모든 손동작에는 대안이 있다: 두 손가락 크기·회전은 손잡이를 한 손가락으로 끌어 하고(옮기기는 원래 한 손가락 끌기), 스크린리더는 칸 위 꾸미기마다 있는 요소(최소 44pt)의 동작(고르기 · 위아래·좌우로 · 크게·작게 · 돌리기 · 맨 앞으로 · 지우기, 테이프는 크기·맨 앞으로 빼고)으로 고친다. 버튼 줄은 손가락으로 못 하는 맨 앞으로 · 지우기만 둔다(10/15 — 옮기기·크기·돌리기 버튼은 뺐다). 본문은 작은 화면·키보드에서 세로로 밀리고, 칸 위에 손가락이 있는 동안은 스크롤이 잠긴다. 서랍 탭은 44pt 이고 좁은 화면에서 두 줄로 감긴다. 화면 치수는 `componentTokens.promotionEditor`, 간격은 `semanticTokens.spacing` 이 정본이다. 머리 제목은 큰 글자에서 잘리지 않고 여러 줄로 감기며 머리 높이가 같이 는다. 접수 완료 확인창이 열린 동안 뒤의 편집기는 스크린리더에서 숨는다.
- 주 행동은 종이 아래 [완료] 하나(위 ③). 신청 창이 닫힌 00~07시면 버튼 자리에 「아침 7시에 다시 열려요」(07시가 되면 다시 읽어 저절로 열린다), 잔액이 부족하면 버튼이 꺼지고 아래 줄에 이유가 나온다. 자정이 지난 뒤 이미 낸 홍보는 읽기 전용이다 — 서랍·버튼 줄을 걷고 「자정이 지나 고칠 수 없어요. 아침 7시에 실려요」만 둔다(10/14). 화면을 열어 둔 채 자정이 지나면 다시 읽어 읽기 전용이 되고, 저장하지 않은 고친 것 대신 서버에 남은(잡지에 실릴) 칸을 보인다.
- 서버와 맞추는 규칙: 재료 목록은 따로 읽어 늦거나 실패해도 편집기 응답만으로 먼저 열린다. 다시 읽는 동안에는 신청·새로 꾸미기 버튼이 꺼진다. 잔액 부족·창 닫힘·이미 신청 같은 거절은 화면을 다시 읽는다. 늦게 온 신청 성공이 그 사이 받은 마감 상태를 덮지 않는다. 게스트 섬장이 회원 전환을 마치면 그 자리에서 다시 읽는다. 서버 칸으로 바뀌면 고르기를 푼다.
- 싣거나 고쳐 저장하면 토스트 한 줄(「잡지에 신청했어요」 · 「고친 내용을 저장했어요」 — 실리는 건 다음 07시라 「실렸어요」라고 하지 않는다)과 함께 회관으로 돌아간다 — 늦은 응답·같은 키 재시도로 온 성공도 같다(10/15, 발도장·접수 확인창 없음). 마감 다시 읽기로 편집이 꺼지면 칸 위에서 하던 손동작은 그 자리에서 버린다. 글 문제(빈 글 · 금칙어 · 60자 초과)는 글 단계로 돌아가 종이 아래 빨간 안내, 그 밖의 거절은 토스트로 알린다.
- 섬 홍보 소식: 섬장이 아닌 주민이 내 섬 홈에 들어오면 이 기기에서 아직 안 본 홍보 소식을 토스트로 한 번 알린다(`usePromotionNewsToast`). 그 홍보가 실릴 호가 나오기 전(신청한 KST 날짜 다음 날 07시 전)까지만 알리고, 같은 날이면 「오늘 … 내일 아침 잡지에 실려요」, 자정이 지난 00~07시면 「어제 … 오늘 아침 잡지에 실려요」다.
- 서버 없이 확인할 때는 목업 모드(`EXPO_PUBLIC_DEMO=1`)에 `EXPO_PUBLIC_MAGAZINE_MOCK` 상황(open · closed · applied · latest · poor · private · guest · member · news)을 준다. 손가락 조작은 `EXPO_PUBLIC_MAGAZINE_PREVIEW=editor` 대본 미리보기가 같은 판 핸들러에 터치를 넣어 단계별로 보여 준다.

### 8.20 고양이 잡지 읽기

- 홍보 칸·편집부 랭킹·새 섬의 `privateIsland`는 키가 없으면 false다. 비공개 섬은 「초대로만 갈 수 있는 섬」을 표시하고 접근성 이름에도 포함한다. 홍보 칸의 주민·평균 줄 아래에 안내를 두고 그 한 줄 높이까지 글 배율에 반영한다. 망원경 동그라미는 숨기며, 편집부의 비공개 섬 줄은 이름 아래에 숫자·안내를 배치한다.

- 잡지는 라우트 `magazine`(인자 = 호 id, 코드 `screens/magazine/MagazineReader`)으로 연다. 섬에서 펼친 잡지라 배경은 섬 홈(흐리게 덮음)이고, 그 위에 속지 그림(`MAGAZINE_UI.page`, 모눈 + 별·물고기·발자국·하트 테두리)을 그림 비율 그대로 화면 안에 가장 크게 둔다. 속지 위 리본에 제호 「냐옹」, 그 아래 표지 띠 「10월 14일 · 19호」, 오른쪽 위 모서리에 닫기(동그란 ✕ 그림, 터치 44). 글·칸은 `componentTokens.magazineReader` 의 안쪽 여백 안에만 둔다.
- 쪽: 첫 장 편집부(「이번 주 랭킹」 리본 + 1~3위 메달 줄(Subtle Pink 카드) · NEW 꼬리표 「어제 새로 생긴 섬」(Sky 카드) · 편집냥 그림과 「편집냥의 조언」(몽돌 팁 14문장 중 하나) 또는 운영 문구가 있는 날 「편집부 소식」(Butter 카드)) → 홍보 칸 3개씩(`AdCell`, 신청 순서) → 칸이 하나도 없으면 「오늘은 실린 홍보가 없어요」 → 섬장만 끝 장 「우리 섬도 실어 볼까요?」와 「홍보는 마을회관에서 쓸 수 있어요. 아침 7시부터 자정까지 신청하면 다음 날 아침 호에 실려요」(쓰기 버튼은 없다 — §8.19). 가로로 밀어 넘기고, 아래 ‹ 쪽/전체 › 가 같은 일을 한다 — ‹ › 는 44×44 누름 자리에 `xl` 26, 쪽 번호는 본문 색 `sm` 14, 첫·끝 쪽의 비활성 화살표는 `button.disabledOpacity`. 쪽 넘김 줄의 누름 높이는 44로, 그림 자리(`navHeight` 30) 가운데를 지킨 채 위·아래로 7씩 늘고 위쪽 몫은 지면과의 틈(`cellGap` 8) 안이다. 버튼 hitSlop 은 가로로만 둬 지면 칸 터치를 가로채지 않는다(GROMO-2413)(끝 쪽 근처에서 다음 칸을 이어 읽어 전체 쪽 수가 늘 수 있어 그동안은 「2 / 4+」, 스크린리더는 「4쪽 넘게 중 2쪽」). 이어 읽기가 실패하면 쪽 번호 자리에 「더 불러오지 못했어요 · 다시」. 쪽이 바뀌면 스크린리더에 알린다. 지면(칸 3개)은 쪽 넘김 줄 위에서 끝나 가로처럼 낮은 화면에서도 겹치지 않고, 회전하면 보던 쪽에 다시 맞춘다. 지면은 가로로 넘기는 목록이라 그 밖은 잘리므로, 꾸미기가 칸 밖으로 실제로 걸치는 만큼(돌린 테이프·스티커 그림의 경계 상자, 그 호 칸 전체의 최댓값 — 적어도 중심 범위 8%, 많아야 30%, `issueBleed`)도 지면 안에 들게 칸을 그만큼 줄이고 첫 칸 위를 비운다(`readerGeometry` 의 `cellPad`). 편집부 쪽이 지면보다 길면 쪽 넘김 줄에 잘리지 않게 지면 높이에 맞춰 줄이고(0.7배까지, 그보다 더 줄여야 하면 세로로 민다 — 10/15), 편집부 섬 줄의 이름은 두 줄까지, 큰 글자(`semanticTokens.typography.largeTextThreshold` 1.3 배 이상)에서는 평균·주민 숫자를 이름 아래로 내린다.
- 섬에서 본 잡지에는 망원경 동그라미가 없다(10/14) — 우리 섬 칸에만 「우리 섬이에요」 배지. 칸을 누르면 화면 폭으로 크게 보고(가로 화면에서는 높이 안에, 칸이 실제로 걸치는 만큼까지 화면 안), 아무 데나 누르면 닫힌다. 펼치는 데 성공하면 그 호에 읽음을 적어 빨간 점이 꺼진다. 7호보다 오래된 호는 「이 호는 이제 볼 수 없어요」.
- 신고는 설정의 신고센터에서 받는다. 잡지 일반·확대 칸에 길게 누르기나 스크린리더 신고 동작을 두지 않는다.

- 들어가는 곳: 우체통 첫 화면 맨 위 [고양이 잡지 보기 · N호](Pink 알약, 안 읽었으면 오른쪽 위 빨간 점) 옆 [잡지 꽂이] — 꽂이는 최근 7호 시트(지금 나와 있는 호 줄만 Subtle Pink + 「오늘」 Butter 배지, 줄마다 「읽음」/「안 읽음」)이고 줄을 누르면 그 호를 편다. 우체통 없는 섬은 홈 잡지 물건을 길게 눌러 꽂이를 연다. 섬 지도의 우체통 위에는 안 읽은 잡지가 있으면 새 소식 배지(친구 편지 배지가 있으면 그쪽만).
- 배달(B2): 오늘 호를 아직 받지 않았으면 섬 홈에 펠리컨 안내창 「우체통에 고양이 잡지가 왔어요!」 [나중에] [우체통 열어보기]가 한 번 뜬다(회관 안내와 같은 자리). 우체통이 없는 섬은 「고양이 잡지 왔어요!」 [나중에 읽기] [잡지 펼치기]이고, 가장 최근 호가 있는 동안(발행이 늦어 지난 호뿐이어도) 홈 「집중 시작」 버튼 바로 위에 잡지 표지 물건(누르면 그 호, 길게 누르면 꽂이, 지금 호를 안 읽었으면 빨간 점)을 둔다 — 왼쪽 아래는 우체통 없는 이른 섬에 늘 있는 건설 카드 자리라 피한다. 펠리컨은 지금 나와 있는 호에만 뜬다. 구경 · 집중 · 다른 안내(우체통·회관·집중 시작 안내) · 화면 전환 중에는 둘 다 띄우지 않는다. 한 번 알린 호는 받음 기록이 실패해도 같은 실행 동안 다시 알리지 않는다(앱을 다시 켜면 다시 알린다). 홈·우체통을 켜 둔 채 07시를 넘기면 07:01 에 오늘 호를 다시 읽고, 발행이 늦으면 10분마다 다시 읽는다.
- 바다 배달(B1 `1228:1308`, GROMO-2314): 먼바다 표류 중(항해·출항 연출·결과창이 아닐 때) 오늘 호를 아직 받지 않았으면 펠리컨 배달을 화면 전체로 한 번 띄운다 — 먼바다 배경 위 Paper 말풍선(Brown 2px · 반경 Preview · `0 4px 0 Brown`, 꼬리는 왼쪽 아래 펠리컨 쪽) 「고양이 잡지 왔어요!」, 왼쪽 아래 펠리컨, 오른쪽 아래 14° 기운 잡지 표지, 아래 [잡지 펼치기](Pink) · 「나중에 읽기」(ghost). 말풍선 앞에 펠리컨 배달 영상(`ota/cutscenes/pelican-mail.mp4`, 5초)이 화면을 덮고 끝나면 말풍선이 뜬다(동작 줄이기에서는 영상 없이 말풍선부터). 영상이 뜬(마운트된) 순간이 «실제로 뜬 순간»이라 그때 받음(SEA)을 적고(영상 첫 프레임이 늦어도 기다리지 않는다)(다른 창 때문에 미뤄진 동안은 적지 않는다), 「나중에 읽기」·안드로이드 뒤로가기(영상 중에도)는 나중에(SEA)를 적는다. 영상 구간의 접근성 라벨은 장면 설명(`magazine.delivery.seaCutscene`)이라 문구가 겹쳐 읽히지 않는다. 유저 카드·한마디 같은 다른 창이 열려 있으면 닫힌 뒤 띄우고, 뒤 바다 장면은 스크린리더에서 숨으며 뜰 때 문구를 한 번 알린다(iOS 는 직접 읽고 안드로이드는 live region). 그림은 402×874 기준 크기를 화면에 맞춰 줄이고 큰 글자·가로 화면에서 넘치면 세로로 민다. 치수는 `componentTokens.magazineReader.seaDelivery`.
- 뗏목 위 잡지(B3 `1228:1341`): 받은 오늘 호(바다·섬 어디서 받았든)가 있으면 표류 중 내 뗏목 오른쪽에 12° 기운 표지 물건(터치 52×60, 안 읽었으면 빨간 점, 읽은 뒤에도 남는다 — `seaObject`)을 둔다. 뗏목이 작은 가로 compact(32~64pt)에서는 표지를 뗏목 크기에 비례해 줄여(`compactArtRatio`) 뗏목 위가 아니라 옆에 나란히 두고, 누르는 자리는 44 이상으로 뗏목 누름 자리와 겹치지 않는다. 항해 중에는 없다. 누르면 그 호를 편다. 바다에는 길게 누르기·꽂이가 없어 `GET /me/magazine/issues` 를 부르지 않는다.
- 바다에서 펼친 잡지(A2 `1227:1359`)는 라우트 `seaMagazine`(인자 = 오늘 호 id, 소속 섬이 없어도 열린다)이다. 같은 `MagazineReader` 를 `place="SEA"` 로 그려 배경은 먼바다, 받음·읽음은 SEA, 칸 오른쪽 아래는 우리 섬 = 「우리 섬이에요」 · 남의 섬(강퇴된 섬 포함) = 망원경 동그라미 · 비공개 섬 = 없음이다. 오늘 호만 보고, 닫기·뒤로가기는 바다로 돌아간다.

- 목업: `EXPO_PUBLIC_MAGAZINE_MOCK` 에 deliver(아직 안 받음) · opened · noissue · emptyissue · paged(커서 나눔) · guest(신고 403)를 준다. 신고는 칸마다 처음은 새 신고, 두 번째부터 이미 신고다. 우체통 없는 섬은 데모 섬으로 볼 수 없어 `EXPO_PUBLIC_MAGAZINE_PREVIEW=home` 미리보기로 본다.

### 도서관 확정 시안 (2026-09-22)

- 기존 도서관 원탁·책 에셋을 유지한다. 개인 일기장은 일·주·월로 나누되 월은 합계 화면이 아닌 달력이다.
- 도서관 방은 마을회관과 같은 자리(왼쪽 위)의 ‹ `NavBtn`으로 섬에 돌아간다. 일기장 머리에는 ‹(뒤로) 하나만 둔다 — 이웃 상세에서는 이웃 목록으로, 그 밖에는 도서관으로 간다(§7.14).
- 기간 탭과 날짜 탐색은 공통 높이에 고정한다. 일·주의 집중/폰 사용 탭도 고정하고 책 안의 본문만 세로 스크롤한다.
- 일별 집중은 총시간, 횟수·최장·물고기, 과목별 시간, 06~05시 순서의 24행 × 10분 6칸 시간표 순이다. 공부 구간은 핑크 한 색으로 표시한다.
- 주별에는 과목명을 표시하지 않는다. 합계·일별 그래프·요약만 표시한다. 집중·폰 사용 그래프는 빈 기록이나 측정 설정 안내에서도 월~일 7칸(2026-10-26 GROMO-2488, 종전 일~토)을 유지하며 미래 날짜는 빈값으로 둔다. 평균과 측정된 날짜의 분모는 오늘까지의 날짜만 센다. 빈 상태의 측정 설정 버튼은 가운데 정렬한다.
- 달력에서 날짜를 선택하면 그날의 집중·폰 사용 시간을 나란히 보여주고 개인 집중 기록을 이어서 표시한다.
- 이웃 일기장의 목록과 상세는 `characters/cat/{color}/idle.png` 전신 에셋을 64pt `contain`으로 표시한다. 잘린 아바타 에셋을 쓰지 않는다.
- 이웃 일기장은 3열 주민 목록에서 선택한다. 최대 15명이며 기본 선택 강조는 없다. 상세는 ‹ 날짜 범위 › 로 옮기는 한 주(월~일, 이번 주는 › 비활성)의 집중·폰 사용 합계와 전 기간 모은 물고기, 그 아래 집중(Pink)·폰 사용(Graph Line) 두 선을 겹친 주간 선그래프(`library/WeekLineChart` — 점은 Paper 채움 + 선 색 테두리, 세로 격자 0·절반·최대(5h 이상), 미래·미측정 날은 점·선 없음, 범례는 그래프 위 한 줄)다. 날짜별 표는 없고(2026-10-26 GROMO-2488) 넘칠 때만 책 안에서 스크롤하되 막대는 숨긴다. 일·주·월 탭과 과목·개별 세션을 노출하지 않는다.
- 이웃 요약과 표의 각 열은 가운데 정렬한다. 설명을 여백 채우기용으로 넣지 않는다. 상태 화면은 제목과 필요한 행동 하나만 둔다.
- `componentTokens.diary`가 책·내용 영역·표·시간표 치수의 정본이다. 공용 `Seg`의 `inset` 변형은 둥근 선택 면을 내부에 배치하며, 테두리와 패딩을 제외한 실제 탭 높이를 44pt로 보장한다. `Button`, 기존 `T`·에셋·네이티브 사용량 리포트를 재사용한다.
- 서버 모드의 통계 날짜 축은 기존 API 계약인 UTC를 유지한다. 모크는 KST 날짜를 유지하되 주 배치는 월요일~일요일이다(2026-10-26 GROMO-2488, 종전 일~토). 미측정은 `—`, 불완전 합계는 `합산 보류`로 표시하며 실제 0분과 구분한다. 기간의 최신 측정 상태가 `pending`·`unavailable`이어도 날짜별 `authorized` 값은 유지하고, `denied`만 기간 값을 차단한다. 오늘의 네이티브 값은 기간 상태가 `authorized`일 때만 표시한다.
- 서버 집중 API는 기간 기여 시간과 완료 시각, 조회 기간의 실제 적립 물고기 합계 `earnedFish`를 제공한다. 일 통계는 KST 날짜 창의 일반 보상·황금 자기 몫·최초 체험 보상을 합산하며 완료 세션만 세거나 집중 시간으로 지급량을 추정하지 않는다. 구간·목표 달성 일수는 주지 않는다. 완료 시각에서 역산해 휴식을 집중으로 색칠하지 않는다. 구간이 없으면 `시간대 기록 없음`으로 표시한다. 물고기 합계가 없는 구 서버 응답은 `—`로 두며 실제 0마리와 구분한다. 시안 숫자를 대입하지 않는다.
- 달력의 선택 날짜 과목·세션은 월 응답을 완료 날짜로 나누지 않고 해당 날짜를 별도 조회한다. 자정을 넘긴 세션도 서버가 산정한 날짜 기여분을 따른다.

Figma의 연결 라이브러리와 이 로컬 UI Kit는 별개이다. 연결 라이브러리가 비어 있어도 GroMo 디자인 시스템이 없는 것이 아니다.

Figma 시안은 다음 순서를 따른다.

1. 이 문서에서 화면의 semantic role과 공용 컴포넌트를 정한다.
2. 해당 기능의 HTML·PNG 표본으로 실제 외형을 확인한다.
3. 기존 Figma 프레임이 있다면 정보 구조와 최신 상태를 대조한다.
4. Pink/Sky/Butter/Cream/Paper/Brown/Ink 토큰으로 스타일을 만든다.
5. 같은 역할의 버튼·카드·칩·행을 프레임마다 새로 그리지 않고 컴포넌트화한다.
6. 새 패턴이 필요하면 이름, 상태, 사용 조건을 이 문서와 코드에 반영한다.

로컬 UI Kit를 Figma에서 Assets 패널로 직접 사용하려면 별도 Figma 라이브러리 파일을 만들고 publish한 뒤 대상 파일에 연결해야 한다. `DESIGN.md`는 에이전트 판단을 통일하지만 Figma 라이브러리 연결 자체를 대신하지는 않는다.

## 10. React Native 구현 규칙

```ts
import { semanticTokens, componentTokens } from '@/design-system/tokens';
import { Button, Card } from '@/design-system/primitives';
import { Page, Group, Row, Btn } from '@/design-system/patterns';
```

- 작은 범용 요소는 `primitives.tsx`를 재사용하거나 확장한다.
- 화면 구조를 포함한 조합은 `patterns.tsx`를 재사용하거나 확장한다.
- 한 기능에만 필요한 컴포넌트는 `screens/<feature>/`에 둔다.
- `.docs`의 HTML·CSS·JS를 런타임에서 직접 import하지 않는다.
- 토큰이 없으면 화면에 raw hex를 넣기 전에 `tokens.ts`에 역할을 정의한다.
- 공용 요소와 거의 같은 로컬 복제 컴포넌트를 만들지 않는다.
- 글자는 공용 `Text`(`design-system/typography`, `Txt`·장면 `T`·건물 안 장면이 모두 거친다)로 그린다. iOS 는 한국어를 글자 단위로 끊어 「시/작해」처럼 단어 중간에서 줄바꿈하므로 공용 `Text` 가 `lineBreakStrategyIOS="hangul-word"` 를 기본으로 붙인다. 화면마다 따로 붙이지 않고, 다른 값이 필요할 때만 호출부에서 덮는다(GROMO-2413).
- 새 공용 토큰·컴포넌트를 추가하면 이 문서도 같은 작업에서 갱신한다.

## 11. 접근성과 반응형

- 모든 상호작용의 실질 터치 영역은 최소 44×44pt이다.
- 버튼·아이콘·장소·이미지에 의미가 있으면 접근성 라벨을 제공한다.
- selected, disabled, checked 상태를 접근성 API에도 반영한다.
- 색만으로 상태를 전달하지 않는다.
- 동적 글자 크기에서 잘림보다 재배치와 스크롤을 우선한다.
- Safe Area, 키보드, 세로·가로, 태블릿 레이아웃을 확인한다.
- 모달이 열린 동안 뒤 콘텐츠는 스크린 리더에서 숨긴다.
- 애니메이션은 Reduce Motion을 존중한다.

## 12. 금지 사항

- UI Kit 확인 없이 생성형 도구의 기본 초록 버튼을 사용하지 않는다.
- Figma 라이브러리 검색 결과만으로 “디자인 시스템이 없다”고 단정하지 않는다.
- raw hex, 임의 spacing, 임의 radius를 화면 코드에 새로 넣지 않는다.
- 기존 공용 컴포넌트와 같은 역할의 요소를 화면마다 다시 만들지 않는다.
- 시연용 숫자·상품·사용자 이름을 실제 정책이나 데이터로 간주하지 않는다.
- 로딩, 빈 상태, 오류, 권한 거부, disabled를 하나의 화면 상태로 뭉치지 않는다.
- 주 행동을 여러 색의 CTA로 경쟁시키지 않는다.
- 아트가 정보 구조와 텍스트 위계를 가리게 하지 않는다.

## 13. 알려진 드리프트

다음은 새 작업에서 무시하지 말고 정리해야 할 차이다.

- HTML 토큰의 기본 `stroke`는 2px이나 앱 `componentTokens.card/input`은 1.5px이다. 런타임 컴포넌트를 사용할 때는 현재 코드값을 따르되, 디자인 갱신 시 역할별 선 굵기로 명시적으로 통일한다.
- Small 버튼의 시각 높이는 38px이다. 접근성 최소 터치 영역 44pt를 만족하도록 hit area 보완이 필요하다.
- `components.json`은 13번까지만 등록되어 있지만 실제 폴더에는 14번 마을회관과 15번 화면 세부가 있다. 자동 인덱스를 갱신할 때 두 항목을 포함해야 한다.
- `components/08-rank-residents/README.md` 제목이 “전망대”로 남아 있다. 폴더 역할은 주민·프로필 목록이며 제목은 오래된 생성 흔적이다.
- 집중 화면의 `OUTLINE`(`screens/focus/FishingIsland.tsx`)은 `componentTokens.nameplate.outline`을 참조하지만, 그 값이 토큰 Brown 과 같은 값의 복제라 Brown 이 바뀌어도 따라가지 않는다. 같은 이름의 `OUTLINE`(`screens/interiors/BuildingInteriors.tsx`, `#7d5f4d`)은 Brown 과 다른 값이므로 둘을 섞어 쓰지 않고, 새 화면은 토큰 `semanticTokens.color.outline`을 참조한다.

### Android 사용량 측정

- 앱 권한 관리의 스크린타임 연결 행에 권한 상태와 연결 동작을 모은다. 별도 “시스템 설정 > 측정 권한” 중복 행은 두지 않는다. 권한 요청·재요청은 연결 스위치 하나로 수행하고 요청 도중에는 스위치만 비활성화한다. 권한 허용에 성공하면 측정 앱 피커를 자동으로 한 번 열고, 거절·취소 시에는 열지 않는다. 추가 요청·시스템 설정 버튼을 동적으로 만들지 않는다. 측정 앱 진입은 중간 설명 없이 시스템 피커를 자동으로 열고 선택·취소 후 돌아온다. 사용 시간 공유 설정은 앱 설정의 개인정보 그룹 한 곳에만 표시한다. 연결 해제 시 기존 시스템 설정 이동과 측정 앱·집중 중 허용 앱 선택은 유지한다.
- 설정의 측정 권한에서 시스템 사용 정보 접근 화면을 열고, 복귀하면 실제 권한을 다시 확인한다. 승인 후에도 같은 화면에서 철회할 수 있다.
- 집중 차단을 지원하는 Android 바이너리에서는 측정 앱과 집중 중 허용 앱을 별도로 선택한다. 전체 앱 측정은 명시적으로 선택하며, 기존 측정 대상 변경은 다음 KST 자정에 적용한다.
- 내 일기장의 폰 사용 탭에서 현재 기기의 권한이 꺼져 있으면 합계 대신 권한 허용 안내와 “권한 설정하기” 버튼을 표시한다. 측정 앱 미선택, 서버 기록 대기, 기간 내 일부 날짜 미측정은 구분한다. 집중 빈 기록에서 “집중하러 가기” 버튼은 표시하지 않고 과거 기록의 “오늘 기록으로”는 유지한다.
- 내 오늘 사용량은 네이티브 조회값을 분 단위로 표시하고, iOS의 15분 단위 기록과 문구를 구분한다.
- 조회 실패·권한 철회·복원할 수 없는 날짜는 실제 0분과 구분하고 미확인 날짜를 퀘스트 달성에 사용하지 않는다.

## iOS 일반 홈 위젯 (2026-10-08)

- 고양이와 오늘의 총 집중시간 두 정보만 표시한다. small/medium을 지원한다.
- 색은 생성된 `ios/Shared/ReportPalette.swift`의 `bg`·`ink`·`inkSub`를 재사용한다.
- 본문은 시스템 caption, 집중시간은 기존 xl 크기(26)·bold·동적 글자 크기·tabular 숫자다.
- 간격은 기존 4/8/16/20 값을 사용한다. 위젯 배경과 시스템 여백은 WidgetKit을 따른다.
- 기존 6색 고양이의 idle·loaf·reading·tilt 정지 그림을 사용하고 시간별 타임라인에 포즈를 고정한다.
- 날짜가 만료되거나 서버 합계가 없으면 숫자는 `—`이다. 한국어/영어는 위젯 Localizable.strings로 제공한다.
- 화면 내 서버 전송 동의·허용 앱 설정은 기존 Group·Row·Toggle·Txt를 재사용한다.
- 권한 거절·요청 취소 뒤에는 재요청 버튼과 시스템 설정 안내를 표시한다. 설정 복귀 시 실제 OS 권한을 다시 읽는다.
- 측정 앱 편집과 설정 요약은 마지막 저장 선택을 보여 주고, 변경 예약은 다음 날 한국 시각 자정 적용으로 안내한다. 실제 측정 대상은 예약과 분리해 유지한다.

### Android 집중·스크린타임 네이티브 표면

`specialUse`를 제거한 Android 빌드는 `supportsFocusShield=false`를 제공한다.
앱 권한 관리에서 집중 중 허용 앱·다른 앱 위에 표시·집중 상태 알림을 숨기고 관련 권한을 조회하거나 요청하지 않는다.
측정 권한 안내에서도 앱 차단 권한 설명을 제외한다. 사용량 측정·측정 앱 선택·홈 위젯은 유지한다.
집중 차단과 집중·휴식 상시 알림, 해당 상태를 갱신하는 Android 집중 푸시 등록은 실행하지 않는다.

측정 앱·허용 앱 선택은 기존 `Group`, `Row`, `Toggle`, `Field`, `Btn`을 사용한다.
네이티브 차단 화면·알림·홈 위젯의 색상은 `scripts/generate-report-palette.cjs`가
semantic token에서 생성한다. 고양이는 iOS 위젯과 같은 기존 6색 정지 에셋을 사용한다.
홈 위젯은 고양이와 오늘 총 집중시간만 표시하고, 미확인 값은 `—`로 표시한다.

### iOS 집중 차단 화면

- iOS `ShieldConfiguration`의 시스템 배치를 사용하며 크림 배경, Ink 제목, Muted 설명, Pink 버튼과 Ink 버튼 글씨로 구성한다. 다크 모드에서도 이 표면은 주간 팔레트를 유지한다.
- `ios/Shared/ShieldPalette.swift`는 공통 생성 스크립트로 semantic token에서 만든다. 아이콘 크기는 `componentTokens.focusShield.iconSize`를 사용한다.
- 위젯의 기존 6색 고양이 focus PNG를 재사용하고, 집중 시작 시 선택한 고양이 색을 App Group으로 전달한다. 계정 초기화 시 이 값도 지운다.
- 제목은 “지금은 집중 시간이에요”, 설명은 현재 집중 주제를 안내한다. 주제가 비어 있으면 일반 집중 안내를 사용한다. “닫기”는 차단된 앱을 닫으며 차단을 해제하지 않는다.

### 도서관 스크린타임 관측

- 서버 수치의 측정 권한과 최종 확정을 구분한다. 오늘의 중간 수치는 통계에 표시하고, 퀘스트 달성 보상에는 마감 후 최종 관측만 사용한다.
- 서버 보고 대기 중이어도 본인의 오늘 수치는 네이티브 측정 권한과 준비 상태를 확인해 표시한다. 서버가 전송 동의 철회를 나타내는 denied 상태이면 숫자를 숨긴다.
- 기간 합계에 중간 관측이 들어 있으면 측정 중인 사용량이 포함됐다고 안내한다.

- 도서관의 날짜·일/주/월 집계·시간표는 KST 달력으로 통일한다. KST 창 시작·끝을 UTC 시각으로 변환해 보고하며, UTC 퀘스트 일계와 구분해 저장한다. 일기장의 주간은 KST 월요일~일요일이다(2026-10-26 GROMO-2488). `/screens/library` 의 이번 주 조각과 섬 랭킹은 일~토 축(`utcPeriodRange`)이라 일기장 주간 조회는 그 조각을 재사용하지 않고 늘 월~일 범위를 직접 묻는다.

### 홈 바다와 해안

홈의 일반 이미지·타일 경로는 같은 낮·밤 반복 바다와 투명 해안을 사용한다. 바다의 기준 크기는 원화 좌표 512px이며 카메라 원점·배율을 섬과 공유한다. 네이티브 SVG Pattern의 이동 시 잘림을 피하기 위해 화면에 걸치는 타일만 일반 Image로 배치하며, 같은 로컬 이미지를 재사용한다. 인접 경계는 같은 물리 픽셀로 반올림해 소수 배율의 틈을 막는다. 섬과 건물 그림·좌표·타일 활성화 조건은 유지한다. 원본 및 재생성 규칙은 `scripts/source-art/island-ocean/README.md`를 따른다.

집중섬도 같은 주간 바다를 사용하되 기존 이미지 렌더러와 중앙 연못·물줄기·폭포를 유지한다. 외부 바다만 분리하고 바다의 원점·배율은 `FishingIsland`의 지도와 공유한다. 집중섬 야간 표현이나 타일 전환은 이 변경에 포함하지 않는다.

건물 탭 진입은 고양이가 입구에 도착하는 즉시 내부를 연다. 갸웃·기지개·문 열림·확대 덮개의 재생 완료를 기다리지 않는다. 고양이를 직접 눌렀을 때의 반응은 유지한다. 네이티브 건물 외곽선은 기본 카메라의 RN 이미지·알파 확장 좌표를 유지하고 부모 transform에 건물과 같은 줌을 적용한다. 빠른 줌에서 내부 이미지를 따로 리사이즈하지 않으며 흰 외곽선 두께도 건물에 대한 상대 크기를 유지한다.

앱 설정은 기본 설정·안전·개인정보 세 그룹을 사용한다. 알림 권한은 섬 홈에 처음 들어올 때 시스템 팝업으로 한 번만 묻고(앱 안의 별도 안내는 두지 않는다), 설정의 「알림」 토글이나 앱 권한 관리의 「알림」 행에서 다시 켠다 — 이미 거부했으면 시스템 설정을 연다(2026-10-26, GROMO-2526). 개인정보 요약 팝업은 제거하고 개인정보처리방침 원문 링크만 둔다. 버전은 설치된 앱 메타데이터로 표시한다. 차단한 사용자 관리는 안전 그룹 첫 줄에서 연다(2026-10-26, 종전 친구 관리 머리). 내 정보의 「저장」은 시트 아래 버튼 줄의 가득 폭 `Btn`이고 처리 중에는 입력과 함께 막힌다. 털색 고르기는 한 줄 3칸 정사각 — 그림이 칸을 채우고 색 이름은 읽는 이름으로만 둔다.

홈의 섬 이름·집중시간 알약은 화면 가로폭의 50% 이내로 제한한다. 섬 이름은 한 줄 말줄임하고 접근성 이름에는 전체 섬 이름과 시간을 유지한다. 게시판 공지·퀘스트·방명록 패널의 전환 화살표는 표시하지 않고 닫기와 배경 진입 영역을 유지한다.

### 집중 종료 길게 누르기

집중 화면의 종료 버튼 문구는 ‘종료하기’로 표시한다. 버튼 자체를 1.5초 연속으로 누르면 확인창 없이 바로 종료한다. 기존 `FiButton`의 `holdToConfirm` 변형을 사용하며, 크림 바탕 위 핑크 채움이 왼쪽부터 오른쪽으로 진행한다. `componentTokens.focusEndHold`로 1.5초와 120ms 간격의 약한 햅틱을 관리한다. 진동 설정을 끈 경우 진동하지 않는다. 종료 판정은 누른 시점의 1.5초 타이머로 처리하고, 채움은 왼쪽을 기준으로 네이티브 scaleX 애니메이션을 사용한다. 버튼 내부의 작은 손가락 움직임과 화면 시간 갱신은 진행을 끊지 않는다. 손을 떼거나 터치 영역을 벗어나거나 앱이 비활성화되면 취소하고 진행을 초기화한다. 튜토리얼의 대체 버튼도 같은 제약을 적용한다. 스크린리더는 활성화하면 같은 1.5초 타이머·채움·진동으로 종료를 대기하고, 다시 활성화하면 취소한다. 대기 중에는 접근성 이름과 동작을 종료 취소로 바꾸며 앱 비활성화·화면 이탈 시에도 취소한다. iOS의 접근성 탭과 Android의 activate 동작을 모두 지원하고, 이 경로에서는 짧은 터치 해제 이벤트가 대기를 취소하지 않는다.

### 응원 말풍선

응원 이모지는 고양이를 향한 뾰족한 꼬리의 말풍선 안에 표시한다. `FocusEmoteBubble`과 `componentTokens.focusEmoteBubble`을 공용으로 사용하고, Paper 배경에 옅은 Brown 윤곽을 둔다.

### 집중섬 자리 선택

도착 안내는 섬 아래 바다에 배경·테두리 없는 중앙 정렬 글자로 표시한다. 노란 배지는 사용하지 않는다. 자리 선택 중에는 기존 육지·주민·시설·보상 배치·이동 경로 검증을 통과한 빈자리 최대 8곳을 투명한 원으로 표시한다. 이는 추천 위치이며 원 밖의 유효한 빈 땅도 선택할 수 있다. 착석하면 안내와 원을 숨긴다.

### 집중 준비

준비 창은 할 일을 선택 입력으로 받으며 비워 두면 기본 주제 ‘집중’으로 시작한다. 오른쪽 위 X는 키보드를 닫고 자리 선택으로 돌아간다. 튜토리얼도 입력을 건너뛸 수 있다.

### 휴식에서 돌아가기

휴식 화면에는 ‘집중 이어가기’ 버튼만 둔다. 한 번 누르면 기존 세션을 이어 집중섬으로 돌아간다. 별도의 휴식 종료 버튼·확인창·3초 누름은 제공하지 않는다.

### 집중 결과

결과창은 확정 C안으로 상단의 작은 화면 제목과 가운데 정렬한 과목명, 그 아래 왼쪽 집중 시간과 오른쪽 물고기 보상 열을 배치한다. 집중 시간은 HH:MM:SS, 물고기는 그림 아래 +3처럼 숫자만 표시한다. 큰 글자 설정에서는 시간과 보상을 세로로 배치한다. 안쪽에 굵은 테두리 상자를 중첩하지 않는다. 기존 `FiModal`의 footer로 돌아가기 버튼을 내용 스크롤과 분리해 화면이 낮거나 퀘스트가 많아도 버튼이 보이게 한다. 실제 달성한 퀘스트가 있는 경우에만 구분선 아래 목록을 표시하며, 퀘스트가 없거나 미달성·조회 중·조회 실패로 표시할 달성 항목이 없으면 제목·빈 안내·진행률 영역을 만들지 않는다. 서버의 claimable·claimed와 로컬 해당 날짜 achieved 판정을 그대로 사용한다. `FocusResultSummary`와 `componentTokens.focusResult`를 공유한다.

이번 집중에 받은 꾸미기가 있으면 시간·물고기 아래 구분선 뒤에 「낚은 아이템」 제목과 한 줄(그림 `componentTokens.focusResult.itemSize` 정사각 `OutfitItemArt` · 이름 · 처음 받은 것이면 공용 `Badge` small 「NEW!」, 세로 가운데)을 둔다. 받은 것이 없거나 카탈로그가 모르는 상품이면 칸을 만들지 않는다. 스크린리더는 「낚은 아이템 이름 NEW!」로 한 번에 읽는다.

## 바다 첫 만남 온보딩 (2026-10-21)

- 로그인 → 여섯 고양이 선택 → 바다 첫 대화 중 이름 입력 → 망원경 → 실제 첫 항해 집중 순서다. 브랜드는 `집중할고양`이다.
- 승인한 20장 시안의 대사를 `onboardingStory` 번역 키로 관리한다. 친구를 만나고 함께 지낼 곳을 만들고 싶다는 두 대사는 유지한다.
- 첫 바다에는 고양이·뗏목·바다만 둔다. 배경은 실제 집중의 `seaAssets.background`, 비율 유지 중앙 cover다. 첫 말풍선은 1.2초 뒤 등장한다.
- 짧은 대사는 작은 말풍선에 타이핑한다. 타이핑 중 탭은 현재 문장 완성, 다음 탭은 다음 장면이다. 결심 대사 완료 후 앉는다. 건너뛰기는 배경 없는 ghost 버튼이다.
- 고운돋움과 기존 Btn·입력·색 토큰을 사용한다. 장면 치수와 타이핑 속도는 `componentTokens.onboarding`이 관리한다. 화면 읽기·동작 줄이기는 타이핑 대기를 생략한다.
- 이름·털색 등록 전 재시작은 고양이 선택부터다(유효 로그인은 재요청하지 않음). 등록을 마친 계정에 현재 섬이 없으면 이야기 이력과 관계없이 바다로 진입·복귀하며, 서버 진행 세션 복구가 우선한다. 첫 실제 집중 성공 후 이야기를 완료한다.
- 연출 체크포인트는 기존 계정 귀속 로컬 저장본에만 보관한다. 서버 `onboardingComplete`(이름·털색 등록)와 `onboarded`(현재 섬)는 의미를 바꾸지 않는다. 섬 없는 사용자는 바다에서 망원경을 눌러 목적지를 고른다. 예전 첫 섬 선택 화면과 생성·참여 선택 메뉴는 제거한다.
- 승인 시안의 누운 그림은 검정·흰색·삼색, 치즈·크림·회색은 기존 loaf다. 검정 망원경 외 색은 승인 시안처럼 앉은 자세다. 이 임시 포즈를 새 완성 에셋으로 표현하지 않는다.
- 망원경은 실제 목록·항해 시간과 주민 수·완공 건물 수를 사용한다. 일반 망원경과 같은 `ISLAND_STAGE_ART`·`islandStage`로 승인 v5의 집 0·1·3·5채를 표시한다. 주민 0명 무인도는 집 0채다. 기존 섬 목록이 비었거나 들어갈 섬이 없으면 서버가 마련한 개인 무인도 하나(15분)를 망원경 중앙에 표시한다. 정원이 남은 섬이나 이미 가입한 섬이 하나라도 있으면 기존 목록·순서를 유지하고 예약 무인도는 숨긴다. 소속이 없다는 이유만으로 무인도를 우선하지 않는다. 무인도에는 항해 버튼만 두며 실제 도착 후 방장 소속으로 정착한다. 앱이 임의의 섬 id나 집중 완료를 만들지 않는다.
- 집중 중 내 말풍선을 눌러 한마디 입력이 가능하다. 기존 20자·회원 전환·5분 잠금 정책과 세션 타이머를 유지한다. 도착 전 종료 버튼은 `집중 마치기`다.
- 웹 `?onboarding`은 실제 RN 화면 검토용이며 서버 로그인·프로필·세션 API를 호출하지 않는다. `?onboarding=uninhabited`는 섬 없는 사용자의 바다 → 망원경 → 무인도 항해를 검토한다.
