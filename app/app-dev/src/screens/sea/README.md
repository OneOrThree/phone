# 먼바다 화면

## 구현 범위

`SeaScreen`은 서버 정본을 전달받는 화면이다. 실제 세션 API를 대신하거나 로컬에서
보상을 지급하지 않는다. 웹 `?sea`에서 테스트 데이터로 모든 상태를 확인할 수 있다.
`?sea&canvas&stage=focus` / `stage=arrived`는 화면 크기별 비교용이다.

- S1 `1202:907`: 나는 앞에 고정하고 나머지 참여자를 최대 5명씩 탐색.
  10명 방에서는 다른 참여자가 5+4명으로 표시된다. 바다 장면을 가로 스와이프해 탐색하며 페이지 화살표·숫자 표시는 두지 않는다(2026-10-20 사용자 정정). 서버 스냅샷 순서 변경으로
  페이지를 초기화하지 않는다. 화면 밖 독서 모션은 정지한다.
- V1 `1203:1029`: `SeaVoyagePreparation`의 선택적 한마디와 시작 콜백.
- V2 `1203:1071`: 섬 그림 없이 독서 포즈, 과목·도착 정보·시간·진행률, 항해 그만두기.
- V3 `1203:1111`: 도착 전 중도 종료 확인.
- V5 `1203:1194`: 항해 중과 동일한 배치·먼바다를 유지하고 같은 버튼을 섬에 내리기로 교체.
- 결과 `1335:1346`: 섬 이름·정산된 이번 항해 시간·대표 개인 꾸미기 하나. 여러 보상을 받으면 나머지 이름도 함께 표시한다. 사용자 수정대로
  `낚은 아이템`(섬 결과창과 같은 `common.caughtItem`, GROMO-2382), 분류 부제 없음, `섬 둘러보기`를 사용한다.
  처음 받은 아이템(`seaReward.newProductIds`)에는 `NEW!` 배지를 붙이고 옷장의 안 본 새 꾸미기에 넣는다.
- G2 `1207:1326`: 2026-10-20 승인한 `DepartureStory`의 출항 준비 영상(`ota/cutscenes/departure.mp4`)으로 교체했다.
  `SeaDeparture`와 집중섬 `focusTravel`이 같은 4초 영상을 쓰고 끝나면 각 목적지로 이어진다.

## 참가자 카드와 가로 탐색 (2365)

- 최신 승인 배치대로 나는 고정, 다른 참가자는 5+4명으로 가로 탐색한다. 스냅샷 전체를 받으며, 순서가 바뀌어도 기존 자리·페이지를 유지한다. 한마디는 위, 이름과 초록 집중 시간은 뗏목 아래다.
- 유저 카드에서 기존 `SeaRaft`·`CatOutfitLayers`로 고양이를 보여주고, 이름·집중 시간·한마디 전체를 표시한다. 표류 중 시간은 마지막 서버 값(세션이 없으면 0)이다. 본인·이미 떠난 유저에게 친구 요청을 제공하지 않는다. 신고·차단 시트는 열지 않는다.
- `SeaVoyageHost`가 `POST /friends/requests {targetUserId}`를 연결한다. 성공 뒤에만 `요청 보냄`으로 바꾸고 친구 목록을 재조회한다. 중복·권한·전송 오류는 안내 후 재시도할 수 있고, 게스트는 기존 회원 전환 흐름을 연다. 화면 이탈·계정 세대 변경 뒤의 응답은 버린다. 카드 진입은 바다 소켓을 추가로 열지 않는다.
- `seaRealtime.ts`의 `name=null`·`catColor=null` 폴백은 `???`·`gray`다. 서버 바다 member 계약에는 현재 appearance가 없어서 다른 참가자의 장착을 추측하거나 섬 주민 API로 우회 조회하지 않는다. 내 장착과 전달된 `outfit`은 기존 레이어로 합성하며 `undefined`·`null`은 모두 미장착이다.
- 한국어·영어 문구와 공용 모달 스크롤·접근성 차단 규칙을 사용한다.

## 고양이 잡지 (2314)

- `CurrentScreens` 가 `sea` 라우트에서도 오늘 호(`useMagazineToday`)를 읽어 `e.magazineToday` 로 넘긴다. `SeaVoyageHost` 는 표류(`sea` · 세션 없음 · 출항 연출 아님) 중에만 `SeaScreen.magazine` 을 준다.
- 펠리컨 배달 B1(`SeaMagazineDelivery`): 아직 받지 않은 오늘 호면 한 번 띄운다. 받음 `{place: SEA}` 와 `markDelivered` 는 실제로 뜬 순간(`onShown`)에만 — `SeaScreen` 이 다른 창(유저 카드·한마디·이모트·결과창) 때문에 미루는 동안은 적지 않는다. 그 사이 항해가 시작되거나 다른 곳에서 받았으면 띄울 차례를 거둔다. 「나중에 읽기」·안드로이드 뒤로가기(SeaScreen BackHandler, App 이 먼저 부르면 호스트 `backOverride`)는 `{place: SEA, deferred: true}`. 먼저 펠리컨 배달 영상(`pelican-mail.mp4`)을 보여 주고 끝나면 말풍선을 띄운다. 띄운 동안 장면을 모달로 숨기고 문구를 스크린리더에 한 번 알린다.
- 뗏목 위 잡지 B3: 받은 호가 있으면 `SeaScene` 이 내 뗏목 오른쪽에 표지 물건(안 읽음 빨간 점)을 둔다. 가로 compact 에서는 뗏목 크기에 비례해 줄여 뗏목 옆에 나란히 둔다(누르는 자리 44 이상, 뗏목과 겹치지 않음). 꽂이·길게 누르기는 없다(`GET /me/magazine/issues` 를 부르지 않는다).
- 펼치기는 라우트 `seaMagazine`(`seaRouteHeld` 에 포함 — 소속 섬 가드를 타지 않는다) → `MagazineReader place="SEA"`. 망원경 동그라미는 `pinToTelescope(id, 'magazine', promotionId)` 뒤 `e.replace('telescope')` 라 망원경 뒤로가기가 바다로 간다. 요청 중 잡지를 닫으면 이동하지 않고, 빠진 섬 토스트만 알린다.
- 알려진 한계(범위 밖): 소속 섬이 없는 표류 유저가 망원경(바다 [망원경] · 잡지 동그라미 모두)으로 가면 App 의 소속 가드가 `telescope` 를 지키지 않아 섬 선택으로 보낸다. 기존 바다 [망원경] 버튼과 같은 동작이다.

## 표류 중 위쪽 HUD (2404)

- `SeaVoyageHost` 는 표류(`drifting`) 중에만 `SeaScreen.hud` 를 준다 — 친구 요청 수는 홈(`WorldMap`)과 같은 출처(서버면 `e.friendsScreen`, 목업이면 `state.friends`)이고 `go` 는 App 의 라우트 이동이다. 항해 집중·결과창·출항 연출에서는 null 이라 그리지 않는다.
- `SeaScreen` 은 `voyage` 가 없고 `hud` 가 있을 때만 `sea-hud`(안전 영역 안 위쪽, `box-none`)를 그린다: 왼쪽 `HudAvatarButton`(내 털색·장착 → `wardrobe`), 오른쪽 `HudActions`(`friends` 배지 · `settings`). 모양·접근성 라벨은 홈과 같다.
- App 의 `SEA_HUD_ROUTES`(`friends`·`friendSearch`·`blockedUsers`·`settings`·`profile`·`language`·`permission`·`screenTimeApps`·`wardrobe`)는 계정 단위 화면이라 소속 가드가 섬 없이도 허용한다(`NO_ISLAND_ROUTES` — 망원경과 같은 목록). 섬을 잃는 순간(서버 동기화든 목업 강퇴 복구 신호든) 이 화면에 있었다면 바다로 보내지 않고 그 자리에 둔다 — 강퇴 안내만 뜨고, 닫기(`home()`)·뒤로가기 때 바다로 간다. 강퇴된 섬을 보는 방문·항해 화면은 종전대로 옮긴다. 닫기 목적지는 소속 여부가 아니라 연 곳(App 기록의 바닥이 바다 라우트인지)으로 정한다 — 소속 섬이 있어도 바다에서 열었으면 바다로, 홈에서 열었으면 홈으로.
- 옷장(`useShop`)은 소속 섬이 없어도 개인 인벤토리(`GET /me/inventory`)와 외양 변경(`PATCH /me/appearance`)을 한다 — `scope` 가 섬 id 대신 `personal` 이 되고, 상점 상세(제목)는 부르지 않으며 칸 제목은 꾸미기 카탈로그가 준다. 상점·주문·축음기는 종전대로 섬이 있어야 한다.
- `CurrentScreens` 의 친구 freshness 경계(`friendsSafetyRouteActive`)에 `sea` 를 넣어 홈과 같은 주기로 요청 배지를 다시 검증한다.

## 서비스 연결 지점과 남은 작업

2026-10-17 기준 main `725504d3c`에는 PR #1129·#1149가 통합돼 있다.
`Telescope.tsx`의 `TODO E1-5`가 항해 집중 연결 지점이며, 바다 방과 집중 세션의
실제 연결은 아직 없다. GROMO-2303은 디자인과 에셋 인계 및 확인용 화면을 제공하고,
GROMO-2309·2310에서 실제 진입 경로와 서버 어댑터를 연결한다.

GROMO-2310(2026-10-18)이 1·2·3·6을 `SeaVoyageHost`(라우트 `sea`·`seaArrival`)와
`services/seaRealtime.ts`로 연결했다. 남은 것은 4·5(GROMO-2311 결과창·보상·환영)다.

1. **2310 에서 연결** — 2299 세션 어댑터: `SeaVoyage`에 현재 세션·서버 시간·도착 판정을 전달한다.
   화면은 100% 진행률만으로 `canDisembark`를 추론하지 않는다. 서버 시간 보간,
   백그라운드 복귀 재조회, 세션 복원은 기존 세션 명령 계층에 연결해야 한다.
2. **2310 에서 연결** — 2300 방 어댑터: 방 전체(최대 10명)를 `participants`에 전달한다. 입퇴장,
   실시간 재연결/중복 이벤트, 한마디 5분 잠금, 이모트 TTL은 서버 계약대로 처리한다.
   화면에는 현재 `messageCooldownSeconds`와 아직 유효한 이모트만 전달한다.
   기존 한마디를 비우면 `onMessage('')`로 삭제를 요청한다. 삭제에도 같은 쿨다운을 적용한다.
3. **2310 에서 연결** — `onFinish(sessionId, intent)`: 기존 명령 계층에서 동일 의도의 멱등 키·버전·계정
   경계를 유지하며 종료한다. 성공한 정산 응답 또는 미확인 결과를 `result`로 전달한다.
   Promise 성공만으로 화면이 결과/보상을 추측하지 않는다.
   `intent`는 사용자 의도이며 서버의 최종 도착 상태를 대신하지 않는다. 오래된 스냅샷에서
   `stop`을 보냈더라도 이미 도착한 세션의 정산을 누락시키지 않도록 서버가 최종 상태로
   처리하거나 최신 상태와 함께 거절해야 한다. `voyage` 해제와 `result` 설정은 한 번에 전달한다.
   어댑터 요청에는 타임아웃·취소를 적용한다. 화면은 세션/결과 변경 시 이전 요청의 UI 잠금을
   해제하고, 이전 요청 완료가 새 요청의 잠금·오류·패널에 영향을 주지 않도록 구분한다.
4. **2311 에서 연결** — 카탈로그 기반 결과창(`GET /customization/catalog`, 없으면 id 만). 이전 메모: 2301 보상/2313 기본 단계표 데이터: `seaRewardCatalog`에 실제 itemId와 에셋을 매핑한다.
   현재 실사용 카탈로그는 비어 있고 오리는 `SeaPreview`에서만 주입된다.
   `rewards`는 서버가 지급한 모든 `grantedProductIds`를 순서대로 보존한다. 첫 아이템을 대표 이미지·이름으로, 나머지는 이름 목록으로 표시한다.
   `rewards`가 있으면 획득, 비어 있고 `rewardsUnknown=false`면 미획득 확인, `rewardsUnknown=true`면 확인 불가다.
   서버 `seaReward: null`은 지급 없음이 아니라 모름이므로 어댑터는 `rewardsUnknown=true`로 전달한다.
   복원 응답만으로 지급을 추측하지 않고 인벤토리 정본을 확인한다. 모르는 아이템은 id 만,
   미획득과 미확인은 각각 다른 문구를 표시한다. `minutesToNextTier`가 있으면 다음 단계까지 남은 분을 함께 보인다.
5. **2311 에서 연결** — `SeaVoyageHost.onExplore`(도착 기록·환영·인벤토리 재조회·방문/주민 라우트), 주민 소식 토스트는 `islandRealtime` events. 이전 메모: `onExplore(result)`: 결과 확인 처리·인벤토리 재조회·기존 방문자/주민 라우트 이동.
   첫 주민 환영/2302 주민 소식도 이 어댑터에서 기존 흐름과 연결한다.
6. **2310 에서 연결(망원경 쪽)** — 망원경 [항해하기] → `SeaVoyagePreparation` → 바다 항해 집중 시작
   → `SeaScreen`. 그만두기는 같은 finish 뒤 항해 중단 영상(`abandon.mp4`, 3초)으로 멀어지고 표류 상태로 남는다.
   G1/G3 뗏목 목적지 화면은 티켓 2363, 먼바다·집중섬 공통 출항 세 컷은 티켓 2364에서 연결했다.
   한마디는 바다 세션에 과목이 없어 집중 중에도 말풍선에 뜬다(`SeaScene`).

`SeaVoyagePreparation`을 열 때 호스트는 배경 화면의 접근성을 숨기고 입력을 막아야 한다.
미리보기는 준비창이 열린 동안 장면과 도구 모음을 `no-hide-descendants`/`aria-hidden`으로 숨긴다.

계정 변경 시 호스트는 사용자 ID를 React key로 사용하여 화면을 재생성해야 한다.
`guest`가 참이거나 동적 boolean이면 `onSignIn`을 반드시 전달해 로그인 안내에서
실제 회원 전환 흐름으로 이동할 수 있게 한다. 회원 전용 화면은 둘 다 생략할 수 있다.
요청 취소/버전 충돌 처리는 명령 계층의 책임이며 UI의 중복 탭 방지로 대체하지 않는다.
