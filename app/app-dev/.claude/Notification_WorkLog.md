# 알림 화면·보관함 WorkLog (GROMO-661)

> 홈 우측 상단 종 → 알림 화면. 수신한 서버 푸시를 로컬 보관함에 저장해 목록으로 보여주고,
> 안 읽은 알림이 있으면 종에 빨간 점을 띄운다.
>
> - 티켓: GROMO-661 (홈 우측상단 앱 알림 화면 구현)
> - 브랜치: `afeat/GROMO-661-notification-screen` · 최초 구현 2026-07-13
> - 푸시 수신 자체(FCM 토큰·리스너·딥링크)는 [Push_WorkLog.md](./Push_WorkLog.md)(GROMO-393) 참고 — 이 문서는 그 위에 얹은 "보관함 + 화면"만 다룬다.

---

## 1. 범위

- **In**: 알림 화면(`NotificationsScreen`) · 로컬 보관함(`notificationInbox`) · 푸시 수신/탭 경로에 저장 배선 · 홈 종 뱃지(빨간 점) 실연동 · 종 탭 계측(`notification_bell`)
- **Out(후속)**: BE 알림 이력 API 연동 · "저장할/안 할 알림 타입" 분류 정책 · 알림 개별 삭제/페이지네이션

## 2. 아키텍처 결정

### 데이터 원천: 로컬 저장 우선, BE API 나오면 교체 (하이브리드)

- 백엔드는 푸시(승급/강등·리그 마감·순위 추월·미접속 복귀 4종)를 **보내기만** 하고, 유저별
  발송 이력 테이블/조회 API가 없다 (`notification_sent_logs`는 순위 추월 중복방지 전용).
- 정석은 서버 이력(BE 티켓 선행)이지만, 화면을 먼저 완성하기 위해 **로컬(AsyncStorage) 저장**으로
  시작하기로 결정 (2026-07-13 오스카 — 옵시디언 `결정기록` 참조).
- 교체 대비: 저장/조회/읽음을 전부 **`services/notificationInbox.ts` 한 모듈에 격리** —
  BE API가 생기면 이 모듈 내부만 바꾸면 화면·홈은 무수정.

### ⚠️ iOS 캡처 한계 (하이브리드의 트레이드오프)

- 앱이 **백그라운드/종료 상태로 도착만 하고 탭하지 않은** 알림은 앱 코드가 실행되지 않아
  저장되지 않는다. notification payload 푸시는 `setBackgroundMessageHandler`도 타지 않음
  (data-only + content-available가 아니면 iOS가 앱을 깨우지 않음).
- 즉 로컬 보관함 = "포그라운드 수신 + 탭해서 연 알림"의 부분집합. 완전한 이력은 BE 전환 시 해결.

### 저장/비저장 타입 분류는 미정 — 정책 교체 지점만 마련

- `notificationInbox.ts` 상단 `STORED_TYPES` 상수가 유일한 적용 지점. 현재 `'all'`(전부 저장).
- 정책이 정해지면 `['rank_change', ...]` 형태로 이 상수만 수정.

### 기타 결정

- **읽음 모델**: 알림 화면 진입 = 진입 시점 스냅샷의 id만 읽음 처리(개별 읽음 없음).
  ~~전체 읽음~~ → 스냅샷 직후 도착한 알림이 화면에 안 보인 채 읽음 처리되는 걸 막기 위해
  id 스코프로 변경(§6 리뷰 반영). 종 뱃지는 개수 없는 빨간 점이라 이 모델로 충분.
- **중복 방지**: FCM `messageId`를 저장 키로 사용 — 같은 메시지를 여러 경로에서 만나도 1건.
- **보관 상한**: 최근 50건, 초과분은 오래된 것부터 폐기.
- **뱃지 갱신**: 보관함 변경 구독(`subscribeInbox`) — 알림 화면에서 읽음 처리하거나 포그라운드
  푸시가 저장되면 홈이 마운트된 상태 그대로 즉시 반영(탭 네비게이터라 홈은 항상 마운트).
- **아이콘 매핑은 딥링크(link) 기준**: 서버 4종 푸시가 `data.type`을 보내는지는 미확인이고
  `data.link`(gromo://league·focus·home)는 확실히 오므로, 목록 아이콘은 link 경로로 분기.
