# 3D 웹 품질 검토 — 2026-11-07

초기 구현에서 6차례 기능·복구·반응형 검토를 수행한 뒤, 사용자 피드백에 따라 시각 표현과 이동 경험을 다시 수정했다. 초기 6차례의 테스트 통과만으로 아트·애니메이션의 완성도가 확보됐다고 판단할 수 없다. 아래에는 최초 검토 이력과 추가 수정의 근거를 구분해 기록한다.

검토 대상은 별도 브랜치 `afeat/GROMO-2786-cattus-metaverse-web`의 `app/metaverse-web`이다. 앱·서버 운영 데이터에 연결하지 않고 `127.0.0.1`에서만 검증했다.

## 1차 — 빌드와 첫 렌더

- 타입 검사와 Vite 빌드 후 Chromium에서 1440×1000 화면을 캡처했다.
- 발견: 앱 토큰 import가 Expo tsconfig에 의존했고, 원본 폰트가 dev 서버의 파일 허용 범위 밖이었다. 지면 경로가 잔디 아래에 있었고 Drei HTML 이름표의 독립 React root에서 unmount 경고가 발생했다.
- 수정: 원본 토큰을 가상 모듈로 읽고, 폰트를 로컬 번들로 제공했다. 경로 높이를 올리고 이름표는 독립 React root 없이 DOM 층에 투영했다. 조명과 고양이 크기도 조정했다.
- 재검증: 타입·빌드 성공, 정상 첫 화면에서 `console.error`와 `pageerror` 0건.

## 2차 — 이동과 행동 전환

- 바다·건물·나무 충돌, 장애물 우회, 네 장소 도착, 대각선 속도, 긴 프레임 중단, 메뉴 입력 차단을 검토했다.
- 발견: 모닥불 목적지가 충돌 반경 안에 있었고, 부두 가장자리에서 격자 반올림 결과가 바다가 되면 길을 찾지 못했다. 경로 중간 노드를 통과할 때 잠시 낚시 상태가 켜졌다.
- 수정: 모닥불 접근 지점을 바꾸고 실제로 도달 가능한 시작 격자를 선택했다. 마지막 노드에 도착할 때만 도착 행동으로 전환한다.
- 재검증: `npm test` **11/11 통과**. 부두 전 낚시 금지와 가장자리 탈출을 회귀 테스트로 포함했다. 실제 브라우저에서 키보드·지면 클릭 후 `(0, 10.2)` 부두 도착과 타이머 시작을 검증했다.

## 3차 — 두 브라우저 실시간 공유

- 서로 다른 브라우저 컨텍스트 2개가 같은 로컬 서버에 접속했다.
- 이름·회색 털·이동을 다른 창의 이름표 위치 변화로 검증했고, 실제 WebSocket 스냅샷에서 인사 행동까지 전달되는 것을 확인했다. 창을 닫으면 접속 수가 2에서 1로 돌아왔다.
- 깨진 위치·행동·털색·이름은 상태에 적용하지 않는다. 다른 Origin과 잘못된 Origin은 연결을 거부한다. 브라우저 전체 요청 중 localhost 밖 요청은 0건이었다.
- 발견·수정: 첫 렌더 준비 전에 로딩을 끝내던 상태를 실제 두 번째 프레임 이후로 옮겼다. 정적 섬은 메모해 HUD 갱신에 따라 재생성하지 않는다.
- 재검증: `tests/room.test.ts`, `tests/browser-qa.mjs` 통과.

## 4차 — 모바일·입력·접근성

- 320·375·414·768px에서 장면·설정 대화창을 각각 캡처했다. 가로 넘침이 없으며 화면의 버튼은 모두 최소 44×44px이다.
- 입력창에 `wasd`를 적어도 고양이가 움직이지 않는다. Escape로 일반 대화창을 닫으면 원래 버튼으로 초점이 돌아간다. OS 설정과 화면 설정의 동작 줄이기를 각각 검증했다.
- 발견·수정: 768px의 소개 문구가 부두를 가려 해당 폭에서는 소개 문구를 접고 장소 버튼만 유지했다. 안내 고양이의 기본 위치를 옮겨 작은 화면의 이름표 겹침도 줄였다.
- 재검증: 4개 폭의 화면과 터치 영역 자동 검사 통과. 최종 768px 캡처에서 소개 문구가 부두를 가리지 않는다.

## 5차 — 연결·그래픽 실패와 복구

- WebSocket을 끊은 상태에서도 이동 가능함을 검증했다. 이후 실제 로컬 서버에 자동 재연결했다.
- 가벼운 화면, 카메라 회전·초기화, WebGL context 소실, 새로 불러오기, WebGL 자체 미지원 상황을 검토했다.
- 발견·수정: 렌더 실패 안내를 로딩이 덮지 않게 했고, context 소실 안내가 Escape로 사라져 조작 불능 화면에 남지 않게 했다. 오류 안내 문장의 한글 단어 줄바꿈도 보완했다.
- 재검증: `tests/recovery-qa.mjs` **5개 시나리오 통과**. 복구 가능한 오류에서는 다시 불러오기 버튼을 제공한다. 미지원 상황은 의도한 오류를 안내 화면으로 받는다.

## 6차 — 빌드 산출물과 실제 터치 입력

- `npm run build`의 `dist`를 `npm run preview -- --port 4174`로 실행했다. 개발 서버뿐 아니라 빌드 산출물에서 사용자 흐름 13개·복구 5개를 재검증했다.
- Chromium 터치 이벤트로 조이스틱 이동·손을 떼면 정지, 땅 터치 이동, 한 손가락 회전, 두 손가락 핀치 확대와 시점 초기화까지 **4개 시나리오 통과**했다.
- 고운돋움 TTF 7,226,720 bytes를 WOFF2 444,468 bytes로 압축했다. 문자 매핑이 동일하고 12,539개 글리프를 모두 보존했다. 새로 추가한 폰트 라이선스도 포함했다.
- 최종 타입 검사·단위/통합 테스트·웹 빌드·Prettier 검사·`git diff --check` 통과. 정상 사용자 흐름에서 브라우저 오류 0건, 외부 네트워크 요청 0건.
- 변경 범위 재검토: `app/metaverse-web/` 신규 구현, 기존 앱의 실행 스크립트·디자인 설명만 변경했다. 서버·인프라·배포 워크플로는 편집하지 않았다. 원래 작업 폴더의 진행 중 수정은 보존했다.

## 추가 검토 — 시각 표현과 이동 경험

초기 결과는 멀리서 보는 섬 구도와 단순 모델에 치우쳤다. 앱 원화의 큰 눈·곡선 꼬리가 약했고, 확대하면 지붕 아래 빈 면과 단순한 조형이 드러났다. 이 상태를 완성도 높은 메타버스로 표현한 최초 완료 보고는 근거가 부족했다.

- 고양이: 앱의 `cat-black.png`를 다시 보고 크림색 눈·눈동자·휘어진 꼬리·수염·발을 수정했다. 실제 이동 거리로 걸음 위상을 진행하고 걷기·앉기·인사 자세 사이를 보간한다.
- 시점: 가까이서 고양이를 따라가는 시점을 기본으로 바꿨다. 전체 섬을 보는 모드와 원래 시점 복귀도 제공한다. 추적 카메라와 고양이 사이의 건물·나무는 옅게 표시한다.
- 공간: 지붕 아래 박공을 채우고 지붕 이음새·목재 테두리·화분·굴뚝을 더했다. 해안선에 굴곡을 주고 잔디·들꽃을 추가했다.
- 발견한 동작 오류: 원격 고양이의 보간 위치가 React 갱신 때 원래 prop으로 덮였다. 시작 위치를 고정하고 프레임에서만 갱신하도록 수정했다. 행동 버튼을 누른 뒤 WASD가 차단되던 입력 조건도 고쳤다. 키보드로 버튼을 누르는 Space 동작은 유지한다.
- 경로: 충돌 없이 연결할 수 있는 중간 경유점은 생략한다. 장애물 우회와 부두 도착 단위 검사는 유지한다.
- 확인한 화면: 1440×1000·375×812에서 기본 추적, 전체 섬, 앉기·인사·낚시를 캡처해 확인했다. 이전 화면과 비교하면 표정·건물의 세부 요소가 읽히며 가까운 시점에서도 행동 도크와 고양이가 겹치지 않는다. 이것은 캡처된 구도의 검토 결과이며 모든 카메라 각도에 대한 보증은 아니다.
- 새 자동 검사: 데스크톱에서 행동 버튼을 누른 뒤 바로 키보드로 이동하고, 모바일에서는 Chromium 터치 이벤트로 이동했다. 고양이 좌표는 변하고 추적 이름표는 화면 중심 부근에 유지된다. 전체 시점으로 전환했다 돌아와도 추적을 재개한다. `tests/experience-qa.mjs` 4개 검사에서 브라우저 오류는 0건이었다.
- 가림 검토: 마을회관 앞까지 걸어간 뒤 카메라를 건물 뒤로 돌렸다. `artifacts/quality-revision/occlusion.png`에서 건물 너머 고양이가 보이는 것을 확인했고, 시점 초기화 후 건물이 원래 불투명도로 돌아온 화면도 확인했다.
- 수정 후 단위/통합 11개를 다시 통과했다. 빌드 산출물에서는 기존 브라우저 흐름 13개, 실패 복구 5개, 터치 4개, 새 시점·입력 4개 검사를 다시 통과했다. 정상 흐름의 브라우저 오류와 외부 네트워크 요청은 0건이다. 타입 검사·빌드·Prettier·`git diff --check`도 통과했다.

## 추가 검토 — 넓은 섬·모닥불 30석·음원·바다

사용자의 여섯 가지 추가 요청을 반영했다. Orca 실행 `run_f24429b9dd3a`의 Claude 작업자가 장면 에셋과 바다 셰이더를 재제작했다. 외부 모델이나 생성형 이미지가 아니라 저장소의 TypeScript로 생성하는 3D geometry이며, [제작 기록](docs/asset-rebuild.md)에 구성을 적었다.

- 섬의 걷는 면적을 초기 구현의 약 6.5배로 늘리고 모닥불 둘레에 12석·18석 두 줄로 30개 의자를 배치했다. 별도 집중섬으로 이동하지 않고 클릭한 의자에 즉시 앉는다. 서버가 자리 중복을 막고, 자리만 바꿀 때 집중 시작 시각을 보존한다.
- 기존 `campfire.m4a`와 `forest-wind.m4a`를 바이트 그대로 복사했다. 첫 직접 입력 뒤 숲바람을 재생하고 집중 시 모닥불로 전환한다. 두 브라우저의 자리 공유, 타이머 진행, 음원 gain 전환, 자리 변경 시 음소거 유지, 집중 종료 뒤 숲바람 복귀를 확인했다. 실제 Chromium에서 두 파일의 90초 디코드·루프 설정·오디오 시간 진행을 검사했다. 스피커로 청취한 결과는 아니다.
- 별도 로컬 preview(4176)에서 테스트 WebSocket 주민 29명과 브라우저 1명이 모두 다른 의자에 앉았다. 집중 30/30과 안내 고양이를 포함한 31개 고양이 표시를 캡처했다. 이는 로컬 정원·렌더 기능 검사이며 AWS 또는 운영 부하 검사가 아니다. 실사용자 30명의 기기 성능을 검증한 결과도 아니다.
- 실제 3D 의자의 hover·클릭으로 즉시 집중하는 흐름을 확인했다. 수면 영역의 850ms 간격 캡처는 일반 모드에서 달라지고 동작 줄이기에서는 같았다. 물결·해안 포말·바위 포말이 있는 전체 섬과 30명 착석 화면을 시각 검토했다.
- 가까운 기본 시점에서 나무가 화면 중앙을 가리지 않도록 카메라를 조정했다. 장소 이름표는 상단 조작부 뒤에 들어가면 숨긴다.
- 기존 소켓 종료 테스트가 클라이언트의 close만 기다린 뒤 재예약해 간헐적으로 실패했다. 서버 스냅샷에서 퇴장과 빈 좌석을 확인한 뒤 한 번 예약하도록 수정했다. 임의 지연이나 재시도로 덮지 않았다. 전체 단위·통합 21개 및 해당 테스트 반복 5회 통과를 작업자가 보고했다.
- 초기 확장 섬 검사는 Chromium headless shell의 SwiftShader 소프트웨어 렌더링을 사용했다. 두 창 검사에서 GPU 프로세스의 CPU 사용이 높아지고 고정 600ms 이동·5초 연결 대기가 실패했다. 실제 좌표 이동을 기다리도록 검사를 고치고 full Chromium의 ANGLE Metal로 바꿨다. 로컬 WebGL renderer는 `ANGLE Metal Renderer: Apple M5 Pro`로 확인했다. 이 환경 차이를 실제 모바일 기기 성능으로 해석하지 않는다.
- 모바일의 옆쪽 의자에서는 모닥불이 화면 밖으로 치우쳤다. 집중 시 의자 뒤에서 고양이와 모닥불 사이를 바라보도록 시점을 수정했다. 375px의 네 방향 좌석에서 모닥불 이름표가 화면 중앙·상단 UI 아래에 유지되는 것을 검사하고 캡처를 확인했다.
- 최종 확장 섬 검증: 브라우저 흐름 13개, 복구 5개, 터치 4개, 추적 시점 4개, 집중·음원·반응형 8개, 의자 클릭·바다·30석 표시 3개로 총 **37개 통과**. 정상 흐름의 브라우저 오류와 브라우저/집중 검사에서의 외부 요청은 0건이었다. 집중 중 그래픽 context를 잃으면 자리와 모닥불 음원이 해제되는 것도 확인했다. 타입 검사·빌드·Prettier·`git diff --check` 통과. 검증한 렌더 코드와 같은 빌드를 4174 로컬 preview에 반영했다.

## 최종 추가 검토 — 일반 섬·낚시섬 분리

사용자의 최신 지시에 따라 일반 섬의 산책·건물·모닥불 휴식과 낚시섬의 물가 의자 집중을 분리했다. 위의 같은 섬 모닥불 30석 검토는 이전 구현의 이력이다. 아래 검토가 최신 변경을 대상으로 한다.

- Claude 상태 작업자는 섬 이동, 30개 예약, 주제, 휴식 제외 누적 시간, 복귀, 종료 결과, 연결 중단을 구현하고 단위·통합 44개 통과를 보고했다. UI 작업자는 실제 낚시섬 연결 후 53개 화면 흐름을 검증했다. 에셋 작업자는 연못·폭포·물길·다리·식생·의자 낚시 자세를 코드로 만들고 30개 의자의 찌가 모두 수면 안에 있으며 몸·낚싯줄이 이웃 자리와 겹치지 않음을 수치로 확인했다. 상세는 `docs/island-split-{state,ui,assets}.md`에 있다.
- 코디네이터 통합 빌드(4176): 타입 검사·Vite 빌드·Prettier·`git diff --check` 통과. 3D 의자 직접 hover/클릭, 바다와 연못의 움직임/동작 줄이기, 섬별 주민 표시, 로컬 29개 테스트 소켓+브라우저의 30석 착석·만석·휴식 예약 등 시각/기능 5개 통과. 복구 5개도 통과하며 오류 0건이었다.
- 집중/음원 통합 검사는 두 창의 주민 분리·자리 중복 방지, 휴식 시간 정지, 같은 자리 복귀, 주제·음소거 유지, 90초 오디오 디코드와 gain 전환, 키보드 길게 종료까지 진행했다. 320px 실제 터치 종료에서 손을 떼는 순간 결과창까지 닫히는 오류가 발견돼 전체 검사를 통과로 기록하지 않았다.
- 터치 결과창: 새 모달에서 시작하지 않은 포인터 클릭은 무시하고, 배경 닫기는 배경에서 누르고 뗀 동작만 받도록 수정했다. 실제 터치 종료 후 결과창 유지·두 결과 버튼·모달 닫기·체크박스·이름표 검사를 포함한 별도 회귀 25개가 통과했다.
- 이름표: 내 이름과 장소를 우선하고 다른 고양이는 가까운 순서로 배치한다. 겹치면 한 줄 위로 옮기거나 숨긴다. 30명 장면에서 DOM 31개(안내 포함)는 유지하며 확인한 전체/가까운/회전/375px 구도에서 보이는 이름표 겹침은 0개다.
- 수정 후 작업자가 코디네이터의 집중 검사 13개·시각 검사 5개를 스크립트 변경 없이 4187 production preview에서 통과했다. 90초 오디오 디코드·gain 전환·모바일 실제 터치가 포함된다. 오류 및 집중 검사 외부 요청 0건. 코디네이터는 최종 통합 4176 빌드에서 기존 브라우저 흐름 13개와 실제 터치 이동·회전·핀치 4개도 통과했다.
- 물길: `focus-water.ts`의 순수 좌표를 렌더와 이동 판정이 공유하도록 추출했다. 다리 밖 물길·소는 몸 반경까지 고려해 막고, 두 다리 위는 양방향 통과를 허용한다. 이동 샘플 간격을 15cm에서 5cm로 줄여 입구의 물을 스치는 경로를 막았다. 작업자는 새 물길 검사 7개를 포함한 단위·통합 **51/51**(3회), 다리 양방향 12경로, 30석 출구·시작점·휴식 자리 회귀, 지형 높이 12,960점의 변경 전후 일치를 확인했다.
- 최신 검증 묶음은 브라우저 흐름 13 + 복구 5 + 실제 터치 이동 4 + 집중/음원/반응형 13 + 시각/30석 5 = **40개**다. 별도로 UI 흐름 53개와 터치 결과창·이름표 회귀 25개를 작업자가 보고했다. 검사 환경과 실행 주체는 `docs/validation-results.json`에 구분했다.
- 최종 빌드의 JS/CSS가 4176 통합 검증 번들과 바이트 단위로 같음을 확인하고, 4174 사용자 preview 서버도 새 프로토콜로 재시작했다. 실제 4174에서 1440px·375px 각각 섬 이동→착석→휴식→이어가기→길게 종료→결과→일반 섬을 통과했다. 모바일은 실제 CDP 터치 종료 후 결과창 유지도 확인했으며 오류 0건이다.
- 빌드는 성공하지만 JS 단일 청크는 1,309.82kB(gzip 369.65kB)로 1,200kB 경고 기준을 넘는다. Vite의 향후 native config loader 관련 확장자 경고도 남아 있다. 현 로컬 빌드·서빙을 막는 오류는 아니다.

## 추가 검토 — 한글 WASD·카메라 이동·줌

- 실제 CDP 키 이벤트 `key=ㅈ, code=KeyW`로 이전 4174 빌드에서 600ms 동안 좌표가 `(0.0,12.2)`로 고정되는 것을 재현했다. 이동키를 `event.key` 대신 물리 `event.code`로 해석하고, 키를 뗄 때 언어가 달라도 같은 키를 지운다. 입력창·모달·브라우저 단축키는 이동으로 처리하지 않는다. 입력창을 떠나 장면을 누르면 산책 입력을 받는다.
- `CameraRig.tsx`로 카메라를 분리했다. 우클릭·Shift 드래그·두 손가락 밀기로 평면 이동하고, 따라가기 모드에서는 다시 걸을 때 고양이 중심으로 돌아온다. 이동량을 제한해 섬에서 과하게 벗어나지 않으며 드래그·핀치 뒤의 클릭이 고양이 이동이나 의자 선택으로 이어지지 않게 한다.
- 휠/트랙패드 이동량을 정규화하고 줌 목표 거리로 보간한다. ± 버튼과 키보드 +/−를 제공한다. 전체/추적 전환은 0.45초 보간, R·시점 버튼은 구도 복귀다. 가까운 낚시 시점은 시선 중심을 고양이 쪽으로 당긴다. 동작 줄이기는 관성과 전환 애니메이션을 생략한다. 모달을 열면 남은 관성을 버린다.
- 단위·통합 **54/54**, 새 조작 검사 **14/14**, 기존 터치 4·복구 5·의자/수면/30석 시각 5를 합친 이번 브라우저 검토 **28개** 통과, 오류 0건. 한글 네 방향 이동·한영 전환 후 키 해제·입력창 보호·우클릭/Shift 이동·추적 복귀·휠 줌·거리 제한·다중 프레임 전환·동작 줄이기·의자 집중 잠금·실제 두 손가락 이동/핀치·320/375/768/1024px 카메라 버튼을 확인했다.
- 첫 동작 줄이기 검사는 버튼 클릭 직후 DOM 이름표가 다음 렌더 프레임을 반영하기 전에 읽어 실패했다. 두 렌더 프레임 후 위치를 읽고 그 뒤 250ms 동안 같음을 확인하도록 고쳤다. 제품 애니메이션을 검사에서 끄거나 허용 오차를 늘리지 않았다.
- 4174 최신 빌드에서 한글 물리 KeyW 입력 뒤 좌표 `(0.0,12.2)`→`(0.0,10.3)` 이동과 확대 버튼 동작을 확인했다. 최종 배치 검증 번들과 JS/CSS가 바이트 단위로 동일하며 Orca 브라우저를 산책 화면으로 갱신했다.
- 실제 Orca 1024px 창에서 카메라 도구와 섬 둘러보기의 겹침을 발견해 좁은 창은 2×2 버튼으로 바꾸고 하단 메뉴 높이에 맞춰 올렸다. 버튼 최소 너비 때문에 서로 겹치는 부분도 수정했다. 320×568, 375×812, 768×812, 1024×775, 1440×650, 1440×1000의 일반/전체 시점 **12개 배치**에서 44px 이상 조작 영역, 버튼끼리·상단·하단·안내와 겹침 없음, 화면 안 배치를 확인했다. 조작 28개 검사 후 제품 변경은 이 반응형 CSS이며, 기존 설치 버전인 `three-stdlib 2.36.1`을 직접 의존성으로 명시했다. 최종 타입 검사·빌드·Prettier 통과.
- [검증 결과](docs/controls-validation.json), [Orca 화면](docs/controls-orca.png), [가까운 줌](docs/controls-zoom-near.png), [먼 줌](docs/controls-zoom-far.png), [낚시 확대](docs/controls-fishing-zoom.png), [모바일 핀치](docs/controls-touch-pinch.png).
- 카메라 조작 의미는 [Three.js OrbitControls 공식 문서](https://threejs.org/docs/pages/OrbitControls.html)를 참고했고 실제 API는 설치된 `three-stdlib` 구현과 대조했다. 실기기·Safari에서는 확인하지 않았다.

## 범위와 남은 제약

- Chromium의 데스크톱·모바일 에뮬레이션에서 검증했다. 물리 iPhone/Android 기기와 Safari의 검증 결과는 없다.
- 현재 결과는 로컬에서 검토 가능한 일반 섬 산책·별도 낚시섬 의자 집중·모닥불 휴식 구현이다. 절차적 모델과 리깅·동작을 재제작했지만, 실제 기기의 프레임 안정성·발열·장시간 조작감은 검증하지 않았다. 테스트 개수나 작업 시간으로 아트 완성도를 판단하지 않는다.
- 서버는 인증 없는 로컬 검토용 방이다. 운영 실시간 서버 연결·계정·영속 데이터·재화·건물 내부 전체 기능은 이번 이동/애니메이션 구현 범위 밖이다.
- 기존 네이티브 화면은 바꾸지 않았다. 새 폴더는 기존 Expo 앱 CI의 검사 경로 밖이므로 여기 기록한 별도 로컬 검증을 사용했다.
- 브랜치 초기 push만 수행했다. 구현은 별도 worktree의 미커밋 변경으로 남겼고 PR 생성·머지·배포는 수행하지 않았다.
